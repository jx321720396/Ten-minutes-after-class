## 1. 事实源在 Notion（不在仓库）

玩法规格的**唯一事实源是 Notion 玩法文档**：

- **Notion 链接**：`待补充 —— 请在此填入 Publish 后的 notion.site 链接`
- 仓库**不维护玩法正文**：避免与 Notion 形成双源漂移。玩法问题查 Notion；需要变更规格时，用仓库的「设计讨论 / 规格变更」Issue 记录**实现影响**。

## 2. 仓库侧保留什么（工程契约）

仓库只保留**实现所必需的工程契约**——它们不随 Notion 的文案调整而变化：

| 契约 | 位置 | 说明 |
|---|---|---|
| 设计铁律 | [`../design/架构总览.md`](../design/架构总览.md) 第 5 节 | 禁止脚本化、禁止角色 ID 判断、观察层只读、假信息必须有破绽、数值可标定 |
| 规则与观察层编号 | Notion 玩法文档 §10（R1–R13 / O1） | 代码中的规则编号以此为唯一出处 |
| 数据接口 | [`../design/数据模型.md`](../design/数据模型.md) | 矩阵与个体属性的字段名、`data/` 表结构 |
| 公式与参数骨架 | [`../design/规则引擎设计.md`](../design/规则引擎设计.md) | 主循环、传导公式、参数读取方式 |
| 术语与标识符 | [`../design/术语表.md`](../design/术语表.md) | 中文术语 ↔ 代码标识符对照 |
| 目录与依赖边界 | [`../design/架构总览.md`](../design/架构总览.md) 第 1–3 节 | 内核 / 表现层分离、目录约定 |

## 4. 细化文档写在哪里

v3.0 §16 的开发优先级已转化为 [`../production/路线图.md`](../production/路线图.md)（M0–M3）。

模块级**实现细节**（数据结构、伪代码、验收指标、数值表结构）写在 [`../design/`](../design/架构总览.md) 与 `data/`，**不写回本目录**——本目录只做入口与契约登记。

## 5. 修订流程

1. 玩法改动在 **Notion** 修改（策划主导）；
2. 若改动影响实现（字段、规则编号、公式、数值来源），开仓库「设计讨论 / 规格变更」Issue，记录实现影响，并更新 `../design/` 对应文档；
3. 范围变化同步到 [`../production/里程碑.md`](../production/里程碑.md)；
4. 影响结论的变更记入 `CHANGELOG.md`（「文档」或「变更」分类）。
