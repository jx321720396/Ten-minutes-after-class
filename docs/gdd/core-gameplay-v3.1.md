# 第一章 游戏定位与目标

## 1.1 玩家身份

《下课十分钟》是一款以高中班级为场景、以涌现为主题的老师管理模拟游戏。玩家扮演刚入职学校的实习老师，受到领导重视，被提拔为班主任。

玩家通过教室监控观察学生，也可以进入教室巡视、调座位、检查书包和没收物品，或把学生叫到办公室私聊。学生根据自身数值、公开被动、当前关系与环境自主行动。

## 1.2 两项任务

1. **提高班级平均成绩**：第七天进行第一次周考，平均成绩不达规定目标，老师被辞退。
2. **维持班级安全与关系**：防止形成达到判据的孤立、霸凌、退学和严重伤害。风险有预警与处理窗口；达到失败判据后，老师被辞退。

玩家需要在有限时间内兼顾学习、学生的承受能力和关系变化。推动某个学生学习，可能增加他的压力；安排聊天，可能改善关系，也会消耗学习时间。

## 1.3 班级规模

- 角色池固定为 **16 名学生，一局全部入局**。
- 老师是玩家控制的管理实体，**不作为第十七个学生社交节点**。
- 学生之间保留好感与敌对两张有向矩阵，尺寸为 16×16。
- 标准座位关系以 4×4 学生座位为基础。旧场景的讲桌旁第十七座如何保留、置空或复用属于后续场景迁移，不自动保留旧玩家座或皇帝位加成。

## 1.4 单局范围

本轮没有另行裁定学期长度，保留原有 **30 个上学日**与每日三个课间、两个上课段的时间骨架。第七天周考是第一个明确考核节点。

七天可作为最先验证的区间，不能据此把正式学期直接改成七天。后续周考安排、目标递进及学期成功收束条件列入第十五章的待裁定事项。

# 第二章 涌现主题与闭环

## 2.1 涌现主体

涌现主体是**班级关系结构及其后果**：朋友圈、跨圈联系、持续排斥、群体冲突，以及这些结构给学习和老师管理带来的影响。

压力、动力和学业收益提供管理取舍；公开被动提供个体差异。它们本身不是涌现的充分证明。宏观格局必须由学生之间反复发生的局部互动形成。

## 2.2 两道检验

- **检验一：把关系发展换成固定脚本，核心玩法还成立吗？** 若改为某天固定争吵、某天固定孤立，老师通过调座位、鼓励、调解改变关系与事件的能力就应失去意义。若只管理成绩仍能完整替代游戏，则关系涌现尚未承担核心内容。
- **检验二：整体是否拥有个体没有、也没有被个体完整安排的性质？** 学生只决定学、玩、找谁聊天；全班最终形成的关系结构应来自多次局部选择，而不是某个角色或老师预设的全班剧本。

## 2.3 必须保留的反馈

**座位与当前状态 → 接触及具体事件 → 好感、敌对和压力变化 → 下一次接触选择 → 新的关系格局。**

关系必须影响学生找谁聊天、靠近谁、回避谁，并影响学习受扰和冲突风险。老师没有发出指令时，学生之间也会自主社交。

簇标签、孤立标签和风险标签只解释运行结果，不回写矩阵。鼓励可以促成一次尝试，不能直接保证友谊或把指定学生写成必然的救助者。

## 2.4 制度与剧情的边界

课程表、学期长度、第七天周考属于固定制度，可以按日期配置。谁被排斥、谁与谁发生冲突、谁崩溃不得按日期或角色名脚本化。

# 第三章 学期、课间与结算时间

## 3.1 每日结构

保留三个可操作课间与两个上课发酵段，放学后跨天结算并生成每日简报。上课不冻结学生系统；上课行为子集与老师在上课段的操作权限需要后续裁定。

老师操作需要时间；处理一名学生时，其余学生继续行动。现实播放倍率、每段 tick 数及具体行动耗时由配置决定，不能把旧学生版数值默认为本轮已重新确认的参数。

## 3.2 结算职责

| 结算 | 时间口径 | 内容 |
|---|---|---|
| 老师干预与具体事件 | 行动生效或事件完成时 | 训斥、安抚、鼓励目标、没收、聊天和调解的效果 |
| 学习与娱乐累计 | 固定活动时段 | 压力、动力、学业收益及符合条件的被动；不按渲染帧数发奖 |
| 座位基础关系 | **每个课间一次** | 第八章的 +1、−1、+5 三条基础规则 |
| 跨天结算 | 当日结束、进入次日之前 | 今日学业收益计入成绩，生成明细并开始新一天的累计 |

老师干预当场影响后续选择；已经发生的学习和娱乐结果保留。上述职责不能互相替代。

## 3.3 课间关系结算的整理落点

当前策划整理采用**每段课间结束时统一结算一次**。先处理到期活动，再读取座位及实际活动状态，结算座位基础关系，最后清理旧段状态并进入下一相位。

每课间一次已经确认；用课间末快照还是课间过程记录判定学习／娱乐，仍需在实现前确定，见第十五章。不能在清理活动后把所有人误判为娱乐，也不能同时保留旧版每日两次上课好感涓流造成重复加算。

# 第四章 数值定义

## 4.1 三个独立数值与当前成绩

| 名称 | 含义 | 主要职责 |
|---|---|---|
| **压力** | 当前承受的负担 | 风险、崩溃及承受空间 |
| **动力** | 当前学习的意愿 | 决定默认学习或娱乐状态 |
| **今日学业收益** | 当日累计、次日将计入成绩的净变化 | 记录真正发生的学习收益与娱乐损失，允许正负 |
| **当前成绩** | 已完成跨天结算的成绩 | 计算班级平均成绩与周考考核结果 |

压力与动力按 0–100 的个体量管理；今日学业收益是有符号累计量，以成绩分数计，不能按 0–100 钳制。学生当前成绩、班级平均成绩与周考目标采用高考总分尺度，本次先按 750 分制整理，个人成绩范围为 0–750；总分、初始分布及具体收益幅度放入配置。目标均分是全班 16 名学生总成绩的平均目标，不是全班成绩之和，也不默认要求达到满分。

同一行为可以同时增加压力和动力，但两者没有固定换算关系。高动力高压力、低动力高压力等组合都必须成立。

“学习动力”这一旧称退出第三项的命名：促使学习的是动力，已经积累的成绩变化叫学业收益。

## 4.2 好感与敌对

- **好感 A[i][j]**：i 对 j 的亲近意愿。
- **敌对 H[i][j]**：i 对 j 的不满、反感和记恨。
- 两者保留 0–100 值域和方向性：i 对 j 与 j 对 i 分别存储。
- 两轴独立。好感增加不自动扣敌对，敌对增加不自动扣好感；同一对子可以同时高好感、高敌对。

## 4.3 删除与替代

老师版删除透明度、信任度以及隐藏的性格四维修正。学生差异改由开局配置中的**公开专属被动**提供，见第十章。

不得把删除的数值换名后继续作为隐藏修正，也不得因删除信任就把敌对折成好感的负数。旧信念过滤、性格倍率、深层敌对、情绪传染和影响力传导不自动沿用；是否迁入及如何简化需单独裁定。

## 4.4 跨天成绩结算

**次日成绩 = 当前成绩 + 今日学业收益**，再按配置成绩值域处理边界。结算成功后，今日学业收益清零；收益明细进入日末记录。

例如，上午学习累计 +5，下午娱乐减少 2，当日净收益为 +3，次日成绩增加 3。不能因进入娱乐状态而清空上午成果，也不能把剩余动力直接加到成绩上。

压力和动力是否衰减、保留多少、是否有自然补充尚未裁定。不得直接采用旧压力保留率，也不得通过每天全部归零抹去长期管理后果。

# 第五章 学习、娱乐与崩溃

## 5.1 默认状态选择

在固定的行为决策点判断：

- 动力 **>50**：默认进入学习。
- 动力 **<50**：默认进入娱乐，再根据当前关系、物品和可用活动选择具体行为。
- 动力 **=50**：保持当前学习／娱乐状态。开局没有前一状态时，由配置明确初始状态。

压力不承担学习／娱乐切换职责。不得每帧检查并切换行为。决策点采用新段开始、当前活动结束等明确边界；具体学习时段长度需要配置。

## 5.2 活动方向

| 活动 | 压力 | 动力 | 今日学业收益 |
|---|---|---|---|
| 学习 | 增加 | 减少 | 增加 |
| 听歌、聊天、打闹、玩手机、吃零食等娱乐 | 减少 | 基础规则保持不变 | 减少 |

娱乐降低的“学习动力”按本轮术语理解为学业收益，不再混入新设动力。不同活动的耗时、减压、收益损失与事件影响分别配置。

娱乐既占用学习时间又减少学业收益，存在双重成本；标定时须确认减压足以产生合理休息策略。公开被动与具体事件可以修正基础效果，但界面必须解释来源。

## 5.3 崩溃

压力过高可以触发崩溃并中断当前活动。崩溃检查独立于默认活动决策点，不能让正在硬撑学习的人因尚未到下一决策点而失去预警与中断机会。

入口阈值、概率或持续时间判据、恢复方式及附加影响需要配置并裁定。已积累的学业收益不因活动中断自动清空。

本轮不把压力倒 U 学习效率曲线作为必做要求；先验证学习消耗动力、积累压力所形成的取舍。

# 第六章 老师操作

## 6.1 操作清单

| 操作 | 用途与已确认效果 | 仍需规定 |
|---|---|---|
| 看监控 | 观察现有教室中的行为、接触与风险，不直接改关系 | 时间播放与观察权限 |
| 进入教室／巡视 | 到场增加教室内学生的压力；能够观察并介入现场 | 压力幅度、停留影响、是否改变动力 |
| 办公室安抚 | 目标压力降低，动力及既有学业收益不直接改变 | 耗时、减压幅度 |
| 办公室训斥 | 目标压力和动力都增加，不直接产生学业收益 | 耗时、两项增量 |
| 打听关系 | 获取学生关系和近期矛盾的信息 | 每次信息范围及呈现 |
| 鼓励 | 给目标一次自主或指定对象的聊天目标 | 耗时、目标有效期 |
| 调座位 | 改变全班后续接触机会与基础关系结算 | 可操作时点、频率、耗时 |
| 检查书包／没收 | 查找并移除手机、小说、零食等物品；没收增加较大压力 | 搜查与没收各自耗时、压力、动力及物品恢复规则 |
| 处理冲突／调解 | 制止正在发生的伤害，降低风险，并按事件修复敌对 | 处理耗时、敌对减量、后续复查 |

办公室私聊包括安抚、训斥、打听、鼓励四个方向。老师操作不能绕过学生当前状态、目标有效性和时间预算。

## 6.2 有限时间

行动耗时是管理资源。玩家巡视时不能同时在办公室私聊；处理一名学生时，其余学生继续活动。学生赴办公室与参与聊天也占用自己的时间。

不得通过瞬时、无限重复的“训斥加动力—安抚去压力”取消管理成本。到场加压属于一次真实到场事件，不能按每帧或每次打开界面重复触发；反复进出及连续针对同一人的规则须在行动参数中明确。

## 6.3 物品与取舍

没收可以减少对应娱乐机会或干扰，同时移除一个泄压途径。学生失去物品后，按剩余可用活动重新选择，不直接锁死为学习。

手机、小说和零食的持有属于物品事实，不能成为隐藏人格。旧赠书、免罚券、皇帝位及考试奖励不自动迁入老师版。

# 第七章 鼓励与交流目标

## 7.1 两种用途

| 模式 | 老师意图 | 学生行动 |
|---|---|---|
| 鼓励交流 | 帮助近期缺少交流的学生建立联系 | 按当前关系与可用对象选择一个人，尝试聊天 |
| 鼓励指定交流 | 请擅长聊天的学生帮助另一人融入，或改善两人关系 | 尝试与老师指定的学生聊天 |

鼓励给学生一个可见的临时行动目标，**本身不直接增加好感、学习动力或学业收益**。是否产生额外情绪效果需要以后单独裁定。

## 7.2 执行边界

1. 老师完成鼓励后，记录一次交流目标。
2. 学生在下一次可行动时，优先尝试该目标；不能打断已占用的活动或忽略崩溃。
3. 对象忙碌时可以等待；对象的接受、拒绝及聊天结果仍由正常规则处理。
4. 一次目标只促成一次尝试，不自动无限重试。完成、拒绝或到期后，记录结果并结束目标。
5. 恢复由动力决定的默认活动。指定聊天是临时优先行动，不通过把动力强行改到 50 以下实现。

## 7.3 结果与成本

真正发生聊天后，才结算正常减压、学业收益和关系变化；符合条件的聊天被动在正常结算点生效。

老师能够保证安排一次尝试，不能保证对方接纳、好感增长或长期友谊。若本课间未完成，应显示未完成原因；目标是否跨课间保留及具体有效期列入参数裁定。

鼓励消耗老师时间，聊天消耗学生学习时间。擅长聊天者可以帮助别人，但反复安排他社交也会影响其学业收益。

# 第八章 座位与关系结算

## 8.1 邻域定义

基于座位表判断，临时走动位置不替代固定座位：

只对不同学生的关系结算，不对自身关系写入增减。

- **正交邻座**：前、后、左、右相邻一格。
- **对角邻座**：斜向相邻一格。
- **周围一圈之外**：与目标座位的最大行列距离大于一格。

## 8.2 每课间一次的基础规则

| 条件 | 基础变化 |
|---|---|
| 前后左右邻座 | 双方各自对对方好感 **+1** |
| 对角邻座 | 不因座位关系增加好感 |
| 周围一圈以外 | 双方各自对对方好感 **−1** |
| 学习状态学生的正交邻座处于娱乐状态 | **学习者对娱乐者敌对 +5**；不自动反向增加 |

四条规则按用户本轮原案保留。好感 +1 与敌对 +5 可以在同一对子同时发生，各自写入，不覆盖、不抵消。

基础 +5 不改写为“只有发生可见噪音才增加”。真实聊天、打闹、停止打扰、友善互动和老师调解等事件可以另行增减关系，与基础变化叠加。

## 8.3 长期变化

关系好的学生换座后仍可能走到一起聊天，实际交流可以维系关系；长时间远离与持续的 −1 会使联系逐渐变弱。关系不好的学生成为邻座后也会积累好感，但已有敌对需要通过具体事件修复。

角落与中央的邻居数量不同，可能导致结构性关系差异。保留上述原规则，并在多局标定中检查是否出现角落学生无论如何管理都会失去关系的情况；不把远处衰减擅自改为“只有无交流才发生”。

## 8.4 结算与事件去重

每个课间只执行一次基础关系结算，按“天数＋课间编号”去重。具体事件按事件编号结算；聊天被动不能在座位结算时再发一次。

新规则取代旧版八邻域共同学习／上课好感涓流作为默认关系基线。若以后保留其他关系来源，必须列明触发条件和频率，不能无声叠加旧参数。

# 第九章 学生自主行为与关系修复

## 9.1 自主选择

学生的默认活动由动力决定；任何需要伙伴的行为都遵循下述找伴、接受与带朋友规则。当前占用、距离、物品及活动参与条件决定对象是否可参与，关系变化会改变下一次选择。

老师没有发出鼓励时，学生也会自主聊天和走动。高好感不保证每次互动顺利，高敌对不保证每次接触都发生暴力。

### 9.1.1 找伴：熟人优先

任何需要伙伴的行为，优先邀请自己对其好感最高、且满足当前活动参与条件的学生。好感按“发起者 → 候选伙伴”的方向读取，不按角色名或固定 ID 选人。独自学习、听歌等不需要伙伴的行为不强制找伴；好感并列时的选择方式在实现前配置，并保证同种子可复现。

优先邀请不等于对方必然接受。老师鼓励指定交流时，指定对象替代自主找伴结果，仍执行正常接受规则。

### 9.1.2 接受：现有成员逐人投票

邀请或申请加入活动时，由现有活动成员对加入者分别投票；两人新建活动时，由被邀请者作为唯一现有成员投票，加入者不参与投票。

- 每名成员读取自己对加入者的有向关系：**好感 − 敌对 ≥ 10，投同意票；否则投拒绝票**。恰好高 10 点也同意。
- **同意票超过现有成员总数的一半才接受；平票拒绝**。因此双人团体须两票同意，三人团体至少两票同意。
- 每次请求统一读取关系、投票并产生一次团体结果，不逐人掷概率，不额外叠加隐藏性格、压力修正或旧版接受概率。
- 忙碌、空间不足或不满足活动参与条件属于暂时无法参与，不作为关系投票拒绝；鼓励目标的等待与有效期仍按第七章处理。
- 接受后加入同一场活动，成员与活动结束时间统一管理；一次请求不得重复结算同一条互动关系。拒绝不代表活动已经发生。

个人同意门槛 **10** 必须在实现时放入 `data/`，不得硬编码；当前仅确认策划规则，尚未替换旧运行时的接受实现。

### 9.1.3 带朋友：邀请加入原活动

活动参与者可以按找伴规则邀请自己的朋友加入当前活动。新朋友仍须满足活动参与条件，并由全部现有成员按同一套规则投票；邀请者有一票，不能替其他成员保证接纳。

接受后并入原活动，不另开重复活动，不重算原成员之间已经结算的互动。带朋友不直接增加好感或减少敌对，实际活动发生后才按对应事件结算。活动人数上限、邀请时机与频率在实现前配置；本条不预设三人上限，也不允许同一决策点无限连锁邀请。

## 9.2 具体事件

| 事件 | 作用方向 |
|---|---|
| 顺利、友善的交流 | 增加相关方向的好感，并可减少敌对 |
| 被拒绝、受到持续打扰 | 按事件增加压力或敌对 |
| 停止打扰并维持一段无伤害接触 | 满足修复条件时减少敌对，不抹除所有历史 |
| 老师调解 | 制止冲突、降低风险，按明确效果降低敌对 |
| 高敌对下的接触 | 提高争吵或伤害风险，仍需具体行动与事件条件 |

每种事件必须写清参与者、方向、耗时、生效点、数值来源和日志。降低敌对是真正对敌对轴的减量，不能只增加好感来代替。

## 9.3 观察与原因

朋友圈、孤立与风险标签是只读结果。不得写“因为已被标记孤立，所以全班继续减少对他的好感”；标签可以提示老师采取行动，行动再按正常规则产生影响。

# 第十章 公开专属被动

## 10.1 角色差异

每名学生有一条开局配置的公开专属被动，学生档案与相关行为预览直接显示效果。用可计算的差异替代隐藏性格四维，玩家可以据此调整座位、学习安排和交流目标。

角色差异来自配置，统一规则读取被动。禁止在行为脚本中判断角色名或固定角色 ID 来实现加成。老师选择某名学生作为操作目标不属于角色专属逻辑。

## 10.2 候选效果

下表用于明确被动写法，**尚未等于 16 名学生的最终分配表**：

| 候选被动 | 可见效果 | 结算要求 |
|---|---|---|
| 专注 | 每完成一个固定学习单位，今日学业收益额外 **+1** | 单位长度固定，不能反复开始／停止刷奖励 |
| 健谈 | 每完成一次聊天，本人对聊天对象的好感额外 **+1** | 方向明确；多人聊天的覆盖范围另行裁定 |
| 乐观 | 每完成一次娱乐，压力额外减少 1 | 作为候选，须检查基础减压与频率 |
| 自律 | 每完成一个学习单位，动力消耗减少 1，最低为 0 | 作为候选，不把消耗减成动力恢复 |

前两项来自用户提出的被动示例；后两项是候选扩展。具体角色绑定与其余被动需要后续表格，不按名字推断擅长什么。

## 10.3 清晰与平衡

- 一条被动明确一个效果、一个触发单位、作用对象和生效点。
- 被动按真实完成事件结算，不按画面帧数或按钮点击结算。
- 行为预览显示基础值、被动修正和预计结果，例如“学业收益 +3＝基础 +2＋专注 +1”；此例仅解释展示方式，不定基础值。
- +1 的强度必须结合基础收益和频率标定；基础收益为 1 时，额外 +1 就是翻倍，不能因绝对数小便认定差异轻微。
- 不新增隐藏人格倍率替玩家解释结果，也不让某个被动保证固定社交结局。

# 第十一章 风险判定、预警与失败

## 11.1 通用流程

**具体行为及关系记录 → 风险判定 → 预警与介入 → 持续观察 → 达到失败判据或风险缓解。**

短暂独处不直接判孤立，普通争吵不直接判霸凌。危机需要明确的时间窗口、行为证据和阈值，允许老师提前发现并处理。

## 11.2 判据组成

| 风险 | 判定应包含的证据 | 不能单独作为判据 |
|---|---|---|
| 孤立 | 持续缺少被接纳的关系、接触机会受限、尝试交流反复失败或受到持续排斥 | 一次独处、一次拒绝、单个低好感值 |
| 霸凌 | 对同一对象重复或持续的伤害，以及人数、支持关系或实际伤害上的不对等 | 一次普通争吵、仅有高敌对 |
| 退学风险 | 持续受伤、压力失控与关系支持不足等记录 | 一次娱乐、一次崩溃 |
| 严重伤害 | 真实发生且达到严重程度的伤害事件 | 仅有风险提示 |

阈值与窗口尚未裁定。因安静独处而缺少聊天不能自动等价为失败；观察层根据证据输出标签，不直接改变行为。

## 11.3 干预与失败

预警期内，老师可以巡视、安抚、鼓励、调座位和调解。处理能停止伤害、降低风险，但不能直接把好感和敌对重置成理想值。

第七天周考平均成绩不达标，或已经达到确认的孤立、霸凌、退学、严重伤害失败判据时，触发辞退。预警与一般争吵本身不等于这些失败事件；重大事件发生后的处理不能伪造为事件从未发生。

## 11.4 解释义务

预警说明对象、依据、趋势和可采取的行动；失败说明触发了哪个判据，以及相关行为和干预记录。禁止没有证据、没有可观察破绽的随机辞退。

## 12.1 核心可见信息

**2026-10-14 关注卡片实施**：第三张“需要关注”纸卡已接入真实高压名单与实际活动人数。高压预警阈值从 data/ui/attention_card.json 读取，当前试用值为 80，不等于崩溃或辞退判据；点击名单可进入学生档案。学习／娱乐／其他人数按实际活动、在场与移动状态归类，排除旧玩家，不由平均动力推算。普通争吵只接受真实事件记录，按事件 ID 去重并以最后状态为准，已结束不计；当前模拟尚未提供这些记录，因此显示“—”，不从敌对、打闹或压力爆发推断争吵。三张卡片按可用屏高缩放，详情保持完整视口。验收见 [关注卡片验收](../qa/关注卡片验收-2026-10-14.md)。

## 12.2 监控与私聊分工

- **监控**：复用当前教室场景，观察谁在学习、娱乐、聊天、移动，谁接触谁，谁在打扰或伤害谁。
- **私聊打听**：获取具体关系与近期矛盾，记录对象、方向、来源和发生时间，帮助老师安排交流与调解。
- 不再以透明度或信任阈值遮挡信息。关系是否默认全量展示、打听每次提供多少信息需要裁定；获取过的旧记录不能伪装成当前实时关系，未知不能当作中立。

## 12.3 行动反馈

行动完成后展示实际变化与来源。巡视加压、训斥加动力、被动额外收益、聊天拒绝和调解减少敌对都需要可见反馈。

鼓励显示“交流目标：与某某聊天一次”，并记录完成、拒绝或未完成的原因。打开只读档案或切换监控目标不得产生新的关系效果。

## 12.4 每日简报

简报至少包含：个人与全班的学业收益明细、结算后的成绩变化、压力与动力趋势、已发生互动及关系变化、鼓励执行结果、风险预警和老师干预记录。

朋友圈等标签来自实际关系；解释可以指出形成原因，不能用预制剧情替代事件日志。

## 12.5 档案中的玩家手动关系标注

同学档案对每个有向学生对子显示**一组当前好感／敌对标注**，每一轴分别注明来源和记录时间。没有真实消息时，由玩家自行推断与选择；获得真实消息后，覆盖对应方向、对应轴的当前标注，不要求把消息与推测分成两套并排数值。

- 打开学生甲的档案，选择学生乙作为关系对象，明确当前方向为“甲 → 乙”；反向关系单独保存。
- 玩家分别标注好感与敌对，两轴独立，可以同时判断为较高。
- 未标注且未获知的轴显示“未判断”；玩家可以修改或清除自己的推测。未判断不等于中等或零。
- 获得真实消息时，只覆盖消息涉及的方向与轴，并显示“已获知”、获取时间与来源。只获知好感不覆盖敌对，甲对乙不覆盖乙对甲。
- 消息表示获取时的关系，不实时同步后台。玩家以后再次手动修改该轴时，来源改为“我的推测”；获取过的消息继续保留在历史记录中。
- 当前标注、来源、方向、修改时间与历史消息随本局存档保存；它们属于观察／玩家笔记，不写真实关系矩阵，不改变学生行动、压力、动力、风险或随机序列，不根据隐藏状态即时判定推测对错。
- 不恢复信任、透明度或学生对老师的关系轴。

交互整理建议采用每轴独立的档位选择：“未判断／较低／一般／较高／很高”，适合移动端直接点击；这是界面建议，不把档位强行换算成精确后台数值。最终档位、是否支持额外数字估计与备注，需在界面实施前确认。

## 12.6 推理板中的多人分析

**同学档案负责一对学生的定向关系判断，推理板负责多人关系及其原因的整理。** 玩家可以在推理板联系多个学生、事件和线索，记录朋友圈、跨圈联系、矛盾来源或持续排斥的假说；这些内容仍是玩家推理，不能作为真实风险标签回写内核。

推理板中的多人假说不由档案里的某个高好感或高敌对标注自动判定。如果推理板展示同一条双人关系判断，应读取同一份玩家标注，避免维护互相冲突的副本；具体联动与操作形式需要界面设计。系统观察到的关系格局、已获知线索与玩家假说须有清楚的视觉区别。

# 第十三章 工程边界与迁移约束

## 13.1 不变的约束

1. **数据驱动**：角色差异来自公开被动和开局状态；行为逻辑依赖被动配置、关系、环境及当前状态，不判断角色名或固定 ID。
2. **观察层只读**：簇标签、孤立和风险识别不回写任何矩阵。
3. **数值集中**：阈值、增量、窗口、耗时、频率、被动修正放在 `data/`。动力 50、关系 +1／−1／+5 也要配置化。
4. **内核纯净**：模拟内核只接收数据和命令，不依赖 UI、表现节点或引擎导航类型。
5. **可复现**：随机数使用带种子的 `RandomNumberGenerator`；同种子、同命令序列得到相同结果。
6. **唯一结算**：事件、每课间关系和跨天成绩各自去重；矩阵访问走访问器，表现层不能直接改数值。

## 13.2 数据与存档

老师版应包含学生阵容、公开被动、好感／敌对矩阵、压力、动力、当前成绩、今日学业收益及明细、当前活动、座位／临时位置、物品、老师位置与行动占用、交流目标、风险所需历史、相位时间和随机状态。玩家手动关系标注、获取过的线索和推理板笔记作为独立观察／笔记数据保存，不替代真实关系矩阵。

保存和恢复需要保留未结算收益及结算去重信息，避免读档重复加成绩或重复发被动。学生版存档含第十七个玩家节点和被删除轴，不能未经版本检查直接作为老师版存档读取。

## 13.3 实现状态

教室表现已区分监控和实际进入教室两种状态；右侧为老师行动与只读学生档案入口，旧学生行为栏、纸条和邀请弹窗不再运行或显示。旧玩家形象与拾取体仅在表现层隐藏／关闭，模拟仍为待迁移的学生版；巡视数值、私聊、调座位和冲突处理效果不由本次 UI 改动宣称完成。

2026-10-14 已新增移动端办公室表现界面：同一教室实例保留运行，办公室提供教室监控、去教室、叫学生来、同学档案、推理板与百科入口。监控为只读视图；“叫学生来”目前只有学生选择与未接入提示，不执行私聊或任何老师数值效果。办公室界面完成不代表下述老师版内核迁移完成；详情见 [办公室界面验收](../qa/办公室界面验收-2026-10-14.md)。

# 第十四章 制作优先级与验收

## 14.1 实施顺序

1. 三个数值与跨天成绩结算，固定决策点的学习／娱乐状态。
2. 老师有限时间与安抚、训斥，监控中的清楚反馈。
3. 16 名学生、公开被动及每课间一次的座位基础关系。
4. 学生自主聊天与移动、具体事件修复敌对，鼓励的一次交流目标。
5. 风险证据、预警、处理与辞退，七天首次周考闭环。
6. 搜包／没收完整链、上课段权限、跨天继承、后续考核与 30 天学期收束。

本轮只规定顺序，不承诺新的交付日期。赛事提交目标仍按制作文档跟踪，旧学生版冲刺任务不能作为老师版已完成情况。

## 14.2 规则验收

| 检查 | 应满足的行为 |
|---|---|
| 默认活动边界 | 动力 >50／<50／=50 正确；压力不能替代动力判定 |
| 学业收益账目 | 学习与娱乐累计可追溯；跨天只计入一次；切换、崩溃和读档不清空已获得收益 |
| 被动 | 固定完成单位生效，方向可见；反复启动、渲染帧数和重复事件不能刷奖励 |
| 关系基线 | 正交 +1、对角不加、圈外 −1、学习者对娱乐邻居 +5；独立叠加、每课间一次 |
| 修复 | 友善交流、停止打扰和调解确实减少敌对，不只抬高好感 |
| 找伴／接受／带朋友 | 所有需伙伴行为优先找高好感对象；成员对加入者好感减敌对恰为 10 时同意、低于 10 时拒绝；严格过半通过、平票拒绝；邀请者不能绕过团体投票；加入原活动不重复结算旧边 |
| 鼓励 | 一次尝试、正常接受规则、真实完成才结算；拒绝和到期能解释 |
| 风险 | 短暂独处和一般争吵不误判；持续伤害可预警和介入；失败有证据 |
| 玩家关系标注 | 方向与轴分别保存；未判断不等于中立；真实消息只覆盖对应方向与轴并记录来源；历史保留，手动修改改为推测；标注不改变模拟状态 |
| 确定性与边界 | 同种子同命令复现；观察层调用前后矩阵一致；老师不是学生节点 |

## 14.3 涨落与管理验收

多种子检验动力消耗、压力积累、学业收益增长及修复速度是否匹配。不能仅看一局平均分。

检查无限训斥／安抚、反复进门、反复开始学习、频繁换座、临近铃声切状态等操作是否绕过成本；检查角落学生是否必然失去关系、敌对 +5 是否压过全部修复、被动是否形成绝对优胜者。

还要检查没有动力自然补充时是否很快全员停在娱乐状态。跨天补充或保留规则未裁定前，不能宣称长期动态已经成立。

## 14.4 涌现验收

同一开局、同一种子下，分别采用集中督学、分区排座、主动鼓励交流等策略。应观察关系结构、冲突来源、支持关系和管理难题的差异，不只比较最终分数。

老师不下社交指令时，学生仍需形成自主接触和关系变化。预期现象是验证目标，不保证每局固定发生；不能安排某天必然分裂或某人必然成为社交中心。

# 第十五章 确认事项、整理落点与待裁定参数

## 15.1 本轮确认

- 玩家改为实习老师／班主任，管理全班成绩与关系安全。
- 学生与全班平均成绩、周考目标均分按高考总分尺度表示；具体达标线仍待裁定。
- 压力、动力、今日学业收益分别定义；动力以 50 为学习／娱乐边界，等于 50 保持状态。
- 学习增加压力、消耗动力、累计学业收益；娱乐降低压力并减少学业收益。
- 训斥增加压力和动力；安抚降低压力；两者不直接产生学业收益。
- 学业收益跨天累计结算，切换状态不清空；老师干预有有限时间。
- 保留原案正交好感 +1、对角不加、圈外 −1、学习者对娱乐邻居敌对 +5；每个课间一次，具体事件修正。
- 好感与敌对独立；友善交流、停止打扰、老师调解可以减少敌对。
- 失败有明确判据与预警；短暂独处不是孤立，一般争吵不是霸凌。
- 删除透明度、信任度；公开被动替代隐藏性格修正。
- 增加鼓励交流与鼓励指定交流，促成一次真实聊天尝试。
- 需要伙伴的行为优先找好感最高的可参与对象；现有成员逐人按“对加入者好感 − 敌对 ≥10”投同意票，严格过半才接受，平票拒绝；参与者可邀请朋友加入原活动，仍须团体投票。
- 界面显示压力、动力、今日学业收益；监控看行为，私聊补关系信息，日末解释成绩变化。
- 同学档案支持玩家手动标注学生之间的好感与敌对；同一组当前标注先由玩家推断，获真实消息后按方向与轴覆盖并注明来源；推理板承担多人关系与原因分析。

## 15.2 本次整理采用的落点

以下用于把讨论写成连贯策划；实现前需与参数表一起核对，不伪装成用户已经给定的精确数值：

- 座位基础关系放在课间结束统一结算；老师干预在行动生效时处理。
- 娱乐、安抚对新动力的基础影响取保持不变；其他变化须有明确事件或被动来源。
- 16 名学生构成社交网络，老师在网络之外；标准布局采用 4×4。
- 日结后的学业收益清零；压力和动力另行规定继承。
- 鼓励采用一次临时交流目标，不强行修改学习动力，也不保证友谊。
- 一局保留 30 天；七天仅作为首次考核和优先验证区间。
- 高考总分尺度本次先采用 750 分制，示例当前均分 474、目标 525、差距 51；这些示例不确定初始分布或实际周考达标线，不自动换算学习收益或被动 +1。
- 关系手动判断建议使用各轴独立的档位选择，未判断单独保留；具体档位和额外数字估计未定。
