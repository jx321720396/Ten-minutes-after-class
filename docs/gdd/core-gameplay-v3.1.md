# 第一章 游戏概述

## 1.1 游戏定位

《下课十分钟》是一款以高中校园为场景的社交模拟游戏。玩家扮演一名转学生，作为班级社交节点之一（角色池共 24 人，按难度随机抽取 8/16/24 个 NPC 入局，玩家另算，本局共 9/17/25 个节点），在**一个学期（30 个上学日）里每一天的三个课间**通过搭话、递纸条、调侃、安慰、举报等行为，参与并扰动一个自运行的班级社交系统。

游戏核心不是完成固定目标，而是：**你埋下种子，系统自己发酵，长出的班级格局不属于你也不属于任何一个 NPC。** 玩家的每一次操作只是在关系矩阵中拨动一个数值，整个系统自行重新洗牌，涌现出独属于这一局的班级格局。

## 1.2 核心概念

- 玩家不是上帝，而是系统的一部分。NPC 和玩家共用同一套底层规则。
- 即使玩家什么都不做，NPC 之间也会自发社交、传八卦、抱团、对立、崩溃。
- 没有预设剧情、没有固定结局、没有正确答案。谁和谁成了朋友、谁被孤立、哪两个阵营对立、谁在这一天崩溃了——全部从底层规则中涌现。

## 1.3 玩家目标

***用有限的信息，拼出你认为的班级真相。***

玩家不是"观察者"，而是"解释者"：每个课间获取的只言片语、矛盾情报、虚假态度线，都进入玩家的**推理板**。玩家的操作影响班级走向，而推理板记录玩家如何理解这个走向。局末，玩家看到自己拼出的"真相"与系统实际格局的对照——理解对了是洞察，理解错了是这一局独有的故事。

## 1.4 一局流程（一学期 = 30 天）

一局 = 一个完整学期 = 30 个上学日。每个上学日的结构：

1. 上午课间（操作，实时）
2. 上午课堂（发酵过场，快进）
3. 中午午休（操作，实时）
4. 下午课堂（发酵过场，快进）
5. 放学结算（跨天继承 + 每日简报）

第 2 天从上午课间继续，关系矩阵跨天继承

第 30 天放学 → 《学期格局报告》

- 每天三个可操作段 = 上午课间 / 中午午休 / 下午课间；每天实时约 5 分钟，30 天总计约 2.5~3 小时（单日即一个自然游玩/存档单元）。
- 两段上课过场负责"发酵"：课间埋下的矛盾在上课期间继续发展，玩家无法干预。
- 放学后生成《每日简报》并执行跨天结算（关系继承与衰减）；学期末生成《学期格局报告》，回顾 30 天涌现出的班级格局。

# 第二章 涌现主题阐释

## 2.1 两道检验题

本游戏的所有设计都经过以下两道检验题的筛选：

- **检验一**：把涌现的部分换成脚本，游戏还成立吗？如果还成立，主题就只是装饰。
- **检验二**：玩家面对的那个整体，是否拥有任何部分都没有、也没有任何部分想要的性质？

## 2.2 排除假涌现

- **因果链不是涌现**：A 导致 B，B 导致 C，是蝴蝶效应，每一环都能单独解释。
- **数量累加不是涌现**：种满 30 朵花只是部分加在一起，整体没有新性质。


## 2.3 涌现主体：班级格局

没有任何一个 NPC 想要形成小团体、想要排挤某人、想要和另一个阵营对立。每个个体只维护自己的好感、敌对、信任、压力等数值，遵循简单规则。**小团体、孤立、阵营对立、压力崩溃后的关系重塑，是整个系统运行后自发浮现的宏观性质。**

用检验一验证：如果"成团""孤立""对立"换成预设脚本（第 2 个课间 A/B 必然成团、第 3 个课间 C 必然被孤立），游戏失去核心——因为本游戏里**根本没有成团规则，只有读矩阵的标签器**。

# 第三章 时间与节奏系统

## 3.1 一局 = 一个学期 = 30 天

一局游戏覆盖一个完整学期（30 个上学日），每天含 3 个可操作课间段和 2 个上课发酵段。**每段课间的游戏内时间仍是 10 分钟（扣住标题），实时压缩播放；每天实时约 5 分钟，学期总计约 2.5~3 小时。** 关系矩阵跨天继承——今天的恩怨，明天继续发酵。

## 3.2 tick 定义

| **阶段** | **游戏内时长** | **实时时长** | **1 tick** | **每段 tick 数** |
| --- | --- | --- | --- | --- |
| 课间段 ×3 | 10 分钟 | 100 秒 | 6 秒游戏内 = 1 秒实时 | 100 |
| 上课段 ×2 | 45 分钟 | 15 秒（快进） | 30 秒游戏内 | 90 |
- 每天总 tick ≈ **480**（课间 300 + 上课 180）；每天实时 ≈ 3×100 + 2×15 ≈ **5 分钟**（结算界面不计入）。
- 学期总 tick ≈ **14,400**（480 × 30 天）；学期总时长约 2.5~3 小时，单日即一个自然游玩/存档单元。
- 课间 = 高分辨率模拟：全部行为规则 + 玩家操作。
- 上课 = 低分辨率发酵层：只跑规则子集（见 §3.3）。
- 放学后 = 跨天结算层：关系继承 + 衰减 + 每日简报（见 §3.5）。



## 3.3 上课发酵层（低分辨率 · 只跑行为子集）

上课不是暂停，而是「发酵结算层」。上课期间座位固定、玩家不可操作，只运行以下内容：

| 内容 | 上课期间的行为 |
|---|---|
| **共同学习** | 相邻（距离 ≤1 格）且双方主行为均为「学习」的对子，**每天结算 2 次**（上午 / 下午）：好感 +1、信任 +1 |
| **流言传播** | 低频触发（每 3~5 tick 一次，只能传纸条 / 小声说话） |
| **影响力传导** | 继续运行（态度在座位邻近与信任链上缓慢扩散） |
| **压力发酵** | 事件驱动照常；压力涓流（**学习 +1 / 独处 −2**，参数在 `data/rules/behavior_probs.csv`）随涓流结算一并执行 |
| **搭话 / 闲聊 / 调侃 / 安慰 / 求助 / 道歉 / 举报** | **禁用**——课间埋下的矛盾上课无法解决，只能积累（但流言仍在暗处扩散） |
| **睡觉** | 若上课前已入睡，则不参与任何交互（见 §10.8） |
| **玩家** | 不可操作，但可查看情报日志 + 推理板（等待变成思考时间） |

> ⚠️ v3.0 快照 §3.3 中的「**座位相邻缓慢加好感**」一条**已废弃**：物理相邻不再直接改数值，只提高自发互动的概率（见 §10.15 注释 5）。

设计意义：

1. **慢积累 + 快相变**：课间埋矛盾 → 上课发酵 → 下个课间爆发，爆发有因果、有铺垫。
2. **"我埋的种子自己发酵"**直接回应检验一：玩家上课时什么都做不了，格局还在自己变。
3. 三阶段形成叙事弧线：上午埋因 → 中午发酵 → 下午爆发/成团，简报可写出"从混乱到秩序"。

## 3.4 数值标定目标（反推所有涓流与事件值）

以每天 480 tick、学期 14,400 tick 为基准，所有数值按以下目标反推，而不是先定数值再凑时长：

1. **好感**：关系是**慢变量**——从陌生（20）到明显可见的变化（约 45–60）需要 **约 10 天**（一天净增 1–3 点，靠长期累积而非单次事件）；单日不能饱和，**也不能一天涨很多**。玩家应在一局的中后段才明显感到「格局成形」。
2. **压力爆发**：平均 **每 1~2 天一次**，且集中在每天的第 2、3 段课间（发酵之后），不是开局就爆。
3. **30 天不饱和（长期形态）**：一局结束时全班好感**饱和率（≥95）应 < 10%**，均值落在 **45–65**，且分布保持**分化**（标准差 ≥ 20）——这是「涌现不提前死亡」的硬指标；**只看前 10 天的均值会漏判**（见 §7.1 第 4 条）。
   *当前实测（**40 局 × 30 天**，第四道门默认口径；判定读真值 + `reject_stress`=2 + `join_chat_affinity`=43）：**四项全部达标** —— 饱和率 **0.0%** ✓、**爆发均值 17.9** ✓（目标 15–30）、均值 **55.4** ✓（目标 45–65）、**SD 22.6** ✓（目标 ≥20）。口径与重标定过程见 §18.9「2026-10-07 判定口径收口」及 §6.4。*
   *⚠️ 口径不一致，待测试处理：上一行的达标数字测于 **40 局口径**，而第四 / 第五道门默认样本量已于 2026-10-07 上调至 **100 局**（见 §18.9）—— **不要在 100 局口径下引用这组数字**；下一轮跑门时按 100 局复测并替换。*
   *⚠️ 标定纪律补充：**爆发次数是长尾指标，必须跑大样本**。同一份代码只换种子集：8 局 → 11.6 / 20 局 → 13.6 / 40 局 → 17.8 / 60 局 → 21.9 ⇒ 小样本会系统性误判（第四道门默认种子集已因此由 8 提到 40，并于 2026-10-07 再提到 100；第五道门同步由 20 提到 100）。*
   *⚠️ 已知张力（标定时须一起看）：「爆发次数」与「好感均值」是**同一个压力旋钮的两端**——压力高则爆发多，但 `M_state` 会同时压制好感使均值下降。*
   *〔历史记录·信念口径时期，已被下文取代〕实测扫描：`interrupted_stress` = 0.7 → （爆发 16 / 均值 66.1 / SD 20.8）、1.0 →（34 / 59.3 / 22.1）、1.3 →（30 / 58.9 / 23.6）、1.6 →（51 / 54.9 / 23.2）。关键路径：把搭话判据从「`B_A >= 40`」（先验恰为 40 → 永远通过）改为「信念 + 对方性格，门槛 45」，**打通了关系变差的通道**，SD 才从 10.6 升到 25.1。详见 §10.17。*
4. **格局弧线（学期尺度）**：第 1 周关系试探、轮廓未明 → 第 2–3 周关系分化（阵营雏形、个别孤立）→ 第 4 周格局成形或爆发大事件。**因为好感是慢变量，前两周不应出现明显的派系对立**——与第 1 条一致。

### 3.4.1 标定纪律：旋钮与耦合（动手前必读）

> **本作有一条隐藏的耦合链**：`M_state` 规定「压力 40–70 时正面事件 ×0.75」，
> 于是**任何"提高压力"的旋钮都会同时压低好感**。
> 这不是 bug —— 它的语义是「**被针对的班级，关系整体更冷**」，是正确的涌现；
> 但标定时**必须知道它存在**，否则会反复出现「调好一个指标、搞坏另一个」。

**动手前先问一句：这个旋钮会不会同时推动另一个指标？**

| 旋钮 | 主要影响 | **会连带推动什么** | 是否"单向" |
| --- | --- | --- | --- |
| `transmission.beta_*`（传导强度） | 好感增速 | 与保留率**共同**决定稳态 `A* ≈ 增益/(1−保留率)`；单调 β 只能平移，去不掉饱和 | ✗ 半耦合 |
| `decay.decay_a_no_interact`（好感保留率） | 好感稳态 | **只压好感，不产生压力** | ✅ **单向，微调首选** |
| `transmission.feedback`（负反馈） | 好感饱和上限 | 只作用于**正向轴**，不产生压力 | ✅ **单向** |
| `behavior_probs.interrupted_stress`（被打断代价） | 压力 | **同时压低好感**（经 `M_state`）→ mean 与爆发**反向** | ✗ 耦合 |
| `behavior_thresholds.join_chat_affinity`（搭话门槛） | 好感 | **同时涨压力**（拒绝变多 → `reject_stress`）→ 爆发随门槛上升而**暴增** | ✗ 耦合 |
| 初始信念分化（`belief.w_bias` 等） | 初始误差 | **同时涨好感**（搭话通过率上升）→ mean↑ / SD↓ | ✗ 耦合 |
| `decay.retain_s`（压力保留率） | 压力稳态 | 过高会**全员**高压（实测 0.85 时全班均值冲到 59）→ 「人人都崩溃」≠ 涌现 | ✗ 危险 |
| `behavior_probs.chat`（闲聊频率） | 好感增长 **+** 压力消解 | ⚠️ **一身两职**：`chat` 既产生好感，也通过 `topic_stress`(−2) **减压**。降它会同时造成「好感涨慢」**和**「压力堆积」—— 实测 0.06 → 0.008 时，**爆发从 21 飙到 82** | ✗✗ **双耦合** |
| **减压侧 ↔ 压力** | 睡觉 / 闲聊 | ⚠️ 压力**进得少**未必是「进得不够」，可能是**漏得快**。实测：`sleep_relief` 8→3 让爆发均值 8.8→11.6；但再压到 1→12.2、**0→9.0（反降）** —— 「睡觉」本身有价值，全禁适得其反。**先查哪里漏，再决定加多少**。 | ✗ ✗ 双向 |
| **怕吵者专属 ↔ 全员** | 环境层 | ⚠️ `noise_pressure` 的 `fear` 当初只算「怕吵的人」（内向 / 专注），于是 `stress_k` **放大 12 倍仍无效** —— 因为压力**只落到少数人身上**。加 `noise_base_fear`（基础项，全员受嘈杂影响）后立刻起效：爆发均值 11.6 → 15.9。**「信号只发给了小部分人」是隐蔽的失效方式。** | ✗ 间接耦合 |
| **标签接入**（`tags.csv`） | 行为意愿 | ⚠️ 会**经由 `chat` 双重角色**间接推高爆发：标签让「爱学习」者少闲聊 → 全班闲聊量下降 → 减压变少 → 压力堆积（实测 3205 → 2743 次闲聊，**爆发 24 → 54**） | ✗ 间接耦合 |
| 音量基线 ↔ 压力 | 环境层 | 两者**互相牵动**：压力低 → `chat` 的「压力 ≥70 时 ×0.5」不生效 → 聊天更活跃 → **音量升高**（实测调低压力后，音量从 75 被顶回 86~88） | ✗ 耦合 |

> **📐 标定口径**：§3.4 的目标约束的是**分布的下限与上限**，**不是单局结果** —— 它管的是「**机制在不在场**」，而不是「结果长什么样」。谁成为欺凌者、哪条边结死仇、派系怎么切、爆发落在哪天，**都是要保护的良性方差**，
> 任何标定都不得压缩它；只有「机制整条线没上场」才属于要拦截的失效方差。
> （口径来源：外部核对提出「方差分两种」，经核验成立，已固化为第五道门。）

**⚠️ 第七条：先查「机制在不在场」，再谈「结果好不好」。** 方差分两种：
**良性方差**（谁成为欺凌者、哪条边结死仇、派系怎么切、爆发落在哪天）→ **要保护**；
**失效方差**（机制整条线没上场）→ **要拦截**，因为那不是「另一种结局」，而是「承诺的体验在这局里缺席」。∴ 判据应是**存在性检查**：**机制上场率** + **跨局指纹差异**（第五道门 `tools/diversity_report.py`）。

**⚠️ 第八条：同一维度的方向约定必须钉死，禁止各调用点自行解释。** 本会话发现 `dims[3]`（**直读为 J 强度**，见下）
在 **6 处调用点被按两套语义混用**（有的当 P、有的当 J），导致「J 越高越怕吵」「高 J 反从众」「高 J 温度更低」
三条注释与实现**方向相反**且长期未被发现 —— 因为它们**不报错**，只是悄悄把关系反了过来。

> **约定**：`dims[3]` **直读为 J 强度**（50 = 中性）。**凡公式要表达「J」的，一律用助手 `arg_j(i)`**，
> 禁止再手写 `(dims[3] ± 50)`。
>
> ⚠️ **同时更正一处文档与数据的矛盾**：§5.5 曾把第 4 维描述为「感知度 P（0 端=判断 J）」，但**种子数据实际存的是 J**（李峥 ESTJ=95 且注释写明「J=95 派生」；王磊 ESFP=25），**以数据为准**。曾按旧文字写成 `(50 − dims[3])/50`，那会把**全班人格镜像**。
> 并优先使用助手 `arg_j(i)` / `arg_i(i)`（`core_sim.py`），从根上消灭方向歧义。
> 已同步写入 `数据模型.md`（维度方向约定表）与 `术语表.md`。

**⚠️ 第六条：标定结论必须基于「多种子分布」，不能看单局。** 用单个种子把参数调到达标，本质是**拟合那一个种子**——本会话就发生过：几轮标定都以 `seed=12345` 为准、逐轮报「四项达标」，而在 8 个种子上复跑后发现 **爆发合格率仅 12%、均值 12%、标准差 25%、举报 0/8**。∴ 第四道门 `check_metrics.py` 已改为**多种子**。

**⚠️ 但「每局都达标」同样是错的**（用户指正）—— **涌现的本意就是每局都不一样**，要求每个种子都合格，等于反向扼杀多样性。∴ 门最终改为判**分布**：

| 判据类型 | 要求 | 理由 |
| --- | --- | --- |
| **跨局均值** | 落在目标区间 | 「平均对不对」 |
| **畸形项**（如好感饱和） | **每一局都守住** | 那是病态，不是多样性 |
| **跨局分化度** | 足够大（均值跨局差 ≥3、爆发差 ≥5） | 防止退化成「每局一模一样」 |
| **涌现覆盖率** | 只报比例，**不要求每局都发生** | 举报/排挤本就该是稀有事件 |

**一句话：允许每局不同，但不允许平均不对、也不允许全员畸形。**

**⚠️ 第九条：往文档里写「行内代码」时，不要把它放进 shell 命令行。** shell 会把**反引号**当成命令替换，
于是 `` `join_feedback` `` 会被**静默吃掉**，只在文档里留下一个空括号 `（）`——而命令**返回成功**，看不出任何异常。
本会话就发生过一次：一次 `python -c "..."` 里的三处反引号全部被替换掉，文档写入了不完整内容却毫无报错。

> **做法**：凡是含反引号 / `$` / 双引号的内容，一律**写进脚本文件再执行**（或整体用单引号包裹），
> **不要**塞进 `python -c "..."` 的双引号里。
> **另**：这类失败属于「**回执≠真相**」——命令成功 ≠ 内容写对了，所以**写完要回读校验**（本次即靠回读发现）。

**⚠️ 第五条：验证链必须用 `&&`，不能用 `;`。** 本会话有一次 `check_config` 返回非零（`cc=1`），但因为命令里用了 `;` 而非 `&&`，**失败没有阻止后续提交**，坏状态被推了上去。凡「跑校验 → 提交」的链条，校验必须能**中断**流程；否则校验等于没跑。

**⚠️ 第四条（本会话反复踩的坑）：改了配置值，必须同步它的注释与文档引用。**
`data/` 各表的 `note` 列常写着「按实测 xxx 定」这类**具体数值**，改了 value 却不改 note，
下次就会照着过时的注释去判断（本会话已出现多次：`volume_threshold` 值改 20 而注释仍写 36；`behaviors.csv` 的 `noise` 值变更而文档表格未同步）。改完请**直接 grep 实际文件内容**核对。

**三条操作建议**：

1. **优先用单向旋钮做微调**：需要"把好感压下来一点"时，用 `decay_a_no_interact` 或 `feedback`，
   **不要**去动压力类或门槛类参数；
2. **改压力相关参数后，一定要同时看 mean 与 SD** —— 它们是耦合的另一端；
3. **一次只动一个旋钮，并且记录前后数据**（`tools/calib_experiment.py` 就是为此存在的）。

## 3.5 跨天结算层（放学后）

每天放学后执行一次，让"一天"成为长线涌现的积木：

| **结算项** | **规则** |
| --- | --- |
| 关系继承 | 好感/敌对/信任矩阵完整保留到第二天（今天的恩怨明天继续） |
| 好感衰减 | 当天**无互动**的对子 ×0.86（`decay_a_no_interact`）；**有互动**的对子 ×0.98（`decay_a_interact`）；「有互动」判据 = 当天该对子事件类结算次数 ≥ `interact_min_events`（1） |
| 敌对衰减 | **表层** ×0.95（`decay_h`）；**深层** ×0.995（`deep_decay`，极慢）；深层是总数底线，不得被表层衰减压穿（§10.22、§10.29） |
| 信任衰减 | ×0.93（`decay_t`，信任需要持续维护） |
| 压力衰减 | ×0.735 跨天保留（`retain_s`；0.50 永远够不到爆发阈值、0.85 会把基础涓流放大成全员高压）；若当天爆发过，携带「心结」标签 3 天，每天初始压力 +5 |
| 信念遗忘 | 每天 `B ← B + λ_b·(prior − B)`（`belief.lambda_b` = 0.02，§18.5）——信念不再「只学不忘」 |
| 座位重排 | 每天开局可重新选/被调座位，改变相邻格局（**改变的是自发互动的机会，不是直接数值**，见 §10.15） |
| 每日简报 | 生成《每日简报》，归档进学期日志 |

***心结可传染（连环爆发）**：压力爆发时，除本人获得「心结」外，还会**扩散给与本人关系最鲜明的少数人**（`status_tags.csv` 的 `spread_ratio` × 在场人数，上限 `spread_max`；按 `|A − H|` 排序取前几名）。情绪传染沿**关系**传播——死党会替朋友焦虑、死对头也会因对手崩溃而紧张，泛泛之交则不受影响。因此「连环爆发」的形态由班级关系结构决定，而非随机撒点。

*衰减系数已按 §3.4 目标标定（当前取值见 `data/rules/decay.csv`）。衰减的意义：关系必须持续经营才维持得住，否则 30 天会全部饱和到 100，涌现提前死亡。**关键关系：稳态 `A* ≈ 每日增益 / (1 − 保留率)`**——所以「全班饱和」与「衰减太快」其实是同一个旋钮的两端，单靠调这个旋钮无法同时满足；真正的解法是 §7.1 第 4 条的负反馈。*

# 第四章 系统架构总览

## 4.1 三层架构

系统分为三层，各司其职，不冗余、不循环依赖：

| 层级 | 内容 | 特性 |
| --- | --- | --- |
| 行为接口层 | 第十章的人物行为（闲聊 / 搭话 / 举报 / 告密 / 窃听 / 流言；状态层：走动 / 睡觉） | 决定这一 tick 谁和谁发生什么互动，快变量 |
| 情绪状态层 | 压力值（唯一累积情绪变量） | 累积-爆发机制，中变量 |
| 底层态度轴 | 好感/敌对/信任（有向矩阵）+ 透明度/性格（个体） | 稳定的关系与人格，慢变量 |

## 4.2 闭环说明

底层态度轴决定规则触发条件（谁能搭话、谁会传八卦、谁能成团）；规则执行后回写底层轴和压力值；状态变化又改变下一次规则的触发条件。玩家的每一次操作，只是在这个闭环中拨动一个节点的数值，然后整个系统自己重新洗牌。

# 第六章 统一数值计算公式

## 6.1 好感/敌对/信任的统一公式

所有事件对好感、敌对、信任的影响，全部使用同一个公式：

**Δvalue = base × clamp(1 + Σ(wᵢ × dᵢ), 0.1, 1.2)**

| **符号** | **含义** | **范围** |
| --- | --- | --- |
| base | 事件对该数值的基础变化量（正=增，负=减），策划填表 | 任意整数 |
| dᵢ | MBTI第i维偏差值 = (维度值−50)/50 | [−1, +1]，50为中性 |
| wᵢ | 该事件类型对第i维的敏感度权重，策划填表 | 通常[−1, +1] |
| clamp | 倍率区间 **0.1 ~ 1.2**（性格影响温和：最多放大 20%） | [0.1, 1.2] |

四个维度固定顺序：d₁=E/I, d₂=S/N, d₃=T/F, d₄=J/P。

## 6.2 透明度：种子为准 + 压力系数

透明度不是事件直接加减：

**当前透明度 = 基础透明度 × 压力系数**

- **基础透明度 = 角色种子值（opacity_init）**，由性格派生（§11.4）：
  `opacity_init = clamp(50 + 1.2·(E−50) + 0.3·(F−50), 15, 85)` —— **内向 / 低 F 更不透明**，外向 / 高 F 更通透；角色差异只来自开局种子。
  `data/characters/seeds.csv` 已按该公式填好（如苏晴 15、何川 23、陈阳 82）；新增角色时用同一公式生成。

压力系数（`M_state`）：**以实现为准** —— 取值集中在 `data/rules/axis_coef.csv`，代码与文档都读它：

| 压力区间 | 系数 | 含义 |
| --- | --- | --- |
| 0–40（常规区） | ×1.0 | 心态平稳，事件按原幅度结算 |
| 40–70（中度区） | **负面 ×1.5 ／ 正面 ×0.75** | 越慌越敏感（负面被放大）；同时**听不进去劝**（正面被压缩） |
| 70–90（高压区） | ×1.5 | 临界区，事件一律放大 |
| ≥90 | ×1.0 | **阈值相变交给 §8.5 的每日概率爆发**，事件系数不再放大 |

- 「≥90 按性格分化」**不再挂在压力系数上**，改由 §8.5 的**爆发形态**表达（好斗 → 当众指责 / 封闭；敏感 → 崩溃 / 透明度归零；随和 → 退缩）——一处口径，不再两处。
- 中度区「负面放大 + 正面压缩」是同一条耦合的另一面：压力高 → 关系被压低（§3.4.1 的 mean 与爆发放反）。

## 6.4 统一判定公式（决策 / 判定）

所有行为判定统一为**两段式概率判定**，只有一套公式，不因行为而异：

### 决策侧（做不做）——读信念，概率化

```
触发强度 s ∈ (0,1)，没有 0/1 硬门槛
  环境类  s = p_base × Π 修正系数                     // 本来就概率化
  阈值类  s = σ((x − θ) / scale)                      // 越过多少决定概率，低概率也可能发生
  意向类  s = softmax(U_b / τ_i)                      // U_b 含软门槛项（见下）
软门槛项 = w_gate × [σ((A[i][j] − θ_A)/scale_A) + σ((θ_S − Stress[i])/scale_S) − 1]
```

**决策侧只能读两样东西**：我自己的立场（真值 `A[i][*] / H[i][*] / T[i][*]`）与
我眼中别人的态度（信念 `B_A / B_H / B_T`）。**不得出现 `A[j][i]` 这类"别人对我的真值"**（§18.7 不变式 3）。

**玩家跳过决策侧**：玩家是否发起由人自己决定，不再掷"想不想"的骰——这是玩家相对 NPC 的优势（§12.1）。

### 判定侧（成不成）——读真值，sigmoid + 掷骰

```
score = f(参与者 A/H/T + 性格四维 + 当前状态)
p     = σ((score − θ) / scale) = 1 / (1 + exp(−(score − θ)/scale))
结果  = Bernoulli(p)
```

- `p ∈ (0,1)`：**概率再低也可能成功，再高也可能失败**，没有固定门槛。
- `θ` 是 `p = 0.5` 的拐点（不是闸门），`scale` 控制坡度，均落在 `data/rules/behavior_thresholds.csv`。
- **判定侧读真值**：谁接纳谁由参与者的真实 `A/H/T` 决定。
- **唯一例外是展示层**：给玩家的成功率用信念 `B` 重算（§10.32.3）——同一公式两种输入：内部结算用真值、UI 展示用信念。

### 两段式与效果层

```
决策侧（想不想，读 B，玩家跳过）→ 判定侧（成不成，读真值，sigmoid 掷骰）→ 效果层（走 §6.1）
```

> **命名口径**：本节沿用「决策 / 判定」命名。设计讨论中的「触发判定（产生想法）」
> 即本节的**决策侧**，「决策判定（实际能否成功）」即本节的**判定侧**；语义一致，仅名称不同。

# 第七章 影响力传导机制（非线性版）

## 7.1 核心原理

好感的方向就是权力的方向：A[i][j] 高，意味着 i 愿意听 j 的话。但传导不是线性求和——**弱态度不扩散，多方拉扯要竞争，传导量有上限**：

1. **阈值（传不传）**：j 对 k 的态度低于阈值时不传导。
2. **竞争归一化（听谁的）**：i 同时被多个 j 拉扯时，按 i 对各 j 的听从度加权平均，而不是简单求和。
3. **软饱和（传多少）**：传导量经过软饱和 `sat(u) = u / (1 + |u|/U_X)` 压缩，高值收敛于 `U_X`（见 §6.1）。线性传导会让全班态度收敛到同一个均值，抹平分化；饱和让系统存在多个吸引子，派系可以稳定共存。
4. **负反馈（越满越难涨）**：**统一写入点的正向轴**（好感 / 信任）在写入前乘 `(1 − feedback·X[i][k]/100)`；**负面轴（敌对 / 压力）不适用**——否则「敌意升级」会被压死。
   没有这一项时，好感是**正反馈**：`A` 越高传导越强 → 稳态 `A* = 每日增益 / (1 − 跨天保留率)` ≈ 192 → **30 天全班一起封顶**（实测饱和率 90.8%）。只把负反馈加在传导上**不够**（实测 30 天仍 32% 饱和）——因为事件增益不受它约束，且 `C` 会随越阈人数增长而抵消抑制；**必须作用到统一写入点**。实测（25 天，`feedback`=1.0、`β_A`=0.20、保留率 0.95）：**饱和率 0.0% / 均值 45.9 / SD 18.6**，且 `C` 大的对子稳态更高 → **保留差异化**而不是整体平移。

## 7.2 传导公式

**传导归入涓流类，每天结算 2 次**（`settle_interval` = 240 tick，上午 / 下午各一次；见 §6 三类结算与 §18.3）。对每个接收者 i 和第三方 k：

```
w_ij   = A[i][j] / 100                        // i 对 j 的听从度
A'[j][k] = max(0, 感知A(j,k) − θ_A)           // 【感知值】j 对 k 的超阈值好感
H'[j][k] = max(0, 感知H(j,k) − θ_H)           // 【感知值】j 对 k 的超阈值敌对
T'[j][k] = max(0, 感知T(j,k) − θ_T)           // 【感知值】j 对 k 的超阈值信任
net_A = ( Σ_j w_ij·A'[j][k] − Σ_j w_ij·H'[j][k] ) / ( Σ_j w_ij + ε )
net_H = ( Σ_j w_ij·H'[j][k] − Σ_j w_ij·A'[j][k] ) / ( Σ_j w_ij + ε )
net_T = ( Σ_j w_ij·T'[j][k] ) / ( Σ_j w_ij + ε )
room_A = 1 − feedback · A[i][k] / 100        // 【负反馈】越接近饱和增益越小；负面轴不适用
room_T = 1 − feedback · T[i][k] / 100        // 信任同样受负反馈约束（正向轴）
Δ_A = round( room_A · sat( β_A · net_A, U_A ), 0.1 )   // 软饱和 + 精度 0.1，见 §6.1
Δ_H = round( sat( β_H · net_H, U_H ), 0.1 )            // 敌对轴不加负反馈
Δ_T = round( room_T · sat( β_T · net_T, U_T ), 0.1 )
写入：A[i][k] += Δ_A（若 Δ_A > 0）；H[i][k] += Δ_H（若 Δ_H > 0）；T[i][k] += Δ_T（若 Δ_T > 0）
      —— 三条轴各自独立累加，均钳制 0–100（好感 / 信任不因负向传导而扣减）
```

> 与早期版本的区别：**饱和函数由 `tanh` 换成统一软饱和 `sat_X`**（全系统一个公式，见 §6.1），**结算频率由「每 tick」改为「每天 2 次」**——这是「传导归入涓流类」的直接后果；**新增负反馈 `room`**（见 §7.1 第 4 条），这是阻止 30 天全班饱和的关键项，**同样适用于 §6.1 的事件写入**（统一写入点）。

参数表（初始值，待批量局标定；**权威来源 `data/rules/transmission.csv`**）：

| **参数** | **含义** | **初始值** |
| --- | --- | --- |
| θ_A / θ_H / θ_T | 好感 / 敌意 / 信任传导阈值 | 30 / 40 / 40 |
| U_A / U_H / U_T | 软饱和尺度（见 §6.1） | 25 / 25 / 20 |
| β_A / β_H / β_T | 传导系数（**每天 2 次结算**） | 0.20 / 0.30 / 0.15（敌意更容易传染；已含负反馈的补偿） |
| `feedback` | **负反馈强度**（0–1） | 1.0 |
| `settle_interval` | 涓流结算间隔 | 240 tick（每天 2 次） |
| ε | 防除零 | 0.01 |

## 7.3 双通道

- **态度通道**：走 §7.2 公式，权重是好感（你模仿你喜欢的人的立场）。
- **事实通道**：不走本公式，走 **流言传播（消息传歪）** 的信任判定——≥70 全信、40–70 半信、<40 不信；这条判定本身带阈值，是非线性的。

## 7.4 传导输入：感知态度（正式条款）

公式中的 `A'[j][k]`、`H'[j][k]` **一律使用"i 感知到的 j 对 k 的态度"**（经透明度 + 信任两层过滤后的值），而不是后台真实值。

含义：**低透明度的人，他的真实态度不扩散，只有他"演出来"的那部分才扩散**——这是"藏得住的人真的藏得住"在机制上的保证。

> 实现细节见 [`../design/统一影响公式.md`](../design/统一影响公式.md) §2.2 与 [`../design/信念矩阵.md`](../design/信念矩阵.md) §11。
## 7.5 涌现现象验证

| **现象** | **新机制如何产生** |
| --- | --- |
| 派系领袖 | 多人对同一 j 的 w 高 → 加权平均中 j 的态度占主导 → 群体复制；软饱和防止无限放大 |
| 墙头草 | 两个阵营 P≈N → net 在 0 附近 → Δ 符号随权重微扰反复翻转 → 态度横跳 |

| 团内隐形等级 | 谁的 w 高谁就是实际话事人，从 A 矩阵直接读出，无需显式角色标签 |

# 第八章 情绪状态层

## 8.1 设计原则

情绪状态层只存压力值这一个累积变量。其他情绪（开心、焦虑、愤怒、低落）全部由压力值、近期事件效价、性格底色派生，不独立存储。

心理学依据：Russell情绪环形模型——所有情绪都可以落在唤醒度（高/低）x效价（正/负）两个维度上。压力值即唤醒度，近期事件的好坏决定效价，两者交叉定位出具体情绪。

## 8.2 压力值

| 属性 | 说明 |
| --- | --- |
| 数据结构 | Stress[i]，个体单值，0-100，快变量 |
| 定义 | 社交焦虑、窘迫、紧张的累积程度 |
| 特点 | 事件驱动不自然涨，达到阈值触发情绪事件 |

## 8.3 情绪标签派生表

| **压力** | **近期效价** | **外向/随和** | **敏感/内向** | **好斗** |
| --- | --- | --- | --- | --- |
| 低 | 正 | 放松、满足 | 安心、自在 | 得意 |
| 低 | 负 | 无聊、无所谓 | 低落、落寞 | 不耐烦 |
| 中 | 正 | 兴奋、活跃 | 羞涩但开心 | 亢奋 |
| 中 | 负 | 有点烦 | 焦虑、不安 | 愠怒 |
| 高 | 正 | 激动、热闹 | 紧张但强撑 | 亢奋到失控 |
| 高 | 负 | 烦躁 | 窘迫、快哭了 | 愤怒、要爆发 |

## 8.4 压力来源与消解

| **事件** | **压力变化** | **结算类型** | **性格修正** |
| --- | --- | --- | --- |
| 被当众拒绝/被打断聊天 | +3 | 事件 | 敏感 ×1.5，外向 ×0.7 |
| 被八卦谣言指向 | +3 | 事件 | 敏感 ×1.5 |
| 被小团体明确排斥（重大） | +5 | 事件 | 随和 ×1.3（更受伤） |
| 被多人同时搭话 | +2 | 事件 | 内向 ×2，外向 −1（人来疯） |
| 信任的人背叛/传秘密 | +5 | 事件 + 状态 | 全性格大幅上涨；附加「心结」3 天，每天 +5 |
| 和高好感+高信任的人聊天（话题共鸣） | −2 | **事件**（每次闲聊结算一次） | — |
| 默认学习（未参与任何互动） | **+1** | 涓流（**每天 2 次**，`behavior_probs.csv` 的 `study_stress`） | — |
| 独处（不在任何对话中） | **−2** | 涓流（**每天 2 次**，`alone_stress`） | 内向额外 −1（独处回血快） |
| 离开人群聚集区 | −3 | 事件 | — |
| **行为被相位切换打断** | **+0.5** | 事件（相位切换时判定一次） | — |
> **性格系数区间 = 0.1 ~ 1.2**：性格对效果的影响**温和**——最敏感者最多放大到 1.2 倍（+20%），最迟钝者降到 0.1 倍。因此文档中「敏感 ×1.5」「内向 ×2」之类的表述，一律理解为**通过该事件的 `w` 系数实现，且最终倍率落在 0.1~1.2 之间**（敏感者接近 1.2、普通人接近 0.6、迟钝者接近 0.15）。
> 例外：**概率类修正**（成功率 +25%、守密概率 −30%）与 **`M_state`**（压力区间系数）不是这个倍率，不受此限。


## 8.5 概率爆发（不是「到点必爆」）

压力跨过**入口阈值 70**（= §8.3 高压区的入口）后，**每天判定一次**：

```
severity = (stress − 70) / (100 − 70)            // 0 = 刚过阈；1 = 满压
p_burst  = burst_p_max × severity                // burst_p_max 初值 0.5
爆发成功 → stress −= 40
         本人获「心结」，天数 × (1 + severity)
         传染范围 spread_max × (1 + severity)，被波及者心结天数亦 × (1 + severity)
```

**三条设计意图**：

1. **概率化（而非阈值相变）**：高压区是一个**危险斜区**，而不是一堵墙。若做成"到 90 必爆"，行为会在阈值附近疯狂跳变（UIF §2.6 边界③）；
2. **越晚越猛**：`severity` 同时放大**波及范围**与**心结时长**——拖得越久，爆得越大。这制造了「他快撑不住了…」的张力；
3. **大爆放大传染**：而传染又推进下一轮爆发 → 这就是**连环爆发**的结构来源（§3.5 心结可传染）。

> 参数：`burst`（阈值 70）在 `behavior_thresholds.csv`；`burst_p_max`（0.5）在 `behavior_probs.csv`；
> `spread_ratio` / `spread_max` 在 `status_tags.csv`。三者皆可标定，设 `burst_p_max = 0` 即关闭概率爆发。
> **实测（30 天，seed=12345）**：爆发 **16 次** ✓（目标 15–30）、饱和率 0.0% ✓、压力峰值 53.6
> （爆发成为主要泄压出口，故峰值低于入口阈值）。

# 第九章 信息可见性系统

## 9.1 核心设计

玩家看到的不是真实数值，而是经过两层过滤的态度信息：

真实态度（后台矩阵）→ 第一层：透明度（这个人有多容易被看穿）→ 第二层：信任（你通过谁获取信息，信息有多可信）→ 你最终看到的信息

## 9.2 透明度控制UI呈现

| **透明度** | **玩家看到的效果** |
| --- | --- |
| 高（80+） | 态度线是实线，颜色清晰（暖=好感，冷=敌对），粗细准确反映强度 |
| 中（40-80） | 态度线是半透明虚线，颜色偏淡，能看出大概方向但不确定强度 |
| 低（20-40） | 态度线时隐时现，旁边带问号，只能猜大概站哪边 |
| 极低（<20） | 完全看不到态度线，这个人是个谜 |

## 9.3 信任值解锁信息

基础可见：所有NPC的态度线默认按透明度显示。

信任解锁：当你和NPC X的信任度过线，X会主动透露他对其他人的真实态度——你看X对别人的态度线时，清晰度强制提升一档。

二手情报：信任度更高时，X还会透露别人对第三方的态度，相当于你通过X解锁了B对C的真实态度线。

信息可信度：X告诉你的信息，准确度 = X的透明度 x 你对X的信任。如果X本身透明度低或者你不信任他，他给的情报可能是错的。

## 9.4 信息可以是错的

透明度低的NPC，态度线可能是假的——他假装对C友好（显示暖色线），实际敌对（后台是冷色）。

信任度低的NPC给你的情报，可能是传歪的八卦。同一个人的态度，你从不同渠道获取的信息可能互相矛盾，需要交叉验证。

这把游戏从观察模拟器变成了信息博弈：你看到的班级格局，取决于你和谁信任度高、谁愿意跟你说实话。不同玩家因为社交路径不同，看到的是完全不同的班级地图。

## 9.5 推理板与矛盾高亮

- **推理板**：玩家构建"班级真相"的工作台，记录玩家对每个 NPC 立场、每个阵营归属、每次事件的解释。
- **矛盾高亮（硬功能）**：任何来源的信息与既有记录冲突时，推理板自动高亮。矛盾来源包括：
1. 某人的态度线与他本人在敏感话题（八卦、评价他人）中的发言冲突；
2. 二手情报与他人的传话内容冲突；
3. 情报与标签层事实（如违规标签）冲突。
- **闭环要求**：假信息必须留下可验证破绽，玩家可以通过交叉验证逼近真相；没有破绽的假信息 = 纯噪声，禁止出现。

## 9.6 标签的可见性

**默认状态：所有标签对玩家不可见。** 玩家通过三条路径获知某人的标签：

| 路径 | 条件 | 能知道什么 |
|---|---|---|
| **① 观察**（靠透明度） | 目标 `O[j]` 达档 | 通透（80+）：全部标签；可见（50–79）：仅「行为标签」；模糊（20–49）与封闭（<20）：均不可见 |
| **② 被告知**（靠信任 + 好感） | `T[j][玩家] ≥ 70` **且** `A[j][玩家] ≥ 50` | 目标**主动告知**自己的标签（愿意让你知道，也认为你值得知道） |
| **③ 推断**（靠行为痕迹） | 反复观察到对应行为 | 推理板解锁该标签（附证据条目） |

关键约束：

- **标签必然留下行为痕迹**：带手机的人课间真的会掏手机，谈恋爱的人会频繁与特定对象互动。否则玩家除了等别人开口别无办法——这违反「假信息必须留下可验证破绽」（§9.5）。
- **行为痕迹也是举报载体**：目击到这些痕迹的角色获得举报把柄（§10.2），因此举报有内容、有可见性前提，而不是"谁都可以被举报"。
- **三类标签的可见难度不同**：`行为标签`（带手机 / 爱聊天 / 爱学习）最容易被观察到；`关系类`（小情侣）需长期观察或被告知；`秘密类`（泄密者 / 嘴严）几乎只能靠被告知或推断。
- **观察不等于确认**：路径 ① 与 ③ 得到的标签仍需玩家在推理板上自行认定，**可能与真相不符**（见 §9.4）。

# 第十章 人物行为设计

> **分层总则（2026-10-06 定稿）**：第十章只列**会改数值的行为**；**状态层**（学习 / 睡觉 / 走动）不算行为——它们改的是"位置 / 占用"，不是 A/H/T/Stress（见 §10.4、§10.8、§10.15）。
>
> **行为触发方式总则**（详细算法见 [`../design/NPC行为决策.md`](../design/NPC行为决策.md)）：
>
> | 触发方式 | 判据 | 行为 |
> |---|---|---|
> | **环境类** | 固定基础概率 × 修正系数 | 闲聊、流言、窃听 |
> | **阈值类** | `p = σ((x−θ)/scale)` 概率化 | 举报、压力爆发 |
> | **意向类** | 门槛 → 意向评分 → softmax 采样 | 搭话、调侃、安慰、求助、道歉、秘密交换 |
>
> 三类都必须走统一影响公式结算（§6）；**意向类**中"对方的反应预期"一律取信念矩阵 `B`，自己的立场取真值。
> 三类触发方式与结果判定统一为**两段式统一判定公式**（§6.4）：**决策读信念、判定读真值**。
>
> **所有事件的触发条件都是「好感 / 敌对 / 信任 / 透明度 / 压力」的函数**——不存在按天数、轮次或固定剧本触发的「第 N 天必然发生 X」。新增行为时必须给出可判定的数值条件。

## 10.1 流言（附加行为）

1. 触发条件：（1）当A通过对B的流言判定（与好感度和敌对值有关），将对B的流言存入A的记忆，流言倾向根据A对B的好感度或者敌对值生成；（2）举报产生
2. 流言倾向：从-2到2由完全负面到完全正面，0为中立流言，流言倾向只为整数，且无法超出该范围
3. 传播条件：当A记忆中含有流言且A不为流言对象
4. 传播结果：当针对B的流言存入A的记忆，根据流言倾向数值增加A对B的好感值或敌对值（流言倾向大于0，则A对B的好感值加上流言倾向的绝对值；流言倾向小于0，则A对B的敌对值加上流言倾向的绝对值；为0则不改变）
5. 传播偏移：流言具有流言倾向（从-2到2由完全负面到完全正面，0为中立流言），如果传播者对传播对象(好感值-敌对值>0)则流言倾向加一；为0则不变；<0则流言倾向减一
6. 传播方式：（1）闲聊（2）窃听（3）**纸条**（= 流言的**私密传递方式**，不可被窃听 / 不可被搭话；**不再是独立行为**，见 §10.6 已合并）（4）告密
7. 传播限制：（1）单次闲聊只能够传播一条流言，但可以A传播给B的同时B也传给A（2）每条流言都有序号，如果某一条流言已记入过A的记忆则不能记入第二次
8. 流言传播顺序：（1）A接收流言（2）A对流言对象的好感值或敌对值发生改变（3）A对该流言的流言倾向进行更改（4）传播流言并删除记忆/流言自动遗忘
9. 流言消失：（1）一旦通过任何方式传递出去流言会从记忆里清除；（2）流言最多在一个人记忆中停留三个课间，若三个课间流言仍未传播则流言自动清除

## 10.2 举报（主行为）

1. 触发条件（概率化，无硬门槛）：
   （1）**载体**：A 在最近 `report_witness_window` 天内**目击过 B 的标签行为痕迹**（如带手机者课间玩手机；§9.6「标签必然留下行为痕迹」）。目击记录是一手观察，**不追溯流言源头**。
   （2）**概率**：`z = (H[i][j] − θ_H)/scale_H − w_A·A[i][j]/100 − w_T·T[i][j]/100`，`p = report_p × σ(z)`——敌对越高越可能举报，好感/信任越高越不可能（**好友几乎不举报，但概率永不为 0**）。
2. 行为结果：（1）本节课间举报者消失不出现在教室内，与走动到室外相同；（2）举报会大幅提升被举报者的压力值，概率生成针对 A 或 B 的流言（要么直接将一条对A的流言倾向为-2的流言存入B的记忆；要么直接将一条对B的流言倾向为-2的流言存入A的记忆）；（3）举报后A对B的敌对值会下降

## 10.3 告密（主行为）

1. 触发条件：当A记忆中含有对B的流言，且A通过对B的告密判定
2. 行为结果：（1）在本课间B不会移动,A会在课间走向B的位置并对B进行告密（与闲聊纸条不同，是独立的主行为），告密无法被窃听；（2）A与B对互相的好感度增加，根据流言倾向增加A与B对班级其余人的好感值或敌对值（流言倾向大于0则增加好感值，小于0则增加敌对值）；（3）B在被告密后把流言存入记忆并在课间结束后立刻删除

## 10.4 走动（状态层，非行为）

> ⚠️ **规格已补，原型未实装**（`core_sim.py` 暂无 `do_move`，座位即位置）。落地时按本节实现，并把 `position` 纳入 §18.2 存档。

1. **两个位置概念**：
   - **座位**（`seat_of`）：跨天固定（§10.20），决定"默认邻居"与上课段位置；
   - **临时位置**（`position`）：课间走动后的当前位置，互动距离与活动圈以它为准；段末 / 上课铃响回座位。
2. **NPC 走动判定**：每段课间开始（下课瞬间），非睡觉 NPC 掷一次 `move`（`behavior_probs.csv`）：
   - 修正：`E ≥ 50` 者 ×(1 + (E−50)/100)，`E < 50` 者 ×(1 − (50−E)/200)——外向更爱走动、内向更少，但**永不为 0**。
3. **NPC 目标选择**：在教室内空闲站立点里加权抽一个：
   - 权重 = `1 + Σ_j A[i][j]/100 − Σ_j H[i][j]/200`（想靠近喜欢的人、躲开讨厌的人）；对"想加入的活动圈"所在位置额外 ×1.5；
   - 权重下限 0.1（再不喜欢也偶尔走动，不锁死）。
4. **走动期间**：消耗 15 tick（§12.2 时间成本表），期间不能发起 / 接受新交互；走动本身不产生数值变化。
5. **玩家移动**：玩家可主动选择走到任意空闲站立点（消耗 15 tick），**无概率判定**——玩家只受时间预算约束。这是玩家与 NPC 的差别之一（§12.1：人做选择）。
6. **归位**：段末或相位切换时，所有走动者回到自己的座位；被上课铃打断按 §10.4 的 `interrupted_stress` 结算（走动不豁免）。

## 10.5 闲聊（主行为）

1. 触发条件：A、B 双方互相处于对方闲聊范围内时，概率触发闲聊
2. 行为结果：（1）闲聊发生后闲聊成员各自判定增加好感度或者敌对值；（2）减小闲聊成员的压力值
3. 闲聊内容可被范围内未处于闲聊状态的同学窃听
4. 闲聊成员中如有成员记忆中含有流言，且流言对象不是剩余的闲聊成员，可进行传播（每一个闲聊成员在本次闲聊中只能传播一次流言）

## 10.6 传纸条（已合并入流言）

> ✅ **2026-10-06 定稿**：传纸条**不再是独立行为**，它是**流言（及闲聊）的一种私密传递方式**——不可被窃听、不可被搭话。触发时走 §10.1 的传播流程，只是把"口头传播"换成"纸条传递"；不再单独占行为槽、不再单独出现在行为表。

## 10.7 搭话（主行为）

1. 触发条件：当A未发生闲聊且闲聊范围内已有人发生闲聊，概率发生搭话判定，通过则加入闲聊；否则A对闲聊二人敌对值增加
2. 行为结果：与闲聊一致

> ✅ **已实现**（2026-10-05）：按**段**粒度判定（⚠️ 不是 tick —— 早期误写在每 tick 决策里，导致 96% 的课间都在睡）；睡着者**不被任何人交互**、段末一次性减压 `sleep_relief`。

## 10.8 睡觉（状态层，非行为）

1. 触发条件：概率触发睡觉判定，通过判定则进行睡眠
2. 行为结果：本次课间无法进行其他任何活动，课间结束压力减少
3. **排除条款**：睡觉中的角色**不参与任何交互**（闲聊 / 搭话 / 共同学习 / 被调侃 / 被安慰 / 被求助…），也**不作为相邻类判定的对象**——坐在睡着的人旁边不产生「共同学习」。唯一的数值变化是课间结束时的压力减少。
4. **策略含义**：睡觉是用「社交机会」换「压力缓解」——你会错过本课间全部互动与观测。

## 10.9 窃听（附加行为）

> ⛔ **本行为为可选，不纳入任何版本实现**（2026-10-07 决定，见 §18.9）：
> §17 三个版本的排期均未列入；上游缺「流言记忆」与「范围判定」两个结构（§10.1 的流言目前
> 只是即时染色，没有可携带的对象）。`data/rules/behavior_probs.csv` 已将其概率置 `0.0`
> 显式关闭——原值 `1.0` 的语义是「未做主行为即必触发」，照字面接线会让全班无条件互相窃听。
> **本节规格仅作留存**，重启前须先补 §10.1 的记忆模型。

1. 触发条件：当人物没有进行任何主行为时
2. 行为：捕获自身一定范围内所有人的闲聊内容
3. 行为结果：（1）将闲聊中的流言存入记忆；（2）若窃听者为流言对象本人，则会根据流言倾向改变数值（若流言倾向大于0则压力减小，对闲聊双方的好感值上升；若流言倾向小于0则压力增大，对闲聊双方的敌对值上升；（3）若窃听者为流言对象本人，在窃听后把流言存入记忆并在课间结束后立刻删除

## 10.10 求助（主行为）

> ✅ **已实装（2026-10-07，Python 内核 `core_sim.do_ask_help`）**。门槛随外向度**三段插值**：
> `E=50 → 30、E=0 → 50、E=100 → 20`（对应下条「≥30；内向 ≥50；外向 ≥20」，连续不跳变）。
> 判定侧读**真值** `A[j][i] + 对方外向度加成`（§6.4：判定读真值），决策侧的目标选择读**信念**。
> ⚠️ **未实装**：「被亏欠」状态（下条第 3 点末）与「被拒压力 ×1.5 / 好斗敌对 ×2」（第 4 点后半）
> —— 前者需 `status_tags` 支持「条件修正」语义，后者超出 `M_personality` 的 `[0.1,1.2]` 钳位。

1. 触发条件：对目标好感 ≥30（内向型需 ≥50）
2. 发起成本：发起者压力 +2
3. 行为结果：
   - **被拒绝**：发起者压力 +3、对目标敌对 +3、信任 −3
   - **成功**：被求助者对你好感 +2、信任 +3；发起者压力 −2、好感 +3；被求助者进入「被亏欠」状态（3 天内你向他求助成功率 +25%）
4. 性格修正：内向门槛抬高到好感 ≥50、被拒压力 ×1.5；外向门槛降到 20；好斗被拒后敌对 ×2

## 10.11 道歉 / 和解（主行为）

> ✅ **已实装（2026-10-07，Python 内核 `core_sim.do_apologize`）**，并有两处**裁决/发现**：
>
> **① 接受的敌对变化是「表层 −3」而非 −5**（2026-10-07 用户裁决）。
> 原因：`apply_event` 对 `tier=major` 的 hostility 会执行 `H_deep += |Δ|` —— **负的 Δ 也照加**，
> 照本文第 4 点字面写「−5（major）」会变成「**和解反而加深心结**」，与 §10.22「心结永不衰减」冲突。
> 故降为**常规档 −3**，且**只消表层** `H`、不动 `H_deep` —— 语义是「道歉能消当下的气，
> 但忘不掉的还是忘不掉」。§10.16 的分档表已同步。
>
> **② 本文的「双方敌对 ≥30」在当前标定下几乎不可达**（实测 30 天 `H` 上限仅 19–24，
> `H ≥ 20` 的（有向）对子·tick 占比 **0.000%**；`H ≥ 30` 十局合计仅出现 14 次）。这与 §10.24.3
> 记载的排挤问题**同源：敌对缺少积累通道**（§10.17「关系缺少变差通道」）。当前实现**按本文的 30 保留**
> —— 于是道歉只在**冲突真正升级过**的局里出现（10 局 ×30 天实测 14 次，全部发生在 NPC 之间）。
> 若要让道歉成为常客，应改的是**敌对能不能涨上去**，而不是把门槛调到初始区间内。
>
> **③ 效果不做关系调制**（`no_modulation=True`）：门槛保证 `H ≥ 30` → 净态度 `M` 常为负 →
> 常规档会把「敌对回落」乘负 `M` **翻成敌对上升**（越道歉越糟）。修复类行为与 `M` 的冲突是结构性的。
>
> ⚠️ **未实装**：「透明度临时 +10」（无临时透明度机制）与第 5 点的性格修正倍率。

1. 触发条件：双方敌对 ≥30，一方主动发起
2. 发起成本：发起者压力 +3，透明度临时 +10
3. 接受概率 = 对方对你的好感 + 对方随和系数 − 敌对值 ×0.5
4. 行为结果：
   - **接受**：敌对 −3（表层；见上①）、好感 +3、信任 +2、双方压力 −3
   - **拒绝**：敌对 +2、发起者压力 +4、信任 −3
5. 性格修正：高 F（随和）接受概率 +30%；高 T / 好斗 −25%；敏感型被拒后压力 ×1.5，可能触发爆发

## 10.12 当众调侃（主行为）

1. 触发条件：周围 ≥3 人围观，且满足下列**之一**：
   - **好意调侃**：发起者对目标好感 `A ≥ 40`（按 §10.16 判为「玩笑」档）；
   - **挑衅式调侃**：目标对发起者敌对 `H ≥ 25`，**或**发起者对目标好感 `A < 25`（按 §10.16 判为「嘲讽」档）。

   > ⚠️ **2026-10-05 修订（P0）**：原条件只写「发起者对目标好感 ≥ 40」，与 §10.16 的嘲讽档判据（`H ≥ 40` **或** `A < 25`）**互斥** —— `A ≥ 40` 时不可能 `A < 25`，而 `H ≥ 40` 又依赖「已有敌对」→ **嘲讽档永远发不出来**，敌对链路因此半死锁（见 §10.17.2）。
   > **「嘲弄是敌对的第一发声」**，不该要求先有高敌对。
2. 成本：目标压力 +3，发起者压力 +1
3. 成功概率 = 目标对发起者好感 ×0.5 + 目标外向系数 − 目标敏感系数
4. 行为结果：
   - **成功（玩笑接住了）**：双方好感 +3，围观者对发起者好感 +2，目标压力 −2
   - **失败（玩笑过火）**：目标敌对 +4、压力 +4；围观者按性格分裂——外向 / 八卦好感 +2，随和 / 敏感好感 −2
5. 性格修正：外向成功率 +20%、被调侃压力 ×0.5；敏感被调侃压力 ×1.5、敌对 ×1.5；八卦型失败后把这件事当流言传播（→ 10.1）

## 10.13 安慰（主行为）

> ✅ **已实装（2026-10-07，Python 内核 `core_sim.do_comfort`）**。好感门槛按外向度分两段：
> `E ≥ 50 用 50`，`E < 50` 时向内向端线性抬高到 70（对应下条「≥50；内向 ≥70」，连续不跳变）。
> 效果为**重大档**（`comfort_target_*` 在 `w_events.csv` 中为 `tier=major`），与本文数值一致。
>
> ⚠️ **这是一个「窄条件」行为**：`Stress ≥ 70` 的（节点·tick）占比仅 **2.31%**，还要求
> 「发起者对他好感跨过门槛」且「发起者此刻空闲」——实测**机会数只有 0–2 次/天**，
> 故 `behavior_probs.comfort_p` 取 **0.35**（机会来临时基本会行动）而非环境类的小概率。
> 10 局 ×30 天实测 163 次（约 16 次/局）。**它本来就该稀有**：关系的跃升发生在「救援时刻」。
>
> ⚠️ **未实装**：第 4 点的共情判定与效果 ×1.5（`Stress ≥ 90` 时），与第 5 点的性格修正倍率
> （倍率超出 `M_personality` 的 `[0.1,1.2]` 钳位；`w_f` 列已提供「被安慰者越情感型、收益越大」的近似）。

1. 触发条件：目标压力 ≥70，且发起者对目标好感 ≥50（内向型需 ≥70）
2. 发起成本：发起者压力 +2
3. 行为结果：目标压力 −5、对你好感 +4、信任 +5
4. 目标正在爆发（压力 ≥90）：效果 ×1.5，但需通过共情判定（成功率 = 随和系数 + 敏感系数 − 好斗系数）
5. 性格修正：高 F + 高敏感（高共情）效果 ×1.5、成功率 +25%；好斗效果 ×0.5、成功率 −20%

## 10.14 秘密交换（主行为）

1. 触发条件：双方信任 ≥60，一方主动发起
2. 行为结果：
   - 发起者把一条秘密告诉对方，对方进入「守密」状态
   - **对方泄密**：发起者对其信任 −5、敌对 +4、压力 +5；泄密者获得「泄密者」标签（3 天）
   - **对方守密超过 5 tick**：双方进入「秘密同盟」——每个涓流结算点（每天 2 次）双方信任 +1（涓流类）
3. 性格修正：高 N（爱脑补 / 爱八卦）守密概率 −30%；内向 / 随和 +20%；好斗被背叛后敌对涨幅 ×1.5

> 以上五个社交行为依据 v3.0 规格回填，并按全局数值铁律（常规 `base ∈ [1,3]`、重大 `[4,5]`、结算类型见 [`../design/统一影响公式.md`](../design/统一影响公式.md) §2.5）改写；它们补齐了 §6.3 事件权重表中「被当众调侃」「安慰他人」等事件的行为来源。

## 10.15 注释：

1. 走到室外的同学不参与任何本次课间的活动
2. 编写的行为顺序也是行为的优先级顺序
3. 所有主行为（包括默认学习）和附加行为在课间前完成决定，课间开始直接执行
4. 闲聊可以减少压力值，若人物没有任何主行为且课间没有发生走动，默认在原位置学习，会增加压力
5. **相邻不直接改数值**：物理相邻只把自发互动（闲聊 / 搭话）的触发概率 ×1.5；数值变化一律来自有内容的事件——包括「共同学习」（相邻且双方都在学习，见 §3.3）。

## 10.16 行为的分类与判定来源

> 本节回答一个架构问题：**每个行为的"加减"到底由什么决定？** 结论先行——
> **方向用阈值判、强度用连续量调制**；不要用"净态度 `M` 的符号"判方向（见下方反例）。
> 本表是行为实现的分类依据，也是新增行为时的"归类检查表"。

### 五类行为

| 类别 | 定义 | 读什么 | 典型行为 | 在涌现中的角色 |
| --- | --- | --- | --- | --- |
| **A 纯增益型** | 只往正向轴加，不看好坏 | 无（仅轻量性格修正） | 闲聊（话题共鸣）、共同学习、安慰（对目标轴） | 提供**关系基本盘**的持续涨落 |
| **B 纯损害型** | 只往负向轴加，不看关系 | 无 | 流言（负面染色）、举报、被拒绝的反噬 | 提供**破坏与压力**的来源 |
| **C 信念驱动型** | **决策读信念、判定读真值** | 决策：`B_A` `B_H` `B_T`（i 眼中对方对 i 的态度）｜判定：`A[j][i]` | 搭话（判对方是否接纳）、求助（判对方是否愿帮） | 提供**误判与戏剧性**（以为自己被喜欢） |
| **D 信任 / 透明度驱动型** | 读 `T` / `O` 决定**成败与可见性** | `T[i][j]`、`O[j]` | 秘密交换（`T ≥ 60`）、告密（`O` 决定是否被听到）、窃听（`O` 决定能听到什么） | 提供**信息博弈** |
| **E 混合判定型** | 读**多轴 + 阈值分档**，**结果方向可变** | `A` + `H`（+性格） | **当众调侃**（玩笑 / 尴尬 / 嘲讽三档）、道歉和解（`H ≥ 30` 后修复） | 提供**同一行为在不同关系下的分岔**——戏剧性最强 |

### 行为按数值分档（2026-10-06 重排）

> 分档标准：每个轴（A 好感 / H 敌对 / T 信任）都应覆盖 `+1/+2/+3` 与 `−1/−2/−3`；一个行为可以"一体两面"（成功加、失败减）。本节只**重排现有行为**，缺口显式保留，待后续机制或标定补齐。

| 档位 | A 好感 | H 敌对 | T 信任 |
| --- | --- | --- | --- |
| **+3** | 闲聊、求助成功、道歉接受 | 被拒绝搭话、求助被拒、嘲讽档、流言（负倾向 −3）、打闹旁观、从众、音量定向 | 闲聊、求助成功 |
| **+2** | 打闹参与者、调侃玩笑档 | 道歉被拒 | 道歉接受 |
| **+1** | **缺口** | **缺口** | 秘密同盟（涓流，非即时行为） |
| **−1** | **缺口** | **缺口** | **缺口** |
| **−2** | 被调侃 | **缺口** | **缺口** |
| **−3** | 被拒绝搭话 | 道歉接受（**仅表层** `H`，不动心结） | 求助被拒、道歉被拒 |
| **重大档（±4/±5）** | 排挤（−4）、安慰成功（+4） | 举报（+5） | 秘密泄露（−5）、安慰成功（+5） |

> ⚠️ **2026-10-07 调整**（随 §10.10–§10.13 落地）：
> ① **安慰成功升入重大档**（+4 / +5 / 压力 −5）—— 按 §10.13 的数值落地，门槛苛刻（须已有好感 + 对方正崩溃）；
> ② **道歉接受从重大档移入常规档**（好感 +3、敌对 −3）—— 原因见 §10.11 的分歧①（major 负向 hostile 会误写深层敌对）；
> ③ 补齐 **求助被拒 → H +3**（§10.10）。
> 表中「**缺口**」为显式保留项：`H` 与 `T` 的 ±1 档仍无行为覆盖。

> ⚠️ **重大档里的 `羞辱` / `秘密泄露` 不是独立行为**：羞辱 = 当众调侃的**嘲讽档升级后果**（§10.23，写深层敌对）；秘密泄露 = 秘密交换的**失败侧后果**（§10.14）。`孤立` 是**观察层标签**（§10.26.4），只读、不回写——排挤行为会造成孤立标签，但标签本身不是行为。

**一体两面行为**：搭话（成功=闲聊，失败=被拒三轴反噬）、调侃（玩笑 / 尴尬 / 嘲讽）、安慰（成功 / 只付成本）、求助（成功 / 被拒）、道歉（接受 / 拒绝）、流言（倾向正负）、打闹（参与者 / 旁观者）。

### 三条边界（详见 [`../design/统一影响公式.md`](../design/统一影响公式.md) §2.6）

1. **信念只决定「做不做」，不决定「效果多大」**：意向层读 `B`，**效果层写真值轴**；否则会出现"我误以为他恨我，于是我的调侃真的把关系弄坏了——基于一个不存在的事实"；
2. **重大档（`tier=major`）不做关系调制**（`M_eff = 1`）：否则「我们关系好，所以他举报我反而是好事」会塌掉欺凌线与信任崩塌线（注意不是 `max(0, M)`——那会让关系差时伤害归零）；
3. **门槛用阈值（硬）、幅度用公式（软）**：别退化成「每类一个 if-else」，否则行为会在阈值附近疯狂跳变；
4. **统一判定公式两段式（§6.4）**：决策侧读 `B`（做不做）、判定侧读真值 `A/H/T`（成不成）；玩家展示侧从 `B` 重算成功率。

### 判定规则：方向用阈值，强度用连续量

以**当众调侃**（E 类）为例：

| 档位 | 判据（`behavior_thresholds.csv`） | 结果 |
| --- | --- | --- |
| **玩笑** | `A ≥ 55` **且** `H < 25` | 双方好感↑、被逗笑减压 |
| **尴尬** | 其余 | 不结算（效果自然为 0） |
| **嘲讽** | `H ≥ 40` **或** `A < 25` | 目标压力↑、对发起者敌对↑、围观者按性格分裂 |

> **注意**：本表判的是**结果方向**，§10.12 判的是**能否发起** —— 两者必须相容。`A ≥ 40` 的发起门槛曾使嘲讽档无法达成（P0，已修为双轨），详见 §10.12 的修订说明。

强度（不只是方向）仍由连续量 `M(i,s) = clamp((A−H)/50, −1, +1)` 调制——**两者分工明确**：

```
方向 = 阈值分档（离散、可配、可解释）
强度 = |M| 调制（连续、自动、无需特例）
```

### ⚠️ 反例：为什么不能用 `M` 的符号判方向

一个诱人的想法是"调侃是玩笑还是嘲讽，看 `M` 的正负即可"。**实测否决了这个方案**：

```
M = (A − H)/50  → 零点在 A = H
但本作里 A 的基线是 25~40，H 的基线只有 0~15
∴ 开局 M ≈ (25−8)/50 = 0.34 > 0  →  永远判为「玩笑」
  → 好感↑ → M↑ → 更是玩笑（正反馈）
∴ 30 天实测：好感均值 89.4、标准差 1.5（全班趋同）、爆发 0
```

**根因**：`M` 的零点（`A = H`）与游戏的**关系基线**不重合，`M` 恒偏正。因此：

- **`M` 适合做强度**（连续调制，零点偏正只是"整体略偏正向"，无害）；
- **`M` 不适合做方向**（方向需要的是"相对于基线在哪一侧"，那必须用**绝对阈值**）。

改用阈值分档后，同一个 30 天实测变为：好感均值 79.8、标准差 10.6——**改善但未达标**，
因为还有一个更根本的缺口：**B 类（纯损害型）行为几乎空白**，关系缺少"变差"的常规通道（详见 §10.17）。

### 新增行为时的归类检查

1. 它读哪些轴？（无 / 信念 / 信任·透明度 / 多轴）→ 决定它属于 A–E 哪一类；
2. 它的**结果方向**是否可变？若是，方向判据必须写成 `behavior_thresholds.csv` 里的**绝对阈值**，不得用 `M` 的符号；
3. 它的**数值**是否全部来自 `data/`？（铁律：脚本内不得出现魔法数字）
4. 它是否引入角色 ID / 名字判断？（违反 §11.1 即为缺陷）

## 10.17 关系缺少「变差」通道（待补）

> 状态：**好感侧已解决，敌对侧仍未打通**。且诊断显示这不是「缺一个行为」，而是**敌对系统缺少「种子」**。

### 已解决：好感侧的单向棘轮

`do_join_chat` 原用 `B_A[i][j] >= 40` 判定对方是否接纳，而**信念先验恰好等于 40**（`belief.csv` 的 `prior_a`）
→ 开局永远通过 → 唯一的「好感扣减」路径（`reject_affinity`）从不触发，好感成为单向棘轮，
标准差随天数收敛（当时实测 30 天 sd 仅 10.6）。改为「**信念 + 对方性格，门槛 45**」后通道打通，**SD 回到 23.6**。

### 未解决：敌对侧（诊断结论）

**现象**：30 天实测敌对**均值 0.2、单点最大 14.2** —— 全系统几乎**不存在「敌人」**。
因此 B 类行为【排挤】（判据 = ≥3 人对目标 `H ≥ 40`）**恒为 0 次**，即便把门槛放宽到 `H ≥ 25 / 2 人` 也不触发。

**定量根因**：

```
所有敌对事件都是常规档 +3，且一次只作用于一条边
→ 平均每边 +0.15/天，经 ×0.95/天 衰减 → 稳态约 3
→ 要稳态 40，需「每条边每天被敌对事件击中 0.67 次」——不可能
```

而**能产生重大档敌对的事件全部卡在死循环**里：

| 事件 | 前置 | 为何循环 |
| --- | --- | --- |
| 举报 | 敌对累积到阈值（`H ≥ 60`） | 而 `H` 恰好涨不到 60 |
| 泄密 | 先有秘密交换 | 该行为尚未实现 |
| 敌意传导（§7.2） | `H ≥ θ_H`（40） | 同样循环；实验把 `θ_H` 降到 15，单点最大也只升到 14.2 |

**结论**：本作缺的是**「敌对种子」**——一个能在**不依赖既有敌对**的前提下产生**重大档敌对**的事件。

### 10.17.1 【追逐打闹】—— 种子机制的第一版实验（**诊断结论已被解决，见下**）

> ✅ **2026-10-05 更新**：本节记录的「量级不足」**已经解决** ——
> 下面「下一步方向」的三条建议 **① 引入空间 / ② 让旁观者固定 / ③ 长期累积** 均已落地
> （分别是 §10.20 座位表、§10.20.3 打闹只吵邻座、§10.18 音量氛围 + §10.22 两层敌对）。
> **实测现状：排挤 80% 局上场、欺凌线成立**（见 §10.25 / §10.26 / §18.9 的「已落实」表）。
> **本节保留原文作为「诊断过程」的记录** —— 它展示了「机制对、但量级不够」这类问题的定位方法。

**机制**（已落地，见 §10.18）：`roughhouse` —— 参与者互相**好感↑**（A 类），
**路过的旁观者对参与者敌对↑**（B 类）。它满足种子判据：**t = 0 即可触发**（只需「有人在打闹」+
「有人在场」），不引用任何已有敌对值，因此**确实解开了死锁**（这是本机制的意义所在）。

**实测（30 天）**：

| 指标 | 结果 |
| --- | --- |
| 打闹次数 | 119 次（≈4 次/天） |
| *(以下两行为**当时**的实测，保留作对照)* | |
| 单点敌对最大 | **14.6**（此前 14.2 —— 有提升但**远低于排挤门槛 40**） |
| 四项玩法指标 | 爆发 28 / 饱和 0.0% / 均值 61.7 / SD 21.7 —— **全部达标** ✓ |

**为什么量级仍不够（定量）**：

```
每次打闹 ≈ 6 条边 × 约 1.5 点 = 9 点
4 次/天 × 9 = 36 点/天
但 17 人班级有 272 条**有向边** → 每条边 +0.13/天
×0.95 衰减 → 稳态 ≈ 2.7   （实测单点 14.6，说明偏好确实带来了一定聚焦，但不足以跨门槛）

要跨 40 → 需要每条边 +2/天 → 差约 15 倍
```

**真正的瓶颈不是机制，而是「边数」**：272 条边会把任何全局性事件摊薄。
实验中"旁观者按安静专注型排序"看似聚焦，但排序前先过滤了 `busy`，导致每次选到的人**并不固定**，
边没有真正固化下来。

**下一步方向（当初的候选）** —— **①②③ 全部已落实**：

1. ✅ **引入空间**（§10.20 座位表）：有向边 **272 → 88**，「路过的人」= **邻居**，同一对子反复相遇。
2. ✅ **让旁观者固定**（§10.20.3）：打闹旁观者**只取邻座**，去掉了「全班随机 + 排序受 `busy` 干扰」的问题。
3. ✅ **改为持续累积而非一次性**（§10.18 音量氛围 + §10.22 两层敌对）：音量是**持续**的压力/敌对源，
   而深层敌对**永不衰减**，冲突得以沉淀。
4. ⚠️ **提高单次幅度**：**未采用** —— 实测证明**加压无效**（`stress_k` 放大 12 倍仍无感，
   因为「信号只发给了小部分人」，见 §10.28.1）；真正起效的是**增加通路**（§10.23 当众羞辱 → `major` 写入深层）。

> **结论修正**：本节的诊断「瓶颈不在机制、而在边数」**是对的，但不完整** ——
> 真实瓶颈有**三层**：**边数（集中度）× 频率 × 跨阈值能力**，三者各需一把钥匙
> （座位表 / 音量氛围 / 两层敌对，见 §10.25.2 与 §18.9）。

## 10.18 环境层（班级级状态：音量）

> ✅ **已接线**（2026-10-05）：超阈音量 → **定向敌对**（单向），见 §10.21；超阈音量 → **压力**（`stress_k`），见 §10.28。

> 前面各节的系统状态只有两类：**个体**（`O` / `Stress`）与**关系**（`A` / `H` / `T`）。
> 本节引入**第三类 —— 环境**：整个教室的一个标量。**它不是"第六轴"**，而是与个体、关系并列的**另一层**。

### 为什么需要它

1. **量的累积产生质变**：2 个人聊天无所谓，**10 个人聊天就吵到别人**。
   这是关于「**集体**」的判断，不指向某个具体的人；
2. **它不受「边数摊薄」**：所有关系量都落在 N×N 条边上（17 人 = 272 条有向边），
   任何全局性事件都会被摊薄 272 倍；而环境量是一个**标量** ——
   同一个「打闹」，作为关系边被摊薄 272 倍，作为音量则 **100% 落到全班**；
3. **它给出「旁观者」的第二种形态**：此前只有「我讨厌你」（个人敌对），
   现在多了「**你们太吵**」（环境压迫）——而且这是**对群体的**，天然解释**责任分散**
   （「大家都吵，凭什么怪我」）。

### 动态

```
target  = clamp( Σ noise(各人当前行为), 0, volume_max )
volume ← volume + adapt_rate × (target − volume)     ← 有惯性（声音不会一秒消失）
excess  = max( 0, volume − volume_threshold )        ← 阈值效应，与传导阈值同构
Stress += excess × stress_k × 怕吵程度                ← 高 J（专注型）/ 内向者更敏感
```

**只有「发声」行为为正，安静行为一律 0** —— 安静的人不是「制造安静」，而是「不发声」；
「学习的人多 → 聊天的人少 → 音量自然低」是**自动**的，**不需要负号**。
（早期实现给安静行为写了负值，结果 `15 人学习 × (−5)` 把 `2 人聊天 × (+12)` 抵消成负数，音量恒为 0。）

### 阈值效应（已实测）

### 音量影响值的规格（0–3 常规 / 4–5 特殊）

与 `base` 铁律**同构**，但**下限可为 0**：

| 档 | 取值 | 含义 | 例 |
| --- | --- | --- | --- |
| **无声** | **0** | 物理上不产生声音 | 窃听 |
| **常规** | **1–3** | 日常行为的响度 | 学习 1、走动 1、流言（低声/纸条）1、告密 1、闲聊 2、搭话 2、当众调侃 3 |
| **特殊** | **4–5** | **很大的声音** | **追逐打闹 5** |

**定标原则：单人贡献必须小（因为人多）。**
全班 17 人都会发声 —— 若 `chat = 6`，17 人全聊 = 102 **必然爆表**（这正是早期版本音量恒 100 的根因）；
改 `chat = 2` 后：17 人全聊 = 34（不爆表），而 **10 人 = 20** 正是「开始吵」的位置。

**阈值必须跟着降**：60 需要 30 人才能达到，**永远触发不了**；最终按**实测音量**取 **20**
（课间 28.3 / 上课 18.7 —— 分界正在中间）。

#### 音量按「场」计，不按「人头」计

**多一个人加入同一场对话，音量几乎不变**（大家轮流说话，声音不叠加）；真正的吵闹来自
「**多出好几摊人各自在聊**」。所以同一场闲聊只有**一个声源**（发起者计入，加入者与被搭话者不计）：

| 情形 | 按「场」（正确） | 按「人头」（错误） |
| --- | --- | --- |
| 2 人同一场聊 | **2** | 4 |
| 3 人同一场聊 | **2**（与 2 人相同 ✓） | 6 |
| 两摊各 2 人 | **4**（递增 ✓） | 8 |

#### 音量的惯性 ≈ 5 秒

声音不会一秒消失，但也不该停留太久。`adapt_rate = 0.2`（时间常数 5 tick）≈ **5 秒现实**。
⚠️ **受 tick 粒度限制**：课间 1 tick = 6 秒，所以「3–5 秒」在数值上**不到 1 tick**，
只能在 1 tick 内趋近 —— 早先的 `adapt_rate = 0.02`（时间常数 50 tick = **5 分钟**）明显过久。


按 `chat` 噪音 = 6 反推，恰好对齐「10 个人聊天就吵」：

| 同时在闲聊 | 目标音量 | 判定 |
| --- | --- | --- |
| 1–8 人 | 6 – 48 | 正常 |
| **10 人** | **60** | **达阈（吵到别人）** |
| 12 人 | 72 | 吵到别人 |

### 当前状态（音量尺度已定标；压力效果已开启，氛围代价仍关闭）

- ✅ 机制与阈值效应已验证：开启 `stress_k` 后平均压力由 10~20 升至 **44.6**，确实生效；
- **当前取值**（以 `data/rules/environment.csv` 为准）：`stress_k = 0.40`（**已开启**，与 `noise_base_fear` 2.8 配合，§18.9 亦记为「环境层压力（已开启）」）；**`deviance_k = 0.0` 仍关闭** ——「偏离氛围只加压力」（§10.19）尚未启用，故双稳态还起不来；
- ⚠️ **仍未解决的是「音量的起伏」本身**（机制在跑，但起伏不够）：
  · 音量**长期饱和在 ~98**（`chat` 每 tick 6% × 持续 30 tick → 实测同时约 17 人在聊，全班都在聊，不现实）；
  · **专项标定轮已尝试过并记录结论**（把 `chat`/`tease`/`roughhouse` 频率降到 1/8，**音量确实出现了起伏：50.3 ~ 91.8，低段首次可见**），但代价是四项指标崩坏（**爆发 21 → 82**）——根因是 `chat` **一身两职**（见 §3.4.1 耦合表：它既是好感来源，又是减压来源）；
  · **结论**：音量起伏与四项指标**不能分两轮调**，必须做一次**联合标定**（同时考虑 `chat` 频率、`interrupted_stress`、`retain_s`、`decay_a_*` 与两个环境压力系数）。当前已**还原到四项达标的状态**，音量的「起伏」作为**已知待标定项**保留；
- 🔜 它是**双稳态**的基础：安静 → 更多学习 → 更安静（自习课）；吵 → 更多聊天 → 更吵（放羊课）。
  这一步需要「**行为选择受音量影响**」，尚未实现。

### 可扩展性

音量只是环境层的第一个标量。同一层还可以容纳「秩序度」「集体情绪」等 ——
它们共享同一个特征：**班级级、有惯性、过阈才产生个体后果**。

## 10.19 从众与环境反馈（氛围 → 行为选择）

> §10.18 只做了「环境 → 压力」的单向。本节补上闭环的另一半：**环境 → 行为意愿**，
> 并确立一条原则 —— **偏离氛围只增加压力，不禁止任何行为**。

### 从众度：大部分从众，少数有主见

```
conformity(i) = clamp( 0.5 + (F−50)/100 − (J−50)/100·0.5 − (N−50)/100·0.5, 0, 1 )
```

- **高 F**（情感型，在意氛围）→ 从众；
- **高 J**（判断型，有自己的计划）**+ 高 N**（直觉型，脑内自成一套）→ 反从众。

实测 17 人分布在 `0.00 ~ 0.90`（从众者 7 人 / 反从众者 8 人）——
**两类人天然并存，不需要任何特例**。

### 氛围 → 行为意愿

```
想社交的意愿 += conformity × volume/100          （吵 → 从众者更想参与）
想学习的意愿 += conformity × (1 − volume/100)    （静 → 从众者更想学习）
```

从众者跟着环境走；**反从众者完全不受影响**。于是就自然出现了那两种情况：
**「安静也要聊天」和「吵闹也会学习」**。

### 偏离 → 压力（而不是禁止）

安静教室里偏要聊天 → 压力上升（会被侧目）；吵闹教室里偏要学习 → 压力上升（「学不进去」）。
低从众度者不是不被罚，而是**本来就少偏离、且扛得住**。

> **这是「社会压力」的机制化**：你可以顶着氛围来，但要付代价。
> 若改成「禁止」，环境层就变成了「纪律」——那是另一回事，也丢掉了戏剧性。

### 为什么这构成双稳态

```
吵  →  从众者更想聊  →  更吵      ┐
静  →  从众者更想学  →  更静      ┘   两个吸引子（§7.1 所说的「多个吸引子」）
反从众者提供「噪声」，使系统可能被推过临界点、翻到另一个态
```

### ⚠️ 什么不能做：「学霸」不是规则

「**学霸除了压力爆发都会学习**」这个描述**不能照字面实现** —— 那是**身份判断**，违反铁律 §11.1
（「换成脚本还成立吗」这一检验会立刻崩掉）。正解是让「总在学习」**涌现**：

```
总在学习 = 高 J（有计划）
         × 低从众度（不受氛围左右）
         × 「爱学习」标签（study_bias +50%）
           ↑ 三项全是 f(性格, 标签, 状态)，没有一项是「因为他是学霸」
```

**标签是结果，不是原因。** 观察层可以给这样的人贴上「学霸」的**描述性**标签，
但它**只读**，不得回写任何数值（§10 观察层铁律）。

## 10.30 观察层（簇标签器）—— 只读、按透明度过滤、每角色一份视角

> ✅ **已实现**（2026-10-05）：`core_sim.ObserverLayer`。规格来源 `信念矩阵.md` §11。

### 10.30.1 两条约束，不是一条

| 约束 | 保证什么 |
| --- | --- |
| **只读**（不回写） | 标签**不干扰**模拟 —— 不产生「因为你是被孤立的所以大家排斥你」的自证循环 |
| **按透明度过滤** | 标签看到的是**玩家该看到的东西** —— 不是上帝视角 |

> ⚠️ **只靠「只读」不够**：标签器完全可以「只读、不回写」却**直接读真值矩阵**，那对玩家就是**全知视角**。
> §7.4 的原则是「**凡是涉及感知的读取都要经透明度（+信任）过滤**」，而标签器的输出正是
> 「**玩家感知到的班级结构**」，因此它**是透明度的下属**。
> 这与 §10.24.2（从众不再读真值）是**同一个原理**。

### 10.30.2 实现（三档可见性，复用 §11.1 阈值）

```
visibility(viewer, target)  由【被观测者】O[target] 决定：≥50 clear / ≥20 blurry / 否则 sealed
seen_matrix(viewer, axis)   clear→真值 ｜ blurry→只知「有变化」取中性 ｜ sealed→null（看不见＝不知道）
cluster_tags(viewer)        §11.1 强连接阈值 A≥60（**双方都能看见**才连边）→ 连通分量 → ≥3 人成簇
isolated_tags(viewer)       被好感低于均值 −15 且 给好感高出被好感 +15（§10.26.3 的判据）
```

**于是「藏着的人，连标签都藏住了」** —— 低透明度角色的关系读不到，自然落不进任何簇。

### 10.30.3 ⚠️ 首次运行照出两个底层问题（**这是标签器的价值，不是它的缺陷**）

**① 好感分布是「温和的平原」，没有山峰。**
实测（30 天）：好感均值 57，而亲近阈值是 60 —— 「60」在实际分布里只是「略高于平均」，
于是强连接连成一片：**簇大小分布 ［9, 9, 9, …］，而不是小团体该有的 3~5 人**。
> 这说明**亲疏分化不足**。已加一条相对判据（要高于双方各自的 75 分位）作为缓冲，
> 但根子在**好感矩阵本身缺少「局部高、全局中」的结构**。
> **🟡 P1 设计立项（§18.9）**：需要引入「社交精力 / 排他性」机制——人只能维持少数强连接，
> 多出来的互动收益递减；属于**设计级决策**而非调参，单独讨论，不在数值门里硬压。

**② 透明度没有分化 → 所有人视角相同。**
`seeds.csv` 的 `opacity_init` 原全为 50，17 人里 16 人 `clear`、视角种类数 **1/17**。
> ✅ **已修（§6.2）**：`opacity_init` 改为性格派生
> `clamp(50 + 1.2·(E−50) + 0.3·(F−50), 15, 85)`，`seeds.csv` 已重填，
> 视角种类应随透明度分化恢复；重跑后需在多样性门里复核"视角种类数"。
`seeds.csv` 的 `opacity_init` **全是 50**，17 人里 16 人 `clear`、视角种类数 **1/17**。

> 原设计里透明度有「压力高则被看穿 / 封闭」的语义（`统一影响公式.md` §2.4），

## 10.31 所有活动都可加入：从 `join_chat` 到「跟着做」

> ✅ **已实现**（2026-10-05）。数据：`behaviors.csv` 的 `join_mode` 列；参数：`free_join_rate`。

### 10.31.1 问题：只有闲聊能"加入"

`join_chat` 原本是一个**特例** —— 只有"加入别人的闲聊"这条路径存在，
而每个人做其他事（学习 / 打闹 / 走动 / 睡觉）时都是**独立决定**，然后碰巧撞在一起。

**但现实中"加入"是普遍现象**：

```
别人在学习 → 我也摊开书        （学习圈）
别人在打闹 → 我也凑过去        （打闹圈）
别人在聊八卦 → 我也凑过去听    （聊天圈）
别人走动   → 我也跟着走        （走动圈）
```

### 10.31.2 设计：`join_mode` 三分类

| 类型 | 含义 | 活动 |
| --- | --- | --- |
| **`accept`** | **需要对方判定**（接受 / 拒绝） | 闲聊 / 搭话 / 当众调侃 / 追逐打闹 / 安慰 / 求助 / 秘密交换 / 告密 |
| **`free`** | **自由跟随，无需谁同意** | **学习** / 睡觉 / 走动 / 窃听 |
| **`none`** | 不可加入 | 举报 / 排挤 / 道歉和解 |

- **`accept` 类**沿用 `do_join_chat` 的判定（**被请求者的真值好感 `A[j][i]`** + 对方外向度）——
  **接受 → 绿圈；拒绝 → 红圈**（拒绝还会反噬，见 `reject_*` 三个事件）。
- **`free` 类**由新增的 `free_join()` 处理：**「别人做什么，我也跟着做什么」**。

### 10.31.3 `free_join` 与 `conformity` 的关系（从众第一次落到行为层）

> **`conformity(i)`（§10.19）管「我倾向做什么」**（氛围影响意愿，原有）；
> **`free_join` 管「我具体跟谁做」**（看到别人在做，我也做，**新增**）。

```
跟随概率 = free_join_rate × conformity(i)
```

**于是"从众"第一次从意愿层落到了行为层**：
高 F 者随大流（看到别人学就学、看到别人走动就走）；高 J / 高 N 者有主见，**不被裹挟**。

> ⚠️ **「学习」是个例外**：它是 `default` 状态、不占用时间槽，**不体现在 `current_act` 里**。
> 但现实中它恰恰最常被跟随（"看他摊开书，我也学"）。
> ∴ 判定为：**邻居此刻既不忙、也不在做别的事 → 他在学习 → 可跟着学**。

### 10.31.4 只读查询（供 UI 画圈 / 上色，零副作用）

| 查询 | 返回 |
| --- | --- |
| `activity_of(i)` | 某人此刻在做什么 |
| **`active_circles()`** | **当前的「活动圈」**：按「此刻在做同一件事」分组 → `{'chat': [2,3,5,9,12], 'roughhouse': [1,14,16]}` |
| `join_feedback(i, j)` | 这次加入判定会「接受」还是「拒绝」→ **供 UI 上绿 / 红** |

> **「活动圈」与簇标签器是两个尺度**：
> **活动圈**是**实时、局部、可见**的（秒级，对应 §15.1「小人在教室的物理位置就是第一画面」）；
> **簇标签**是长期的格局（天级，供每日简报与阵营分裂判定）。两者不冲突，各有用途。

**内核只提供"谁和谁在一起"；画绿圈 / 红圈、不同活动不同颜色是 Godot 渲染层的事。**

### 10.31.5 实测与标定

`free_join_rate` = **0.10**、`stress_k` = 0.40：跟做正常发生（30 天十余次），活动圈正确输出多类分组；
四项指标 **爆发 18.9（15–30）· 好感均值 59.5 · SD 21.9** ✓。

> ⚠️ **它与压力有耦合**：`free_join` 让人扎堆 → 音量↑ → 压力↑ → 爆发↑。
> 实测 `free_join_rate` 0.25 → 0.05 时爆发由 52 降到 36，故最终取 0.10 并配合 `stress_k` 标定。
> **这是"跟随"带来的自然代价：班级更容易一起行动，也更容易一起吵。**
## 10.32 判定展示：NPC 静默，玩家掷骰

> ✅ 规格（用户设计）。内核侧只读查询：`verdict(i, j, kind)`（`core_sim.py`）。

### 10.32.1 同一次判定，两种呈现

**判定公式只有一套**（NPC 与玩家完全同源，不做任何区别对待）；区别只在**呈现**：

| 对象 | 呈现 |
| --- | --- |
| **NPC ↔ NPC** | **静默出结果** —— 不弹窗、不展示过程 |
| **涉及玩家** | **展示三拍**：① 当前成功率 → ② 掷骰 → ③ 结果（绿 / 红） |

> **为什么 NPC 静默**：一个课间段可能发生几十次判定，逐个展示会**淹没玩家**，
> 而且会**泄露别人的关系状态**（那正是观察层要按透明度过滤的东西，§10.30）。
> **NPC 的结果照常影响世界，只是不告诉玩家"这里刚刚掷了一次骰"。**

### 10.32.2 为什么玩家需要「掷骰」而不是直接给结果

用户指出的问题：**「直接就同意或拒绝不好」** ——

- **直接拒绝**会让玩家觉得**被系统针对**（"凭什么？我又没做错什么"）；
- **直接同意**则让玩家觉得**理所当然**，关系毫无分量。

**掷骰把"运气"放进画面**：玩家看到"我有 72% 的把握"→ 掷 → 失败，接受的是**手气**，
而不是"游戏在刁难我"。同时它**顺带给出了情报**：成功率本身就在告诉玩家
「**你和这个人现在到什么程度了**」。

### 10.32.3 ⚠️ 关键约束：成功率必须从「信念」算，不能从真值算

**这是本设计唯一必须守住的点。**

```
展示（玩家看到的成功率）= f( B_A[i][j] )   ← 信念：「我以为对方对我多有好感」
结算（实际掷骰用的 p）  = f( A[j][i] )     ← 真值：「对方实际对我多有好感」
```

> **两侧必须分开实现**：结算侧 `join_score` 读真值 `A[j][i]`，展示侧 `join_feedback` 读信念 `B_A`。
> 若两侧都用信念（曾如此），显示值就**永远是准的**，本节的「认知偏差具象化」会被架空；
> 若两侧都用真值，则等于把对方心里的态度直接告诉玩家，**泄露隐藏信息**。
> 2026-10-07 已按此收口，见 §18.9。

因为信念属于**感知层**（§7.4），所以：

| 好处 | 说明 |
| --- | --- |
| **不泄露隐藏信息** | 玩家看到的只是**自己的猜测**；对方心里怎么想，界面**不会**替他揭晓 |
| **概率高也可能失败** | 「我以为他喜欢我」≠「他真的喜欢我」—— **掷骰成为认知偏差的具象化** |
| **与观察层一致** | 与 §10.30「藏着的人连标签都藏住了」同一条原则：**凡是涉及感知的读取都要过滤** |

> **∴ 掷骰不是装饰，而是把「信息不对称」演给玩家看**：
> 他会经历「我明明有 80% 把握……」—— 这正是这个游戏想要的体感。

### 10.32.4 成功率的形状：**渐变的把握，不是门槛的开关**

> 实现过程中改过两次，两次都是**"展示没有信息量"**导致的：

| 版本 | 写法 | 后果 |
| --- | --- | --- |
| 初版 | `if 对方压力 > 70 → p = 0` | 全班压力普遍偏高 → **成功率恒 0%**，玩家永远看到 0 |
| 二版 | `p = 0.5 + (把握 − 门槛)/40` | 斜率太陡，`accept` 稍低就掉到 0 → 实测落在 **0~17%** |
| **采用（现行）** | `p = σ((score − θ)/scale)`（logistic sigmoid），压力**降低**把握而非归零 | 概率再低也可能成功、再高也可能失败，无固定门槛 |

**两条原则**（可复用到所有"成功率展示"）：

1. **压力是程度，不是闸门** —— 它应当**削弱把握**，而不是把概率打到 0。
   判定本身也改为同一 `p` 掷骰（§6.4），不再保留"越过门槛才成功"的硬闸门。
2. **把握必须渐变且非线性** —— 用 `σ((score − θ)/scale)`：门槛处 50%，两侧平滑延伸且**永不为 0/1**。
   概率低也可能成功、概率高也可能失败，成功率始终是情报，不是结果的复读。

### 10.32.5 适用面

本规格**不限于加入活动**。§5.4 起文档里已多处出现「成功率 / 概率修正」
（求助 +25%、守密 −30%、调侃按共情判定……），它们的**玩家侧呈现规则一致**：

```
NPC 用 → 静默；涉及玩家 → 三拍（成功率 → 掷骰 → 结果）
```

内核实现时，各行为判定按同一模式提供只读的 `verdict()` 即可，**不必各写一套**。
# 第十一章 人物设计（分层重构）

> **标签按底层轴分类**（见 `data/rules/tags.csv`）：标签不是「身份」，而是**对某个轴的调制**。
> 作用轴四类：`behavior`（行为倾向）/ `info`（信息：守密·传播·泄露）/ `relation`（关系倾向）/ `environment_fact`（客观条件，如「带手机」，**不是倾向**）。
> 影响强度两级：`weak`（小部分影响，约 ±10%）/ `strong`（长久影响，约 ±50%）。
> 这样行为逻辑才能保持为 `f(性格, 标签, 状态)` —— 见 §10.19 结尾「学霸不是规则」。

## 10.21 音量氛围 → 定向敌对（单向通道）

> ✅ **已实现**（2026-10-05）。参数：`environment.csv` 的 `noise_hostility_base` / `noise_scale`；
> 事件：`w_events.csv` 的 `noise_hostility`。

### 10.21.1 设计（不对称是灵魂）

超阈音量除了「转化为压力」（§10.18 `noise_pressure`），还会**转化为敌对**——
但**只在一个方向上**：

| 方向 | 成立？ | 原因 |
| --- | --- | --- |
| **安静 / 学习者 → 敌视吵闹者** | ✅ | 他**真的在受损**（被打扰、学不进去） |
| 吵闹者 → 敌视安静者 | ❌ | 他**不觉得自己被打扰** |

∴ 这是本项目**第一条天然单向的关系通道**（其余通道都对称）。
它来自一个朴素的现实观察：**被吵到的人记恨，吵的人浑然不觉。**

### 10.21.2 实现

| 环节 | 规则 |
| --- | --- |
| **谁怕吵** | 复用已有的 `fear_e` / `fear_j`（§10.18）—— `fear = f_j·(P−50)/50 + f_e·(50−E)/50`，越内向、越专注越怕吵 |
| **恨谁** | **邻居中最吵的 2 个**（`noise_of` 取自 `behaviors.csv` 的 `noise` 列）—— 只有近处的人吵得到我 |
| **多恨** | `base × scale × 性格调制 × 关系调制`，走统一影响公式（`scale` 随音量强弱缩放） |
| **多久一次** | 涓流：每天 2 次（`settle_interval`），与 `noise_pressure` 同一节奏 |

**与 `noise_pressure` 是同源分岔**：同一个 `fear`、同一个超阈音量，
一份转成**压力**（内耗），一份转成**敌对**（指向他人）。这正是「同一刺激、两种社会后果」。

### 10.21.3 实测与瓶颈

30 天（seed=12345，17 节点）：

| 指标 | 结果 |
| --- | --- |
| 恨噪音结算 | **475 次**（约 5.4 次/边，频率充足） |
| **敌对 max** | **8.8 → 19.5**（2.2 倍） |
| `H ≥ 25` 的边 | 0（**仍未跨过排挤门槛**） |
| 四项玩法指标 | b=29 / sat 0.0% / mean 62.0 / SD 21.5 ✓ |

> ⚠️ **瓶颈定位**：`494 次 ÷ 88 边 ≈ 5.6/边 × 3 点 ≈ 16.8`，与实测 `max 17.5` 吻合。
> 换算日增量 **0.56/天 → 稳态 11**，要跨 25 需 **1.25/天**，还差 2.2 倍。
> **加大 `base` 无效**（实测 2.0→4.7、3.0→17.5、4.0→11.7）——因为**`room_for` 负反馈**
> （"越满越难涨"）是硬约束：**推得越猛，越早撞天花板**。
>
> ∴ 要真正跨过阈值，需要的是**结构性手段**（记恨边状态 §10.17.2 种子六、状态标签），
> 而不是继续调幅度参数。

## 10.22 两层敌对（表层会消，心结永远在）

> ✅ **已实现**（2026-10-05）。**已由 §10.23「当众羞辱」打通** —— 深层敌对第一次真正转起来。
> 空转阶段的记录保留在 §10.22.3，它解释了「为什么光做机制还不够」。

### 10.22.1 为什么要分两层

用户提出的直觉：**人对仇恨的记忆非常深刻**，被背后捅刀子这种事不该随时间淡掉。

但「所有敌对都不衰减」会带来一个数学后果：`H` 单调递增 → 关系**只坏不好** → 再也回不来，
连「后来和好了」这种剧情都发生不了。∴ 采取**两层分离**：

| | **表层** | **深层** |
| --- | --- | --- |
| **来源** | 日常摩擦：调侃、音量、打闹、传谣 | **只为 `tier = major` 的负性事件**（举报、秘密泄露） |
| **衰减** | 每天 ×`decay_h`（0.95） | **永不衰减** |
| **能否修复** | ✅ 道歉、相处可磨平 | ❌ **永远在** |
| **参与 `room_for`？** | 是 | **否** |

```
H[i][j]（总敌对） = 表层 + 深层
```

这正是现实里最真实的那种关系：**「我可以原谅你，但我忘不了那件事。」**

### 10.22.2 实现（单点改动）

`H` 存的仍是**总敌对**，`H_deep` 记其中「忘不掉的那一部分」。于是衰减只需一行：

```python
deep = self.H_deep[i][j]
self.H[i][j] = deep + (self.H[i][j] - deep) * decay_h     # 深层原样保留
```

写入走统一影响公式，但**不经 `room_for`**：

> ⚠️ 负反馈是给「表层摩擦」用的。若也套在深层上，仇恨会**自己封顶**（越满越涨不动），
> 「不可消减」就名存实亡了。

### 10.22.3 实测：机制正确，但空转

30 天（seed=12345）：

| 指标 | 结果 |
| --- | --- |
| **深层写入次数** | **0** ← 空转 |
| **总敌对 max** | **19.5（与实现前完全一致）** → **无回归** ✓ |
| 普通对子敌对 | 均值 0.11 / max 15.3 → **「不误伤」守住** ✓ |
| 四项玩法指标 | b=29 / sat 0.0% / mean 62.0 / SD 21.5 ✓ |

**为什么空转**：`major` 档的 hostility 事件只有两个，而**两个都不会发生**：

| 事件 | base | 门槛 | 现状 |
| --- | --- | --- | --- |
| `report_hostility`（举报） | 5 | 需 `H ≥ 60` | 最高只到 19.5 → **不发生** |
| `leak_hostility`（秘密泄露） | 4 | 需「先有秘密交换」 | 该行为**未实现** → **不发生** |

> ∴ **门修好了，只是还没有人走。** 下一步应先让**某条通往 `major` 的路打通**，
> 而不是再调敌对幅度参数（那已被 `room_for` 证明无效，见 §10.21.3）。

## 10.23 当众羞辱 → 深层敌对（把 §10.22 的门打开）

> ✅ **已实现**（2026-10-05）。事件：`humiliate_hostility`（`w_events.csv`，`tier=major`，base 4）；
> 阈值：`humiliate_bystanders`（`behavior_thresholds.csv`，= 3）。
>
> ⚠️ **2026-10-05 修 P0：本节的判据曾长期「恒真」，实际从未生效**（外部核对发现，经核验成立）。三处连锁错误：
> ① `do_tease` 调用处写了 `audience[:3]` —— **把围观者截断为恰好 3 人**，与门槛 3 构成 `3 ≥ 3` 恒真；
> ② 围观者曾取「**全班非忙碌角色**」（13~15 人），任何「被围着」的门槛都会恒真 —— 但「围观」本是**空间概念**（§10.12「周围 ≥3 人」），已改为「**调侃双方的共同邻居**」（最多 4 人）；
> ③ 阈值表把整串 `humiliate_min_bystanders` 写进了 `behavior` 列，键变成
>    `humiliate_min_bystanders_bystanders` → 代码 `th.get(..., 3.0)` **静默回落到默认 3.0**。
> **∴ 修正前「每次过火都写深层」**（羞辱/过火 = 1.00），§10.23 所说的区分从未生效；
> 修正后为 **0.54**（只有被围满者才写深层）。而此前的「四道门全绿」正是建立在那个错误前提上 —— 修正后深层写入由 200 次降到 13 次，指标随之回落，**需重新标定**。

### 10.23.1 为什么是「当众」

§10.22 建好两层敌对后**一直是空转的**：`major` 档的 hostility 事件只有举报（需 `H ≥ 60`）与秘密泄露
（所需行为未实现），两个都不会发生 —— **门修好了，却没有路通向它**。

打通它的关键是找到一个**真正会发生的 `major` 场景**。「过火调侃」（嘲讽档）每天都有，
但**它本身不该是 `major`** —— 那句话可能有三种社会含义，多数只是"过火"，不是"创伤"。

**区分在哪？** 观察到的现实：**同样一句难听话，私下说只是摩擦，被人围着说就是羞辱。**

| 情形 | 后果 |
| --- | --- |
| 私下的嘲讽 / 一般过火 | 表层摩擦（会淡忘，`decay_h` 照常） |
| **当众羞辱**（围观者 ≥ `humiliate_min_bystanders`） | **写进永不衰减的深层** |

∴ 升级条件**只看"有多少人在看"** —— 这是纯粹的处境条件，**与是谁无关**（没有角色特例）。

### 10.23.2 实现

在 `do_tease` 的**嘲讽档**分支里，多结算一次：

```python
if len(audience) >= th.get("humiliate_min_bystanders", 3.0):
    self.apply_event(j, i, "humiliate_hostility")   # tier=major → 自动写进 H_deep
```

不需要新代码路径 —— `apply_event` 里已有「`tier=major` 的 hostility 同时写深层」的规则（§10.22）。

### 10.23.3 实测（**已按修正后的机制重测**）

> ⚠️ **本节的旧数字（羞辱 38 次/局、深层 max 100、`H ≥ 25` 5 条）是「判据恒真」时代的产物** ——
> 那时 `audience[:3]` 截断 + 门槛默认值静默回落，使「每次过火都算羞辱」。
> 判定修好后（§10.23 开头的 P0 说明），机制的真实量级如下。
> 数据口径：**8 局 × 30 天**（§3.4.1 六：看分布不看单局）。
> ⚠️ **本节的数字测于「判定读信念」时期（2026-10-07 之前），已不适用**，见 §18.9。

| 指标 | 结果 |
| --- | --- |
| 过火调侃 | 均值 **28 次/局** |
| 当众羞辱 | 均值 **17 次/局** |
| **羞辱 / 过火** | **0.63**（旧 1.00）—— 区分真正生效：**约四成过火是「私下摩擦」，不写深层** |
| **深层 max** | 均值 **20.2** ［3.1, 35.7］（`deep_cap`=70，且受 `deep_decay`=0.995 抑制） |
| **总敌对 max** | 均值 **24.2** ［8.6, 45.7］ |
| **`H ≥ 25` 的边** | 均值 **0.8 条/局** ［0, 3］ |
| 误伤 | 普通对子（非邻居）敌对均值 **0.16** ✓ |
| 四项玩法指标 | 爆发均值 **20.2**（15–30）✓ |

> **结论修正**：判据修好后，**深层敌对与「欺凌线」都变稀少了** ——
> `H ≥ 25` 的边从「5 条/局」降到 **0.8 条/局**。
> 这不是退化，而是**真实的量级**：深层只由「被围满的当众羞辱」写入，
> 而那种场面本就该是**罕见**的（§10.23.1 的设计意图正是如此）。
>
> ∴ 「欺凌线首次成立」这个旧表述应改为：**欺凌线存在但稀少（约每局 1 条边）**。
> 若希望班级里出现更明显的欺凌 / 孤立结构，应该**让「被围满」更容易发生**
> （例如让羞辱更易引发连锁、或扩大围观的空间范围），而**不是**降低羞辱的门槛 ——
> 后者会退回到「每次过火都写深层」的恒真状态。

> **`H` 不再打到 100**：§10.27 的 `deep_cap`(70) 与 §10.29 的 `deep_decay`(0.995) 双重约束下，
> 深层 max 均值 20.2、总敌对 max 均值 24.2。「结下死仇」仍可能（个别局到 45.7），
> 但不再是「一条边永久锁死 100」的吸收态。

> ⚠️ **过程中修掉一个自引入的 bug**：衰减写成 `deep + (H − deep) × decay_h` 时，
> 若 `H` 曾被和解类事件降到低于 `deep`，`(H − deep)` 为负、会把总数**继续往下带**，
> 结果出现「深层 17.5 而总数只有 9.0」的自相矛盾。已夹住 `surf = max(0, H − deep)`。

## 10.24 从众 → 敌对（散落的敌意 → 集体围攻）

> ✅ **已实现**（2026-10-05）。阈值：`conformity_see` / `conformity_min`（`behavior_thresholds.csv`）；
> 事件：`conformity_hostility`（`w_events.csv`，normal，base 3）。

### 10.24.1 机制

**做过公开行为的人才被看见，藏着的人不会被跟风。**

### 10.24.3 ⚠️ 由此发现的真问题：**排挤的判据方向反了**

排挤的门槛是「**≥3 人同时对同一目标敌对 ≥40**」。但这个判据假设了「多人恨同一人」——
而**欺凌的真实结构是「多对一」**：

| | 施害方 | 受害方 |
| --- | --- | --- |
| 人数 | **多人** | **一个人** |
| 关系方向 | 对受害者**做损害行为** | **单向**记恨（只有他受损） |

∴ **受害者只有一个人，只能单向记恨，永远凑不出「3 人恨他」** —— 从众再强也没用。

> 例：0 被 2、3、11、14 四个人欺负 —— 「有 4 个人在损害 0」才是可观测的集体行为；
> 而「有 3 个人恨 0」在这个结构里不可能成立，因为施害者不恨受害者。

> ✅ **2026-10-05 已修**（见 §8.4 修订与 §10.25）。

## 10.25 排挤判据修订（视角从受害者移到施害者）

> ✅ **已实现**（2026-10-05）。阈值：`exclude_window` / `exclude_count` / `exclude_cooldown`（`behavior_thresholds.csv`）。

### 10.25.1 原判据的问题

原判据是「**≥3 人同时对同一目标敌对 ≥40**」。它假设「多人恨同一人」——
但**欺凌的真实结构是「多对一」**：

| | 施害方 | 受害方 |
| --- | --- | --- |
| 人数 | **多人** | **一个人** |
| 关系方向 | 对他**做损害行为** | **单向**记恨 |

**受害者只有一个人、只能单向记恨，永远凑不出「3 人恨他」。**
实测证实：`H ≥ 25` 的边是 `(0→2,100) (0→3,57) (0→11,33) (0→14,43.7) (2→0,33)`，
即**节点 0 被 2、3、11、14 四个人都羞辱过** —— 完整的欺凌结构，
但**没有任何目标被 2 人以上「恨」**，所以原判据永不成立。

### 10.25.2 修订后的判据

```
旧：有多少人【恨】他 ≥40        ← 受害者视角，凑不齐
新：有多少人【近期对他做过重大敌对行为】  ← 施害者视角，可观测
```

新增一张 N×N 表 `hurt_day[i][j]`（最近一次 i 对 j 做**重大**敌对行为的日），
由**调用点**用 `mark_hurt(施害者, 受害者)` 显式维护：

```python
def mark_hurt(self, perpetrator, victim):
    self.hurt_day[perpetrator][victim] = self.day
```

> ⚠️ **2026-10-07 修正：不能放在 `apply_event` 里按 `(i, j)` 自动维护。**
> `apply_event(i, j, …)` 的 `(i, j)` 是「**被作用方 → 作用方**」（如 `apply_event(被羞辱者, 施害者, "humiliate_hostility")`），
> 而本表与读者（§10.25 排挤、§10.24 从众）要的是「**施害者 → 受害者**」——两者在一次调用里**恰好相反**。
> 后果实测：受害者被同时记成施害者，排挤/从众判据因此被虚增（`hurt_day[受害者][施害者]` 也被写上）。
> 现在方向只由 `mark_hurt(施害者, 受害者)` 一处决定；调用点仅限 `tier = major` 的事件
> （`do_tease` 的当众羞辱、`do_report` 的举报），见 `tools/core_sim.py`。

排挤判据改为：`近期(≤ exclude_window) 对 j 做过重大敌对行为的人 ≥ exclude_count`。

### 10.25.3 两个必须处理的副作用（都是实测发现的）

**① 「损害」必须只算重大档。** 最初记录的是「任何 `delta > 0` 的 hostility」，
结果 `noise_hostility` 每天让**几乎所有人互相「损害」**，「被 3 人损害」成了常态 →

## 10.26 孤立：从「单向记恨」到「双向疏远」

> ✅ **已实现**（2026-10-05）。事件：`exclude_affinity`（`w_events.csv`，`major`，base −4）。

### 10.26.1 问题

`do_exclude` 原本只做「**被排挤者 → 参与者**」好感下降（`exclude_affinity`，符合 §8.4 原文）——
即「**他恨上了排斥他的人**」。

但这样「被孤立」只表现为**受害者单向记恨**，**观察不到全班对他的疏远**。

### 10.26.2 补齐

`do_exclude` 现在做**双向**好感下降（复用同一事件，不改公式）：

apply_event(j, i, "exclude_affinity")   # 他恨上了排斥他的人（原有）

| --- | --- | --- | --- | --- |

| 10 | 33.2 | 59.4 | +26.1 | 33.1 |
| 3 | 43.3 | 59.8 | +16.5 | 53.5 |

> **全班都不喜欢他，而他还喜欢大家** —— 「想融入但没人要他」。

## 10.27 深层敌对的软上限

> ✅ **已实现**（2026-10-05）。参数：`environment.csv` 的 `deep_cap`（默认 70）。

### 10.27.1 为什么需要上限

`H_deep` 只增不减、又不参与 `room_for` —— 这保证了「忘不掉」，但也意味着**单调累积**：
当众羞辱约 1.3 次/天，一学期（30 天）即可让少数边累加到百米量级。
若不设限，**那条边的举报门槛（`H ≥ 60`）会永久满足**，最终退化成「死仇复读机」——
关系不再变化，只剩一个永远触发的事件。

### 10.27.2 做法：软上限而非衰减

```python
cap = self.env.get("deep_cap", 70.0)
self.H_deep[i][j] = min(cap, self.H_deep[i][j] + abs(delta))
```

| 方案 | 语义 | 取舍 |
| --- | --- | --- |
| **软上限（采用）** | 「**恨到顶了**」，到了就不再加深 | 忘不掉依然成立；**总 `H` 仍可更高**（深层 + 表层），死仇强度不被压平 |
| 极慢衰减 ×0.995 | 百天尺度缓慢收敛 | 会削弱「不可消减」，与用户直觉不符 |

**实测**：`deep_max` 由 100 → **≤70**（各局 ［23.4, 70.0］），一致性（总 ≥ 深层）保持 ✓。

### 10.27.3 待观察

上限值 70 有效（实测深层 max 均值 20.2，未出现锁死；爆发指标已达标，见 §3.4.1 六）。
建议后续加入观测指标「**举报对子重复率**」（同一对子被举报 ≥2 次的比例），
用它来判断上限是否需要下调。

## 10.28 环境层 → 压力：基础项与减压侧

> ✅ **已实现**（2026-10-05）。参数：`noise_base_fear` / `stress_k`（`environment.csv`）、`sleep_relief`。

### 10.28.1 一个隐蔽的失效方式：信号只发给了小部分人

`noise_pressure` 原本的压力系数是：

```
fear = f_j·(P−50)/50 + f_e·(50−E)/50      ← 越内向、越专注越怕吵
```

即**只有「怕吵的人」会被嘈杂环境影响**。后果是：把 `stress_k` **放大 12 倍**，
爆发均值也只从 7.5 到 9.4 —— 因为**压力只落在少数人身上**，全班压力水平几乎不动。

**修正**：加入**基础项** —— 嘈杂环境对**所有人**都有压力：

```
fear = noise_base_fear + (原怕吵项)
```

起效立竿见影：爆发均值 **11.6 → 15.9**，进入目标区间。

> **教训**：调一个系数十倍无效时，先怀疑「这个信号是不是只发给了小部分人」，
> 而不是继续加大系数。

### 10.28.2 减压侧：先查哪里漏

## 10.29 深层的极慢衰减（防吸收态）

> ✅ **已实现**（2026-10-05）。参数：`decay.csv` 的 `deep_decay`（默认 0.995/天）。

### 10.29.1 「永不衰减」是一个吸收态

§10.22 把深层定义为**永不衰减**，§10.27 又加了软上限 —— 但两者合起来仍是一个**吸收态**：
到了上限就不动，**锁死在那里**。核验证据非常干净：

```
20 局实测：deep_max 均值 50.2，其中 6 局顶到上限 70
而这 6 局【全部】是「举报 > 0」的局 —— 举报>0 ⟺ deep=70，6/6 完全吻合
```

即：**只要那条边没锁死，举报就不会发生。**

吸收态的危害不止于平衡，而是**反涌现**：时间足够长，**所有局会掉进同一个终态**
（几条边锁死、举报门槛永久满足、格局冻结），局与局的差异被时间**单调抹掉**。
这正是「不同结果可以存在」的反面。

### 10.29.2 做法：极慢衰减

```python
self.H_deep[i][j] *= d["deep_decay"]      # 0.995/天
```

| 时间尺度 | 效果 |
| --- | --- |
| **30 天（一学期）** | `0.995^30 ≈ 0.86` → **几乎不衰减**，「忘不了」依然成立 |
| 百年尺度 | 会缓慢收敛 → **死仇也有戏剧性解冻的可能** |

这与 `deep_cap`（软上限）**并存**：上限管「涨到哪里」，极慢衰减管「能不能解冻」。
「不可消减」的**直觉被保留**（一学期内看不出衰减），而**结局空间的开放性被保住**。

### 10.29.3 实测

| 指标 | 加衰减前 | 加衰减后 |
| --- | --- | --- |
| **深层锁死率** | 6/20（30%） | **0/20（0%）** ✓ |
| `deep_max` 跨局 | ［19.0, 70.0］ | **［28.3, 69.7］** |
| 第四道门（分布判据） | 全绿 | **全绿**（爆发 15.5 / 均值 58.9 / SD 22.6 / 饱和 0%） |

# 第十二章 玩家操作映射

## 12.1 总原则（玩家不是特权者）

玩家与 NPC **共用同一套行为与同一套判定**：玩家能做的，NPC 都能做；NPC 的判定流程（门槛 → 意向 → 采样 → 效果）对玩家同样生效。差异只有两处：

| | NPC | 玩家 |
|---|---|---|
| 决策来源 | 决策算法（见 [`../design/NPC行为决策.md`](../design/NPC行为决策.md)） | 人的主动选择 |
| 独有能力 | 无 | 仅 3 项（见 §12.3） |

> **玩家的优势**：玩家发起行为时**跳过决策侧**（§6.4）——NPC 要先过"想不想"的概率判定，玩家只要想就能发起；但玩家仍要过"能不能"的判定侧概率（§6.4 / §10.32）。

## 12.2 玩家可用行为（与 NPC 完全相同）

**状态层（不占"行为"名分，只改位置/占用）**：走动 / 换座位（§10.4）、睡觉（§10.8）、学习（默认，§10.15）。

> **本节的分类面向玩家**，是 **UI 行动菜单的分组依据**——按「玩家在做什么」分三组。
> 同一批动作的**实现分类**（A–E 五类，按读哪条轴分）见 §10.16；**两者是同一批动作的两种切法，不要混进同一张表**。

### 12.2.1 开口说话（走过去，对某个人说）

### 12.2.3 不接触（看 / 换位置 / 什么都不做）

| 菜单项（标识符） | 玩家视角 | 依据 |
|---|---|---|
| 走动 `move` | 换个位置站 / 坐 | §10.4 |
| 睡觉 `sleep` | 趴一整节课，谁都不理你 | §10.8 |
| 学习 `study` | 默认状态：没在忙别的就是在学习 | §10.15 |
| 情报日志 `intel_log` | 上课时翻已经发生的事（**界面**，不占时间） | §12.3 |
| 推理板 `clue_board` | 记下判断，自动标出对不上的地方（**界面**，不占时间） | §12.3 |

> **本作不设「什么都不做」这个选项**——不选，就是学习，压力会涨。

**时间成本**：每个行为都消耗 tick（一个课间段共 100 tick）。走动要花时间、互动要花时间——**课间只有 10 分钟，做不了太多事**。这就是玩家侧天然的操作预算，不需要额外的「每段最多 N 次」限制。

具体耗时见 **`data/rules/behaviors.csv`**（行为主表），核心法则：**收益越大，耗时越长**。

| 行为 | 耗时(tick) | 收益档 | 说明 |
| --- | --- | --- | --- |
| 学习 | 0 | 1 | 兜底状态：占满所有不忙的时间（见下方语义说明） |
| 流言 / 搭话 / 递纸条 | 10 | 2 | 一句话的量 |
| 走动 | 15 | 1 | 耗时低收益也低 |
| 求助 / 告密 / **打听** | 20 | 3 | 「一次动作」档 |
| **闲聊 / 当众调侃** | **30** | 3 | 主行为，要聊一会儿 |
| 举报 | 40 | 5 | 重大事件，得跑一趟 |
| 排挤 | 40 | −4 | 群体驱逐 |
| 安慰 / 道歉和解 | 50 | 3–4 | 深度沟通 |
| 追逐打闹 | 50 | −3 | 群体活动：参与者相互好感↑、旁观者敌对↑ |
| **秘密交换** | **60** | 5 | 收益最大，耗时最长 |
| 睡觉 | 100 | 4 | 占用整个课间段 |

> **`duration` 的语义 = 占用「时间槽」的 tick 数**（期间不能再发起新行为）。`duration = 0` **不是「时间停止」**，而是「不占用时间槽」，其中有两种情形：
> - **兜底状态**（学习）：它**占满所有不忙的时间**，只是不作为动作登记——「没在忙」≡「在学习」。代价体现在压力涓流（每天 2 次、+1）。**本作不设「什么都不做」这个选项**。
> - **并行行为**（窃听）：搭便车，不做主行为时顺便生效（正在专注做事的人听不到）。**⛔ 该行为已关闭、不在任何版本排期内（§18.9），此条仅存语义定义——`duration = 0` 目前实际只有「兜底状态」一种情形。**

> 按此表，一个课间大致只够做 **2–4 件事**——「做不了太多事」是**算出来的**（时间预算），不是外加的限制。
> 实现：行为开始时双方进入**忙碌期** `busy_until = tick + duration`，期间不能发起新行为（替代早期的「一律 20 tick 冷却」）。

## 12.3 玩家独有能力（仅 3 项）

| 能力 | 说明 |
|---|---|
| **打听** | 消耗一次课间动作，向某人打听另一人的事；透露度 = 他对你的信任（§9.3） |
| **推理板** | 记录与标注、查看矛盾高亮（§9.5）——玩家独有的「显式信念」工作台 |
| **情报日志** | 上课段查看已获得的观测与事件（只读） |

## 12.4 玩家不能做的事

- 直接读写任何数值（好感 / 敌对 / 信任 / 透明度 / 压力）；
- 看到未经 §9 两层过滤（透明度 + 信任）的原始数据；
- 在非课间段操作（上课段只能查看情报日志与推理板）。

## 12.5 一切由数值驱动

玩家的每次操作只是在关系矩阵中拨动一个数值；**其后的一切（谁来找你、谁翻脸、谁抱团、谁崩溃）都由数值条件自动触发**，不存在为玩家预设的剧情分支。
# 第十三章 社会事件

社会事件 = **多阶段、跨相位、全体参与、结果改变结构**的班级级过程。

> ⚠️ 它**不是剧本**：触发、过程、结果全部由数值决定（见 §10 总则「一切由数值驱动」）。任何"第 N 天举行 X"的写法都视为错误实现。

## 13.1 层级位置

```
行为层       逐 tick、15 个行为、个体决策（§10）
社会事件层    多阶段、跨相位、全体参与、结果改变结构      ← 本章
结算层       跨天衰减、座位重排、简报（§3.5、§14）
```

## 13.2 通用规范

| 项 | 规范 |
|---|---|
| **触发** | 由数值条件满足触发，**不看日期** |
| **阶段** | 每个事件由 N 个阶段组成，每阶段绑定一个相位（课间 / 上课 / 放学） |
| **过程** | 每阶段内部仍走既有机制（流言、意向评分、阈值判定），**不写死台词或结果** |
| **结束** | 产出结构变化（身份 / 标签 / 关系），并归档进日志供简报引用 |
| **玩家** | 各阶段参与方式不同，且**不能操纵结果** |
| **并发** | 同一时间至多一个社会事件在进行中 |

## 13.3 数值档位

社会事件的直接数值影响使用**重大档**（`base ∈ [4,5]`，见 §6.3），并可附加状态标签（如「落选」3 天）。

## 13.4 班委选举

### 触发条件（任一满足，全部为数值判据）

1. **权威崩解**：现任班长（身份层持有「班委」标签者）曾压力爆发（≥90），且其影响力 `influence` 跌至班级中位数以下；
2. **阵营分裂**：班级存在 ≥2 个稳定簇（簇标签），且两簇之间的平均敌对 ≥ 阈值；
3. **玩家提议**：玩家消耗一次课间动作提议改选，并满足支持门槛（≥N 人对玩家好感 ≥ 阈值）。

> `influence(c)` = 有多少人愿意听 `c` 的话，可由矩阵直接读出：`Σ_j max(0, A[j][c] − θ)` 归一化。

### 五个阶段

| 阶段 | 相位 | 机制 | 玩家可参与 |
|---|---|---|---|
| ① 酝酿 | 课间 | 「改选」作为一条**流言**进入系统（§10.1：带倾向、会染色、会被窃听） | 打探 / 表态 / 传话 |
| ② 提名 | 课间 | 候选人 = 各强连接簇的**话事人**（簇内 `influence` 最高者）；玩家可自荐（需支持门槛） | 自荐 / 支持他人 |
| ③ 模拟投票 | 课间 | 非正式试探：通过闲聊 / 打听探口风 → 影响各方**信念** | 拉票 / 试探 / 虚张声势 |
| ④ 实际投票 | **上课** | 正式投票，玩家**不可操作**（上课是发酵层） | 只能看情报日志 |
| ⑤ 结果公布 | 放学 | 计票 → 新身份 + 簇标签重算 + 简报条目 | 看《每日简报》 |

> ③ 与 ④ 的相位安排（模拟投票下课、实际投票上课）是刻意的：**结果在你无法干预时产生**。

### 投票算法

```
选民 i 对候选人 c 的投票倾向：
  U_vote(i, c) = α_A · A[i][c] + α_T · T[i][c] + α_I · influence(c)
  倾向转概率：softmax(U_vote / τ)，每人一票

开票：得票最高者当选；平票按 influence 破平
```

注意：**「我信任他」与「他说话管用」是两件事**——因此会出现"人缘好但没实权者落选"这类结果。

### 结果的结构影响

| 对象 | 影响 |
|---|---|
| 当选者 | 获得「班委」身份标签 → 影响后续（举报倾向、责任种子、被拉拢概率） |
| 落选者 | 压力 **+4~5**（重大档）+ 可能对当选者敌对上升 |
| 支持者 | 通过关系调制自然产生"阵营效应"（支持落选者的人对当选者好感下降） |
| 全班 | 簇标签重算 → 格局可能重新洗牌 |
| 玩家 | 参选并当选则获得身份，同时背上相应责任种子 |

## 13.5 同层可扩展的其他社会事件

| 事件 | 触发（数值） | 结构影响 |
|---|---|---|
| 班级冲突爆发 | 两个簇的敌对同时过阈值 | 全体站队 |
| 真相揭露 | 推理板矛盾累积到阈值 | 秘密 / 诬告公开 |
| 集体活动（春游 / 运动会） | 学期中段 + 班级压力中位数偏高 | 强制互动、关系重排 |

# 第十四章 每日简报与学期格局报告

每天放学生成《每日简报》，第 30 天放学生成《学期格局报告》。每一句话都来自后台日志，不是预制文案。

- 【小团体】列出本局形成的所有簇及成因（如"A、B、C 凑成圈子，因为 C 被 D 排斥后倒向他们"）——数据来自簇标签器与日志。
- 【孤立】列出全程独自坐着没加入任何对话的人及原因。
- 【对立】列出阵营之间的紧张关系及导火索。
- 【大事件】列出压力爆发、举报、秘密泄露等重大事件及周围人的分裂反应。
- 【你的影响】明确指出玩家的哪个操作间接导致了什么格局变化。
- 【真相对照】玩家推理板中的结论与系统实际格局的对照——理解对了是洞察，错了是这一局独有的故事。

《每日简报》聚焦当天发生了什么；《学期格局报告》在每日简报基础上追加：

- 【学期演变】每个阵营、每段孤立、每对宿敌在 30 天内的兴衰时间线；
- 【学期真相对照】玩家 30 天推理结论与学期最终格局的总对照。

简报的核心价值：玩家做了一些操作，然后看到系统自己长出了他没预料到的格局，并且报告告诉他为什么会这样。这就是"看见涌现"。

## 15.1 三层实时可视化

> ✅ **空间底座已实现**（2026-10-05，见 §10.20 空间层）：4×4 座位表 + 讲桌旁 1 座 = 17 座，邻接为 8 邻域。下面第 1 条「空间聚散」因此有了**真实的物理位置**（不再是抽象坐标）。

1. **空间聚散**：小人在教室的物理位置就是涌现的第一画面。好感高的不自觉靠近，敌对高的保持距离，小团体肉眼可见凑成圈（簇标签器描淡轮廓），被排斥的人移到边缘。
2. **情绪图标**：每个小人头顶极简表情图标（开心、平静、焦虑、愤怒、低落、兴奋），是唯一直接暴露情绪的窗口，**不暴露数值**。
3. **关系氛围线**：小人之间偶尔闪现极淡视觉线索——好友闪过柔和细线，敌对闪过小闪电。只在**质变瞬间**出现，不常驻。
4. **活动圈**（§10.31）：**正在做同一件事的人，被同一颜色的圈框起来** —— 这是「小团体肉眼可见凑成圈」的**实时版**。
   - **与第 1 条的「簇」是两个尺度**：**活动圈是秒级的**（此刻谁和谁在一起，随课间流动）；
     **簇是天级的**（谁和谁长期要好，用于每日简报与阵营分裂判定）。两者并存，**不互相替代**。
   - **不同活动不同颜色**：聊天 / 打闹 / 学习 / 走动……各自一色（配色待定；建议暖色给「热闹类」，冷色给「安静类」）。
   - **加入反馈**：当有人想加入别人的活动时，**判定结果直接可见** ——
     **接受 → 绿色提示；拒绝 → 红色提示**。背后是 §10.31 的 `join_feedback`（信念 + 对方外向度），
     而**拒绝还会反噬关系**（`reject_hostility` / `reject_stress`）—— 所以红圈不只是「没进去」，是「**被拒了、还伤了**」。
   - **为什么用「圈」而不是只高亮图标**：圈把「**同做一个活动**」这件事**空间化**了 ——
     玩家一眼看到的是「那三个人凑成一堆在聊」「这两个人一起走开了」，而不是逐个辨认图标。
     §15.3 的回放里这一条尤其有效：**看着圈一个个成形、又一个个散开**。

## 15.2 上课过场

上课段以快进动画呈现：NPC 回到座位，座位相邻关系慢慢发酵，纸条偶尔传递，情绪图标在头顶缓慢变化，玩家可随时切到情报日志 / 推理板查看。

## 15.3 回放功能（进阶 · 第三版）

放学后可回看加速动画：看着一团乱的小人慢慢聚成几个圈子，看着某个人被慢慢边缘化，看着一次八卦如何在人群中扩散变形。**玩家亲眼看到秩序从混乱中自己浮上来。**

> 实现依赖：事件日志必须可重放 → 随机数必须来自可复现的种子化 RNG（见 §18.2 存档模型）。

# 第十八章 工程实现规范

> 本章是**程序实现的唯一依据**，汇总自 `docs/design/` 各篇。策划只需读 §1–§17；程序从本章入手。
> 对应的分篇文档仍保留（含更细的推导、手算例与待确认项），但**本章内容自包含**——两处冲突时以本章为准。

> **引擎定稿（2026-10-06）**：Godot 4.7.2（GDScript）。本章以 Godot / GDScript 约定为准；`docs/design/` 各篇中的 GDScript 代码块即实际实现语言。

## 18.1 架构总览

本作是**数据驱动模拟**：内核每 tick 计算完成后再通知表现层，**表现层不参与数值计算**。

```
       ┌────────────── SimulationCore（无 UI 依赖，可无头运行）──────────────┐
       │  TimeSystem ──tick──► RuleScheduler ──► Behaviors(§10) ──► A/H/T / Stress │
       │        ▲                   │                                    │        │
       │        │                   └──► 涓流结算（传导 / 共同学习 / 独处，每天 2 次）│
       │   TermState（天 / 段 / 相位）              │                              │
       │                                          └──► ObserverLayer（簇标签 / 孤立，只读）│
       └──────────────────────────────────────────┼───────────────────────────────┘
                                                  ▼
              EventBus（信号）──► Presentation（场景、可视化、推理板、简报、存档）
```

**硬性边界**：`scripts/core/`、`scripts/systems/`、`scripts/npc/` 不得 `preload` 任何 `scenes/`；**模拟内核必须能在无渲染环境下跑完一局**（批量标定与单测依赖这一点）。

| 层 | 目录 | 职责 | 禁止 |
|---|---|---|---|
| 模拟内核 | `scripts/core/` | 时间推进、矩阵与压力状态、结算 | 依赖节点树 / UI |
| 规则层 | `scripts/systems/` | 行为触发与效果、影响力传导（§10） | 角色名 / ID 判断 |
| 观察层 | `scripts/systems/observer/` | 簇标签、孤立标签 | 回写任何数值 |
| 决策层 | `scripts/npc/` | NPC 的**规则选择**（用哪条、选谁） | 绕过规则直接改数值 |
| 表现层 | `scenes/`、`scripts/ui/`、`scripts/game/` | 渲染、输入、动画、推理板、简报 | 直接改矩阵（只能走内核 API） |
| 全局单例 | `autoload/` | 状态持有、事件总线、存档、配置读取 | 承载玩法规则 |

**目录约定**：`scenes/` 与 `scripts/` 同构（`ui/` `game/` `core/` `npc/` `systems/`）；全局单例在 `autoload/` 并注册 `project.godot`；配置与数值表在 `data/`（代码只读）；离线脚本在 `tools/`。

## 18.2 数据模型

**运行时状态**（一局的全部可变数据，索引 `0 … N-2` 为 NPC，`N-1` 固定为玩家）：

```gdscript
class Relations:                      # 关系矩阵：N×N 有向，0–100
    var affinity: PackedFloat32Array   # A[i][j] = i 对 j 的好感
    var hostility: PackedFloat32Array  # H[i][j] = i 对 j 的敌对（与 A 独立，不是负数）
    var trust: PackedFloat32Array      # T[i][j] = i 对 j 的信任

class ActorState:                     # 个体属性（长度 N）
    var opacity: PackedFloat32Array    # O[i] 透明度
    var stress: PackedFloat32Array     # S[i] 压力（唯一累积情绪变量）
    var mbti: PackedFloat32Array       # 4×N：E/N/F/P 各维度 0–100 连续值

class Belief:                         # 信念矩阵：三份 N×N（§18.5）
    var b_affinity: PackedFloat32Array # B_A[j] = i 猜测「j 对 i 的好感」
    var b_hostility: PackedFloat32Array
    var b_trust: PackedFloat32Array
```

- **有向存储**：`A[i][j] ≠ A[j][i]`，读写一律用"谁对谁"的语义；**建议提供 `a(i, j)` 访问器而非裸下标**，避免矩阵转置错误。
- **钳制统一在写入点**处理（§6.1 的 `clamp`）。
- N 由难度决定：简单抽 8（N=9）、标准抽 16（N=17）、困难全池 24（N=25）；**同种子同阵容**，绑定组（小情侣等）整组同抽。

  9. 事件日志引用：当天与学期的 `log_event` 索引（简报 / 回放的唯一数据源）；
  10. 玩家推理板状态（§9.5）；
  11. **本局抽取结果**：难度档、抽中的 NPC 索引映射、绑定组、座位分配；

- 回放（§15.3）依赖事件日志可重放 → **随机数必须来自可复现的种子化 RNG**，且上述 1–12 任一缺失都会让"同种子重放"对不上。

## 18.3 规则引擎

**主循环**：

```
一局 = 30 天 × 每天 480 tick（课间 3×100 + 上课 2×90）
for day in 1..30:
    for phase in [上午课间, 上午上课, 中午午休, 下午上课, 下午课间]:
        for t in 1..phase.tick_count:
            run_rules(phase.active_rule_set)      # §3.3：上课只跑规则子集
            if global_tick % settle_interval == 0:  # 涓流：传导 / 共同学习 / 独处，一天 2 次
                apply_transmission(); apply_study_together(); apply_stress_drip()
            observer.update()                        # 簇标签器，只读
            emit(log_event)                          # 简报与推理解释的唯一数据源
    settle_day()                                     # §3.5 跨天结算 + 生成《每日简报》
```

**相位与规则启用**（§3.3）：

| 相位 | 启用规则 |
|---|---|
| 课间段 | 全部人物行为 + 玩家操作（§10） |
| 上课段 | 共同学习（相邻且双方都在学习）、流言传播（低频）、压力涓流；**搭话禁用** |
| 放学结算 | 不跑规则，执行跨天衰减与简报生成 |

> ⚠️ 涓流类（传导 / 共同学习 / 独处恢复）**不是每 tick 结算**，而是**每天 2 次**（`settle_interval` = 240 tick，上午 / 下午各一次）——结算判据必须基于**全程 tick 计数**，而不是相位内计数，否则会退化成"每相位一次"。

**规则实现约定**——每条规则实现为独立类，统一接口：

```gdscript
class Rule:
    func gather(ctx: SimContext) -> Array[CandidateAction]   # 谁能对谁发起
    func resolve(ctx: SimContext, action: CandidateAction) -> Array[Effect]  # 结果
    func apply_effects(ctx: SimContext, effects: Array[Effect]) -> void
```

- **决策与效果分离**：`gather` 处理触发条件（读 A/H/T/S/O/MBTI 与信念），`resolve` 处理结果判定（含概率），`apply_effects` 统一走 §6.1 增量公式并钳制。
- **行为选择（谁做什么）不在规则层定义** —— 它属于决策层（§18.6）。规则层只定义"行为发生后效果怎么算"。
- **数值外置**：所有增量、阈值、概率系数从 `data/rules/` 与 `data/balance/` 读取，脚本中不得出现魔法数字。

**同 tick 冲突消解**（拟定，M1 用批量局验证后固定）：

1. 优先级：危机类（举报、安慰）> 主动类（搭话、调侃、道歉、秘密交换）> 被动类（回应、话题共鸣）> 环境类（共同学习 / 相邻概率修正）；
2. 同级按角色索引升序，保证可复现；
3. 已被占用（处于对话中）的角色本 tick 不再接受新交互。

**传导实现要点**：阈值 + 竞争归一化照旧（§7.2），饱和用统一软饱和 `sat_X(u) = u / (1 + |u|/U_X)`；**传导计算必须基于本结算点开始时的矩阵快照**，否则同点内写入互相污染、结果不可复现。性能：N³ 三重循环（最大 25³）在 14,400 tick 下的开销需实测，必要时改为稀疏更新（仅处理 `A'|H' > 0` 的对子）。

## 18.4 统一影响公式（要点）

完整定义见 §6（公式）与 §7（传导），推导与手算例见 `docs/design/统一影响公式.md`。核心链条：

```
P = E + C                # 事件推动 + 传导推动
E = base × M_personality × M(i,s)     # 性格倍率 × 关系调制
Δ = round( sat_X(P), 0.1 )            # 软饱和后四舍五入到 0.1
X ← clamp(X + Δ, 0, 100)              # 统一写入点
```

- `sat_X(u) = u / (1 + |u|/U_X)`：小量近似直通，大量收敛于 `U_X`。
- `M_personality = clamp(1 + Σ w_t·d_t, 0.1, 1.2)`（`d_t = (维度−50)/50`）：**性格只能温和放大或削弱，不能翻倍**。
- `M(i,s) = clamp((A[i][s] − H[i][s]) / 50, −1, +1)`：按**净态度**调制；态度不明显时只削弱，**敌对压过好感时反转**（这就是"敌对反应"的来源，不是靠额外的惩罚规则）。
- **三类结算方式**：事件类（即时，每次交互最多一次）、涓流类（传导 / 共同学习 / 独处，每天 2 次）、状态类（压力与跨天衰减，按 §3.5）。
- **数值铁律**：常规事件 `base ∈ [1,3]`、重大事件 `base ∈ [4,5]`（判据 = 前置条件苛刻）；涓流类单次 1–5；**单次结算幅度 ≥ 0.1，小于 0.1 的增量在 `round` 后会被舍去**（这也是不引入小数堆叠的原因）。
- **事件去重**：同一对子、同一规则、**同一课间段内只结算一次**。

## 18.5 信念矩阵（要点）

完整定义见 `docs/design/信念矩阵.md`。核心：**决策读信念，判定读真值**（与设计讨论中的「触发判定 / 决策判定」同义——触发判定 = 决策侧、决策判定 = 判定侧；本文统一沿用「决策 / 判定」命名，见 §6.4）。

- **三份矩阵** `B_A / B_H / B_T`，`B[i][j]` 的语义是"i 猜测 **j 对 i** 的态度"（与真值矩阵下标方向一致）。
- **观测三源**：直接互动、旁观他人互动、二手转述（流言）；玩家额外有"打听"（`ask_about`）。
- **更新规则**：`B ← B + η·(obs − B)`，其中
  - 学习率 `η = η0 · (0.3 + 0.7·T[i][j]/100)` —— **越信任对方，越相信自己的判断**；
  - 观测值 `obs = 真值 + 噪声`，噪声上限 `σ_max·(1 − O[j]/100)` —— **对方越透明，看得越准**；
  - `lambda_b` 每日把信念向先验缓慢回归（遗忘）。
- **初始值（开局先验）**：**由双方性格共同决定** —— `bias_A(i,j) = perceived(j) × (1 + bias_observer_k · observer(i))`，其中 `perceived(j)` 是**对方**「看起来」多友善（外向/共情型显得友善），`observer(i)` 是**我自己**多倾向于把人往好处想。
  **不是 `null`**（它是「不知道」，见 §11），**也不是复制真值矩阵**（那是开天眼）。
  · **乘法而非加法**：对方友善 + 我乐观 → 强烈高估；对方友善 + 我多疑 → 只略高估；对方冷淡 + 我乐观 → 仍略低估。
  · **天然不对称**：`bias(i,j) ≠ bias(j,i)`——同一个「话痨」，乐观者与多疑者判断不同（实测 92% 对子有双向差异）。
  · `bias_H = −bias_A`；`bias_T` **只受观察者影响**（对方「看起来」是否可信没意义，但「我是否容易先信任别人」有意义）。
  **偏差是性格的函数、不是随机数** → 「话痨型总被高估亲近、冰山型总被低估好感」成为**可预测的系统性错觉**。
- **读取规则**（最容易写错的地方）：**我自己的立场**（要不要做）读真值 `A[i][*]`、`T[i][*]`；**对方的反应预期**（他会不会接纳我）**必须读信念** `B_A[i][*]`、`B_T[i][*]` —— 读真值就等于开天眼。
- 误判是**特性而非缺陷**：它让"我以为他喜欢我"变成戏剧的来源（§9.4）。

## 18.6 NPC 行为决策（要点）

完整定义见 `docs/design/NPC行为决策.md`。**三段式**：门槛 → 意向评分 → softmax 采样。
> 三段式即 §6.4 统一判定公式中**决策侧（意向类）**的实现；判定侧（成不成）的 `score → p → 掷骰` 公式同见 §6.4。

**三类触发方式**：

| 类型 | 判据 | 行为 | 设计意图 |
|---|---|---|---|
| 环境类 | 固定基础概率 × 修正系数 | 闲聊、流言、窃听 | 不需要"想"——有条件就按概率发生 |
| 阈值类 | `p = σ((x − θ)/scale)`（越过阈值只是概率升高，不保证发生） | 举报、压力爆发 | 保留"积累到临界点"的相变手感，但不再 0/1 |
| 意向类 | 门槛 → 意向评分 → softmax | 搭话、当众调侃、安慰、求助、道歉、秘密交换 | 需要"选择"，因此受性格与信念影响 |

> **意向类还要按「判定来源」归类**（见 §10.16）：纯增益型 / 纯损害型 / **信念驱动型**（搭话读 `B_A`）/ **信任·透明度驱动型**（秘密交换读 `T`、告密读 `O`）/ **混合判定型**（当众调侃读 `A`+`H` 并用绝对阈值分档）。**方向用阈值、强度用 `|M|`** —— 不可用 `M` 的符号判方向（反例与实测见 §10.16）。
> **玩家路径**：玩家不跑 NPC 的决策侧（跳过"想不想"的采样），由人直接选择行为并进入判定侧（§12.1）。

**意向类完整算法**：

```
① 门槛（硬条件，取自主文档 §10 的"触发条件"）
   搭话：A[i][j] ≥ 30 且 stress_i ≤ 80 且 j 不在对话中
   调侃：周围 ≥3 人 且（A[i][j] ≥ 40 或（H[i][j] ≥ 25 或 A[i][j] < 25））  ← 好意 / 挑衅双轨，见 §10.12
   安慰：stress_j ≥ 70 且 A[i][j] ≥ 50
   求助：A[i][j] ≥ 30（内向型 ≥50）    道歉：H[i][j] ≥ 30（双向）    秘密交换：T[i][j] ≥ 60
   → 不通过的组合不进入候选集（概率恒为 0，不允许"小概率硬做"）

② 意向评分
   U_b(i) = Σ_X α_X(i) · Δ_X^pred(i, b)
   我自己的立场 → 真值；对方的反应预期 → 信念（§18.5）

③ 性格权重 α（Σα = 1；系数以 `data/balance/npc_weights.csv` 为准）
   α_A      ∝ 0.5 + 0.5·F/100 + 0.3·E/100          情感型 / 外向型更在意好感
   α_T      ∝ 0.5 + 0.30·J/100                      判断型更在意信任（**跟 J 正向**，选项 C）
   α_H      ∝ 0.5 + 0.5·(1−F/100) + 0.30·J/100     思考型 + 判断型更在意敌对（**跟 J 正向**，选项 C）
   α_stress ∝ 0.5 + 0.5·(1−E/100)                   内向型更在意压力消解
   系数落在 data/balance/npc_weights.csv

   ⚠️ **选项 C 语义**：α_T 与 α_H **都跟 J 正向**——J 型"爱恨分明"（谁值得信、谁是敌人，先判断再下结论）。
   此前文档写 α_H ∝ 1−J（随性型更在意敌对）与实现相反，已废弃。
   ⚠️ **连带**：§13 社会事件投票 `U_vote = α_A·A + α_T·T + α_I·influence` 引用的 α_T 语义已变，
   将来标定 `α_I` 时必须按新的 α 口径重定，不要沿用旧值。

④ 温度与采样
   p(b) ∝ exp( U_b / τ_i )
   τ_i = τ0 · (1 + 0.3·(1 − J_i/100)) · stress_modifier
   τ0 = 1.0 ｜ stress_modifier = 1.0（<70）/ 1.5（≥70，冲动）
```

τ 的物理含义：**τ → 0 退化成 argmax（刻板），τ → ∞ 退化成纯随机（噪声）**；1.0 附近是"有偏好但不死板"。

> **性能与可复现**：候选集上限 `top_n`（默认 5）；同一 tick 内的决策顺序必须确定性（按索引升序或固定种子洗牌），否则同种子不可复现。

## 18.7 工程不变式汇总（违反即为缺陷）

1. **禁止角色名 / ID 判断**：行为逻辑必须只依赖 `f(性格四维, 透明度, 状态)` 与信念；角色差异只能来自 `data/characters/` 的开局种子。
2. **观察层只读**：簇标签器与孤立标签**绝不回写**任何矩阵。
3. **决策读信念，判定读真值**：决策路径中不得出现 `A[j][i]`、`H[j][i]`、`T[j][i]`（"别人对我的态度"）。
4. **不引入脚本化剧情**：不得出现"第 N 天 / 第 N 段必然发生 X"。
5. **数值集中**：增量、阈值、系数一律来自 `data/`，脚本中不得出现魔法数字。
6. **可无头运行 + 可复现**：内核能在 `--headless` 下跑完整局；随机数一律来自种子化 RNG，同种子同结果。
7. **写入点唯一**：所有轴值变化都经 §6.1 的公式与 `clamp`，不得绕过。
8. **全部轴值域 0–100**；`null ≠ 0`（"不知道"不等于"中立"）。

# 附录：行为速查表

> 本表是第十章「人物行为设计」的速查版，**完整细则（触发判定、数值、记忆与遗忘规则）以第十章为准**。
> 类型说明：**主行为** = 课间主要活动（每角色每课间一项）；**附加行为** = 在主行为之外并行判定。

| 行为 | 类型 | 触发条件 | 结果要点 |
| --- | --- | --- | --- |
| 闲聊 | 主 | A、B 双方互相处于对方闲聊范围内，按概率触发 | 双方各自判定好感/敌对变化；降低双方压力；内容可被范围内未闲聊角色窃听 |
| 搭话 | 主 | A 未发生闲聊，且其闲聊范围内已有人闲聊，按概率判定 | 通过则加入该闲聊（结果同闲聊）；未通过则 A 对闲聊双方敌对值上升 |
| 举报 | 主 | A 对 B 的敌对值累积到阈值，或特殊行为触发 | 本课间举报者离场（同走动到室外）；被举报者压力大幅上升；按概率生成一条倾向 −2 的流言（存入 A 或 B 的记忆）；举报后 A 对 B 敌对值下降 |
| 睡觉 | 状态层 | 按概率触发睡觉判定 | 本课间无法进行其他任何活动；课间结束压力减少 |
| 走动 | 状态层 | 下课瞬间立即执行位置更新 | 角色按概率变更位置（**不改数值**，见 §10.4） |
| 窃听 | 附加 | 角色本课间未进行任何主行为 | 捕获自身范围内所有闲聊内容；将流言存入记忆；若窃听者本人是流言对象，则按倾向降低/提升压力与对闲聊双方的好感/敌对，并课间结束后立即删除记忆 |
| 流言 | 附加 | A 对 B 的流言判定通过（与好感、敌对相关），或由举报产生 | 将针对 B 的流言存入 A 的记忆；倾向 ∈ [−2, 2]；A 对 B 的好感或敌对按倾向变化；传播时按传播者态度产生偏移；可用**纸条**私密传递（不可窃听 / 不可搭话）；每条流言最多在一个人记忆中停留 3 个课间 |

> 优先级：行为编写顺序即优先级顺序（见第十章 10.10 注释）。所有主行为（含默认学习）与附加行为在课间开始前决定，课间开始直接执行。
