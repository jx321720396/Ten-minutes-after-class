# 第一章 游戏概述

## 1.1 游戏定位

《下课十分钟》是一款以高中校园为场景的社交模拟游戏。玩家扮演一名转学生，作为班级社交节点之一（角色池共 24 人，按难度随机抽取 8/16/24 个 NPC 入局，玩家另算，本局共 9/17/25 个节点），在**一个学期（30 个上学日）里每一天的三个课间**通过搭话、递纸条、调侃、安慰、举报等行为，参与并扰动一个自运行的班级社交系统。

游戏核心不是完成固定目标，而是：**你埋下种子，系统自己发酵，长出的班级格局不属于你也不属于任何一个 NPC。** 玩家的每一次操作只是在关系矩阵中拨动一个数值，整个系统自行重新洗牌，涌现出独属于这一局的班级格局。

## 1.2 核心概念

- 玩家不是上帝，而是系统的一部分。NPC 和玩家共用同一套底层规则。
- 即使玩家什么都不做，NPC 之间也会自发社交、传八卦、抱团、对立、崩溃。
- 没有预设剧情、没有固定结局、没有正确答案。谁和谁成了朋友、谁被孤立、哪两个阵营对立、谁在这一天崩溃了——全部从底层规则中涌现。

## 1.3 玩家目标

***用有限的信息，拼出你认为的班级真相。***

玩家不是"观察者"，而是"解释者"：每个课间获取的只言片语、矛盾情报、虚假态度线，都进入玩家的**推理板**。玩家的操作影响班级走向，而推理板记录玩家如何理解这个走向。局末，玩家看到自己拼出的"真相"与系统实际格局的对照——理解对了是洞察，理解错了是这一局独有的故事。

## 1.4 一局流程（一学期 = 30 天）

一局 = 一个完整学期 = 30 个上学日。每个上学日的结构：

1. 上午课间（操作，实时）
2. 上午课堂（发酵过场，快进）
3. 中午午休（操作，实时）
4. 下午课堂（发酵过场，快进）
5. 放学结算（跨天继承 + 每日简报）

第 2 天从上午课间继续，关系矩阵跨天继承

第 30 天放学 → 《学期格局报告》

- 每天三个可操作段 = 上午课间 / 中午午休 / 下午课间；每天实时约 5 分钟，30 天总计约 2.5~3 小时（单日即一个自然游玩/存档单元）。
- 两段上课过场负责"发酵"：课间埋下的矛盾在上课期间继续发展，玩家无法干预。
- 放学后生成《每日简报》并执行跨天结算（关系继承与衰减）；学期末生成《学期格局报告》，回顾 30 天涌现出的班级格局。

# 第二章 涌现主题阐释

## 2.1 两道检验题

本游戏的所有设计都经过以下两道检验题的筛选：

- **检验一**：把涌现的部分换成脚本，游戏还成立吗？如果还成立，主题就只是装饰。
- **检验二**：玩家面对的那个整体，是否拥有任何部分都没有、也没有任何部分想要的性质？

## 2.2 排除假涌现

- **因果链不是涌现**：A 导致 B，B 导致 C，是蝴蝶效应，每一环都能单独解释。
- **数量累加不是涌现**：种满 30 朵花只是部分加在一起，整体没有新性质。


## 2.3 涌现主体：班级格局

没有任何一个 NPC 想要形成小团体、想要排挤某人、想要和另一个阵营对立。每个个体只维护自己的好感、敌对、信任、压力等数值，遵循简单规则。**小团体、孤立、阵营对立、压力崩溃后的关系重塑，是整个系统运行后自发浮现的宏观性质。**

用检验一验证：如果"成团""孤立""对立"换成预设脚本（第 2 个课间 A/B 必然成团、第 3 个课间 C 必然被孤立），游戏失去核心——因为本游戏里**根本没有成团规则，只有读矩阵的标签器**。

# 第三章 时间与节奏系统

## 3.1 一局 = 一个学期 = 30 天

一局游戏覆盖一个完整学期（30 个上学日），每天含 3 个可操作课间段和 2 个上课发酵段。**每段课间的游戏内时间仍是 10 分钟（扣住标题），实时压缩播放；每天实时约 5 分钟，学期总计约 2.5~3 小时。** 关系矩阵跨天继承——今天的恩怨，明天继续发酵。

## 3.2 tick 定义

| **阶段** | **游戏内时长** | **实时时长** | **1 tick** | **每段 tick 数** |
| --- | --- | --- | --- | --- |
| 课间段 ×3 | 10 分钟 | 100 秒 | 6 秒游戏内 = 1 秒实时 | 100 |
| 上课段 ×2 | 45 分钟 | 15 秒（快进） | 30 秒游戏内 | 90 |
- 每天总 tick ≈ **480**（课间 300 + 上课 180）；每天实时 ≈ 3×100 + 2×15 ≈ **5 分钟**（结算界面不计入）。
- 学期总 tick ≈ **14,400**（480 × 30 天）；学期总时长约 2.5~3 小时，单日即一个自然游玩/存档单元。
- 课间 = 高分辨率模拟：全部行为规则 + 玩家操作。
- 上课 = 低分辨率发酵层：只跑规则子集（见 §3.3）。
- 放学后 = 跨天结算层：关系继承 + 衰减 + 每日简报（见 §3.5）。



## 3.3 上课发酵层（低分辨率 · 只跑行为子集）

上课不是暂停，而是「发酵结算层」。上课期间座位固定、玩家不可操作，只运行以下内容：

| 内容 | 上课期间的行为 |
|---|---|
| **共同学习** | 相邻（距离 ≤1 格）且双方主行为均为「学习」的对子，**每天结算 2 次**（上午 / 下午）：好感 +1、信任 +1 |
| **流言传播** | 低频触发（每 3~5 tick 一次，只能传纸条 / 小声说话） |
| **影响力传导** | 继续运行（态度在座位邻近与信任链上缓慢扩散） |
| **压力发酵** | 事件驱动照常；压力涓流（**学习 +1 / 独处 −2**，参数在 `data/rules/behavior_probs.csv`）随涓流结算一并执行 |
| **搭话 / 闲聊 / 调侃 / 安慰 / 求助 / 道歉 / 举报** | **禁用**——课间埋下的矛盾上课无法解决，只能积累（但流言仍在暗处扩散） |
| **睡觉** | 若上课前已入睡，则不参与任何交互（见 §10.8） |
| **玩家** | 不可操作，但可查看情报日志 + 推理板（等待变成思考时间） |

> ⚠️ v3.0 快照 §3.3 中的「**座位相邻缓慢加好感**」一条**已废弃**：物理相邻不再直接改数值，只提高自发互动的概率（见 §10.15 注释 5）。

设计意义：

1. **慢积累 + 快相变**：课间埋矛盾 → 上课发酵 → 下个课间爆发，爆发有因果、有铺垫。
2. **"我埋的种子自己发酵"**直接回应检验一：玩家上课时什么都做不了，格局还在自己变。
3. 三阶段形成叙事弧线：上午埋因 → 中午发酵 → 下午爆发/成团，简报可写出"从混乱到秩序"。

## 3.4 数值标定目标（反推所有涓流与事件值）

以每天 480 tick、学期 14,400 tick 为基准，所有数值按以下目标反推，而不是先定数值再凑时长：

1. **好感**：关系是**慢变量**——从陌生（20）到明显可见的变化（约 45–60）需要 **约 10 天**（一天净增 1–3 点，靠长期累积而非单次事件）；单日不能饱和，**也不能一天涨很多**。玩家应在一局的中后段才明显感到「格局成形」。
2. **压力爆发**：平均 **每 1~2 天一次**，且集中在每天的第 2、3 段课间（发酵之后），不是开局就爆。
3. **30 天不饱和（长期形态）**：一局结束时全班好感**饱和率（≥95）应 < 10%**，均值落在 **45–65**，且分布保持**分化**（标准差 ≥ 20）——这是「涌现不提前死亡」的硬指标；**只看前 10 天的均值会漏判**（见 §7.1 第 4 条）。
   *当前实测（30 天）：饱和率 **0.0%** ✓、均值 **66.3** ✓、**SD 25.1** ✓（首次达标）、好感跨度 3.6~91.0（确有孤立者）；爆发 **2 次**（目标 15–30，**唯一未达标项**，可通过压力侧独立微调——因为 SD 已达标，好感侧不再被牵动）。*
   *关键路径：把搭话判据从「`B_A >= 40`」（先验恰为 40 → 永远通过）改为「信念 + 对方性格，门槛 45」，**打通了关系变差的通道**，SD 才从 10.6 升到 25.1。详见 §10.17。*
4. **格局弧线（学期尺度）**：第 1 周关系试探、轮廓未明 → 第 2–3 周关系分化（阵营雏形、个别孤立）→ 第 4 周格局成形或爆发大事件。**因为好感是慢变量，前两周不应出现明显的派系对立**——与第 1 条一致。

## 3.5 跨天结算层（放学后）

每天放学后执行一次，让"一天"成为长线涌现的积木：

| **结算项** | **规则** |
| --- | --- |
| 关系继承 | 好感/敌对/信任矩阵完整保留到第二天（今天的恩怨明天继续） |
| 好感衰减 | 当天无互动的对子 ×0.95；有互动的对子 ×0.98 |
| 敌对衰减 | 敌对 ×0.90（时间冲淡矛盾，但不会自动归零） |
| 信任衰减 | 信任 ×0.93（信任需要持续维护） |
| 压力衰减 | 压力 ×0.50 跨天保留（长线心结，不归零）；若当天爆发过，携带"心结"标签 3 天，每天初始压力 +5 |
| 座位重排 | 每天开局可重新选/被调座位，改变相邻格局（**改变的是自发互动的机会，不是直接数值**，见 §10.15） |
| 每日简报 | 生成《每日简报》，归档进学期日志 |

*衰减系数为初始值，需按 3.4 目标批量标定。衰减的意义：关系必须持续经营才维持得住，否则 30 天会全部饱和到 100，涌现提前死亡。**关键关系：稳态 `A* ≈ 每日增益 / (1 − 保留率)`**——所以「全班饱和」与「衰减太快」其实是同一个旋钮的两端，单靠调这个旋钮无法同时满足；真正的解法是 §7.1 第 4 条的负反馈。*

# 第四章 系统架构总览

## 4.1 三层架构

系统分为三层，各司其职，不冗余、不循环依赖：

| 层级 | 内容 | 特性 |
| --- | --- | --- |
| 行为接口层 | 第十章的人物行为（闲聊 / 搭话 / 举报 / 告密 / 传纸条 / 走动 / 窃听 / 睡觉 / 流言） | 决定这一 tick 谁和谁发生什么互动，快变量 |
| 情绪状态层 | 压力值（唯一累积情绪变量） | 累积-爆发机制，中变量 |
| 底层态度轴 | 好感/敌对/信任（有向矩阵）+ 透明度/性格（个体） | 稳定的关系与人格，慢变量 |

## 4.2 闭环说明

底层态度轴决定规则触发条件（谁能搭话、谁会传八卦、谁能成团）；规则执行后回写底层轴和压力值；状态变化又改变下一次规则的触发条件。玩家的每一次操作，只是在这个闭环中拨动一个节点的数值，然后整个系统自己重新洗牌。

# 第五章 底层态度

## 5.4 透明度（Opacity，O[i]）

- 定义：i 的真实立场被他人准确感知的程度。
- 高透明度（80+）：态度一目了然，是班级的信息源。
- 低透明度（<20）：别人看不透他的真实想法，只能靠猜、靠八卦。
- 玩法意义：直接控制 UI 中态度线的呈现（实线/虚线/消失），是信息可见性系统的第一层过滤。

## 5.5 性格底色（MBTI 四维度）

不使用刻板的16型分类，而是将MBTI四个维度做成0-100的连续数值，每个维度直接修正游戏中的行为系数。24个角色即使MBTI类型相同，程度不同，行为也不一样。

| **维度** | **0端** | **100端** | **影响的规则** |
| --- | --- | --- | --- |
| E/I 外向度 | 极度内向 | 极度外向 | 搭话概率、相邻时的压力敏感度、独处压力恢复速度 |
| S/N 直觉度 | 极度实感（记细节） | 极度直觉（爱脑补） | 流言准确度（S型传得准，N型易传歪）、闲聊话题兴趣 |
| T/F 情感度 | 极度思考（逻辑导向） | 极度情感（共情导向） | 调侃敏感度、安慰效果、道歉接受度 |
| J/P 感知度 | 极度判断（守秩序） | 极度感知（随性） | 小团体归属倾向、被拉拢概率、举报倾向 |

**性格层铁律**：性格只有数值，没有行为；一切角色差异必须能写成这四个维度 + 透明度的纯函数。

# 第六章 统一数值计算公式

## 6.1 好感/敌对/信任的统一公式

所有事件对好感、敌对、信任的影响，全部使用同一个公式：

**Δvalue = base × clamp(1 + Σ(wᵢ × dᵢ), 0.1, 1.2)**

| **符号** | **含义** | **范围** |
| --- | --- | --- |
| base | 事件对该数值的基础变化量（正=增，负=减），策划填表 | 任意整数 |
| dᵢ | MBTI第i维偏差值 = (维度值−50)/50 | [−1, +1]，50为中性 |
| wᵢ | 该事件类型对第i维的敏感度权重，策划填表 | 通常[−1, +1] |
| clamp | 倍率区间 **0.1 ~ 1.2**（性格影响温和：最多放大 20%） | [0.1, 1.2] |

四个维度固定顺序：d₁=E/I, d₂=S/N, d₃=T/F, d₄=J/P。

## 6.2 透明度：种子为准 + 压力系数

透明度不是事件直接加减：

**当前透明度 = 基础透明度 × 压力系数**

- **基础透明度 = 角色种子值（opacity_init）**，见 §11.4 角色池（如苏晴 15、何川 20）；角色差异只来自开局种子。
- MBTI 公式 clamp(50 + d_E × 30 + d_J × 15, 0, 100) 仅作策划新增角色时的默认值生成器，不进运行时。

压力系数：压力0-40→1.0；40-70→0.6；70-90→0.3；90+→按性格，好斗/敏感型爆发=0（封闭），随和/外向型崩溃=1.5（崩溃时什么都说）

|  | 信任 | -5 | 0 | 0 | +0.3 | +0.2 |
|  | 敌对 | +4 | 0 | 0 | +0.2 | 0 |
| 话题共鸣 | 信任 | +3 | 0 | +0.3 | +0.2 | 0 |
|  | 好感 | +3 | +0.2 | +0.2 | 0 | 0 |
|  | 压力 | -2 | +0.3 | 0 | +0.2 | 0 |

**重大事件的附加状态**（不用大 `base`，靠持续影响与阈值相变表达）：

| 事件 | 附加状态 | 效果 |
| --- | --- | --- |
| 被举报 | 「委屈」3 天 | 每天初始压力 +3 |
| 秘密被泄露 | 「心结」3 天 | 每天初始压力 +5 |

> **关系调制**：上表所有「与特定对象互动」的事件（话题共鸣、被当众调侃、安慰他人…）的 `base` 需乘以 `M(i, s) = clamp((A[i][s] − H[i][s])/50, −1, +1)`——按**净态度**调制：态度不明显时只削弱，**敌对明显压过好感时反转**（同一场聊天可能一方加、一方减）。所有增量写入前**四舍五入到 0.1**。详见 [`../design/统一影响公式.md`](../design/统一影响公式.md) §2.1。

# 第七章 影响力传导机制（非线性版）

## 7.1 核心原理

好感的方向就是权力的方向：A[i][j] 高，意味着 i 愿意听 j 的话。但传导不是线性求和——**弱态度不扩散，多方拉扯要竞争，传导量有上限**：

1. **阈值（传不传）**：j 对 k 的态度低于阈值时不传导。
2. **竞争归一化（听谁的）**：i 同时被多个 j 拉扯时，按 i 对各 j 的听从度加权平均，而不是简单求和。
3. **软饱和（传多少）**：传导量经过软饱和 `sat(u) = u / (1 + |u|/U_X)` 压缩，高值收敛于 `U_X`（见 §6.1）。线性传导会让全班态度收敛到同一个均值，抹平分化；饱和让系统存在多个吸引子，派系可以稳定共存。
4. **负反馈（越满越难涨）**：**统一写入点的正向轴**（好感 / 信任）在写入前乘 `(1 − feedback·X[i][k]/100)`；**负面轴（敌对 / 压力）不适用**——否则「敌意升级」会被压死。
   没有这一项时，好感是**正反馈**：`A` 越高传导越强 → 稳态 `A* = 每日增益 / (1 − 跨天保留率)` ≈ 192 → **30 天全班一起封顶**（实测饱和率 90.8%）。只把负反馈加在传导上**不够**（实测 30 天仍 32% 饱和）——因为事件增益不受它约束，且 `C` 会随越阈人数增长而抵消抑制；**必须作用到统一写入点**。实测（25 天，`feedback`=1.0、`β_A`=0.20、保留率 0.95）：**饱和率 0.0% / 均值 45.9 / SD 18.6**，且 `C` 大的对子稳态更高 → **保留差异化**而不是整体平移。

## 7.2 传导公式

**传导归入涓流类，每天结算 2 次**（`settle_interval` = 240 tick，上午 / 下午各一次；见 §6 三类结算与 §18.3）。对每个接收者 i 和第三方 k：

```
w_ij   = A[i][j] / 100                        // i 对 j 的听从度
A'[j][k] = max(0, 感知A(j,k) − θ_A)           // 【感知值】j 对 k 的超阈值好感
H'[j][k] = max(0, 感知H(j,k) − θ_H)           // 【感知值】j 对 k 的超阈值敌对
net_A = ( Σ_j w_ij·A'[j][k] − Σ_j w_ij·H'[j][k] ) / ( Σ_j w_ij + ε )
net_H = ( Σ_j w_ij·H'[j][k] − Σ_j w_ij·A'[j][k] ) / ( Σ_j w_ij + ε )
room_A = 1 − feedback · A[i][k] / 100        // 【负反馈】越接近饱和增益越小；负面轴不适用
Δ_A = round( room_A · sat( β_A · net_A, U_A ), 0.1 )   // 软饱和 + 精度 0.1，见 §6.1
Δ_H = round( sat( β_H · net_H, U_H ), 0.1 )            // 敌对轴不加负反馈
写入：A[i][k] += Δ_A（若 Δ_A > 0）；H[i][k] += Δ_H（若 Δ_H > 0）
      —— 两条轴各自独立累加，均钳制 0–100（好感不因负向传导而扣减）
```

> 与早期版本的区别：**饱和函数由 `tanh` 换成统一软饱和 `sat_X`**（全系统一个公式，见 §6.1），**结算频率由「每 tick」改为「每天 2 次」**——这是「传导归入涓流类」的直接后果；**新增负反馈 `room`**（见 §7.1 第 4 条），这是阻止 30 天全班饱和的关键项，**同样适用于 §6.1 的事件写入**（统一写入点）。

参数表（初始值，待批量局标定；**权威来源 `data/rules/transmission.csv`**）：

| **参数** | **含义** | **初始值** |
| --- | --- | --- |
| θ_A / θ_H | 好感 / 敌意传导阈值 | 30 / 40 |
| U_A / U_H | 软饱和尺度（见 §6.1） | 25 / 25 |
| β_A / β_H | 传导系数（**每天 2 次结算**） | 0.20 / 0.30（敌意更容易传染；已含负反馈的补偿） |
| `feedback` | **负反馈强度**（0–1） | 1.0 |
| `settle_interval` | 涓流结算间隔 | 240 tick（每天 2 次） |
| ε | 防除零 | 0.01 |

## 7.3 双通道

- **态度通道**：走 §7.2 公式，权重是好感（你模仿你喜欢的人的立场）。
- **事实通道**：不走本公式，走 **流言传播（消息传歪）** 的信任判定——≥70 全信、40–70 半信、<40 不信；这条判定本身带阈值，是非线性的。

## 7.4 传导输入：感知态度（正式条款）

公式中的 `A'[j][k]`、`H'[j][k]` **一律使用"i 感知到的 j 对 k 的态度"**（经透明度 + 信任两层过滤后的值），而不是后台真实值。

含义：**低透明度的人，他的真实态度不扩散，只有他"演出来"的那部分才扩散**——这是"藏得住的人真的藏得住"在机制上的保证。

> 实现细节见 [`../design/统一影响公式.md`](../design/统一影响公式.md) §2.2 与 [`../design/信念矩阵.md`](../design/信念矩阵.md) §11。
## 7.5 涌现现象验证

| **现象** | **新机制如何产生** |
| --- | --- |
| 派系领袖 | 多人对同一 j 的 w 高 → 加权平均中 j 的态度占主导 → 群体复制；软饱和防止无限放大 |
| 墙头草 | 两个阵营 P≈N → net 在 0 附近 → Δ 符号随权重微扰反复翻转 → 态度横跳 |
| 敌意沿链放大 | 每级传导都过软饱和，有上限的放大，不会指数爆炸 |
| 团内隐形等级 | 谁的 w 高谁就是实际话事人，从 A 矩阵直接读出，无需显式角色标签 |

# 第八章 情绪状态层

## 8.1 设计原则

情绪状态层只存压力值这一个累积变量。其他情绪（开心、焦虑、愤怒、低落）全部由压力值、近期事件效价、性格底色派生，不独立存储。

心理学依据：Russell情绪环形模型——所有情绪都可以落在唤醒度（高/低）x效价（正/负）两个维度上。压力值即唤醒度，近期事件的好坏决定效价，两者交叉定位出具体情绪。

## 8.2 压力值

| 属性 | 说明 |
| --- | --- |
| 数据结构 | Stress[i]，个体单值，0-100，快变量 |
| 定义 | 社交焦虑、窘迫、紧张的累积程度 |
| 特点 | 事件驱动不自然涨，达到阈值触发情绪事件 |

## 8.3 情绪标签派生表

| **压力** | **近期效价** | **外向/随和** | **敏感/内向** | **好斗** |
| --- | --- | --- | --- | --- |
| 低 | 正 | 放松、满足 | 安心、自在 | 得意 |
| 低 | 负 | 无聊、无所谓 | 低落、落寞 | 不耐烦 |
| 中 | 正 | 兴奋、活跃 | 羞涩但开心 | 亢奋 |
| 中 | 负 | 有点烦 | 焦虑、不安 | 愠怒 |
| 高 | 正 | 激动、热闹 | 紧张但强撑 | 亢奋到失控 |
| 高 | 负 | 烦躁 | 窘迫、快哭了 | 愤怒、要爆发 |

## 8.4 压力来源与消解

| **事件** | **压力变化** | **结算类型** | **性格修正** |
| --- | --- | --- | --- |
| 被当众拒绝/被打断聊天 | +3 | 事件 | 敏感 ×1.5，外向 ×0.7 |
| 被八卦谣言指向 | +3 | 事件 | 敏感 ×1.5 |
| 被小团体明确排斥（重大） | +5 | 事件 | 随和 ×1.3（更受伤） |
| 被多人同时搭话 | +2 | 事件 | 内向 ×2，外向 −1（人来疯） |
| 信任的人背叛/传秘密 | +5 | 事件 + 状态 | 全性格大幅上涨；附加「心结」3 天，每天 +5 |
| 和高好感+高信任的人聊天（话题共鸣） | −2 | **事件**（每次闲聊结算一次） | — |
| 默认学习（未参与任何互动） | **+1** | 涓流（**每天 2 次**，`behavior_probs.csv` 的 `study_stress`） | — |
| 独处（不在任何对话中） | **−2** | 涓流（**每天 2 次**，`alone_stress`） | 内向额外 −1（独处回血快） |
| 离开人群聚集区 | −3 | 事件 | — |
> **性格系数区间 = 0.1 ~ 1.2**：性格对效果的影响**温和**——最敏感者最多放大到 1.2 倍（+20%），最迟钝者降到 0.1 倍。因此文档中「敏感 ×1.5」「内向 ×2」之类的表述，一律理解为**通过该事件的 `w` 系数实现，且最终倍率落在 0.1~1.2 之间**（敏感者接近 1.2、普通人接近 0.6、迟钝者接近 0.15）。
> 例外：**概率类修正**（成功率 +25%、守密概率 −30%）与 **`M_state`**（压力区间系数）不是这个倍率，不受此限。


## 8.5 压力阈值与爆发

| **压力区间** | **行为修正** |
| --- | --- |
| 0-40 正常 | 无修正 |
| 40-70 紧绷 | 透明度降低（开始藏立场），对负面事件敏感度 ×1.5，对示好好感涨幅 **×0.75** |
| 70-90 临界 | 主动发起闲聊概率骤降，开始回避人群，移动速度变慢 |
| 90+ 爆发 | 按性格触发：敏感型→崩溃趴桌/跑出教室；好斗型→当众指责某人（敌对瞬间拉满）；随和型→沉默退缩，透明度归零 |

爆发是全班事件：爆发瞬间，周围人按性格分裂——高共情的同情（好感+、信任+），低共情的嫌弃（敌对+），八卦型立刻开始传播这件事。一次崩溃自己就长出一轮新阵营分化。

# 第九章 信息可见性系统

## 9.1 核心设计

玩家看到的不是真实数值，而是经过两层过滤的态度信息：

真实态度（后台矩阵）→ 第一层：透明度（这个人有多容易被看穿）→ 第二层：信任（你通过谁获取信息，信息有多可信）→ 你最终看到的信息

## 9.2 透明度控制UI呈现

| **透明度** | **玩家看到的效果** |
| --- | --- |
| 高（80+） | 态度线是实线，颜色清晰（暖=好感，冷=敌对），粗细准确反映强度 |
| 中（40-80） | 态度线是半透明虚线，颜色偏淡，能看出大概方向但不确定强度 |
| 低（20-40） | 态度线时隐时现，旁边带问号，只能猜大概站哪边 |
| 极低（<20） | 完全看不到态度线，这个人是个谜 |

## 9.3 信任值解锁信息

基础可见：所有NPC的态度线默认按透明度显示。

信任解锁：当你和NPC X的信任度过线，X会主动透露他对其他人的真实态度——你看X对别人的态度线时，清晰度强制提升一档。

二手情报：信任度更高时，X还会透露别人对第三方的态度，相当于你通过X解锁了B对C的真实态度线。

信息可信度：X告诉你的信息，准确度 = X的透明度 x 你对X的信任。如果X本身透明度低或者你不信任他，他给的情报可能是错的。

## 9.4 信息可以是错的

透明度低的NPC，态度线可能是假的——他假装对C友好（显示暖色线），实际敌对（后台是冷色）。

信任度低的NPC给你的情报，可能是传歪的八卦。同一个人的态度，你从不同渠道获取的信息可能互相矛盾，需要交叉验证。

这把游戏从观察模拟器变成了信息博弈：你看到的班级格局，取决于你和谁信任度高、谁愿意跟你说实话。不同玩家因为社交路径不同，看到的是完全不同的班级地图。

## 9.5 推理板与矛盾高亮

- **推理板**：玩家构建"班级真相"的工作台，记录玩家对每个 NPC 立场、每个阵营归属、每次事件的解释。
- **矛盾高亮（硬功能）**：任何来源的信息与既有记录冲突时，推理板自动高亮。矛盾来源包括：
1. 某人的态度线与他本人在敏感话题（八卦、评价他人）中的发言冲突；
2. 二手情报与他人的传话内容冲突；
3. 情报与标签层事实（如违规标签）冲突。
- **闭环要求**：假信息必须留下可验证破绽，玩家可以通过交叉验证逼近真相；没有破绽的假信息 = 纯噪声，禁止出现。

## 9.6 标签的可见性

**默认状态：所有标签对玩家不可见。** 玩家通过三条路径获知某人的标签：

| 路径 | 条件 | 能知道什么 |
|---|---|---|
| **① 观察**（靠透明度） | 目标 `O[j]` 达档 | 通透（80+）：全部标签；可见（50–79）：仅「行为标签」；模糊（20–49）与封闭（<20）：均不可见 |
| **② 被告知**（靠信任 + 好感） | `T[j][玩家] ≥ 70` **且** `A[j][玩家] ≥ 50` | 目标**主动告知**自己的标签（愿意让你知道，也认为你值得知道） |
| **③ 推断**（靠行为痕迹） | 反复观察到对应行为 | 推理板解锁该标签（附证据条目） |

关键约束：

- **标签必然留下行为痕迹**：带手机的人课间真的会掏手机，谈恋爱的人会频繁与特定对象互动。否则玩家除了等别人开口别无办法——这违反「假信息必须留下可验证破绽」（§9.5）。
- **三类标签的可见难度不同**：`行为标签`（带手机 / 爱聊天 / 爱学习）最容易被观察到；`关系类`（小情侣）需长期观察或被告知；`秘密类`（泄密者 / 嘴严）几乎只能靠被告知或推断。
- **观察不等于确认**：路径 ① 与 ③ 得到的标签仍需玩家在推理板上自行认定，**可能与真相不符**（见 §9.4）。

# 第十章 人物行为设计

> **行为触发方式总则**（详细算法见 [`../design/NPC行为决策.md`](../design/NPC行为决策.md)）：
>
> | 触发方式 | 判据 | 行为 |
> |---|---|---|
> | **环境类** | 固定基础概率 × 修正系数 | 闲聊、传纸条、走动、窃听、睡觉 |
> | **阈值类** | 确定性（条件满足即发生） | 举报、压力爆发（≥90） |
> | **意向类** | 门槛 → 意向评分 → softmax 采样 | 搭话、调侃、安慰、求助、道歉、秘密交换 |
>
> 三类都必须走统一影响公式结算（§6）；**意向类**中"对方的反应预期"一律取信念矩阵 `B`，自己的立场取真值。
>
> **所有事件的触发条件都是「好感 / 敌对 / 信任 / 透明度 / 压力」的函数**——不存在按天数、轮次或固定剧本触发的「第 N 天必然发生 X」。新增行为时必须给出可判定的数值条件。

## 10.1 流言（附加行为）

1. 触发条件：（1）当A通过对B的流言判定（与好感度和敌对值有关），将对B的流言存入A的记忆，流言倾向根据A对B的好感度或者敌对值生成；（2）举报产生
2. 流言倾向：从-2到2由完全负面到完全正面，0为中立流言，流言倾向只为整数，且无法超出该范围
3. 传播条件：当A记忆中含有流言且A不为流言对象
4. 传播结果：当针对B的流言存入A的记忆，根据流言倾向数值增加A对B的好感值或敌对值（流言倾向大于0，则A对B的好感值加上流言倾向的绝对值；流言倾向小于0，则A对B的敌对值加上流言倾向的绝对值；为0则不改变）
5. 传播偏移：流言具有流言倾向（从-2到2由完全负面到完全正面，0为中立流言），如果传播者对传播对象(好感值-敌对值>0)则流言倾向加一；为0则不变；<0则流言倾向减一
6. 传播方式：（1）闲聊（2）窃听（3）纸条（4）告密
7. 传播限制：（1）单次闲聊只能够传播一条流言，但可以A传播给B的同时B也传给A（2）每条流言都有序号，如果某一条流言已记入过A的记忆则不能记入第二次
8. 流言传播顺序：（1）A接收流言（2）A对流言对象的好感值或敌对值发生改变（3）A对该流言的流言倾向进行更改（4）传播流言并删除记忆/流言自动遗忘
9. 流言消失：（1）一旦通过任何方式传递出去流言会从记忆里清除；（2）流言最多在一个人记忆中停留三个课间，若三个课间流言仍未传播则流言自动清除

## 10.2 举报（主行为）

1. 触发条件：（1）当 A 对 B 的敌对值累积到达阈值，触发举报效果；（2）或特殊行为触发
2. 行为结果：（1）本节课间举报者消失不出现在教室内，与走动到室外相同；（2）举报会大幅提升被举报者的压力值，概率生成针对 A 或 B 的流言（要么直接将一条对A的流言倾向为-2的流言存入B的记忆；要么直接将一条对B的流言倾向为-2的流言存入A的记忆）；（3）举报后A对B的敌对值会下降

## 10.3 告密（主行为）

1. 触发条件：当A记忆中含有对B的流言，且A通过对B的告密判定
2. 行为结果：（1）在本课间B不会移动,A会在课间走向B的位置并对B进行告密（与闲聊纸条不同，是独立的主行为），告密无法被窃听；（2）A与B对互相的好感度增加，根据流言倾向增加A与B对班级其余人的好感值或敌对值（流言倾向大于0则增加好感值，小于0则增加敌对值）；（3）B在被告密后把流言存入记忆并在课间结束后立刻删除

## 10.4 走动（附加行为）

1. 触发条件：下课瞬间立刻执行位置更新
2. 行为结果：角色有概率变更位置

## 10.5 闲聊（主行为）

1. 触发条件：A、B 双方互相处于对方闲聊范围内时，概率触发闲聊
2. 行为结果：（1）闲聊发生后闲聊成员各自判定增加好感度或者敌对值；（2）减小闲聊成员的压力值
3. 闲聊内容可被范围内未处于闲聊状态的同学窃听
4. 闲聊成员中如有成员记忆中含有流言，且流言对象不是剩余的闲聊成员，可进行传播（每一个闲聊成员在本次闲聊中只能传播一次流言）

## 10.6 传纸条（主行为）

1. 触发条件：触发闲聊行为后进行传纸条判定，通过判定闲聊则改为传纸条；否则仍然是闲聊
2. 行为结果：与闲聊一致，但无法被窃听与搭话

## 10.7 搭话（主行为）

1. 触发条件：当A未发生闲聊且闲聊范围内已有人发生闲聊，概率发生搭话判定，通过则加入闲聊；否则A对闲聊二人敌对值增加
2. 行为结果：与闲聊一致

## 10.8 睡觉（主行为）

1. 触发条件：概率触发睡觉判定，通过判定则进行睡眠
2. 行为结果：本次课间无法进行其他任何活动，课间结束压力减少
3. **排除条款**：睡觉中的角色**不参与任何交互**（闲聊 / 搭话 / 共同学习 / 被调侃 / 被安慰 / 被求助…），也**不作为相邻类判定的对象**——坐在睡着的人旁边不产生「共同学习」。唯一的数值变化是课间结束时的压力减少。
4. **策略含义**：睡觉是用「社交机会」换「压力缓解」——你会错过本课间全部互动与观测。

## 10.9 窃听（附加行为）

1. 触发条件：当人物没有进行任何主行为时
2. 行为：捕获自身一定范围内所有人的闲聊内容
3. 行为结果：（1）将闲聊中的流言存入记忆；（2）若窃听者为流言对象本人，则会根据流言倾向改变数值（若流言倾向大于0则压力减小，对闲聊双方的好感值上升；若流言倾向小于0则压力增大，对闲聊双方的敌对值上升；（3）若窃听者为流言对象本人，在窃听后把流言存入记忆并在课间结束后立刻删除

## 10.10 求助（主行为）

1. 触发条件：对目标好感 ≥30（内向型需 ≥50）
2. 发起成本：发起者压力 +2
3. 行为结果：
   - **被拒绝**：发起者压力 +3、对目标敌对 +3、信任 −3
   - **成功**：被求助者对你好感 +2、信任 +3；发起者压力 −2、好感 +3；被求助者进入「被亏欠」状态（3 天内你向他求助成功率 +25%）
4. 性格修正：内向门槛抬高到好感 ≥50、被拒压力 ×1.5；外向门槛降到 20；好斗被拒后敌对 ×2

## 10.11 道歉 / 和解（主行为）

1. 触发条件：双方敌对 ≥30，一方主动发起
2. 发起成本：发起者压力 +3，透明度临时 +10
3. 接受概率 = 对方对你的好感 + 对方随和系数 − 敌对值 ×0.5
4. 行为结果：
   - **接受**：敌对 −5、好感 +3、信任 +2、双方压力 −3
   - **拒绝**：敌对 +2、发起者压力 +4、信任 −3
5. 性格修正：高 F（随和）接受概率 +30%；高 T / 好斗 −25%；敏感型被拒后压力 ×1.5，可能触发爆发

## 10.12 当众调侃（主行为）

1. 触发条件：周围 ≥3 人围观，且发起者对目标好感 ≥40
2. 成本：目标压力 +3，发起者压力 +1
3. 成功概率 = 目标对发起者好感 ×0.5 + 目标外向系数 − 目标敏感系数
4. 行为结果：
   - **成功（玩笑接住了）**：双方好感 +3，围观者对发起者好感 +2，目标压力 −2
   - **失败（玩笑过火）**：目标敌对 +4、压力 +4；围观者按性格分裂——外向 / 八卦好感 +2，随和 / 敏感好感 −2
5. 性格修正：外向成功率 +20%、被调侃压力 ×0.5；敏感被调侃压力 ×1.5、敌对 ×1.5；八卦型失败后把这件事当流言传播（→ 10.1）

## 10.13 安慰（主行为）

1. 触发条件：目标压力 ≥70，且发起者对目标好感 ≥50（内向型需 ≥70）
2. 发起成本：发起者压力 +2
3. 行为结果：目标压力 −5、对你好感 +4、信任 +5
4. 目标正在爆发（压力 ≥90）：效果 ×1.5，但需通过共情判定（成功率 = 随和系数 + 敏感系数 − 好斗系数）
5. 性格修正：高 F + 高敏感（高共情）效果 ×1.5、成功率 +25%；好斗效果 ×0.5、成功率 −20%

## 10.14 秘密交换（主行为）

1. 触发条件：双方信任 ≥60，一方主动发起
2. 行为结果：
   - 发起者把一条秘密告诉对方，对方进入「守密」状态
   - **对方泄密**：发起者对其信任 −5、敌对 +4、压力 +5；泄密者获得「泄密者」标签（3 天）
   - **对方守密超过 5 tick**：双方进入「秘密同盟」——每个涓流结算点（每天 2 次）双方信任 +1（涓流类）
3. 性格修正：高 N（爱脑补 / 爱八卦）守密概率 −30%；内向 / 随和 +20%；好斗被背叛后敌对涨幅 ×1.5

> 以上五个社交行为依据 v3.0 规格回填，并按全局数值铁律（常规 `base ∈ [1,3]`、重大 `[4,5]`、结算类型见 [`../design/统一影响公式.md`](../design/统一影响公式.md) §2.5）改写；它们补齐了 §6.3 事件权重表中「被当众调侃」「安慰他人」等事件的行为来源。

## 10.15 注释：

1. 走到室外的同学不参与任何本次课间的活动
2. 编写的行为顺序也是行为的优先级顺序
3. 所有主行为（包括默认学习）和附加行为在课间前完成决定，课间开始直接执行
4. 闲聊可以减少压力值，若人物没有任何主行为且课间没有发生走动，默认在原位置学习，会增加压力
5. **相邻不直接改数值**：物理相邻只把自发互动（闲聊 / 搭话）的触发概率 ×1.5；数值变化一律来自有内容的事件——包括「共同学习」（相邻且双方都在学习，见 §3.3）。

## 10.16 行为的分类与判定来源

> 本节回答一个架构问题：**每个行为的"加减"到底由什么决定？** 结论先行——
> **方向用阈值判、强度用连续量调制**；不要用"净态度 `M` 的符号"判方向（见下方反例）。
> 本表是行为实现的分类依据，也是新增行为时的"归类检查表"。

### 五类行为

| 类别 | 定义 | 读什么 | 典型行为 | 在涌现中的角色 |
| --- | --- | --- | --- | --- |
| **A 纯增益型** | 只往正向轴加，不看好坏 | 无（仅轻量性格修正） | 闲聊（话题共鸣）、共同学习、安慰（对目标轴） | 提供**关系基本盘**的持续涨落 |
| **B 纯损害型** | 只往负向轴加，不看关系 | 无 | 流言（负面染色）、举报、被拒绝的反噬 | 提供**破坏与压力**的来源 |
| **C 信念驱动型** | 读**信念矩阵**决定结果 | `B_A` `B_H` `B_T`（i 眼中对方对 i 的态度） | 搭话（判对方是否接纳）、求助（判对方是否愿帮） | 提供**误判与戏剧性**（以为自己被喜欢） |
| **D 信任 / 透明度驱动型** | 读 `T` / `O` 决定**成败与可见性** | `T[i][j]`、`O[j]` | 秘密交换（`T ≥ 60`）、告密（`O` 决定是否被听到）、窃听（`O` 决定能听到什么） | 提供**信息博弈** |
| **E 混合判定型** | 读**多轴 + 阈值分档**，**结果方向可变** | `A` + `H`（+性格） | **当众调侃**（玩笑 / 尴尬 / 嘲讽三档）、道歉和解（`H ≥ 30` 后修复） | 提供**同一行为在不同关系下的分岔**——戏剧性最强 |

### 判定规则：方向用阈值，强度用连续量

以**当众调侃**（E 类）为例：

| 档位 | 判据（`behavior_thresholds.csv`） | 结果 |
| --- | --- | --- |
| **玩笑** | `A ≥ 55` **且** `H < 25` | 双方好感↑、被逗笑减压 |
| **尴尬** | 其余 | 不结算（效果自然为 0） |
| **嘲讽** | `H ≥ 40` **或** `A < 25` | 目标压力↑、对发起者敌对↑、围观者按性格分裂 |

强度（不只是方向）仍由连续量 `M(i,s) = clamp((A−H)/50, −1, +1)` 调制——**两者分工明确**：

```
方向 = 阈值分档（离散、可配、可解释）
强度 = |M| 调制（连续、自动、无需特例）
```

### ⚠️ 反例：为什么不能用 `M` 的符号判方向

一个诱人的想法是"调侃是玩笑还是嘲讽，看 `M` 的正负即可"。**实测否决了这个方案**：

```
M = (A − H)/50  → 零点在 A = H
但本作里 A 的基线是 25~40，H 的基线只有 0~15
∴ 开局 M ≈ (25−8)/50 = 0.34 > 0  →  永远判为「玩笑」
  → 好感↑ → M↑ → 更是玩笑（正反馈）
∴ 30 天实测：好感均值 89.4、标准差 1.5（全班趋同）、爆发 0
```

**根因**：`M` 的零点（`A = H`）与游戏的**关系基线**不重合，`M` 恒偏正。因此：

- **`M` 适合做强度**（连续调制，零点偏正只是"整体略偏正向"，无害）；
- **`M` 不适合做方向**（方向需要的是"相对于基线在哪一侧"，那必须用**绝对阈值**）。

改用阈值分档后，同一个 30 天实测变为：好感均值 79.8、标准差 10.6——**改善但未达标**，
因为还有一个更根本的缺口：**B 类（纯损害型）行为几乎空白**，关系缺少"变差"的常规通道（详见 §10.17）。

### 新增行为时的归类检查

1. 它读哪些轴？（无 / 信念 / 信任·透明度 / 多轴）→ 决定它属于 A–E 哪一类；
2. 它的**结果方向**是否可变？若是，方向判据必须写成 `behavior_thresholds.csv` 里的**绝对阈值**，不得用 `M` 的符号；
3. 它的**数值**是否全部来自 `data/`？（铁律：脚本内不得出现魔法数字）
4. 它是否引入角色 ID / 名字判断？（违反 §11.1 即为缺陷）

## 10.17 关系缺少"变差"通道（待补）

实测发现：所有行为对**好感**的作用都是"正或零"，导致好感**单向棘轮**——只能涨、不能跌，
标准差随天数收敛（30 天 sd 10.6），双方分化被抹平。

具体两处原因：

1. **B 类行为空白**：没有"冷落""排挤""当面拒绝"等**只损害好感**的常规行为（§8.4 已列出"被小团体明确排斥 +5"，
   但对应行为尚未实现）；
2. **搭话判定卡在边界**（实现缺陷）：`do_join_chat` 用 `B_A[i][j] >= 40` 判定对方是否接纳，
   而**信念先验恰好等于 40**（`belief.csv` 的 `prior_a`）→ 开局永远通过 → 唯一的"好感扣减"路径
   （`reject_affinity`）从不触发。判据应改为**严格大于先验**，或直接用 `信念 + 压力 + 性格` 组合判定。

# 第十二章 玩家操作映射

## 12.1 总原则（玩家不是特权者）

玩家与 NPC **共用同一套行为与同一套判定**：玩家能做的，NPC 都能做；NPC 的判定流程（门槛 → 意向 → 采样 → 效果）对玩家同样生效。差异只有两处：

| | NPC | 玩家 |
|---|---|---|
| 决策来源 | 决策算法（见 [`../design/NPC行为决策.md`](../design/NPC行为决策.md)） | 人的主动选择 |
| 独有能力 | 无 | 仅 3 项（见 §12.3） |

## 12.2 玩家可用行为（与 NPC 完全相同）

| 行为 | 依据 | 行为 | 依据 |
|---|---|---|---|
| 走动 / 换座位 | §10.4 | 睡觉 | §10.8 |
| 闲聊 | §10.5 | 学习（默认） | §10.15 |
| 搭话 | §10.7 | 求助 | §10.10 |
| 传纸条 | §10.6 | 道歉 / 和解 | §10.11 |
| 举报 | §10.2 | 当众调侃 | §10.12 |
| 告密 | §10.3 | 安慰 | §10.13 |
| 窃听 | §10.9 | 秘密交换 | §10.14 |

**时间成本**：每个行为都消耗 tick（一个课间段共 100 tick = 100 秒实时）。走动要花时间、互动要花时间——**课间只有 10 分钟，做不了太多事**。这就是玩家侧天然的操作预算，不需要额外的"每段最多 N 次"限制。

## 12.3 玩家独有能力（仅 3 项）

| 能力 | 说明 |
|---|---|
| **打听** | 消耗一次课间动作，向某人打听另一人的事；透露度 = 他对你的信任（§9.3） |
| **推理板** | 记录与标注、查看矛盾高亮（§9.5）——玩家独有的「显式信念」工作台 |
| **情报日志** | 上课段查看已获得的观测与事件（只读） |

## 12.4 玩家不能做的事

- 直接读写任何数值（好感 / 敌对 / 信任 / 透明度 / 压力）；
- 看到未经 §9 两层过滤（透明度 + 信任）的原始数据；
- 在非课间段操作（上课段只能查看情报日志与推理板）。

## 12.5 一切由数值驱动

玩家的每次操作只是在关系矩阵中拨动一个数值；**其后的一切（谁来找你、谁翻脸、谁抱团、谁崩溃）都由数值条件自动触发**，不存在为玩家预设的剧情分支。
# 第十三章 社会事件

社会事件 = **多阶段、跨相位、全体参与、结果改变结构**的班级级过程。

> ⚠️ 它**不是剧本**：触发、过程、结果全部由数值决定（见 §10 总则「一切由数值驱动」）。任何"第 N 天举行 X"的写法都视为错误实现。

## 13.1 层级位置

```
行为层       逐 tick、15 个行为、个体决策（§10）
社会事件层    多阶段、跨相位、全体参与、结果改变结构      ← 本章
结算层       跨天衰减、座位重排、简报（§3.5、§14）
```

## 13.2 通用规范

| 项 | 规范 |
|---|---|
| **触发** | 由数值条件满足触发，**不看日期** |
| **阶段** | 每个事件由 N 个阶段组成，每阶段绑定一个相位（课间 / 上课 / 放学） |
| **过程** | 每阶段内部仍走既有机制（流言、意向评分、阈值判定），**不写死台词或结果** |
| **结束** | 产出结构变化（身份 / 标签 / 关系），并归档进日志供简报引用 |
| **玩家** | 各阶段参与方式不同，且**不能操纵结果** |
| **并发** | 同一时间至多一个社会事件在进行中 |

## 13.3 数值档位

社会事件的直接数值影响使用**重大档**（`base ∈ [4,5]`，见 §6.3），并可附加状态标签（如「落选」3 天）。

## 13.4 班委选举

### 触发条件（任一满足，全部为数值判据）

1. **权威崩解**：现任班长（身份层持有「班委」标签者）曾压力爆发（≥90），且其影响力 `influence` 跌至班级中位数以下；
2. **阵营分裂**：班级存在 ≥2 个稳定簇（簇标签），且两簇之间的平均敌对 ≥ 阈值；
3. **玩家提议**：玩家消耗一次课间动作提议改选，并满足支持门槛（≥N 人对玩家好感 ≥ 阈值）。

> `influence(c)` = 有多少人愿意听 `c` 的话，可由矩阵直接读出：`Σ_j max(0, A[j][c] − θ)` 归一化。

### 五个阶段

| 阶段 | 相位 | 机制 | 玩家可参与 |
|---|---|---|---|
| ① 酝酿 | 课间 | 「改选」作为一条**流言**进入系统（§10.1：带倾向、会染色、会被窃听） | 打探 / 表态 / 传话 |
| ② 提名 | 课间 | 候选人 = 各强连接簇的**话事人**（簇内 `influence` 最高者）；玩家可自荐（需支持门槛） | 自荐 / 支持他人 |
| ③ 模拟投票 | 课间 | 非正式试探：通过闲聊 / 打听探口风 → 影响各方**信念** | 拉票 / 试探 / 虚张声势 |
| ④ 实际投票 | **上课** | 正式投票，玩家**不可操作**（上课是发酵层） | 只能看情报日志 |
| ⑤ 结果公布 | 放学 | 计票 → 新身份 + 簇标签重算 + 简报条目 | 看《每日简报》 |

> ③ 与 ④ 的相位安排（模拟投票下课、实际投票上课）是刻意的：**结果在你无法干预时产生**。

### 投票算法

```
选民 i 对候选人 c 的投票倾向：
  U_vote(i, c) = α_A · A[i][c] + α_T · T[i][c] + α_I · influence(c)
  倾向转概率：softmax(U_vote / τ)，每人一票

开票：得票最高者当选；平票按 influence 破平
```

注意：**「我信任他」与「他说话管用」是两件事**——因此会出现"人缘好但没实权者落选"这类结果。

### 结果的结构影响

| 对象 | 影响 |
|---|---|
| 当选者 | 获得「班委」身份标签 → 影响后续（举报倾向、责任种子、被拉拢概率） |
| 落选者 | 压力 **+4~5**（重大档）+ 可能对当选者敌对上升 |
| 支持者 | 通过关系调制自然产生"阵营效应"（支持落选者的人对当选者好感下降） |
| 全班 | 簇标签重算 → 格局可能重新洗牌 |
| 玩家 | 参选并当选则获得身份，同时背上相应责任种子 |

## 13.5 同层可扩展的其他社会事件

| 事件 | 触发（数值） | 结构影响 |
|---|---|---|
| 班级冲突爆发 | 两个簇的敌对同时过阈值 | 全体站队 |
| 真相揭露 | 推理板矛盾累积到阈值 | 秘密 / 诬告公开 |
| 集体活动（春游 / 运动会） | 学期中段 + 班级压力中位数偏高 | 强制互动、关系重排 |

> 工程实现（状态机、阶段钩子、配置表、不变式）见 [`../design/社会事件.md`](../design/社会事件.md)。

# 第十四章 每日简报与学期格局报告

每天放学生成《每日简报》，第 30 天放学生成《学期格局报告》。每一句话都来自后台日志，不是预制文案。

- 【小团体】列出本局形成的所有簇及成因（如"A、B、C 凑成圈子，因为 C 被 D 排斥后倒向他们"）——数据来自簇标签器与日志。
- 【孤立】列出全程独自坐着没加入任何对话的人及原因。
- 【对立】列出阵营之间的紧张关系及导火索。
- 【大事件】列出压力爆发、举报、秘密泄露等重大事件及周围人的分裂反应。
- 【你的影响】明确指出玩家的哪个操作间接导致了什么格局变化。
- 【真相对照】玩家推理板中的结论与系统实际格局的对照——理解对了是洞察，错了是这一局独有的故事。

《每日简报》聚焦当天发生了什么；《学期格局报告》在每日简报基础上追加：

- 【学期演变】每个阵营、每段孤立、每对宿敌在 30 天内的兴衰时间线；
- 【学期真相对照】玩家 30 天推理结论与学期最终格局的总对照。

简报的核心价值：玩家做了一些操作，然后看到系统自己长出了他没预料到的格局，并且报告告诉他为什么会这样。这就是"看见涌现"。

# 第十五章 可视化方案

> 迁入自 v3.0 §14。可视化是"让涌现被看见"的手段——**它只呈现，不参与计算**（观察层只读，见 §4）。

## 15.1 三层实时可视化

1. **空间聚散**：小人在教室的物理位置就是涌现的第一画面。好感高的不自觉靠近，敌对高的保持距离，小团体肉眼可见凑成圈（簇标签器描淡轮廓），被排斥的人移到边缘。
2. **情绪图标**：每个小人头顶极简表情图标（开心、平静、焦虑、愤怒、低落、兴奋），是唯一直接暴露情绪的窗口，**不暴露数值**。
3. **关系氛围线**：小人之间偶尔闪现极淡视觉线索——好友闪过柔和细线，敌对闪过小闪电。只在**质变瞬间**出现，不常驻。

## 15.2 上课过场

上课段以快进动画呈现：NPC 回到座位，座位相邻关系慢慢发酵，纸条偶尔传递，情绪图标在头顶缓慢变化，玩家可随时切到情报日志 / 推理板查看。

## 15.3 回放功能（进阶 · 第三版）

放学后可回看加速动画：看着一团乱的小人慢慢聚成几个圈子，看着某个人被慢慢边缘化，看着一次八卦如何在人群中扩散变形。**玩家亲眼看到秩序从混乱中自己浮上来。**

> 实现依赖：事件日志必须可重放 → 随机数必须来自可复现的种子化 RNG（见 §18.2 存档模型）。

# 第十八章 工程实现规范

> 本章是**程序实现的唯一依据**，汇总自 `docs/design/` 各篇。策划只需读 §1–§17；程序从本章入手。
> 对应的分篇文档仍保留（含更细的推导、手算例与待确认项），但**本章内容自包含**——两处冲突时以本章为准。

## 18.1 架构总览

本作是**数据驱动模拟**：内核每 tick 计算完成后再通知表现层，**表现层不参与数值计算**。

```
       ┌────────────── SimulationCore（无 UI 依赖，可无头运行）──────────────┐
       │  TimeSystem ──tick──► RuleScheduler ──► Behaviors(§10) ──► A/H/T / Stress │
       │        ▲                   │                                    │        │
       │        │                   └──► 涓流结算（传导 / 共同学习 / 独处，每天 2 次）│
       │   TermState（天 / 段 / 相位）              │                              │
       │                                          └──► ObserverLayer（簇标签 / 孤立，只读）│
       └──────────────────────────────────────────┼───────────────────────────────┘
                                                  ▼
              EventBus（信号）──► Presentation（场景、可视化、推理板、简报、存档）
```

**硬性边界**：`scripts/core/`、`scripts/systems/`、`scripts/npc/` 不得 `preload` 任何 `scenes/`；**模拟内核必须能在无渲染环境下跑完一局**（批量标定与单测依赖这一点）。

| 层 | 目录 | 职责 | 禁止 |
|---|---|---|---|
| 模拟内核 | `scripts/core/` | 时间推进、矩阵与压力状态、结算 | 依赖节点树 / UI |
| 规则层 | `scripts/systems/` | 行为触发与效果、影响力传导（§10） | 角色名 / ID 判断 |
| 观察层 | `scripts/systems/observer/` | 簇标签、孤立标签 | 回写任何数值 |
| 决策层 | `scripts/npc/` | NPC 的**规则选择**（用哪条、选谁） | 绕过规则直接改数值 |
| 表现层 | `scenes/`、`scripts/ui/`、`scripts/game/` | 渲染、输入、动画、推理板、简报 | 直接改矩阵（只能走内核 API） |
| 全局单例 | `autoload/` | 状态持有、事件总线、存档、配置读取 | 承载玩法规则 |

**目录约定**：`scenes/` 与 `scripts/` 同构（`ui/` `game/` `core/` `npc/` `systems/`）；全局单例在 `autoload/` 并注册 `project.godot`；配置与数值表在 `data/`（代码只读）；离线脚本在 `tools/`。

## 18.2 数据模型

**运行时状态**（一局的全部可变数据，索引 `0 … N-2` 为 NPC，`N-1` 固定为玩家）：

```gdscript
class Relations:                      # 关系矩阵：N×N 有向，0–100
    var affinity: PackedFloat32Array   # A[i][j] = i 对 j 的好感
    var hostility: PackedFloat32Array  # H[i][j] = i 对 j 的敌对（与 A 独立，不是负数）
    var trust: PackedFloat32Array      # T[i][j] = i 对 j 的信任

class ActorState:                     # 个体属性（长度 N）
    var opacity: PackedFloat32Array    # O[i] 透明度
    var stress: PackedFloat32Array     # S[i] 压力（唯一累积情绪变量）
    var mbti: PackedFloat32Array       # 4×N：E/N/F/P 各维度 0–100 连续值

class Belief:                         # 信念矩阵：三份 N×N（§18.5）
    var b_affinity: PackedFloat32Array # B_A[j] = i 猜测「j 对 i 的好感」
    var b_hostility: PackedFloat32Array
    var b_trust: PackedFloat32Array
```

- **有向存储**：`A[i][j] ≠ A[j][i]`，读写一律用"谁对谁"的语义；**建议提供 `a(i, j)` 访问器而非裸下标**，避免矩阵转置错误。
- **钳制统一在写入点**处理（§6.1 的 `clamp`）。
- N 由难度决定：简单抽 8（N=9）、标准抽 16（N=17）、困难全池 24（N=25）；**同种子同阵容**，绑定组（小情侣等）整组同抽。

**静态配置**（`data/`，只读）：

| 文件 | 内容 | 规格来源 |
|---|---|---|
| `characters/seeds.csv` | 24 人全量池：`id` `alias` `mbti` `identity` `tags` `e` `n` `f` `p` `opacity_init` | §11.4 |
| `rules/transmission.csv` | `theta_a/h/t`、`beta_a/h/t/o`、`u_a/h/t/o/s`、`settle_interval`、`epsilon` | §7.2、§18.4 |

## 18.3 规则引擎

**主循环**：

```
一局 = 30 天 × 每天 480 tick（课间 3×100 + 上课 2×90）
for day in 1..30:
    for phase in [上午课间, 上午上课, 中午午休, 下午上课, 下午课间]:
        for t in 1..phase.tick_count:
            run_rules(phase.active_rule_set)      # §3.3：上课只跑规则子集
            if global_tick % settle_interval == 0:  # 涓流：传导 / 共同学习 / 独处，一天 2 次
                apply_transmission(); apply_study_together(); apply_stress_drip()
            observer.update()                        # 簇标签器，只读
            emit(log_event)                          # 简报与推理解释的唯一数据源
    settle_day()                                     # §3.5 跨天结算 + 生成《每日简报》
```

**相位与规则启用**（§3.3）：

| 相位 | 启用规则 |
|---|---|
| 课间段 | 全部人物行为 + 玩家操作（§10） |
| 上课段 | 共同学习（相邻且双方都在学习）、流言传播（低频）、压力涓流；**搭话禁用** |
| 放学结算 | 不跑规则，执行跨天衰减与简报生成 |

> ⚠️ 涓流类（传导 / 共同学习 / 独处恢复）**不是每 tick 结算**，而是**每天 2 次**（`settle_interval` = 240 tick，上午 / 下午各一次）——结算判据必须基于**全程 tick 计数**，而不是相位内计数，否则会退化成"每相位一次"。

**规则实现约定**——每条规则实现为独立类，统一接口：

```gdscript
class Rule:
    func gather(ctx: SimContext) -> Array[CandidateAction]   # 谁能对谁发起
    func resolve(ctx: SimContext, action: CandidateAction) -> Array[Effect]  # 结果
    func apply_effects(ctx: SimContext, effects: Array[Effect]) -> void
```

- **决策与效果分离**：`gather` 处理触发条件（读 A/H/T/S/O/MBTI 与信念），`resolve` 处理结果判定（含概率），`apply_effects` 统一走 §6.1 增量公式并钳制。
- **行为选择（谁做什么）不在规则层定义** —— 它属于决策层（§18.6）。规则层只定义"行为发生后效果怎么算"。
- **数值外置**：所有增量、阈值、概率系数从 `data/rules/` 与 `data/balance/` 读取，脚本中不得出现魔法数字。

**同 tick 冲突消解**（拟定，M1 用批量局验证后固定）：

1. 优先级：危机类（举报、安慰）> 主动类（搭话、调侃、道歉、秘密交换）> 被动类（回应、话题共鸣）> 环境类（共同学习 / 相邻概率修正）；
2. 同级按角色索引升序，保证可复现；
3. 已被占用（处于对话中）的角色本 tick 不再接受新交互。

**传导实现要点**：阈值 + 竞争归一化照旧（§7.2），饱和用统一软饱和 `sat_X(u) = u / (1 + |u|/U_X)`；**传导计算必须基于本结算点开始时的矩阵快照**，否则同点内写入互相污染、结果不可复现。性能：N³ 三重循环（最大 25³）在 14,400 tick 下的开销需实测，必要时改为稀疏更新（仅处理 `A'|H' > 0` 的对子）。

## 18.4 统一影响公式（要点）

完整定义见 §6（公式）与 §7（传导），推导与手算例见 `docs/design/统一影响公式.md`。核心链条：

```
P = E + C                # 事件推动 + 传导推动
E = base × M_personality × M(i,s)     # 性格倍率 × 关系调制
Δ = round( sat_X(P), 0.1 )            # 软饱和后四舍五入到 0.1
X ← clamp(X + Δ, 0, 100)              # 统一写入点
```

- `sat_X(u) = u / (1 + |u|/U_X)`：小量近似直通，大量收敛于 `U_X`。
- `M_personality = clamp(1 + Σ w_t·d_t, 0.1, 1.2)`（`d_t = (维度−50)/50`）：**性格只能温和放大或削弱，不能翻倍**。
- `M(i,s) = clamp((A[i][s] − H[i][s]) / 50, −1, +1)`：按**净态度**调制；态度不明显时只削弱，**敌对压过好感时反转**（这就是"敌对反应"的来源，不是靠额外的惩罚规则）。
- **三类结算方式**：事件类（即时，每次交互最多一次）、涓流类（传导 / 共同学习 / 独处，每天 2 次）、状态类（压力与跨天衰减，按 §3.5）。
- **数值铁律**：常规事件 `base ∈ [1,3]`、重大事件 `base ∈ [4,5]`（判据 = 前置条件苛刻）；涓流类单次 1–5；**单次结算幅度 ≥ 0.1，小于 0.1 的增量在 `round` 后会被舍去**（这也是不引入小数堆叠的原因）。
- **事件去重**：同一对子、同一规则、**同一课间段内只结算一次**。

## 18.5 信念矩阵（要点）

完整定义见 `docs/design/信念矩阵.md`。核心：**决策读信念，判定读真值。**

- **三份矩阵** `B_A / B_H / B_T`，`B[i][j]` 的语义是"i 猜测 **j 对 i** 的态度"（与真值矩阵下标方向一致）。
- **观测三源**：直接互动、旁观他人互动、二手转述（流言）；玩家额外有"打听"（`ask_about`）。
- **更新规则**：`B ← B + η·(obs − B)`，其中
  - 学习率 `η = η0 · (0.3 + 0.7·T[i][j]/100)` —— **越信任对方，越相信自己的判断**；
  - 观测值 `obs = 真值 + 噪声`，噪声上限 `σ_max·(1 − O[j]/100)` —— **对方越透明，看得越准**；
  - `lambda_b` 每日把信念向先验缓慢回归（遗忘）。
- **读取规则**（最容易写错的地方）：**我自己的立场**（要不要做）读真值 `A[i][*]`、`T[i][*]`；**对方的反应预期**（他会不会接纳我）**必须读信念** `B_A[i][*]`、`B_T[i][*]` —— 读真值就等于开天眼。
- 误判是**特性而非缺陷**：它让"我以为他喜欢我"变成戏剧的来源（§9.4）。

## 18.6 NPC 行为决策（要点）

完整定义见 `docs/design/NPC行为决策.md`。**三段式**：门槛 → 意向评分 → softmax 采样。

**三类触发方式**：

| 类型 | 判据 | 行为 | 设计意图 |
|---|---|---|---|
| 环境类 | 固定基础概率 × 修正系数 | 闲聊、传纸条、走动、窃听、睡觉 | 不需要"想"——有条件就按概率发生 |
| 阈值类 | 确定性（条件满足即发生） | 举报、压力爆发 | 制造"积累到临界点突然发生"的相变手感 |
| 意向类 | 门槛 → 意向评分 → softmax | 搭话、当众调侃、安慰、求助、道歉、秘密交换 | 需要"选择"，因此受性格与信念影响 |

> **意向类还要按「判定来源」归类**（见 §10.16）：纯增益型 / 纯损害型 / **信念驱动型**（搭话读 `B_A`）/ **信任·透明度驱动型**（秘密交换读 `T`、告密读 `O`）/ **混合判定型**（当众调侃读 `A`+`H` 并用绝对阈值分档）。**方向用阈值、强度用 `|M|`** —— 不可用 `M` 的符号判方向（反例与实测见 §10.16）。

**意向类完整算法**：

```
① 门槛（硬条件，取自主文档 §10 的"触发条件"）
   搭话：A[i][j] ≥ 30 且 stress_i ≤ 80 且 j 不在对话中
   调侃：周围 ≥3 人 且 A[i][j] ≥ 40
   安慰：stress_j ≥ 70 且 A[i][j] ≥ 50
   求助：A[i][j] ≥ 30（内向型 ≥50）    道歉：H[i][j] ≥ 30（双向）    秘密交换：T[i][j] ≥ 60
   → 不通过的组合不进入候选集（概率恒为 0，不允许"小概率硬做"）

② 意向评分
   U_b(i) = Σ_X α_X(i) · Δ_X^pred(i, b)
   我自己的立场 → 真值；对方的反应预期 → 信念（§18.5）

③ 性格权重 α（Σα = 1）
   α_A      ∝ 0.5 + 0.5·F/100 + 0.3·E/100          情感型 / 外向型更在意好感
   α_T      ∝ 0.5 + 0.5·J/100                       判断型更在意信任
   α_H      ∝ 0.5 + 0.5·(1−F/100) + 0.3·(1−J/100)   思考型 / 随性型更在意敌对
   α_stress ∝ 0.5 + 0.5·(1−E/100)                   内向型更在意压力消解
   系数落在 data/balance/npc_weights.csv

④ 温度与采样
   p(b) ∝ exp( U_b / τ_i )
   τ_i = τ0 · (1 + 0.3·(1 − J_i/100)) · stress_modifier
   τ0 = 1.0 ｜ stress_modifier = 1.0（<70）/ 1.5（≥70，冲动）
```

τ 的物理含义：**τ → 0 退化成 argmax（刻板），τ → ∞ 退化成纯随机（噪声）**；1.0 附近是"有偏好但不死板"。

> **性能与可复现**：候选集上限 `top_n`（默认 5）；同一 tick 内的决策顺序必须确定性（按索引升序或固定种子洗牌），否则同种子不可复现。

## 18.7 工程不变式汇总（违反即为缺陷）

1. **禁止角色名 / ID 判断**：行为逻辑必须只依赖 `f(性格四维, 透明度, 状态)` 与信念；角色差异只能来自 `data/characters/` 的开局种子。
2. **观察层只读**：簇标签器与孤立标签**绝不回写**任何矩阵。
3. **决策读信念，判定读真值**：决策路径中不得出现 `A[j][i]`、`H[j][i]`、`T[j][i]`（"别人对我的态度"）。
4. **不引入脚本化剧情**：不得出现"第 N 天 / 第 N 段必然发生 X"。
5. **数值集中**：增量、阈值、系数一律来自 `data/`，脚本中不得出现魔法数字。
6. **可无头运行 + 可复现**：内核能在 `--headless` 下跑完整局；随机数一律来自种子化 RNG，同种子同结果。
7. **写入点唯一**：所有轴值变化都经 §6.1 的公式与 `clamp`，不得绕过。
8. **全部轴值域 0–100**；`null ≠ 0`（"不知道"不等于"中立"）。

| --- | --- | --- | --- |

| 流言 | 附加 | A 对 B 的流言判定通过（与好感、敌对相关），或由举报产生 | 将针对 B 的流言存入 A 的记忆；倾向 ∈ [−2, 2]；A 对 B 的好感或敌对按倾向变化；传播时按传播者态度产生偏移；每条流言最多在一个人记忆中停留 3 个课间 |
