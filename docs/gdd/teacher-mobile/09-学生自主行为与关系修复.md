# 第九章 学生自主行为与关系修复

## 9.1 自主选择

学生的默认活动由动力决定；任何需要伙伴的行为都遵循下述找伴、接受与带朋友规则。当前占用、距离、物品及活动参与条件决定对象是否可参与，关系变化会改变下一次选择。

老师没有发出鼓励时，学生也会自主聊天和走动。高好感不保证每次互动顺利，高敌对不保证每次接触都发生暴力。

### 9.1.1 找伴：熟人优先

任何需要伙伴的行为，优先邀请自己对其好感最高、且满足当前活动参与条件的学生。好感按“发起者 → 候选伙伴”的方向读取，不按角色名或固定 ID 选人。独自学习、听歌等不需要伙伴的行为不强制找伴；好感并列时的选择方式在实现前配置，并保证同种子可复现。

优先邀请不等于对方必然接受。老师鼓励指定交流时，指定对象替代自主找伴结果，仍执行正常接受规则。

### 9.1.2 接受：现有成员逐人投票

邀请或申请加入活动时，由现有活动成员对加入者分别投票；两人新建活动时，由被邀请者作为唯一现有成员投票，加入者不参与投票。

- 每名成员读取自己对加入者的有向关系：**好感 − 敌对 ≥ 10，投同意票；否则投拒绝票**。恰好高 10 点也同意。
- **同意票超过现有成员总数的一半才接受；平票拒绝**。因此双人团体须两票同意，三人团体至少两票同意。
- 每次请求统一读取关系、投票并产生一次团体结果，不逐人掷概率，不额外叠加隐藏性格、压力修正或旧版接受概率。
- 忙碌、空间不足或不满足活动参与条件属于暂时无法参与，不作为关系投票拒绝；鼓励目标的等待与有效期仍按第七章处理。
- 接受后加入同一场活动，成员与活动结束时间统一管理；一次请求不得重复结算同一条互动关系。拒绝不代表活动已经发生。

个人同意门槛 **10** 必须在实现时放入 `data/`，不得硬编码；NPC 接受路径已由 §9.1.4 的确定投票实现并配置化；新状态锁定与单位同步仍须复验。

### 9.1.3 带朋友：邀请加入原活动

活动参与者可以按找伴规则邀请自己的朋友加入当前活动。新朋友仍须满足活动参与条件，并由全部现有成员按同一套规则投票；邀请者有一票，不能替其他成员保证接纳。

接受后并入原活动，不另开重复活动，不重算原成员之间已经结算的互动。带朋友不直接增加好感或减少敌对，实际活动发生后才按对应事件结算。活动人数上限、邀请时机与频率在实现前配置；本条不预设三人上限，也不允许同一决策点无限连锁邀请。

### 9.1.4 通用加入与单向好感带动（2026-10-15，已实现）

本节更新并优先于上文中“只有空闲者可参与”等旧限制。找伴、接受、加入与带朋友共用一套规则，不限于聊天。**2026-10-15 已在 NPC 自主路径实装（`tools/core_sim.py` 与 `scripts/core/sim_core.gd` 同步）：**闲聊与打闹的找伴、加入、跟随与带朋友统一走本节决策树；多人聊天加入改用 §9.1.2 确定投票，旧概率接纳、规模衰减与敌对硬否决已删除。旧玩家交互路径已在 `3f52cd0` 删除，不再作为待迁移功能。

**找伴与带朋友**：从当前活动之外、符合参与条件的人中，选择自己对其好感最高的人。读取“发起者→候选者”的有向好感，不取双向平均。接纳只要求达到 §9.1.2 的条件，不要求互为最喜欢。独自活动不强制找伴；老师指定交流仍执行聊天目标，不被替换成其他活动。

例如 A 最喜欢 B，A 找 B；B 对 A 达到接纳条件便同意，即使 B 最喜欢 C。之后 B 可以邀请 C，但仍须 A、B 都同意，C 才能加入。B 喜欢 C 不代表 A 接受 C。此例说明带朋友可以由单向好感自然触发。

**两名独立学生原活动不同**：先检查参与条件及接纳，再比较双方有向好感；更在意对方的人跟随对方的活动；本条只作用于自由状态，不得拉走整段学习／游戏锁定或崩溃中的学生。

| 情况（甲学习、乙想玩） | 结果 |
|---|---|
| A[甲][乙] > A[乙][甲] | 甲跟随乙娱乐 |
| A[乙][甲] > A[甲][乙] | 乙加入甲的学习 |
| 两个方向好感相等 | 各自保持活动，本次不合流 |

相同活动则合流。好感比较只决定做什么，不替代接纳条件；跟随后仍需满足活动条件。上述学习／娱乐例子仅解释方向，实际必须先通过 §5.1 状态锁定检查，不能借该例拉走整段学习或游戏者。崩溃、办公室占用、不可中断活动等仍不可参与，不算关系拒绝。活动切换不清空既有学业收益，不强改动力；共同活动结束后恢复正常默认活动决策。自由状态能否主动学习及其收益口径仍待 §15.3 裁定。

**已有多人活动**：新人加入或被带入时跟随原活动，不重新比较好感改变整组活动。邀请者也是投票成员，不能保证接纳；使用 §9.1.2 的确定投票，不再叠加旧聊天概率、规模衰减或敌对硬否决。

| 原活动 | 有人加入后 | 条件与效果 |
|---|---|---|
| 学习 | 一起学习 | 各自按真实学习单位结算，不新增讲题加成 |
| 聊天 | 多人聊天 | 正常聊天效果，统一确定投票 |
| 吃零食 | 分享零食 | 原持有者有可用零食即可，加入者无需自带；正常娱乐效果，加入者对分享者好感增加 |
| 追逐打闹 | 多人打闹 | 满足场地、人数条件，按实际参与结算 |
| 离开教室 | 结伴外出 | 满足外出条件，不因加入额外发奖 |
| 听歌、读课外书、睡觉等 | 通用入口按配置检查 | 共享方式、参与条件未裁定时不自动开放；不可中断者不被强拉走 |

分享零食并入吃零食，不另造分享行为，也不新增采购或每日补充系统。消耗、补充及没收沿用物品规则；若现有运行时没有明确口径，接入前单独裁定，不默认无限供应。分享好感在真实完成共同进食单位后结算，单位与增量配置化；按分享者、接收者及完成单位去重，不重复奖励退出重入，不默认其他成员之间也加好感。

**循环与时序**：每人每个决策点最多发起一次邀请；请求逐次处理，执行时重新检查占用；本决策点新加入者从下一决策点起才能带朋友。不邀请组内成员，不同时参与多个活动，不在同一决策点被拒后无限换人重试。A→B→C→A 的最高好感环可能成组，也可能被拒；成组后不再邀请已在组内的人。处理顺序须明确且可复现。

## 9.2 具体事件

| 事件 | 简单条件与结果 |
|---|---|
| 友善交流 | 正常接纳且实际完成聊天，实际交流对子双方敌对各 −2；不增加额外 50% 修复概率，多人不全组两两修复 |
| 老师调解 | 任一方向敌对 >50，完成后双方敌对各 −5；两方向均不超过 50 时不执行且不扣耗时，不抹去风险历史 |
| 恶语攻击 | 课间接触，发起者对目标敌对 >40，双方同一活动或正交邻座；目标压力增加、目标对发起者敌对增加 |
| 推搡 | 课间接触、发起者对目标敌对 >70、双方同一活动或正交邻座；除敌对门槛外与恶语攻击条件相同；中断目标活动、目标压力较大增加、目标对发起者敌对增加 |

伤害仅恶语攻击与推搡，双方都不得处于学习锁定、办公室或崩溃。**2026-10-16 已裁定**：每 10 秒，每名符合发起条件的学生选一个符合接触及敌对条件的目标，只掷一次 **5%** 伤害概率；不对每个候选对分别掷骰。选人采用带种子的随机选择，不让候选人数增加本次伤害概率。触发后，若对目标敌对 >70，恶语攻击与推搡各 **50%** 选择一种；40<敌对≤70 时只能恶语攻击。不得对两种伤害各自再掷 5%，也不优先推搡。恶语攻击恰好 40 不满足，推搡恰好 70 不满足；其余条件相同，不另设推搡靠近距离门槛。所有概率及数值配置化。

恶语攻击使目标压力 **+5**、目标对发起者敌对 **+3**；推搡使目标压力 **+10**、目标对发起者敌对 **+5**，并中断目标当前活动。动力按一般压力联动规则处理，已得收益按中断规则保留。高敌对不保证必然伤害，取消“敌对等于 90 必然打架”“打架减敌对 20”“另设 50% 吵架”。普通拒绝、无意碰撞和正常打闹不算伤害。

2026-10-16 取消“停止打扰／邻座和平相处”的自动敌对修复规则，不因连续无冲突自动减敌对；保留友善聊天和老师调解修复。伤害门槛的调整不修改 §11.2 霸凌判定的敌对 >50 条件。

每人每课间最多主动伤害一次，两类共用次数，一次只触发一种。老师完成现场制止、调解，或将伤害参与者召唤到办公室后，涉及学生本课间不能再主动伤害；只是进入教室或发出尚未完成的召唤不算制止，不扩成全班禁伤害。现场制止的操作耗时仍待定。每次记录发起者、目标、类型、时间及方向，供风险统计；不因风险标签直接生成伤害。压力按一般规则联动动力，敌对变化不自动反向或改变好感。

**实施口径（2026-10-16 定稿）**：

- **每 10 秒**，每名符合资格的发起者先在自己满足条件的目标里**等概率随机选一个**，再**掷一次 5%**；不对每个候选对象分别掷骰 —— 否则周围人越多、命中越高。每人每课间最多主动伤害一次。
- 敌对 **> 70** 时，触发后**各 50% 选择恶语攻击或推搡**，一次只发生一种；**40 < 敌对 ≤ 70 只能恶语攻击**。避免高敌对后只剩推搡。
- **老师制止范围**：老师完成**现场制止、调解**，或将伤害参与者**召唤到办公室**后，涉及的学生**本课间不能再主动伤害**；仅仅进入教室不算制止，也不让全班自动停手。
- **伤害增量**：恶语攻击使目标压力 **+5**、对攻击者敌对 **+3**；推搡使目标压力 **+10**、敌对 **+5**，并中断目标活动。动力按一般压力联动规则处理。

## 9.3 观察与原因

朋友圈、孤立与风险标签是只读结果。不得写“因为已被标记孤立，所以全班继续减少对他的好感”；标签可以提示老师采取行动，行动再按正常规则产生影响。

## 9.4 聊天会话与多人加入

**2026-10-15 实装**：加入判定已按 §9.1.4 换为 §9.1.2 的确定投票（好感−敌对 ≥ `join_vote_margin` 投同意、严格过半、平票拒绝），旧概率接纳、规模衰减、敌对硬否决与 `chat_join_p` 每 tick 尝试**已删除**，不得再叠加。加入由闲聊／打闹的找伴路径统一触发（§9.1.4）。旧玩家交互路径已在 `3f52cd0` 删除。老师不进入任何学生活动成员集合。

学生间的自主聊天形成**会话**（二人成会，逐人独立计时），他人可随后加入，形成 3 人、4 人… 的递进群聊。核心口径如下（Python 内核与 GDScript 内核同源）：

- **成会**：两人开聊即形成会话；每名成员独立计时，时长 = `chat.duration × uniform[jitter_min, jitter_max]`（逐人掷骰，互不共享）。
- **加入判定**：全体现有成员按 §9.1.2 确定投票（读各自对加入者的真值有向关系）；人数上限 `join_max_members` 满员属条件不满足。
- **入会结算**：加入成功后，加入者对每位在会成员定向结算一次话题共鸣（好感／压力）；旧成员之间不重算。
- **离场与打断**：每名成员独立计时，到期即离场；成员少于 2 人则会话解散。铃响打断所有未完成会话，仍在聊的人付 `interrupted_stress` 代价。

| 参数 | 值 | 含义 |
|---|---|---|
| `join_vote_margin` | 10 | 成员对加入者「好感−敌对」同意票门槛（§9.1.2，恰好等于也同意） |
| `join_max_members` | 4 | 同一场活动的人数上限（含会话） |
| `join_tie_break` | 0 | 找伴好感并列选人方式（0 = 最低节点号，同种子可复现） |
| `invite_friend_p` | 0.04 | 活动组成员每决策点尝试带朋友的概率 |
| `chat_duration_jitter_min` / `max` | 0.8 / 1.2 | 时长随机上下限 |
| `snack_share_affinity` | 2（事件 base） | 分享零食：完成共同进食单位后加入者对分享者的好感 |

观察层（朋友圈、孤立标签）只读这些会话，不回写关系矩阵。
