# 第九章 学生自主行为与关系修复

## 9.1 自主选择

学生的默认活动由动力决定；任何需要伙伴的行为都遵循下述找伴、接受与带朋友规则。当前占用、距离、物品及活动参与条件决定对象是否可参与，关系变化会改变下一次选择。

老师没有发出鼓励时，学生也会自主聊天和走动。高好感不保证每次互动顺利，高敌对不保证每次接触都发生暴力。

### 9.1.1 找伴：熟人优先

任何需要伙伴的行为，优先邀请自己对其好感最高、且满足当前活动参与条件的学生。好感按“发起者 → 候选伙伴”的方向读取，不按角色名或固定 ID 选人。独自学习、听歌等不需要伙伴的行为不强制找伴；好感并列时的选择方式在实现前配置，并保证同种子可复现。

优先邀请不等于对方必然接受。老师鼓励指定交流时，指定对象替代自主找伴结果，仍执行正常接受规则。

### 9.1.2 接受：现有成员逐人投票

邀请或申请加入活动时，由现有活动成员对加入者分别投票；两人新建活动时，由被邀请者作为唯一现有成员投票，加入者不参与投票。

- 每名成员读取自己对加入者的有向关系：**好感 − 敌对 ≥ 10，投同意票；否则投拒绝票**。恰好高 10 点也同意。
- **同意票超过现有成员总数的一半才接受；平票拒绝**。因此双人团体须两票同意，三人团体至少两票同意。
- 每次请求统一读取关系、投票并产生一次团体结果，不逐人掷概率，不额外叠加隐藏性格、压力修正或旧版接受概率。
- 忙碌、空间不足或不满足活动参与条件属于暂时无法参与，不作为关系投票拒绝；鼓励目标的等待与有效期仍按第七章处理。
- 接受后加入同一场活动，成员与活动结束时间统一管理；一次请求不得重复结算同一条互动关系。拒绝不代表活动已经发生。

个人同意门槛 **10** 必须在实现时放入 `data/`，不得硬编码；NPC 接受路径已由 §9.1.4 的确定投票实现并配置化；新状态锁定与单位同步仍须复验。

### 9.1.3 带朋友：邀请加入原活动

活动参与者可以按找伴规则邀请自己的朋友加入当前活动。新朋友仍须满足活动参与条件，并由全部现有成员按同一套规则投票；邀请者有一票，不能替其他成员保证接纳。

接受后并入原活动，不另开重复活动，不重算原成员之间已经结算的互动。带朋友不直接增加好感或减少敌对，实际活动发生后才按对应事件结算。活动不设固定人数上限，但空间、物品与状态条件仍有效；邀请时机与频率配置化，也不允许同一决策点无限连锁邀请。

### 9.1.4 通用加入与单向好感带动（2026-10-15 局部实现记录）

本节更新并优先于上文中“只有空闲者可参与”等旧限制。找伴、接受、加入与带朋友共用一套规则，不限于聊天。**2026-10-15 已在 NPC 自主路径实装（`tools/core_sim.py` 与 `scripts/core/sim_core.gd` 同步）：**闲聊与打闹的找伴、加入、跟随与带朋友统一走本节决策树；多人聊天加入改用 §9.1.2 确定投票，旧概率接纳、规模衰减与敌对硬否决已删除。旧玩家交互路径已在 `3f52cd0` 删除，不再作为待迁移功能。

**找伴与带朋友**：从当前活动之外、符合参与条件的人中，选择自己对其好感最高的人。读取“发起者→候选者”的有向好感，不取双向平均。接纳只要求达到 §9.1.2 的条件，不要求互为最喜欢。独自活动不强制找伴；老师指定交流仍执行聊天目标，不被替换成其他活动。**自由状态的学生在自主决策前先尝试加入自己好感最高的人正在做的事**（每课间一次）；好感最高者不可用时改加入前后左右正在做的事，都不成立才做自己的事（2026-10-19 用户裁定，两侧内核已实现）。

例如 A 最喜欢 B，A 找 B；B 对 A 达到接纳条件便同意，即使 B 最喜欢 C。之后 B 可以邀请 C，但仍须 A、B 都同意，C 才能加入。B 喜欢 C 不代表 A 接受 C。此例说明带朋友可以由单向好感自然触发。

**两名独立学生原活动不同**：先检查参与条件及接纳，再比较双方有向好感；更在意对方的人跟随对方的活动；本条只作用于自由状态，不得拉走整段学习／游戏锁定或崩溃中的学生。

| 情况（甲学习、乙想玩） | 结果 |
|---|---|
| A[甲][乙] > A[乙][甲] | 甲跟随乙娱乐 |
| A[乙][甲] > A[甲][乙] | 乙加入甲的学习 |
| 两个方向好感相等 | 各自保持活动，本次不合流 |

相同活动则合流。好感比较只决定做什么，不替代接纳条件；跟随后仍需满足活动条件。上述学习／娱乐例子仅解释方向，实际必须先通过 §5.1 状态锁定检查，不能借该例拉走整段学习者，也不能让游戏者转入学习；游戏者主动或受邀参与伙伴类娱乐按 §5.1 执行。崩溃、办公室占用、不可中断活动等仍不可参与，不算关系拒绝。活动切换不清空既有学业收益，不强改动力；共同活动结束后恢复正常默认活动决策。自由状态可加入学习成为请教跟随者，收益及免动力规则按 §9.1.5；独自主动学习的决策入口仍待 §15.3 裁定。

**已有多人活动**：新人加入或被带入时跟随原活动，不重新比较好感改变整组活动。邀请者也是投票成员，不能保证接纳；使用 §9.1.2 的确定投票，不再叠加旧聊天概率、规模衰减或敌对硬否决。

| 原活动 | 有人加入后 | 条件与效果 |
|---|---|---|
| 学习 | 多人请教 | 原学习者每 20 秒收益 +1、动力 −5；跟随请教者每实际参与满 20 秒收益 +1，不消耗动力，不补发加入前收益 |
| 聊天 | 多人聊天 | 正常聊天效果，统一确定投票 |
| 吃零食 | 分享零食 | 原持有者有可用零食即可，加入者无需自带；正常娱乐效果，加入者对分享者好感增加 |
| 追逐打闹 | 多人打闹 | 满足场地、人数条件，按实际参与结算 |
| 离开教室 | 结伴外出 | 满足外出条件，不因加入额外发奖 |
| 听歌、读课外书 | 同款娱乐共享 | 2026-10-19 起可加入：加入者做同款娱乐并与发起者同步结束，仍走确定投票；**加入者免物品**（一起看同一本／共用设备） |
| 睡觉、崩溃休息 | 不开放 | 不可中断者不被强拉走 |

分享零食并入吃零食，不另造分享行为，也不新增采购或每日补充系统。消耗、补充及没收沿用物品规则；若现有运行时没有明确口径，接入前单独裁定，不默认无限供应。分享好感在真实完成共同进食单位后结算，单位与增量配置化；按分享者、接收者及完成单位去重，不重复奖励退出重入，不默认其他成员之间也加好感。

**循环与时序**：每人每个决策点最多发起一次邀请；请求逐次处理，执行时重新检查占用；本决策点新加入者从下一决策点起才能带朋友。不邀请组内成员，不同时参与多个活动，不在同一决策点被拒后无限换人重试。A→B→C→A 的最高好感环可能成组，也可能被拒；成组后不再邀请已在组内的人。处理顺序须明确且可复现。

### 9.1.5 走动与多人请教（2026-10-17 确认）

走动人数不固定、不设 8 人上限，不按“每段从 16 人抽出 8 人”强制执行。“一般约 8 人走动”只是表现与标定参考，允许更多或更少，不为凑人数打断学习锁定、崩溃休息或办公室占用；游戏状态因伙伴类娱乐产生的正常走动按 §5.1 执行，不改变状态收益口径；实际走动按状态、活动目标与环境产生。不能据此新增硬人数门槛或固定 50% 逐人概率。

**定向走动（2026-10-19 用户裁定）**：只有**自由状态（动力 30–60）**的学生走动，每课间一次：走向「自己好感最高的人」所在位置；好感最高者就在前后左右（固定座位正交邻座）时不动。学习／游戏锁定、崩溃、睡觉、在办公室、忙碌与走动中的学生都不参与。**找不到可接近的人时（好感最高者全在睡觉／崩溃／办公室）回自己的座位做自己的事**；内核侧同一情形会先退到「加入身边（前后左右）正在做的事」，都不成立才走自己的娱乐／学习。走动本身不改变关系与收益，加入仍按 §9.1.2 投票；只影响画面位置与聊天的空间前置（§10.5）。

走动用于接近伙伴，不是唯一加入资格。邻座及被邀请的学生同样可以提出加入。自主找伴优先自己对其好感最高的合格组外对象；老师指定和自主鼓励按第七章的特殊选人规则。接受仍是 §9.1.2 的全体现有成员确定投票，不直接放行，也不由目标按好感挑两人。

同时请求逐次处理、每次复查当前成员及占用；关系拒绝后不在同一决策点立即尝试第二、第三目标，下一决策点才恢复正常找伴。条件不满足与关系拒绝分开记录。加入后仍可按冷却和正常规则带组外朋友，不因形成三人组就封顶。

**请教为共同学习的免费收益特例**：原学习者正常每 20 秒学业收益 +1、动力 −5；请教跟随者每实际参与满 20 秒获得 +1 学业收益，活动本身不消耗其动力，无额外讲题加成。其他事件造成的动力变化照常生效，不是锁住动力。鼓励多人参与共同学习，但现有鼓励命令仍是一次聊天目标，不擅自增加“鼓励请教”的新老师命令。

请教只对满足参与条件的学生开放，不绕过学习／游戏锁定、崩溃和办公室占用。自由学生可通过正常接纳加入学习获得请教收益；加入者不要求动力 >60，也不被强改动力。活动同步结束而非补足 20 秒，不足完整收益单位不发奖；不重置原学习者计时，不把多人收益额外复制给原学习者。原有“跟随者同样扣动力”的解释在请教中废止。

### 9.1.6 通用活动边界与同刻结算（D11）

1.可加入范围：允许共同参与的学生活动使用统一加入规则，不设置固定人数上限；仍检查空间、物品、正常接纳投票及状态限制。不是所有行为都能加入，办公室命令、伤害、崩溃休息不作为共同活动开放。

2.学习／游戏锁定、崩溃、办公室及不可中断状态继续按主策划限制；共同参与方式未确定的活动不因本条自动开放。独自活动不强制找伴。

3.加入时点：发起者活动进度超过一半后不再接受新人；恰好一半仍可加入。活动进度以发起者为准，成员同步结束，但按各自真实参与时长结算，不补发加入前收益。

4.收益与惩罚：学业收益按完整单位、压力按已有中断规则结算；迟加入不因同步结束获得完整时长奖励。受伤、被没收等针对个人的惩罚只作用于实际对象，不扩成全员同罚；公开被动仍按自身触发条件生效。

5.成员退出：老师命令强制叫走或调座者退出原活动，保留已得收益，其余成员沿原进度继续；少于该活动最低人数才结束。发起者先退出时的计时基准与进度过半判定如何继承，待确认，不能把进度重置供反复加入。

6.冲突制止：吵架和推搡可以立刻调解终止，终止后只加中断幅度，不另减 10。打架不能终止。没有进行中的冲突时，调解走完后双方敌对各 −10。普通进入教室不触发调解。

7.同刻处理：先把截至本tick已经完成的完整活动单位记账并保留清理前状态，再执行阶段边界、到期老师命令、活动结束、鼓励目标尝试及学生自主选择。已发出但未完成的老师命令遇上课则延后，不能先执行效果。

8.刚好完成与打断：例如学习恰满20秒时响铃，先保留这一完整单位的收益，再中断后续活动。活动自然结束与上课中断不得重复计账；课间座位采样在清理前取状态，参与条件按主策划执行。

9.崩溃检查：普通决策前检查一次；任何伤害、训斥、心结等压力变化后也立即检查，不能只在tick开始检查。触发崩溃后停止该学生的其他未执行动作，按主策划进入当日休息，不清空既有收益；同次风险与崩溃不回溯当作正式风险后又崩溃一次。

10.确定性：同类同时请求使用明确、可复现的处理顺序；每次执行重新检查当前条件，防重复占用、多人争抢和重复结算。所有时间、概率、阈值和增量集中配置。

D11 中学习的普通单位扣动力只适用于原学习者，请教跟随者以 §9.1.5 的免动力特例为准。共同活动仍不突破空间和物品事实；没有固定人数上限不表示所有行为无条件可加入。

普通拒绝、无意碰撞和追逐打闹不算伤害。

2026-10-16 取消“停止打扰／邻座和平相处”的自动敌对修复规则，不因连续无冲突自动减敌对；保留友善聊天和老师调解修复。冲突档位不修改 §11.2 霸凌判定的敌对 >50 条件。

每人每课间最多一场。吵架、推搡各自从当课间起冷却 4 个课间，冷却中的档位不降成另一档。打架没有单独冷却，打完敌对 −40 后通常掉出打架档。敌对双向变化，不改好感，也不改压力，因此不联动动力。不因风险标签直接生成冲突。九格座位敌对加减已经取消，座位关系仍按原有正交好感与单向学习敌对结算。

**实施口径（2026-10-18）**：

- 课间开始判定一次，确定发生，不再每 10 秒掷 5%。
- 较低值 ≥90 打架，≥60 推搡，≥40 吵架。先看打架，再推搡，再吵架。
- 吵架、推搡、打架都不改压力。玻璃心仍只放大同学带来的压力（邻座学习），不进入这三条。
- 打架不能调解。调解终止吵架或推搡时只加中断幅度，不另减 10。

## 9.3 观察与原因

朋友圈、孤立与风险标签是只读结果。不得写“因为已被标记孤立，所以全班继续减少对他的好感”；标签可以提示老师采取行动，行动再按正常规则产生影响。

## 9.4 聊天会话与多人加入

**2026-10-15 实装**：加入判定已按 §9.1.4 换为 §9.1.2 的确定投票（好感−敌对 ≥ `join_vote_margin` 投同意、严格过半、平票拒绝），旧概率接纳、规模衰减、敌对硬否决与 `chat_join_p` 每 tick 尝试**已删除**，不得再叠加。加入由闲聊／打闹的找伴路径统一触发（§9.1.4）。旧玩家交互路径已在 `3f52cd0` 删除。老师不进入任何学生活动成员集合。

学生间的自主聊天形成**会话**（二人成会，逐人独立计时），他人可随后加入，形成 3 人、4 人… 的递进群聊。核心口径如下（Python 内核与 GDScript 内核同源）：

- **成会**：两人开聊即形成会话；每名成员独立计时，时长 = `chat.duration × uniform[jitter_min, jitter_max]`（逐人掷骰，互不共享）。
- **加入判定**：全体现有成员按 §9.1.2 确定投票（读各自对加入者的真值有向关系）；旧实现有 `join_max_members`；2026-10-17 目标规格取消固定上限，空间／物品等不足仍属条件不满足。
- **入会结算**：加入成功后，加入者对每位在会成员定向结算一次话题共鸣（好感／压力）；旧成员之间不重算。
- **离场与打断**：每名成员独立计时，到期即离场；成员少于 2 人则会话解散。铃响打断所有未完成会话，仍在聊的人付 `interrupted_stress` 代价。

| 参数 | 值 | 含义 |
|---|---|---|
| `join_vote_margin` | 10 | 成员对加入者「好感−敌对」同意票门槛（§9.1.2，恰好等于也同意） |
| `join_max_members` | 4（旧实现，待移除固定上限） | 同一场活动的人数上限（含会话） |
| `join_tie_break` | 0 | 找伴好感并列选人方式（0 = 最低节点号，同种子可复现） |
| `invite_friend_p` | 0.04 | 活动组成员每决策点尝试带朋友的概率 |
| `chat_duration_jitter_min` / `max` | 0.8 / 1.2 | 时长随机上下限 |
| `snack_share_affinity` | 2（事件 base） | 分享零食：完成共同进食单位后加入者对分享者的好感 |

观察层（朋友圈、孤立标签）只读这些会话，不回写关系矩阵。
