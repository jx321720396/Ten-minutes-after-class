# 第十二章 监控、私聊与界面反馈

## 12.1 核心可见信息

**2026-10-14 关注卡片实施**：第三张“需要关注”纸卡已接入真实高压名单与实际活动人数。高压预警阈值从 data/ui/attention_card.json 读取，当前试用值为 80，不等于崩溃或辞退判据；点击名单可进入学生档案。学习／娱乐／其他人数按实际活动、在场与移动状态归类，排除旧玩家，不由平均动力推算。普通争吵只接受真实事件记录，按事件 ID 去重并以最后状态为准，已结束不计；当前模拟尚未提供这些记录，因此显示“—”，不从敌对、打闹或压力爆发推断争吵。三张卡片按可用屏高缩放，详情保持完整视口。验收见 [关注卡片验收](../../qa/关注卡片验收-2026-10-14.md)。

老师明确看到学生的压力、动力、今日学业收益、当前成绩与公开被动，以及班级平均成绩、周考目标和倒计时。

**2026-10-14 分步 UI 实施**：左上角纸卡已显示实际日期／阶段、缩短式剩余时间条（不显示具体分秒，剩余不超过 20% 时变暖橙并提示即将上课／下课，暂停时冻结并显示已暂停）、首次周考倒计时、试用目标均分及实际差距。周考当天显示“今天周考”，之后显示“首次周考已结束”；均分仅统计学生，不计旧玩家节点。目标从 data/ui/time_card.json 读取，历史试用值 525，不接入辞退判定；现行时间卡配置已同步第八天／380，考核内核亦已实现；辞退流程和考分口径仍待验收。班级概况纸卡也已接入真实平均成绩与平均压力，并替换原音量卡的位置；其“查看全部概况”可打开只读详情。平均动力和今日平均学业收益在缺少老师版数据时显示“—”，不从压力或旧成绩增长反推，数据齐备后通过快照接入。卡片布局与文案由 data/ui/class_overview_card.json 配置。动力、收益已有内核，老师操作已有部分命令；界面快照、操作接线与完整效果尚未完成（§13.3）。验收见 [时间周考卡片验收](../../qa/时间周考卡片验收-2026-10-14.md)。

**2026-10-16 动力 UI 接入**：档案直接读取 `vitality()` 与 `gain_today()`，实时展示动力条、今日有符号净收益和已有收益计入后的次日成绩预览；打开与关闭档案不持有或释放暂停。时钟快照提供 `class_average_motivation`／`class_average_academic_gain`，班级概况与详情直接显示真实均值。公开被动、目标、趋势与收益明细不在本批接入范围。验收见 [动力 UI 接入验收](../../qa/动力UI接入验收-2026-10-16.md)。

今日学业收益与当前动力分开显示，例如“动力 40｜压力 75｜今日学业收益 +5”。“预计明日成绩”读取已经累计的收益，不把它当作当前成绩，也不凭空保证未来未发生的收益。

## 12.2 监控与私聊分工

- **监控**：复用当前教室场景，观察谁在学习、娱乐、聊天、移动，谁接触谁，谁在打扰或伤害谁。
- **私聊打听**：获取具体关系与近期矛盾，记录对象、方向、来源和发生时间，帮助老师安排交流与调解。
- 不再以透明度或信任阈值遮挡信息。关系是否默认全量展示、打听每次提供多少信息需要裁定；获取过的旧记录不能伪装成当前实时关系，未知不能当作中立。

## 12.3 行动反馈

行动完成后展示实际变化与来源。巡视加压、训斥加动力、被动额外收益、聊天拒绝和调解减少敌对都需要可见反馈。

鼓励显示“交流目标：与某某聊天一次”，并记录完成、拒绝或未完成的原因。打开只读档案或切换监控目标不得产生新的关系效果。

## 12.4 每日简报

简报至少包含：个人与全班的学业收益明细、结算后的成绩变化、压力与动力趋势、已发生互动及关系变化、鼓励执行结果、风险预警和老师干预记录。

朋友圈等标签来自实际关系；解释可以指出形成原因，不能用预制剧情替代事件日志。

## 12.5 档案中的玩家手动关系标注

**2026-10-14 移动端档案实施**：现有档案已替换为老师版纸张布局，加入当前成绩、压力、动力、今日学业收益四张卡片，当前活动、座位、公开被动、交流目标，以及“人际关系／状态与记录”页签。移除旧玩家关系对象、信任轴与学生闲聊入口；“叫来办公室”跳转已有办公室选择器，不执行尚未接入的私聊数值效果。关系采用每轴独立的“未判断／较低／一般／较高／很高”触摸档位，可查看反向，笔记不写真实矩阵。旧运行时可读取成绩、压力和实际活动；缺少老师版动力、收益、被动与目标快照时显示“—／暂无记录”，不以旧性格或学习累计推算。本局笔记支持界面重建保留与 JSON 往返；整局存档和继续尚未接通，不能宣称跨启动恢复。详见 [老师版同学档案验收](../../qa/老师版同学档案验收-2026-10-14.md)。

同学档案对每个有向学生对子显示**一组当前好感／敌对标注**，每一轴分别注明来源和记录时间。没有真实消息时，由玩家自行推断与选择；获得真实消息后，覆盖对应方向、对应轴的当前标注，不要求把消息与推测分成两套并排数值。

- 打开学生甲的档案，选择学生乙作为关系对象，明确当前方向为“甲 → 乙”；反向关系单独保存。
- 玩家分别标注好感与敌对，两轴独立，可以同时判断为较高。
- 未标注且未获知的轴显示“未判断”；玩家可以修改或清除自己的推测。未判断不等于中等或零。
- 获得真实消息时，只覆盖消息涉及的方向与轴，并显示“已获知”、获取时间与来源。只获知好感不覆盖敌对，甲对乙不覆盖乙对甲。
- 消息表示获取时的关系，不实时同步后台。玩家以后再次手动修改该轴时，来源改为“我的推测”；获取过的消息继续保留在历史记录中。
- 当前标注、来源、方向、修改时间与历史消息随本局存档保存；它们属于观察／玩家笔记，不写真实关系矩阵，不改变学生行动、压力、动力、风险或随机序列，不根据隐藏状态即时判定推测对错。
- 不恢复信任、透明度或学生对老师的关系轴。

交互整理建议采用每轴独立的档位选择：“未判断／较低／一般／较高／很高”，适合移动端直接点击；这是界面建议，不把档位强行换算成精确后台数值。最终档位、是否支持额外数字估计与备注，需在界面实施前确认。

## 12.6 推理板中的多人分析

**2026-10-14 移动端每日推理板实施**：老师不进入学生关系图。每一天独立整理当天在监控／教室观察到的公开学生互动及当天新增／修改的档案关系笔记；前日事件、人物与连线不自动带入次日，历史按日期回看。放学后冻结当日页并自动展示，收起后继续次日；学期末日页收起后查看既有学期报告。点人物筛选事件，点事件突出涉及学生；好感／敌对、方向、已获知／推测来源仍独立，观察互动不自动确认为友谊、敌对或风险。界面节点预置在 `.tscn`，背景为独立纸张素材，脚本不动态创建推理板节点。记录与档案共享本局笔记，归档在 GameState 持有；完整存档、跨启动恢复、老师私聊及主动干预数值尚未接通。实现边界及本机验证限制见 [每日推理板验收](../../qa/老师版每日推理板验收-2026-10-14.md)。

**同学档案负责一对学生的定向关系判断，推理板负责多人关系及其原因的整理。** 玩家可以在推理板联系多个学生、事件和线索，记录朋友圈、跨圈联系、矛盾来源或持续排斥的假说；这些内容仍是玩家推理，不能作为真实风险标签回写内核。

推理板中的多人假说不由档案里的某个高好感或高敌对标注自动判定。如果推理板展示同一条双人关系判断，应读取同一份玩家标注，避免维护互相冲突的副本；具体联动与操作形式需要界面设计。系统观察到的关系格局、已获知线索与玩家假说须有清楚的视觉区别。

## 12.4 班级压力灯光（2026-10-15）

教室环境光与室内灯只读全班学生平均压力，排除迁移期间的旧玩家节点。低压为奶油暖色，中压为灰杏色，高压为低饱和砖红色；按平均值连续插值并平滑过渡。时段窗光继续独立生效，界面不参与染色，个人高压预警保留。色值、压力控制点与过渡时间统一在 `data/ui/classroom_art.json` 的 `pressure_light` 配置，不作为崩溃判据。灯光不改变压力、关系、行为或随机数；移除灯光反馈不改变模拟结果，通过检验一。
