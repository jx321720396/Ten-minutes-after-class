# 第八章 人物行为设计

> **分层总则（2026-10-06 定稿）**：第八章只列**会改数值的行为**；**状态层**（学习 / 睡觉 / 走动）不算行为——它们改的是"位置 / 占用"，不是 A/H/T/Stress（见 §8.4、§8.8、§8.15）。
>
> **行为触发方式总则**（详细算法见 [`../design/NPC行为决策.md`](../design/NPC行为决策.md)）：
>
> | 触发方式 | 判据 | 行为 |
> |---|---|---|
> | **环境类** | 固定基础概率 × 修正系数 | 闲聊、流言、窃听 |
> | **阈值类** | `p = σ((x−θ)/scale)` 概率化 | 举报、压力爆发 |
> | **意向类** | 门槛 → 意向评分 → softmax 采样 | 搭话、调侃、安慰、求助、道歉、秘密交换 |
>
> 三类都必须走统一影响公式结算（§4）；**意向类**中"对方的反应预期"一律取信念矩阵 `B`，自己的立场取真值。
> 三类触发方式与结果判定统一为**两段式统一判定公式**（§4.4）：**决策读信念、判定读真值**。
>
> **所有事件的触发条件都是「好感 / 敌对 / 信任 / 透明度 / 压力」的函数**——不存在按天数、轮次或固定剧本触发的「第 N 天必然发生 X」。新增行为时必须给出可判定的数值条件。

## 8.1 流言（附加行为）

1. 触发条件：（1）当A通过对B的流言判定（与好感度和敌对值有关），将对B的流言存入A的记忆，流言倾向根据A对B的好感度或者敌对值生成；（2）举报产生
2. 流言倾向：从-2到2由完全负面到完全正面，0为中立流言，流言倾向只为整数，且无法超出该范围
3. 传播条件：当A记忆中含有流言且A不为流言对象
4. 传播结果：当针对B的流言存入A的记忆，根据流言倾向数值增加A对B的好感值或敌对值（流言倾向大于0，则A对B的好感值加上流言倾向的绝对值；流言倾向小于0，则A对B的敌对值加上流言倾向的绝对值；为0则不改变）
5. 传播偏移：流言具有流言倾向（从-2到2由完全负面到完全正面，0为中立流言），如果传播者对传播对象(好感值-敌对值>0)则流言倾向加一；为0则不变；<0则流言倾向减一
6. 传播方式：（1）闲聊（2）窃听（3）**纸条**（= 流言的**私密传递方式**，不可被窃听 / 不可被搭话；**不再是独立行为**，见 §8.6 已合并）（4）告密
7. 传播限制：（1）单次闲聊只能够传播一条流言，但可以A传播给B的同时B也传给A（2）每条流言都有序号，如果某一条流言已记入过A的记忆则不能记入第二次
8. 流言传播顺序：（1）A接收流言（2）A对流言对象的好感值或敌对值发生改变（3）A对该流言的流言倾向进行更改（4）传播流言并删除记忆/流言自动遗忘
9. 流言消失：（1）一旦通过任何方式传递出去流言会从记忆里清除；（2）流言最多在一个人记忆中停留三个课间，若三个课间流言仍未传播则流言自动清除

## 8.2 举报（主行为）

1. 触发条件（概率化，无硬门槛）：
   （1）**载体**：A 在最近 `report_witness_window` 天内**目击过 B 的标签行为痕迹**（如带手机者课间玩手机；§7.6「标签必然留下行为痕迹」）。目击记录是一手观察，**不追溯流言源头**。
   （2）**概率**：`z = (H[i][j] − θ_H)/scale_H − w_A·A[i][j]/100 − w_T·T[i][j]/100`，`p = report_p × σ(z)`——敌对越高越可能举报，好感/信任越高越不可能（**好友几乎不举报，但概率永不为 0**）。
2. 行为结果：（1）本节课间举报者消失不出现在教室内，与走动到室外相同；（2）举报会大幅提升被举报者的压力值，概率生成针对 A 或 B 的流言（要么直接将一条对A的流言倾向为-2的流言存入B的记忆；要么直接将一条对B的流言倾向为-2的流言存入A的记忆）；（3）举报后A对B的敌对值会下降

## 8.3 告密（主行为）

1. 触发条件：当A记忆中含有对B的流言，且A通过对B的告密判定
2. 行为结果：（1）在本课间B不会移动,A会在课间走向B的位置并对B进行告密（与闲聊纸条不同，是独立的主行为），告密无法被窃听；（2）A与B对互相的好感度增加，根据流言倾向增加A与B对班级其余人的好感值或敌对值（流言倾向大于0则增加好感值，小于0则增加敌对值）；（3）B在被告密后把流言存入记忆并在课间结束后立刻删除

## 8.4 走动（状态层，非行为）

> ⚠️ **部分落地**：位置接口 `set_position` / `position_of` / `distance_between` 已进内核（GDScript 与 Python 同步，**只读记录、不动矩阵**）。真实教室已启用玩家与 NPC 闲聊的统一空间校验、移动与占用互斥；NPC 的移动决策（`do_move`）仍未进内核，其他行为的完整空间规则仍待接入。表现层向内核同步位置、座位入口和移动状态，内核不引用场景节点。无场景几何的离线标定仍使用原抽象模型，不代表已验证真实教室的空间分布。完整版落地时把 `position` 纳入 §14.2 存档。
> · **移动状态已接入，移动耗时占用仍未完整实现**：`set_moving` / `is_moving` 独立记录行走，移动中的人不能发起或接受新聊天；行为占用、聊天会话或睡眠期间 NPC 不发起离座。`move.duration` 仍只用于表现层归位时限，不代表内核已按路线长度排定移动结束 tick。真实场景在发布上课归位之前先完成到期活动并中断未完成聊天，避免聊天圈跟随归位。
> · **路线由表现层给出**（2026-10-07）：NPC 走动沿 `classroom3D.tscn` 的**导航网格**折线（`resources/navigation/classroom_nav.tres`）；取不到路线时停在原地，**不直线兜底**（直线会穿桌椅）。玩家路线与内核的空间判定仍走矩形口径，分工见 [`架构总览.md`](../design/架构总览.md)「教室导航与两套几何的分工」。

1. **两个位置概念**：
   - **座位**（`seat_of`）：跨天固定（§9.1），决定"默认邻居"与上课段位置；
   - **临时位置**（`position`）：课间走动后的当前位置，互动距离与活动圈以它为准；段末 / 上课铃响回座位。
2. **NPC 走动判定**：每段课间开始（下课瞬间），非睡觉 NPC 掷一次 `move`（`behavior_probs.csv`）：
   - 修正：`E ≥ 50` 者 ×(1 + (E−50)/100)，`E < 50` 者 ×(1 − (50−E)/200)——外向更爱走动、内向更少，但**永不为 0**。
3. **NPC 目标选择**：在教室内空闲站立点里加权抽一个：
   - 权重 = `1 + Σ_j A[i][j]/100 − Σ_j H[i][j]/200`（想靠近喜欢的人、躲开讨厌的人）；对"想加入的活动圈"所在位置额外 ×1.5；
   - 权重下限 0.1（再不喜欢也偶尔走动，不锁死）。
4. **走动期间**：消耗 `ceil(路径长度 / meters_per_tick)` tick（§10.2 时间成本表；速度放 `data/rules/movement.csv`，**放弃固定 15 tick** —— 耗时随实际行走距离变化；表现层按**导航路径**长度计时），期间不能发起 / 接受新交互；走动本身不产生数值变化。
5. **玩家移动**：玩家**无概率判定**，只受时间预算约束（§10.1：人做选择）。控制方式（`scripts/game/player_controller.gd`，2026-10-07 定稿）：
   - **WASD**：按镜头对应的地面方向连续移动（W 向画面上方、S 向下、A/D 左右，斜向归一化，松键即停）；**位置允许连续变化**，不再每走一步都吸附到站立点；
   - **鼠标左键点地面**：沿**可通行路线**（网格 A*，绕开桌椅）自动前往，再次点击更换目的地；按下 WASD 立刻取消自动行走，松键后不恢复旧路线；
   - 两者共用**同一速度**（`meters_per_tick`）、同一套**桌椅阻挡**与**操作权限**（上课 / 简报 / 暂停 / 转笔演出 / 占用型行为进行中均停止控制，占用状态来自内核 `is_busy`）；
   - **站立点仍用于**：座位、NPC 会面、鼠标点击的吸附目的地（吸附半径内优先）；玩家手动行走不吸附到点。
6. **归位**：段末或相位切换时，所有走动者回到自己的座位；被上课铃打断按 §8.4 的 `interrupted_stress` 结算（走动不豁免）。

## 8.5 闲聊（主行为）

> **2026-10-07 用户裁决：闲聊与原“搭话”合并。** 闲聊是同一个主行为，发起新聊天与加入已有聊天是两种参与方式；加入是 §8.21 的通用操作，不再提供独立“搭话”菜单。完整玩家接线见 [闲聊完整可玩流程计划案](../superpowers/plans/2026-10-07-chat-playable-loop.md)。**2026-10-08 已落地**：统一入口（`preview_player_interaction` / `commit_player_interaction`，kind=chat、mode=start/join）、真实共同活动、原子提交与完成／中断通知、脚下融合圈与玩家线索全部接通；旧 `join_chat` 仅作兼容别名与 NPC 旧路径保留。

1. 触发条件：发起新聊天时，A、B 双方互相处于对方闲聊范围内且能参与聊天；加入已有聊天时，A 空闲、目标聊天会话有效并满足范围，通过该活动的接受判定后加入原会话（§8.7）。NPC 保留规则选择与概率触发；玩家主动选择参与方式，不能绕过范围和占用。首批玩家流程的 start 模式合法后直接开始，join 模式执行原接受判定，不因合并额外增加一次掷骰。
   - **空间口径（2026-10-08）**：双方都在自己的座位入口时，只允许同列、相邻两排的前后座位转身交流，距离不超过 `player_interaction.csv` 的 `seated_chat_range_m`（1.8 米）；是否仍在座位按 `seated_tolerance_m`（0.1 米）判定。左右、斜向、跨排座位不能直接远程聊天。至少一人离座后，双方必须停止移动、处于 `chat_range_m`（1.2 米）内且连线不穿家具，才可成立聊天。玩家与 NPC 共用判定；聊天期间不得离座漫游。前后座位转身交流不要求两座之间的课桌成为可通行区域。
2. 行为结果：（1）闲聊发生后闲聊成员各自判定增加好感度或者敌对值；（2）减小闲聊成员的压力值
3. 闲聊内容可被范围内未处于闲聊状态的同学窃听
4. 闲聊成员中如有成员记忆中含有流言，且流言对象不是剩余的闲聊成员，可进行传播（每一个闲聊成员在本次闲聊中只能传播一次流言）
5. **玩家专属的关系透露**：玩家主动选择与某人闲聊时，闲聊对象会顺带透露其他同学与自己的关系。透露数量由**闲聊对象当前透明度 O**决定：O < 50 时透露 1 条，O ≥ 50 时透露 2 条（与 §7.2 的透明度分界一致）。随机对象必须排除玩家与当前闲聊对象；透露内容只属于本次玩家情报，不写回关系矩阵，也不为 NPC 预设同类行为。NPC 之间的闲聊不触发该规则。

## 8.6 传纸条（已合并入流言）

> ✅ **2026-10-06 定稿**：传纸条**不再是独立行为**，它是**流言（及闲聊）的一种私密传递方式**——不可被窃听、不可被搭话。触发时走 §8.1 的传播流程，只是把"口头传播"换成"纸条传递"；不再单独占行为槽、不再单独出现在行为表。

## 8.7 加入闲聊（原“搭话”，已合并）

1. 本节规定闲聊的**加入方式**，不是第二个主行为。A 未被占用、范围内已有可加入的闲聊会话时，按 §8.21 的 accept 规则请求加入；通过则加入原会话，否则 A 对原聊天成员敌对值增加。
2. 接受后与闲聊共享会话、成员、占用与完成信息；不能把忙碌目标拉进第二个独立交互。玩家菜单仅有闲聊行为及通用加入操作，新交互标识为 `kind=chat`、`mode=start/join`。
3. 现有 `join_chat` 配置行、函数、统计字段与 NPC 旧调用路径暂留作兼容实现，**名称保留不代表独立玩法保留**；本次仅修改设计文档，不删除配置、不调概率、耗时或事件系数。旧文档中的“搭话”数值和测试记录属于该旧实现，不作为新增菜单项的依据。
   > **2026-10-08 落地注记**：玩家侧统一入口已接通（`kind=chat` + `mode=start/join`，见 §8.5 注）；NPC 旧路径与旧入口保持原样，数值与事件系数未动。

> ✅ **已实现**（2026-10-05）：按**段**粒度判定（⚠️ 不是 tick —— 早期误写在每 tick 决策里，导致 96% 的课间都在睡）；睡着者**不被任何人交互**、段末一次性减压 `sleep_relief`。

## 8.8 睡觉（状态层，非行为）

1. 触发条件：概率触发睡觉判定，通过判定则进行睡眠
2. 行为结果：本次课间无法进行其他任何活动，课间结束压力减少
3. **排除条款**：睡觉中的角色**不参与任何交互**（闲聊（发起／加入） / 共同学习 / 被调侃 / 被安慰 / 被求助…），也**不作为相邻类判定的对象**——坐在睡着的人旁边不产生「共同学习」。唯一的数值变化是课间结束时的压力减少。
4. **策略含义**：睡觉是用「社交机会」换「压力缓解」——你会错过本课间全部互动与观测。

## 8.9 窃听（附加行为）

> ⛔ **本行为为可选，不纳入任何版本实现**（2026-10-07 决定，见 §14.9）：
> §13 三个版本的排期均未列入；上游缺「流言记忆」与「范围判定」两个结构（§8.1 的流言目前
> 只是即时染色，没有可携带的对象）。`data/rules/behavior_probs.csv` 已将其概率置 `0.0`
> 显式关闭——原值 `1.0` 的语义是「未做主行为即必触发」，照字面接线会让全班无条件互相窃听。
> **本节规格仅作留存**，重启前须先补 §8.1 的记忆模型。

1. 触发条件：当人物没有进行任何主行为时
2. 行为：捕获自身一定范围内所有人的闲聊内容
3. 行为结果：（1）将闲聊中的流言存入记忆；（2）若窃听者为流言对象本人，则会根据流言倾向改变数值（若流言倾向大于0则压力减小，对闲聊双方的好感值上升；若流言倾向小于0则压力增大，对闲聊双方的敌对值上升；（3）若窃听者为流言对象本人，在窃听后把流言存入记忆并在课间结束后立刻删除

## 8.10 求助（主行为）

> ✅ **已实装（2026-10-07，Python 内核 `core_sim.do_ask_help`）**。门槛随外向度**三段插值**：
> `E=50 → 30、E=0 → 50、E=100 → 20`（对应下条「≥30；内向 ≥50；外向 ≥20」，连续不跳变）。
> 判定侧读**真值** `A[j][i] + 对方外向度加成`（§4.4：判定读真值），决策侧的目标选择读**信念**。
> ⚠️ **未实装**：「被亏欠」状态（下条第 3 点末）与「被拒压力 ×1.5 / 好斗敌对 ×2」（第 4 点后半）
> —— 前者需 `status_tags` 支持「条件修正」语义，后者超出 `M_personality` 的 `[0.1,1.2]` 钳位。

1. 触发条件：对目标好感 ≥30（内向型需 ≥50）
2. 发起成本：发起者压力 +2
3. 行为结果：
   - **被拒绝**：发起者压力 +3、对目标敌对 +3、信任 −3
   - **成功**：被求助者对你好感 +2、信任 +3；发起者压力 −2、好感 +3；被求助者进入「被亏欠」状态（3 天内你向他求助成功率 +25%）
4. 性格修正：内向门槛抬高到好感 ≥50、被拒压力 ×1.5；外向门槛降到 20；好斗被拒后敌对 ×2

## 8.11 道歉 / 和解（主行为）

> ✅ **已实装（2026-10-07，Python 内核 `core_sim.do_apologize`）**，并有两处**裁决/发现**：
>
> **① 接受的敌对变化是「表层 −3」而非 −5**（2026-10-07 用户裁决）。
> 原因：`apply_event` 对 `tier=major` 的 hostility 会执行 `H_deep += |Δ|` —— **负的 Δ 也照加**，
> 照本文第 4 点字面写「−5（major）」会变成「**和解反而加深心结**」，与 §9.3「心结永不衰减」冲突。
> 故降为**常规档 −3**，且**只消表层** `H`、不动 `H_deep` —— 语义是「道歉能消当下的气，
> 但忘不掉的还是忘不掉」。§8.16 的分档表已同步。
>
> **② 本文的「双方敌对 ≥30」在当前标定下几乎不可达**（实测 30 天 `H` 上限仅 19–24，
> `H ≥ 20` 的（有向）对子·tick 占比 **0.000%**；`H ≥ 30` 十局合计仅出现 14 次）。这与 §9.5.3
> 记载的排挤问题**同源：敌对缺少积累通道**（§8.17「关系缺少变差通道」）。当前实现**按本文的 30 保留**
> —— 于是道歉只在**冲突真正升级过**的局里出现（10 局 ×30 天实测 14 次，全部发生在 NPC 之间）。
> 若要让道歉成为常客，应改的是**敌对能不能涨上去**，而不是把门槛调到初始区间内。
>
> **③ 效果不做关系调制**（`no_modulation=True`）：门槛保证 `H ≥ 30` → 净态度 `M` 常为负 →
> 常规档会把「敌对回落」乘负 `M` **翻成敌对上升**（越道歉越糟）。修复类行为与 `M` 的冲突是结构性的。
>
> ⚠️ **未实装**：「透明度临时 +10」（无临时透明度机制）与第 5 点的性格修正倍率。

1. 触发条件：双方敌对 ≥30，一方主动发起
2. 发起成本：发起者压力 +3，透明度临时 +10
3. 接受概率 = 对方对你的好感 + 对方随和系数 − 敌对值 ×0.5
4. 行为结果：
   - **接受**：敌对 −3（表层；见上①）、好感 +3、信任 +2、双方压力 −3
   - **拒绝**：敌对 +2、发起者压力 +4、信任 −3
5. 性格修正：高 F（随和）接受概率 +30%；高 T / 好斗 −25%；敏感型被拒后压力 ×1.5，可能触发爆发

## 8.12 当众调侃（主行为）

1. 触发条件：周围 ≥3 人围观，且满足下列**之一**：
   - **好意调侃**：发起者对目标好感 `A ≥ 40`（按 §8.16 判为「玩笑」档）；
   - **挑衅式调侃**：目标对发起者敌对 `H ≥ 25`，**或**发起者对目标好感 `A < 25`（按 §8.16 判为「嘲讽」档）。

   > ⚠️ **2026-10-05 修订（P0）**：原条件只写「发起者对目标好感 ≥ 40」，与 §8.16 的嘲讽档判据（`H ≥ 40` **或** `A < 25`）**互斥** —— `A ≥ 40` 时不可能 `A < 25`，而 `H ≥ 40` 又依赖「已有敌对」→ **嘲讽档永远发不出来**，敌对链路因此半死锁（见 §8.17.2）。
   > **「嘲弄是敌对的第一发声」**，不该要求先有高敌对。
2. 成本：目标压力 +3，发起者压力 +1
3. 成功概率 = 目标对发起者好感 ×0.5 + 目标外向系数 − 目标敏感系数
4. 行为结果：
   - **成功（玩笑接住了）**：双方好感 +3，围观者对发起者好感 +2，目标压力 −2
   - **失败（玩笑过火）**：目标敌对 +4、压力 +4；围观者按性格分裂——外向 / 八卦好感 +2，随和 / 敏感好感 −2
5. 性格修正：外向成功率 +20%、被调侃压力 ×0.5；敏感被调侃压力 ×1.5、敌对 ×1.5；八卦型失败后把这件事当流言传播（→ 10.1）

## 8.13 安慰（主行为）

> ✅ **已实装（2026-10-07，Python 内核 `core_sim.do_comfort`）**。好感门槛按外向度分两段：
> `E ≥ 50 用 50`，`E < 50` 时向内向端线性抬高到 70（对应下条「≥50；内向 ≥70」，连续不跳变）。
> 效果为**重大档**（`comfort_target_*` 在 `w_events.csv` 中为 `tier=major`），与本文数值一致。
>
> ⚠️ **这是一个「窄条件」行为**：`Stress ≥ 70` 的（节点·tick）占比仅 **2.31%**，还要求
> 「发起者对他好感跨过门槛」且「发起者此刻空闲」——实测**机会数只有 0–2 次/天**，
> 故 `behavior_probs.comfort_p` 取 **0.35**（机会来临时基本会行动）而非环境类的小概率。
> 10 局 ×30 天实测 163 次（约 16 次/局）。**它本来就该稀有**：关系的跃升发生在「救援时刻」。
>
> ⚠️ **未实装**：第 4 点的共情判定与效果 ×1.5（`Stress ≥ 90` 时），与第 5 点的性格修正倍率
> （倍率超出 `M_personality` 的 `[0.1,1.2]` 钳位；`w_f` 列已提供「被安慰者越情感型、收益越大」的近似）。

1. 触发条件：目标压力 ≥70，且发起者对目标好感 ≥50（内向型需 ≥70）
2. 发起成本：发起者压力 +2
3. 行为结果：目标压力 −5、对你好感 +4、信任 +5
4. 目标正在爆发（压力 ≥90）：效果 ×1.5，但需通过共情判定（成功率 = 随和系数 + 敏感系数 − 好斗系数）
5. 性格修正：高 F + 高敏感（高共情）效果 ×1.5、成功率 +25%；好斗效果 ×0.5、成功率 −20%

## 8.14 秘密交换（主行为）

1. 触发条件：双方信任 ≥60，一方主动发起
2. 行为结果：
   - 发起者把一条秘密告诉对方，对方进入「守密」状态
   - **对方泄密**：发起者对其信任 −5、敌对 +4、压力 +5；泄密者获得「泄密者」标签（3 天）
   - **对方守密超过 5 tick**：双方进入「秘密同盟」——每个涓流结算点（每天 2 次）双方信任 +1（涓流类）
3. 性格修正：高 N（爱脑补 / 爱八卦）守密概率 −30%；内向 / 随和 +20%；好斗被背叛后敌对涨幅 ×1.5

> 以上五个社交行为依据 v3.0 规格回填，并按全局数值铁律（常规 `base ∈ [1,3]`、重大 `[4,5]`、结算类型见 [`../design/统一影响公式.md`](../design/统一影响公式.md) §1.5）改写；它们补齐了 §4.3 事件权重表中「被当众调侃」「安慰他人」等事件的行为来源。

## 8.16 行为的分类与判定来源

> 本节回答一个架构问题：**每个行为的"加减"到底由什么决定？** 结论先行——
> **方向用阈值判、强度用连续量调制**；不要用"净态度 `M` 的符号"判方向（见下方反例）。
> 本表是行为实现的分类依据，也是新增行为时的"归类检查表"。

### 五类行为

| 类别 | 定义 | 读什么 | 典型行为 | 在涌现中的角色 |
| --- | --- | --- | --- | --- |
| **A 纯增益型** | 只往正向轴加，不看好坏 | 无（仅轻量性格修正） | 闲聊（话题共鸣）、共同学习、安慰（对目标轴） | 提供**关系基本盘**的持续涨落 |
| **B 纯损害型** | 只往负向轴加，不看关系 | 无 | 流言（负面染色）、举报、被拒绝的反噬 | 提供**破坏与压力**的来源 |
| **C 信念驱动型** | **决策读信念、判定读真值** | 决策：`B_A` `B_H` `B_T`（i 眼中对方对 i 的态度）｜判定：`A[j][i]` | 加入闲聊（判对方是否接纳）、求助（判对方是否愿帮） | 提供**误判与戏剧性**（以为自己被喜欢） |
| **D 信任 / 透明度驱动型** | 读 `T` / `O` 决定**成败与可见性** | `T[i][j]`、`O[j]` | 秘密交换（`T ≥ 60`）、告密（`O` 决定是否被听到）、窃听（`O` 决定能听到什么） | 提供**信息博弈** |
| **E 混合判定型** | 读**多轴 + 阈值分档**，**结果方向可变** | `A` + `H`（+性格） | **当众调侃**（玩笑 / 尴尬 / 嘲讽三档）、道歉和解（`H ≥ 30` 后修复） | 提供**同一行为在不同关系下的分岔**——戏剧性最强 |

### 行为按数值分档（2026-10-06 重排）

> 分档标准：每个轴（A 好感 / H 敌对 / T 信任）都应覆盖 `+1/+2/+3` 与 `−1/−2/−3`；一个行为可以"一体两面"（成功加、失败减）。本节只**重排现有行为**，缺口显式保留，待后续机制或标定补齐。

| 档位 | A 好感 | H 敌对 | T 信任 |
| --- | --- | --- | --- |
| **+3** | 闲聊、求助成功、道歉接受 | 被拒绝搭话、求助被拒、嘲讽档、流言（负倾向 −3）、打闹旁观、从众、音量定向 | 闲聊、求助成功 |
| **+2** | 打闹参与者、调侃玩笑档 | 道歉被拒 | 道歉接受 |
| **+1** | **缺口** | **缺口** | 秘密同盟（涓流，非即时行为） |
| **−1** | **缺口** | **缺口** | **缺口** |
| **−2** | 被调侃 | **缺口** | **缺口** |
| **−3** | 被拒绝搭话 | 道歉接受（**仅表层** `H`，不动心结） | 求助被拒、道歉被拒 |
| **重大档（±4/±5）** | 排挤（−4）、安慰成功（+4） | 举报（+5） | 秘密泄露（−5）、安慰成功（+5） |

> ⚠️ **2026-10-07 调整**（随 §8.10–§8.13 落地）：
> ① **安慰成功升入重大档**（+4 / +5 / 压力 −5）—— 按 §8.13 的数值落地，门槛苛刻（须已有好感 + 对方正崩溃）；
> ② **道歉接受从重大档移入常规档**（好感 +3、敌对 −3）—— 原因见 §8.11 的分歧①（major 负向 hostile 会误写深层敌对）；
> ③ 补齐 **求助被拒 → H +3**（§8.10）。
> 表中「**缺口**」为显式保留项：`H` 与 `T` 的 ±1 档仍无行为覆盖。

> ⚠️ **重大档里的 `羞辱` / `秘密泄露` 不是独立行为**：羞辱 = 当众调侃的**嘲讽档升级后果**（§9.4，写深层敌对）；秘密泄露 = 秘密交换的**失败侧后果**（§8.14）。`孤立` 是**观察层标签**（§9.7.4），只读、不回写——排挤行为会造成孤立标签，但标签本身不是行为。

**一体两面分支**：闲聊的加入（成功=参与原闲聊，失败=被拒三轴反噬）、调侃（玩笑 / 尴尬 / 嘲讽）、安慰（成功 / 只付成本）、求助（成功 / 被拒）、道歉（接受 / 拒绝）、流言（倾向正负）、打闹（参与者 / 旁观者）。

### 三条边界（详见 [`../design/统一影响公式.md`](../design/统一影响公式.md) §1.6）

1. **信念只决定「做不做」，不决定「效果多大」**：意向层读 `B`，**效果层写真值轴**；否则会出现"我误以为他恨我，于是我的调侃真的把关系弄坏了——基于一个不存在的事实"；
2. **重大档（`tier=major`）不做关系调制**（`M_eff = 1`）：否则「我们关系好，所以他举报我反而是好事」会塌掉欺凌线与信任崩塌线（注意不是 `max(0, M)`——那会让关系差时伤害归零）；
3. **门槛用阈值（硬）、幅度用公式（软）**：别退化成「每类一个 if-else」，否则行为会在阈值附近疯狂跳变；
4. **统一判定公式两段式（§4.4）**：决策侧读 `B`（做不做）、判定侧读真值 `A/H/T`（成不成）；玩家展示侧从 `B` 重算成功率。

### 判定规则：方向用阈值，强度用连续量

以**当众调侃**（E 类）为例：

| 档位 | 判据（`behavior_thresholds.csv`） | 结果 |
| --- | --- | --- |
| **玩笑** | `A ≥ 55` **且** `H < 25` | 双方好感↑、被逗笑减压 |
| **尴尬** | 其余 | 不结算（效果自然为 0） |
| **嘲讽** | `H ≥ 40` **或** `A < 25` | 目标压力↑、对发起者敌对↑、围观者按性格分裂 |

> **注意**：本表判的是**结果方向**，§8.12 判的是**能否发起** —— 两者必须相容。`A ≥ 40` 的发起门槛曾使嘲讽档无法达成（P0，已修为双轨），详见 §8.12 的修订说明。

强度（不只是方向）仍由连续量 `M(i,s) = clamp((A−H)/50, −1, +1)` 调制——**两者分工明确**：

```
方向 = 阈值分档（离散、可配、可解释）
强度 = |M| 调制（连续、自动、无需特例）
```

### ⚠️ 反例：为什么不能用 `M` 的符号判方向

一个诱人的想法是"调侃是玩笑还是嘲讽，看 `M` 的正负即可"。**实测否决了这个方案**：

```
M = (A − H)/50  → 零点在 A = H
但本作里 A 的基线是 25~40，H 的基线只有 0~15
∴ 开局 M ≈ (25−8)/50 = 0.34 > 0  →  永远判为「玩笑」
  → 好感↑ → M↑ → 更是玩笑（正反馈）
∴ 30 天实测：好感均值 89.4、标准差 1.5（全班趋同）、爆发 0
```

**根因**：`M` 的零点（`A = H`）与游戏的**关系基线**不重合，`M` 恒偏正。因此：

- **`M` 适合做强度**（连续调制，零点偏正只是"整体略偏正向"，无害）；
- **`M` 不适合做方向**（方向需要的是"相对于基线在哪一侧"，那必须用**绝对阈值**）。

改用阈值分档后，同一个 30 天实测变为：好感均值 79.8、标准差 10.6——**改善但未达标**，
因为还有一个更根本的缺口：**B 类（纯损害型）行为几乎空白**，关系缺少"变差"的常规通道（详见 §8.17）。

### 新增行为时的归类检查

1. 它读哪些轴？（无 / 信念 / 信任·透明度 / 多轴）→ 决定它属于 A–E 哪一类；
2. 它的**结果方向**是否可变？若是，方向判据必须写成 `behavior_thresholds.csv` 里的**绝对阈值**，不得用 `M` 的符号；
3. 它的**数值**是否全部来自 `data/`？（铁律：脚本内不得出现魔法数字）
4. 它是否引入角色 ID / 名字判断？（违反 §9.11 即为缺陷）

## 8.17 关系缺少「变差」通道（待补）

> 状态：**好感侧已解决，敌对侧仍未打通**。且诊断显示这不是「缺一个行为」，而是**敌对系统缺少「种子」**。

### 已解决：好感侧的单向棘轮

`do_join_chat` 原用 `B_A[i][j] >= 40` 判定对方是否接纳，而**信念先验恰好等于 40**（`belief.csv` 的 `prior_a`）
→ 开局永远通过 → 唯一的「好感扣减」路径（`reject_affinity`）从不触发，好感成为单向棘轮，
标准差随天数收敛（当时实测 30 天 sd 仅 10.6）。改为「**信念 + 对方性格，门槛 45**」后通道打通，**SD 回到 23.6**。

### 未解决：敌对侧（诊断结论）

**现象**：30 天实测敌对**均值 0.2、单点最大 14.2** —— 全系统几乎**不存在「敌人」**。
因此 B 类行为【排挤】（判据 = ≥3 人对目标 `H ≥ 40`）**恒为 0 次**，即便把门槛放宽到 `H ≥ 25 / 2 人` 也不触发。

**定量根因**：

```
所有敌对事件都是常规档 +3，且一次只作用于一条边
→ 平均每边 +0.15/天，经 ×0.95/天 衰减 → 稳态约 3
→ 要稳态 40，需「每条边每天被敌对事件击中 0.67 次」——不可能
```

而**能产生重大档敌对的事件全部卡在死循环**里：

| 事件 | 前置 | 为何循环 |
| --- | --- | --- |
| 举报 | 敌对累积到阈值（`H ≥ 60`） | 而 `H` 恰好涨不到 60 |
| 泄密 | 先有秘密交换 | 该行为尚未实现 |
| 敌意传导（§5.2） | `H ≥ θ_H`（40） | 同样循环；实验把 `θ_H` 降到 15，单点最大也只升到 14.2 |

**结论**：本作缺的是**「敌对种子」**——一个能在**不依赖既有敌对**的前提下产生**重大档敌对**的事件。

### 候选方案（待定）

1. **新增【冷落】**（C 类，读信念）：只需「我对你的兴趣下降」即可发起，**不需要高敌对** → 是让关系变差的最直接通道；
2. 新增**重大档敌对事件**（如「当众羞辱」`base=5`，前置 = 围观 ≥5 人且 `A ≤ 30`）；
   ⚠️ **此稿未被采纳**：实际实现见 §9.4 —— 围观 = 调侃双方的**共同邻居**，**几何上界只有 4 人**，
   故「围观 ≥5 人」在任何配置下都**不可达**（若照抄会得到「羞辱永不发生」）。
3. 把**举报的前置**从「敌对达标」改为「掌握证据」，从而解开循环依赖。

### 8.17.1 【追逐打闹】—— 种子机制的第一版实验（**诊断结论已被解决，见下**）

> ✅ **2026-10-05 更新**：本节记录的「量级不足」**已经解决** ——
> 下面「下一步方向」的三条建议 **① 引入空间 / ② 让旁观者固定 / ③ 长期累积** 均已落地
> （分别是 §9.1 座位表、§9.1.3 打闹只吵邻座、§8.18 音量氛围 + §9.3 两层敌对）。
> **实测现状：排挤 80% 局上场、欺凌线成立**（见 §9.6 / §9.7 / §14.9 的「已落实」表）。
> **本节保留原文作为「诊断过程」的记录** —— 它展示了「机制对、但量级不够」这类问题的定位方法。

**机制**（已落地，见 §8.18）：`roughhouse` —— 参与者互相**好感↑**（A 类），
**路过的旁观者对参与者敌对↑**（B 类）。它满足种子判据：**t = 0 即可触发**（只需「有人在打闹」+
「有人在场」），不引用任何已有敌对值，因此**确实解开了死锁**（这是本机制的意义所在）。

**实测（30 天）**：

| 指标 | 结果 |
| --- | --- |
| 打闹次数 | 119 次（≈4 次/天） |
| *(以下两行为**当时**的实测，保留作对照)* | |
| 单点敌对最大 | **14.6**（此前 14.2 —— 有提升但**远低于排挤门槛 40**） |
| 四项玩法指标 | 爆发 28 / 饱和 0.0% / 均值 61.7 / SD 21.7 —— **全部达标** ✓ |

**为什么量级仍不够（定量）**：

```
每次打闹 ≈ 6 条边 × 约 1.5 点 = 9 点
4 次/天 × 9 = 36 点/天
但 17 人班级有 272 条**有向边** → 每条边 +0.13/天
×0.95 衰减 → 稳态 ≈ 2.7   （实测单点 14.6，说明偏好确实带来了一定聚焦，但不足以跨门槛）

要跨 40 → 需要每条边 +2/天 → 差约 15 倍
```

**真正的瓶颈不是机制，而是「边数」**：272 条边会把任何全局性事件摊薄。
实验中"旁观者按安静专注型排序"看似聚焦，但排序前先过滤了 `busy`，导致每次选到的人**并不固定**，
边没有真正固化下来。

**下一步方向（当初的候选）** —— **①②③ 全部已落实**：

1. ✅ **引入空间**（§9.1 座位表）：有向边 **272 → 88**，「路过的人」= **邻居**，同一对子反复相遇。
2. ✅ **让旁观者固定**（§9.1.3）：打闹旁观者**只取邻座**，去掉了「全班随机 + 排序受 `busy` 干扰」的问题。
3. ✅ **改为持续累积而非一次性**（§8.18 音量氛围 + §9.3 两层敌对）：音量是**持续**的压力/敌对源，
   而深层敌对**永不衰减**，冲突得以沉淀。
4. ⚠️ **提高单次幅度**：**未采用** —— 实测证明**加压无效**（`stress_k` 放大 12 倍仍无感，
   因为「信号只发给了小部分人」，见 §9.9.1）；真正起效的是**增加通路**（§9.4 当众羞辱 → `major` 写入深层）。

> **结论修正**：本节的诊断「瓶颈不在机制、而在边数」**是对的，但不完整** ——
> 真实瓶颈有**三层**：**边数（集中度）× 频率 × 跨阈值能力**，三者各需一把钥匙
> （座位表 / 音量氛围 / 两层敌对，见 §9.6.2 与 §14.9）。

## 8.18 环境层（班级级状态：音量）

> ✅ **已接线**（2026-10-05）：超阈音量 → **定向敌对**（单向），见 §9.2；超阈音量 → **压力**（`stress_k`），见 §9.9。

> 前面各节的系统状态只有两类：**个体**（`O` / `Stress`）与**关系**（`A` / `H` / `T`）。
> 本节引入**第三类 —— 环境**：整个教室的一个标量。**它不是"第六轴"**，而是与个体、关系并列的**另一层**。

### 为什么需要它

1. **量的累积产生质变**：2 个人聊天无所谓，**10 个人聊天就吵到别人**。
   这是关于「**集体**」的判断，不指向某个具体的人；
2. **它不受「边数摊薄」**：所有关系量都落在 N×N 条边上（17 人 = 272 条有向边），
   任何全局性事件都会被摊薄 272 倍；而环境量是一个**标量** ——
   同一个「打闹」，作为关系边被摊薄 272 倍，作为音量则 **100% 落到全班**；
3. **它给出「旁观者」的第二种形态**：此前只有「我讨厌你」（个人敌对），
   现在多了「**你们太吵**」（环境压迫）——而且这是**对群体的**，天然解释**责任分散**
   （「大家都吵，凭什么怪我」）。

### 动态

```
target  = clamp( Σ noise(各人当前行为), 0, volume_max )
volume ← volume + adapt_rate × (target − volume)     ← 有惯性（声音不会一秒消失）
excess  = max( 0, volume − volume_threshold )        ← 阈值效应，与传导阈值同构
Stress += excess × stress_k × 怕吵程度                ← 高 J（专注型）/ 内向者更敏感
```

**只有「发声」行为为正，安静行为一律 0** —— 安静的人不是「制造安静」，而是「不发声」；
「学习的人多 → 聊天的人少 → 音量自然低」是**自动**的，**不需要负号**。
（早期实现给安静行为写了负值，结果 `15 人学习 × (−5)` 把 `2 人聊天 × (+12)` 抵消成负数，音量恒为 0。）

### 阈值效应（已实测）

### 音量影响值的规格（0–3 常规 / 4–5 特殊）

与 `base` 铁律**同构**，但**下限可为 0**：

| 档 | 取值 | 含义 | 例 |
| --- | --- | --- | --- |
| **无声** | **0** | 物理上不产生声音 | 窃听 |
| **常规** | **1–3** | 日常行为的响度 | 学习 1、走动 1、流言（低声/纸条）1、告密（低声，计入环境音量）1、闲聊 2、搭话 2、当众调侃 3 |
| **特殊** | **4–5** | **很大的声音** | **追逐打闹 5** |

**定标原则：单人贡献必须小（因为人多）。**
全班 17 人都会发声 —— 若 `chat = 6`，17 人全聊 = 102 **必然爆表**（这正是早期版本音量恒 100 的根因）；
改 `chat = 2` 后：17 人全聊 = 34（不爆表），而 **10 人 = 20** 正是「开始吵」的位置。

**阈值必须跟着降**：60 需要 30 人才能达到，**永远触发不了**；最终按**实测音量**取 **20**
（课间 28.3 / 上课 18.7 —— 分界正在中间）。

#### 音量按「场」计，不按「人头」计

**多一个人加入同一场对话，音量几乎不变**（大家轮流说话，声音不叠加）；真正的吵闹来自
「**多出好几摊人各自在聊**」。所以同一场闲聊只有**一个声源**（发起者计入，加入者与聊天的其他参与者不计）：

| 情形 | 按「场」（正确） | 按「人头」（错误） |
| --- | --- | --- |
| 2 人同一场聊 | **2** | 4 |
| 3 人同一场聊 | **2**（与 2 人相同 ✓） | 6 |
| 两摊各 2 人 | **4**（递增 ✓） | 8 |

#### 音量的惯性 ≈ 5 秒

声音不会一秒消失，但也不该停留太久。`adapt_rate = 0.2`（时间常数 5 tick）≈ **5 秒现实**。
⚠️ **受 tick 粒度限制**：课间 1 tick = 6 秒，所以「3–5 秒」在数值上**不到 1 tick**，
只能在 1 tick 内趋近 —— 早先的 `adapt_rate = 0.02`（时间常数 50 tick = **5 分钟**）明显过久。


按 `chat` 噪音 = 6 反推，恰好对齐「10 个人聊天就吵」：

| 同时在闲聊 | 目标音量 | 判定 |
| --- | --- | --- |
| 1–8 人 | 6 – 48 | 正常 |
| **10 人** | **60** | **达阈（吵到别人）** |
| 12 人 | 72 | 吵到别人 |

### 当前状态（音量尺度已定标；压力效果已开启，氛围代价仍关闭）

- ✅ 机制与阈值效应已验证：开启 `stress_k` 后平均压力由 10~20 升至 **44.6**，确实生效；
- **当前取值**（以 `data/rules/environment.csv` 为准）：`stress_k = 0.40`（**已开启**，与 `noise_base_fear` 2.8 配合，§14.9 亦记为「环境层压力（已开启）」）；**`deviance_k = 0.0` 仍关闭** ——「偏离氛围只加压力」（§8.19）尚未启用，故双稳态还起不来；
- ⚠️ **仍未解决的是「音量的起伏」本身**（机制在跑，但起伏不够）：
  · 音量**长期饱和在 ~98**（`chat` 每 tick 6% × 持续 30 tick → 实测同时约 17 人在聊，全班都在聊，不现实）；
  · **专项标定轮已尝试过并记录结论**（把 `chat`/`tease`/`roughhouse` 频率降到 1/8，**音量确实出现了起伏：50.3 ~ 91.8，低段首次可见**），但代价是四项指标崩坏（**爆发 21 → 82**）——根因是 `chat` **一身两职**（见 §2.4.1 耦合表：它既是好感来源，又是减压来源）；
  · **结论**：音量起伏与四项指标**不能分两轮调**，必须做一次**联合标定**（同时考虑 `chat` 频率、`interrupted_stress`、`retain_s`、`decay_a_*` 与两个环境压力系数）。当前已**还原到四项达标的状态**，音量的「起伏」作为**已知待标定项**保留；
- 🔜 它是**双稳态**的基础：安静 → 更多学习 → 更安静（自习课）；吵 → 更多聊天 → 更吵（放羊课）。
  这一步需要「**行为选择受音量影响**」，尚未实现。

### 可扩展性

音量只是环境层的第一个标量。同一层还可以容纳「秩序度」「集体情绪」等 ——
它们共享同一个特征：**班级级、有惯性、过阈才产生个体后果**。

## 8.19 从众与环境反馈（氛围 → 行为选择）

> §8.18 只做了「环境 → 压力」的单向。本节补上闭环的另一半：**环境 → 行为意愿**，
> 并确立一条原则 —— **偏离氛围只增加压力，不禁止任何行为**。

### 从众度：大部分从众，少数有主见

```
conformity(i) = clamp( 0.5 + (F−50)/100 − (J−50)/100·0.5 − (N−50)/100·0.5, 0, 1 )
```

- **高 F**（情感型，在意氛围）→ 从众；
- **高 J**（判断型，有自己的计划）**+ 高 N**（直觉型，脑内自成一套）→ 反从众。

实测 17 人分布在 `0.00 ~ 0.90`（从众者 7 人 / 反从众者 8 人）——
**两类人天然并存，不需要任何特例**。

### 氛围 → 行为意愿

```
想社交的意愿 += conformity × volume/100          （吵 → 从众者更想参与）
想学习的意愿 += conformity × (1 − volume/100)    （静 → 从众者更想学习）
```

从众者跟着环境走；**反从众者完全不受影响**。于是就自然出现了那两种情况：
**「安静也要聊天」和「吵闹也会学习」**。

### 偏离 → 压力（而不是禁止）

安静教室里偏要聊天 → 压力上升（会被侧目）；吵闹教室里偏要学习 → 压力上升（「学不进去」）。
低从众度者不是不被罚，而是**本来就少偏离、且扛得住**。

> **这是「社会压力」的机制化**：你可以顶着氛围来，但要付代价。
> 若改成「禁止」，环境层就变成了「纪律」——那是另一回事，也丢掉了戏剧性。

### 为什么这构成双稳态

```
吵  →  从众者更想聊  →  更吵      ┐
静  →  从众者更想学  →  更静      ┘   两个吸引子（§5.1 所说的「多个吸引子」）
反从众者提供「噪声」，使系统可能被推过临界点、翻到另一个态
```

### ⚠️ 什么不能做：「学霸」不是规则

「**学霸除了压力爆发都会学习**」这个描述**不能照字面实现** —— 那是**身份判断**，违反铁律 §9.11
（「换成脚本还成立吗」这一检验会立刻崩掉）。正解是让「总在学习」**涌现**：

```
总在学习 = 高 J（有计划）
         × 低从众度（不受氛围左右）
         × 「爱学习」标签（study_bias +50%）
           ↑ 三项全是 f(性格, 标签, 状态)，没有一项是「因为他是学霸」
```

**标签是结果，不是原因。** 观察层可以给这样的人贴上「学霸」的**描述性**标签，
但它**只读**，不得回写任何数值（§8 观察层铁律）。

## 8.20 观察层（簇标签器）—— 只读、按透明度过滤、每角色一份视角

> ✅ **已实现**（2026-10-05）：`core_sim.ObserverLayer`。规格来源 `信念矩阵.md` §9。

### 8.20.1 两条约束，不是一条

| 约束 | 保证什么 |
| --- | --- |
| **只读**（不回写） | 标签**不干扰**模拟 —— 不产生「因为你是被孤立的所以大家排斥你」的自证循环 |
| **按透明度过滤** | 标签看到的是**玩家该看到的东西** —— 不是上帝视角 |

> ⚠️ **只靠「只读」不够**：标签器完全可以「只读、不回写」却**直接读真值矩阵**，那对玩家就是**全知视角**。
> §5.4 的原则是「**凡是涉及感知的读取都要经透明度（+信任）过滤**」，而标签器的输出正是
> 「**玩家感知到的班级结构**」，因此它**是透明度的下属**。
> 这与 §9.5.2（从众不再读真值）是**同一个原理**。

### 8.20.2 实现（三档可见性，复用 §9.11 阈值）

```
visibility(viewer, target)  由【被观测者】O[target] 决定：≥50 clear / ≥20 blurry / 否则 sealed
seen_matrix(viewer, axis)   clear→真值 ｜ blurry→只知「有变化」取中性 ｜ sealed→null（看不见＝不知道）
cluster_tags(viewer)        §9.11 强连接阈值 A≥60（**双方都能看见**才连边）→ 连通分量 → ≥3 人成簇
isolated_tags(viewer)       被好感低于均值 −15 且 给好感高出被好感 +15（§9.7.3 的判据）
```

**于是「藏着的人，连标签都藏住了」** —— 低透明度角色的关系读不到，自然落不进任何簇。

### 8.20.3 ⚠️ 首次运行照出两个底层问题（**这是标签器的价值，不是它的缺陷**）

**① 好感分布是「温和的平原」，没有山峰。**
实测（30 天）：好感均值 57，而亲近阈值是 60 —— 「60」在实际分布里只是「略高于平均」，

## 8.21 所有活动都可加入：从 `join_chat` 到「跟着做」

> ✅ **已实现**（2026-10-05）。数据：`behaviors.csv` 的 `join_mode` 列；参数：`free_join_rate`。

### 8.21.1 问题：只有闲聊能"加入"

> **2026-10-07 收口：** 下文问题描述是旧设计背景。现在“加入”是通用参与操作，闲聊不再拆出“搭话”主行为；在闲聊中以 start／join 记录发起／加入，继续共用同一个活动类型。

`join_chat` 原本是一个**特例** —— 只有"加入别人的闲聊"这条路径存在，
而每个人做其他事（学习 / 打闹 / 走动 / 睡觉）时都是**独立决定**，然后碰巧撞在一起。

**但现实中"加入"是普遍现象**：

```
别人在学习 → 我也摊开书        （学习圈）
别人在打闹 → 我也凑过去        （打闹圈）
别人在聊八卦 → 我也凑过去听    （聊天圈）
别人走动   → 我也跟着走        （走动圈）
```

### 8.21.2 设计：`join_mode` 三分类

| 类型 | 含义 | 活动 |
| --- | --- | --- |
| **`accept`** | **加入时需要对方判定**（接受 / 拒绝） | 闲聊 / 当众调侃 / 追逐打闹 / 安慰 / 求助 / 秘密交换 / 告密 |
| **`free`** | **自由跟随，无需谁同意** | **学习** / 睡觉 / 走动 / 窃听 |
| **`none`** | 不可加入 | 举报 / 排挤 / 道歉和解 |

- **`accept` 类**沿用 `do_join_chat` 的判定（**被请求者的真值好感 `A[j][i]`** + 对方外向度）——
  **接受 → 绿圈；拒绝 → 红圈**（拒绝还会反噬，见 `reject_*` 三个事件）。
- **`free` 类**由新增的 `free_join()` 处理：**「别人做什么，我也跟着做什么」**。

### 8.21.3 `free_join` 与 `conformity` 的关系（从众第一次落到行为层）

> **`conformity(i)`（§8.19）管「我倾向做什么」**（氛围影响意愿，原有）；
> **`free_join` 管「我具体跟谁做」**（看到别人在做，我也做，**新增**）。

```
跟随概率 = free_join_rate × conformity(i)
```

**于是"从众"第一次从意愿层落到了行为层**：
高 F 者随大流（看到别人学就学、看到别人走动就走）；高 J / 高 N 者有主见，**不被裹挟**。

> ⚠️ **「学习」是个例外**：它是 `default` 状态、不占用时间槽，**不体现在 `current_act` 里**。
> 但现实中它恰恰最常被跟随（"看他摊开书，我也学"）。
> ∴ 判定为：**邻居此刻既不忙、也不在做别的事 → 他在学习 → 可跟着学**。

### 8.21.4 只读查询（供 UI 画圈 / 上色，零副作用）

| 查询 | 返回 |
| --- | --- |
| `activity_of(i)` | 某人此刻在做什么 |
| **`active_circles()`** | **当前的「活动圈」**：按「此刻在做同一件事」分组 → `{'chat': [2,3,5,9,12], 'roughhouse': [1,14,16]}` |
| `join_feedback(i, j)` | 这次加入判定会「接受」还是「拒绝」→ **供 UI 上绿 / 红** |

> **「活动圈」与簇标签器是两个尺度**：
> **活动圈**是**实时、局部、可见**的（秒级，对应 §12.1「小人在教室的物理位置就是第一画面」）；
> **簇标签**是长期的格局（天级，供每日简报与阵营分裂判定）。两者不冲突，各有用途。

**内核只提供"谁和谁在一起"；画绿圈 / 红圈、不同活动不同颜色是 Godot 渲染层的事。**

### 8.21.5 实测与标定

`free_join_rate` = **0.10**、`stress_k` = 0.40：跟做正常发生（30 天十余次），活动圈正确输出多类分组；
四项指标 **爆发 18.9（15–30）· 好感均值 59.5 · SD 21.9** ✓。

> ⚠️ **它与压力有耦合**：`free_join` 让人扎堆 → 音量↑ → 压力↑ → 爆发↑。
> 实测 `free_join_rate` 0.25 → 0.05 时爆发由 52 降到 36，故最终取 0.10 并配合 `stress_k` 标定。
> **这是"跟随"带来的自然代价：班级更容易一起行动，也更容易一起吵。**
## 8.22 判定展示：NPC 静默，玩家掷骰

> ✅ 规格（用户设计）。内核侧只读查询：`verdict(i, j, kind)`（`core_sim.py`）。

### 8.22.1 同一次判定，两种呈现

**判定公式只有一套**（NPC 与玩家完全同源，不做任何区别对待）；区别只在**呈现**：

| 对象 | 呈现 |
| --- | --- |
| **NPC ↔ NPC** | **静默出结果** —— 不弹窗、不展示过程 |
| **涉及玩家** | **展示三拍**：① 当前成功率 → ② 掷骰 → ③ 结果（绿 / 红） |

> **为什么 NPC 静默**：一个课间段可能发生几十次判定，逐个展示会**淹没玩家**，
> 而且会**泄露别人的关系状态**（那正是观察层要按透明度过滤的东西，§8.20）。
> **NPC 的结果照常影响世界，只是不告诉玩家"这里刚刚掷了一次骰"。**

### 8.22.2 为什么玩家需要「掷骰」而不是直接给结果

用户指出的问题：**「直接就同意或拒绝不好」** ——

- **直接拒绝**会让玩家觉得**被系统针对**（"凭什么？我又没做错什么"）；
- **直接同意**则让玩家觉得**理所当然**，关系毫无分量。

**掷骰把"运气"放进画面**：玩家看到"我有 72% 的把握"→ 掷 → 失败，接受的是**手气**，
而不是"游戏在刁难我"。同时它**顺带给出了情报**：成功率本身就在告诉玩家
「**你和这个人现在到什么程度了**」。

### 8.22.3 ⚠️ 关键约束：成功率必须从「信念」算，不能从真值算

**这是本设计唯一必须守住的点。**

```
展示（玩家看到的成功率）= f( B_A[i][j] )   ← 信念：「我以为对方对我多有好感」
结算（实际掷骰用的 p）  = f( A[j][i] )     ← 真值：「对方实际对我多有好感」
```

> **两侧必须分开实现**：结算侧 `join_score` 读真值 `A[j][i]`，展示侧 `join_feedback` 读信念 `B_A`。
> 若两侧都用信念（曾如此），显示值就**永远是准的**，本节的「认知偏差具象化」会被架空；
> 若两侧都用真值，则等于把对方心里的态度直接告诉玩家，**泄露隐藏信息**。
> 2026-10-07 已按此收口，见 §14.9。

因为信念属于**感知层**（§5.4），所以：

| 好处 | 说明 |
| --- | --- |
| **不泄露隐藏信息** | 玩家看到的只是**自己的猜测**；对方心里怎么想，界面**不会**替他揭晓 |
| **概率高也可能失败** | 「我以为他喜欢我」≠「他真的喜欢我」—— **掷骰成为认知偏差的具象化** |
| **与观察层一致** | 与 §8.20「藏着的人连标签都藏住了」同一条原则：**凡是涉及感知的读取都要过滤** |

> **∴ 掷骰不是装饰，而是把「信息不对称」演给玩家看**：
> 他会经历「我明明有 80% 把握……」—— 这正是这个游戏想要的体感。

### 8.22.4 成功率的形状：**渐变的把握，不是门槛的开关**

> 实现过程中改过两次，两次都是**"展示没有信息量"**导致的：

| 版本 | 写法 | 后果 |
| --- | --- | --- |
| 初版 | `if 对方压力 > 70 → p = 0` | 全班压力普遍偏高 → **成功率恒 0%**，玩家永远看到 0 |
| 二版 | `p = 0.5 + (把握 − 门槛)/40` | 斜率太陡，`accept` 稍低就掉到 0 → 实测落在 **0~17%** |
| **采用（现行）** | `p = σ((score − θ)/scale)`（logistic sigmoid），压力**降低**把握而非归零 | 概率再低也可能成功、再高也可能失败，无固定门槛 |

**两条原则**（可复用到所有"成功率展示"）：

1. **压力是程度，不是闸门** —— 它应当**削弱把握**，而不是把概率打到 0。
   判定本身也改为同一 `p` 掷骰（§4.4），不再保留"越过门槛才成功"的硬闸门。
2. **把握必须渐变且非线性** —— 用 `σ((score − θ)/scale)`：门槛处 50%，两侧平滑延伸且**永不为 0/1**。
   概率低也可能成功、概率高也可能失败，成功率始终是情报，不是结果的复读。

### 8.22.5 适用面

本规格**不限于加入活动**。§3.6 起文档里已多处出现「成功率 / 概率修正」
（求助 +25%、守密 −30%、调侃按共情判定……），它们的**玩家侧呈现规则一致**：

```
NPC 用 → 静默；涉及玩家 → 三拍（成功率 → 掷骰 → 结果）
```

内核实现时，各行为判定按同一模式提供只读的 `verdict()` 即可，**不必各写一套**。
