## 25.1 为什么要这一章

策划案里角色是「纸片人」（`classroom_actors.gd` 用 `Sprite3D` + `BILLBOARD_FIXED_Y`，不参与碰撞与寻路）。
现状是：**行为变了、立绘不动** —— 只读静态立绘，动作帧虽已入库却无任何代码引用。
本章把「行为 → 动作组」的口径定死，使后续实现有据可依、美术补帧有名可对。

## 25.2 资产命名规范（已有实例就按这个形状对齐）

| 层 | 路径 | 约定 |
|---|---|---|
| 动作帧 | `assets/textures/characters2.5D/<角色>/{<动作>组}_{<序号>}.png` | 序号从 **0** 起连续；每组 **1..N 帧** |
| 立绘场景 | `scenes/characters2.5D/<角色>_billboard.tscn` | 内含 `SpriteFrames`，每组动作 = 一个动画名 |
| 静态立绘 | `scenes/characters/<角色>.tscn` | **回退用**，当前 18 个角色均有 |
| 玩家 | `scenes/characters/player_female|male.tscn` | 按 `GameState.player_gender` 选 |

小写蛇形；`<角色>` 就是 `_chars[i]` 的枚举名（如 `quiet_female`），**绝不在脚本里判断角色名**（主文档 §9.11）。

## 25.4 行为 → 动作组 映射（纯只读）

| 内核行为（`activity_of(i)`） | 动作组 |
|---|---|
| （空串，即空闲） | `stand` |
| `study` | `homework` |
| `chat` | `chat` |
| `sleep` | `sleep` |
| `apologize` | `apologize`（面向对象时可选 `apologize_right`） |
| 其余未映射行为 | `stand` |

硬约束：

1. **只读**：动作切换只读 `activity_of()` 与 `is_moving()`，**不写任何矩阵、不改数值**（主文档 §8 观察层只读）。
2. **不影响玩法**：播哪一组动作不参与判定，不回写内核，不消耗 RNG。
3. **映射外置**：上表落 `data/`（拟 `data/ui/character_actions.csv`，**待建**），不得写死在脚本里。

## 25.5 回退策略（实现时必须逐档生效）

1. 角色**无** 2.5D 立绘目录 → 用**静态立绘**（现状行为）。
2. 有目录但**缺该动作组** → 回退 `stand`。
3. **连 `stand` 也缺** → 回退静态立绘。
4. **玩家**暂无动作帧 → 回退静态立绘（按性别）。

回退必须**静默生效**（不报错、不打断玩法），且**不得因缺帧而隐藏角色**。

## 25.7 验收（实现后必须通过）

1. 给定行为 → 立绘播放对应组（学习看得出在写作业、睡觉看得出在睡）。
2. 缺动作组的角色不报错、不隐身，回退到 `stand` 或静态立绘。
3. 切换过程不改任何内核数值（同种子对拍不受影响）。
