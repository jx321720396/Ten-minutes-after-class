> 状态：策划案 ｜ 实现状态：未开工（**本章只定规格**，代码留待下一批）｜ 制定：2026-10-10
> 依据：用户 2026-10-10 裁定「先定规格再实现」；现状勘察见 `docs/production/人物动作勘察-2026-10-10.md`
> 本章只回答「立绘怎么命名、行为怎么切动作、缺东西怎么回退」—— **不含任何数值与代码落点**（那些进 `data/` 与第二十章）。

## 25.1 为什么要这一章

策划案里角色是「纸片人」（`classroom_actors.gd` 用 `Sprite3D` + `BILLBOARD_FIXED_Y`，不参与碰撞与寻路）。
现状是：**行为变了、立绘不动** —— 只读静态立绘，动作帧虽已入库却无任何代码引用。
本章把「行为 → 动作组」的口径定死，使后续实现有据可依、美术补帧有名可对。

## 25.2 资产命名规范（已有实例就按这个形状对齐）

| 层 | 路径 | 约定 |
|---|---|---|
| 动作帧 | `assets/textures/characters2.5D/<角色>/{<动作>组}_{<序号>}.png` | 序号从 **0** 起连续；每组 **1..N 帧** |
| 立绘场景 | `scenes/characters2.5D/<角色>_billboard.tscn` | 内含 `SpriteFrames`，每组动作 = 一个动画名 |
| 静态立绘 | `scenes/characters/<角色>.tscn` | **回退用**，当前 18 个角色均有 |
| 玩家 | `scenes/characters/player_female|male.tscn` | 按 `GameState.player_gender` 选 |

小写蛇形；`<角色>` 就是 `_chars[i]` 的枚举名（如 `quiet_female`），**绝不在脚本里判断角色名**（主文档 §9.11）。

## 25.4 行为 → 动作组 映射（纯只读）

| 内核行为（`activity_of(i)`） | 动作组 |
|---|---|
| （空串，即空闲） | `stand` |
| `study` | `homework` |
| `chat` | `chat` |
| `sleep` | `sleep` |
| `apologize` | `apologize`（面向对象时可选 `apologize_right`） |
| 其余未映射行为 | `stand` |

硬约束：

1. **只读**：动作切换只读 `activity_of()` 与 `is_moving()`，**不写任何矩阵、不改数值**（主文档 §8 观察层只读）。
2. **不影响玩法**：播哪一组动作不参与判定，不回写内核，不消耗 RNG。
3. **映射外置**：上表落 `data/`（拟 `data/ui/character_actions.csv`，**待建**），不得写死在脚本里。

## 25.5 回退策略（实现时必须逐档生效）

1. 角色**无** 2.5D 立绘目录 → 用**静态立绘**（现状行为）。
2. 有目录但**缺该动作组** → 回退 `stand`。
3. **连 `stand` 也缺** → 回退静态立绘。
4. **玩家**暂无动作帧 → 回退静态立绘（按性别）。

回退必须**静默生效**（不报错、不打断玩法），且**不得因缺帧而隐藏角色**。

## 25.7 验收（实现后必须通过）

1. 给定行为 → 立绘播放对应组（学习看得出在写作业、睡觉看得出在睡）。
2. 缺动作组的角色不报错、不隐身，回退到 `stand` 或静态立绘。
3. 切换过程不改任何内核数值（同种子对拍不受影响）。

## 25.8 已知缺口：同局立绘复用（2026-10-12 立案）

**现象**（实测：`scripts/core/roster_selector.gd` + `data/characters/appearance.csv`）：角色池 24 人只映射到 **12 张在用立绘** —— 16 张 NPC 素材里的 `blunt_female` / `sensitive_male` / `shy_male` / `warm_female` **四张无人使用**，最挤的一张 `quiet_male` 由 4 个角色（03 / 05 / 10 / 16）共用。抽取只做「绑定组 + MBTI 极性覆盖」，**不看立绘是否重复**，因此同局必然出现「同一张脸」：

| 难度 | 本局不同立绘数（含玩家时节点数） | 复用组（示例 seed 20261007） |
|---|---|---|
| 8 NPC（9 节点） | 6 张 | `warm_male`×2（陈阳 / 佳豪）、`lively_female`×2（赵蕊 / 孙悦） |
| 16 NPC（17 节点） | 11 张 | 上述两组 + `sensitive_female`×2、`stern_female`×2、`shy_female`×2 |

**不是重复摆放**：座位没有冲突（`seat_of(i)` 每人一席，实测冲突 0）；差的只是素材复用。

**决策（2026-10-12 用户裁定）：暂不改** —— 维持「24 角色复用 16 张立绘」，一局内的同脸靠**名字牌**区分，等美术补立绘后再收口。

**复核触发条件**（任一满足即重开本项）：

1. 美术补出新脸，或决定改用「抽取按立绘去重」——后者需同时改 `RosterSelector` 与 `tools/core_sim.py`（该类当前**不消费随机数**，名单只由绑定组与极性覆盖决定），并重跑逐 tick 对拍与第四 / 五道门；
2. 选座面板（§22.3）用 `appearance.csv` 的立绘缩略当头像时，同脸复用会变成「两张一样的头像」——那时优先处理；
3. 2.5D 动作组铺开（§25.6）后，同一张立绘的多名角色会**同步播放同一套动作**，辨识度进一步下降。
