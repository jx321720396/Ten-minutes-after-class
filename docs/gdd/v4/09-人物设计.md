# 第九章 人物设计（分层重构）

> **标签按底层轴分类**（见 `data/rules/tags.csv`）：标签不是「身份」，而是**对某个轴的调制**。
> 作用轴四类：`behavior`（行为倾向）/ `info`（信息：守密·传播·泄露）/ `relation`（关系倾向）/ `environment_fact`（客观条件，如「带手机」，**不是倾向**）。
> 影响强度两级：`weak`（小部分影响，约 ±10%）/ `strong`（长久影响，约 ±50%）。
> 这样行为逻辑才能保持为 `f(性格, 标签, 状态)` —— 见 §8.19 结尾「学霸不是规则」。

## 9.1 空间层（座位表）

> ✅ **已实现**（2026-10-05）。数据表：`data/rules/seats.csv`。

### 9.1.1 布局

**4×4 网格 + 讲桌旁 1 座 = 17 座**，正好对上本局节点数（16 NPC + 1 玩家）：

```
        [ 黑 板 ]
      [ 讲 桌 ] [P0]        ← 讲桌旁：老师眼皮底下
      [P1 ][P2 ][P3 ][P4 ]  ← 第一排（离黑板最近）
      [P5 ][P6 ][P7 ][P8 ]
      [P9 ][P10][P11][P12]
      [P13][P14][P15][P16]  ← 最后一排
```

**讲桌旁的座位是「特殊座位」，但不需要任何特殊规则** —— 它的两个效应都由**邻接表自动产生**：
- **邻居最少（2 个，全班最少）** → 社交机会天然最少；
- **离黑板最近** → 学习条件最好。

**三档难度布局（§9.14 抽取人数）**：

| 难度 | 节点数 | 布局 | 空位规则 |
| --- | --- | --- | --- |
| 简单 | 9（8 NPC + 玩家） | **3×3 网格，9 座**，无讲桌旁 | 无空位 |
| 标准 | 17（16 NPC + 玩家） | **4×4 网格 + 讲桌旁 1 座**（本页上图） | 无空位 |
| 困难 | 25（24 NPC + 玩家） | **5×5 网格，25 座**，无讲桌旁 | 无空位 |

- **空位不计邻居**：任何档位下，未分配角色的座位不进邻接表、不作为走动目标；
- **实现要求**：`seats.csv` 按难度分表（或加 `difficulty` 列），`assign_seats()` 先按难度选布局，再把角色洗牌填入该布局的全部座位；**禁止**从单一 17 座表里截前 N 个（那样简单档会把讲桌旁 P0 优先分掉，困难档直接越界）。

> 这是本项目「**不写特例规则**」原则的一次示范：只要座位是真的，
> 「老师眼皮底下」的社会含义就会**从位置本身涌现**出来，不需要 if 判断。

### 9.1.2 邻接与边数

邻接 = **8 邻域**（上下左右 + 对角），即「相邻 ≤ 1 格」（§2.3）。

| | 无向边 | 有向边 |
| --- | --- | --- |
| 修复前（人人彼此相邻） | 136 | **272** |
| 座位表落地后 | 44 | **88** |

**降了 3 倍**，但更关键的不是总数，而是：**邻居是固定的** —— 同一对子会反复相遇，
而不是在 272 条边上随机撒点。

### 9.1.3 接入点

| 机制 | 空间如何介入 |
| --- | --- |
| **选交互目标** `pick_target` | **邻居加权**（`neighbor_pick_mult` = 3.0）：邻居中签概率是非邻居的 3 倍；非邻居仍可能（有人走动），但显著少 |
| **追逐打闹** `do_roughhouse` | 旁观者**只取邻座** —— 修复前是「全班路过的」，一次打闹就摊到全班的边上，这是边数摊薄的主因 |
| **调侃** | 候选**限邻居**（§8.12「周围 ≥3 人围观」的前提就是近） |
| **相邻修正**（§8.15） | 由邻接表给出确切的「相邻 ≤1 格」 |

### 9.1.4 实测效果（30 天）

| 指标 | 结果 |
| --- | --- |
| **邻居间好感** | **66.9**（非邻居 62.7）→ **空间真的改变了关系结构** |
| 讲桌旁邻居数 | **2**（全班最少，平均 5.2） |
| 有向边 | 272 → **88** |
| 四项玩法指标 | b=15 / sat 0.0% / mean 64.0 / SD 20.7 ✓ |

> ⚠️ **重要教训**：空间**解决了「集中度」，没有解决「量」** —— 单边敌对日增量只从 0.13 升到 **0.18**。
> 「边数摊薄」与「种子频率太低」是**两个问题、两把钥匙**（详见 §8.17.2 的实测修正）。

## 9.2 音量氛围 → 定向敌对（单向通道）

> ✅ **已实现**（2026-10-05）。参数：`environment.csv` 的 `noise_hostility_base` / `noise_scale`；
> 事件：`w_events.csv` 的 `noise_hostility`。

### 9.2.1 设计（不对称是灵魂）

超阈音量除了「转化为压力」（§8.18 `noise_pressure`），还会**转化为敌对**——
但**只在一个方向上**：

| 方向 | 成立？ | 原因 |
| --- | --- | --- |
| **安静 / 学习者 → 敌视吵闹者** | ✅ | 他**真的在受损**（被打扰、学不进去） |
| 吵闹者 → 敌视安静者 | ❌ | 他**不觉得自己被打扰** |

∴ 这是本项目**第一条天然单向的关系通道**（其余通道都对称）。
它来自一个朴素的现实观察：**被吵到的人记恨，吵的人浑然不觉。**

### 9.2.2 实现

| 环节 | 规则 |
| --- | --- |
| **谁怕吵** | 复用已有的 `fear_e` / `fear_j`（§8.18）—— `fear = f_j·(P−50)/50 + f_e·(50−E)/50`，越内向、越专注越怕吵 |
| **恨谁** | **邻居中最吵的 2 个**（`noise_of` 取自 `behaviors.csv` 的 `noise` 列）—— 只有近处的人吵得到我 |
| **多恨** | `base × scale × 性格调制 × 关系调制`，走统一影响公式（`scale` 随音量强弱缩放） |
| **多久一次** | 涓流：每天 2 次（`settle_interval`），与 `noise_pressure` 同一节奏 |

**与 `noise_pressure` 是同源分岔**：同一个 `fear`、同一个超阈音量，
一份转成**压力**（内耗），一份转成**敌对**（指向他人）。这正是「同一刺激、两种社会后果」。

### 9.2.3 实测与瓶颈

30 天（seed=12345，17 节点）：

| 指标 | 结果 |
| --- | --- |
| 恨噪音结算 | **475 次**（约 5.4 次/边，频率充足） |
| **敌对 max** | **8.8 → 19.5**（2.2 倍） |
| `H ≥ 25` 的边 | 0（**仍未跨过排挤门槛**） |
| 四项玩法指标 | b=29 / sat 0.0% / mean 62.0 / SD 21.5 ✓ |

> ⚠️ **瓶颈定位**：`494 次 ÷ 88 边 ≈ 5.6/边 × 3 点 ≈ 16.8`，与实测 `max 17.5` 吻合。
> 换算日增量 **0.56/天 → 稳态 11**，要跨 25 需 **1.25/天**，还差 2.2 倍。
> **加大 `base` 无效**（实测 2.0→4.7、3.0→17.5、4.0→11.7）——因为**`room_for` 负反馈**
> （"越满越难涨"）是硬约束：**推得越猛，越早撞天花板**。
>
> ∴ 要真正跨过阈值，需要的是**结构性手段**（记恨边状态 §8.17.2 种子六、状态标签），
> 而不是继续调幅度参数。

## 9.3 两层敌对（表层会消，心结永远在）

> ✅ **已实现**（2026-10-05）。**已由 §9.4「当众羞辱」打通** —— 深层敌对第一次真正转起来。
> 空转阶段的记录保留在 §9.3.3，它解释了「为什么光做机制还不够」。

### 9.3.1 为什么要分两层

用户提出的直觉：**人对仇恨的记忆非常深刻**，被背后捅刀子这种事不该随时间淡掉。

但「所有敌对都不衰减」会带来一个数学后果：`H` 单调递增 → 关系**只坏不好** → 再也回不来，
连「后来和好了」这种剧情都发生不了。∴ 采取**两层分离**：

| | **表层** | **深层** |
| --- | --- | --- |
| **来源** | 日常摩擦：调侃、音量、打闹、传谣 | **只为 `tier = major` 的负性事件**（举报、秘密泄露） |
| **衰减** | 每天 ×`decay_h`（0.95） | **永不衰减** |
| **能否修复** | ✅ 道歉、相处可磨平 | ❌ **永远在** |
| **参与 `room_for`？** | 是 | **否** |

```
H[i][j]（总敌对） = 表层 + 深层
```

这正是现实里最真实的那种关系：**「我可以原谅你，但我忘不了那件事。」**

### 9.3.2 实现（单点改动）

`H` 存的仍是**总敌对**，`H_deep` 记其中「忘不掉的那一部分」。于是衰减只需一行：

```python
deep = self.H_deep[i][j]
self.H[i][j] = deep + (self.H[i][j] - deep) * decay_h     # 深层原样保留
```

写入走统一影响公式，但**不经 `room_for`**：

> ⚠️ 负反馈是给「表层摩擦」用的。若也套在深层上，仇恨会**自己封顶**（越满越涨不动），
> 「不可消减」就名存实亡了。

### 9.3.3 实测：机制正确，但空转

30 天（seed=12345）：

| 指标 | 结果 |
| --- | --- |
| **深层写入次数** | **0** ← 空转 |
| **总敌对 max** | **19.5（与实现前完全一致）** → **无回归** ✓ |
| 普通对子敌对 | 均值 0.11 / max 15.3 → **「不误伤」守住** ✓ |
| 四项玩法指标 | b=29 / sat 0.0% / mean 62.0 / SD 21.5 ✓ |

**为什么空转**：`major` 档的 hostility 事件只有两个，而**两个都不会发生**：

| 事件 | base | 门槛 | 现状 |
| --- | --- | --- | --- |
| `report_hostility`（举报） | 5 | 需 `H ≥ 60` | 最高只到 19.5 → **不发生** |
| `leak_hostility`（秘密泄露） | 4 | 需「先有秘密交换」 | 该行为**未实现** → **不发生** |

> ∴ **门修好了，只是还没有人走。** 下一步应先让**某条通往 `major` 的路打通**，
> 而不是再调敌对幅度参数（那已被 `room_for` 证明无效，见 §9.2.3）。

## 9.4 当众羞辱 → 深层敌对（把 §9.3 的门打开）

> ✅ **已实现**（2026-10-05）。事件：`humiliate_hostility`（`w_events.csv`，`tier=major`，base 4）；
> 阈值：`humiliate_bystanders`（`behavior_thresholds.csv`，= **4**）。
>
> ⚠️ **2026-10-05 第一次修 P0：三处连锁错误**（外部核对发现，经核验成立）：
> ① `do_tease` 调用处写了 `audience[:3]` —— **把围观者截断为恰好 3 人**，与门槛 3 构成 `3 ≥ 3` 恒真；
> ② 围观者曾取「**全班非忙碌角色**」（13~15 人），任何「被围着」的门槛都会恒真 —— 但「围观」本是**空间概念**（§8.12「周围 ≥3 人」），已改为「**调侃双方的共同邻居**」（最多 4 人）；
> ③ 阈值表把整串 `humiliate_min_bystanders` 写进了 `behavior` 列，键变成
>    `humiliate_min_bystanders_bystanders` → 代码 `th.get(..., 3.0)` **静默回落到默认 3.0**。
>
> ⚠️⚠️ **2026-10-07 第二次修 P0：第一次的修法并没有真正生效，恒真一直存在。**
> 删掉 `audience[:3]` 只让 `audience` 从「恒等于 3」变成「**3 或 4**」，
> 而**调用点的 `len(audience) >= 3` 门槛没有跟着动** —— 恒真从 `3 ≥ 3` 平移成 `(3 或 4) ≥ 3`，
> 判定结果一字未变。1000 局实测 **羞辱 / 过火 = 1.00**，上文曾写的「修正后 0.54 / 17 次/局」
> **从未复现过**（与 §14.9 GDScript 虚报同类：把「改了一处」记成了「全部修好」）。
>
> **根本原因：区分变量的取值空间被空间模型压成了 1 bit。**
> 围观者 = 调侃双方的**共同邻居**（8 邻域交集），几何上界就是 4 人；30 局 1407 次调用实测
> `len(audience) ∈ {3, 4}` —— 只有两个取值，而门槛恰好卡在这个 bit 的边界上。
> 「被围着」本该是连续量，落到实现里没有任何区分度。
> **∴ 修法是把门槛抬到几何上界 4**：3 人 = 普通摩擦（表层，会淡忘），4 人 = 被围满（写深层）。
> 这同时让「两人座位紧挨、被同一批人夹住」成为可判定的空间条件，而不是拍脑袋的数字。

### 9.4.1 为什么是「当众」

§9.3 建好两层敌对后**一直是空转的**：`major` 档的 hostility 事件只有举报（需 `H ≥ 60`）与秘密泄露
（所需行为未实现），两个都不会发生 —— **门修好了，却没有路通向它**。

打通它的关键是找到一个**真正会发生的 `major` 场景**。「过火调侃」（嘲讽档）每天都有，
但**它本身不该是 `major`** —— 那句话可能有三种社会含义，多数只是"过火"，不是"创伤"。

**区分在哪？** 观察到的现实：**同样一句难听话，私下说只是摩擦，被人围着说就是羞辱。**

| 情形 | 后果 |
| --- | --- |
| 私下的嘲讽 / 一般过火 | 表层摩擦（会淡忘，`decay_h` 照常） |
| **当众羞辱**（围观者 ≥ `humiliate_bystanders`） | **写进永不衰减的深层** |

∴ 升级条件**只看"有多少人在看"** —— 这是纯粹的处境条件，**与是谁无关**（没有角色特例）。

### 9.4.2 实现

在 `do_tease` 的**嘲讽档**分支里，多结算一次：

```python
if len(audience) >= th.get("humiliate_bystanders", 4.0):
    self.apply_event(j, i, "humiliate_hostility")   # tier=major → 自动写进 H_deep
```

不需要新代码路径 —— `apply_event` 里已有「`tier=major` 的 hostility 同时写深层」的规则（§9.3）。

### 9.4.3 实测（**2026-10-07 基准：θ=4，100 局**）

> ⚠️ **本节历史上先后出现过两组数字，两组都不可引用**：
> ① 「羞辱 38 次/局、深层 max 100、`H ≥ 25` 5 条」——「`audience[:3]` 截断 + 门槛静默回落」时代的产物；
> ② 「羞辱 17 次/局、羞辱/过火 0.63」—— 声称是修好之后测的，但**同样不成立**：
>    删截断没动调用门槛，判据当时仍然恒真，1000 局实测羞辱/过火 = **1.00**。
> 下表是**阈值抬到共同邻居几何上界 4（§9.4 头部）之后**重测的基准。

数据口径：**100 局 × 30 天 × 16 NPC**（种子 1000–1099；§2.4.1 六：看分布不看单局）。

| 指标 | 结果 |
| --- | --- |
| 过火调侃（嘲讽档） | 均值 **25.7 次/局** |
| 当众羞辱 | 均值 **14.9 次/局** |
| **羞辱 / 过火** | **0.58** —— 区分**第一次真正生效**：约四成过火是「普通摩擦」，不写深层 |
| **深层 max** | 均值 **13.6** ［2.3, 36.4］（`deep_cap`=70，且受 `deep_decay`=0.995 抑制） |
| **总敌对 max** | 均值 **15.8** ［2.4, 43.7］ |
| 好感均值 | **56.8** |
| 排挤 | 出现率 **72%**（72/100），均值 **4.02 次/局** |
| 举报 | 出现率 **27%**，均值 **0.37 次/局** |
| 压力爆发 | 均值 **16.7 次/局**；出现率 **96%** ⚠️ 见下 |

> **⚠️ 排挤只剩约 2pp 余量（72% vs 下限 70%）**：这是**结构性**的，不是标定失误 ——
> 排挤的证据 `hurt_day` 只有两个来源（举报 / 当众羞辱），抬高羞辱门槛必然减少证据。
> 实测同批种子：θ=3 时排挤 78%，θ=4 时 72%。
> **不要把羞辱门槛降回去补**（那会退回恒真）；该修的是**证据来源太窄**本身（§8.17 的「敌对种子」问题）。

> **⚠️ 「爆发出场率 100%」这条下限在本门当前样本量下不成立（实测 96%）**：
> 同批种子 θ=3 时为 **94%**、θ=4 时为 **96%** —— **与本节的门槛改动无关**，
> 是样本量由 20 提到 100 之后才暴露出来的尾部门槛问题（§2.4.1 六：门槛必须与样本量匹配；
> 20 局时「20/20」只是抽样还没抽到尾部）。
>
> **用户裁决（2026-10-07，历经两次，以后者为准）：下限 100% → 90%（与「当众羞辱」同档）。**
> 一度定为「维持 100%、接受门保持红」，随后复审改判。改判的理由不是「门红了不好看」，而是**口径错配**：
> 100% 是「**普适性要求**」，而本门管的是「**机制在不在场**」（§2.4.1 七）——
> 「96% 的局里爆发过」显然属于在场。更根本的是：没有任何机制有「必现」的保证，
> 写 100% 等于把门槛变成**样本量的函数**（20 局必绿、100 局必红），而不是机制的信号。
> ⚠️ 这是本次修改中**唯一一处为适配样本量而改动的门值**，理由必须站得住，不能成为惯例。

> **`H` 不再打到 100**：§9.8 的 `deep_cap`(70) 与 §9.10 的 `deep_decay`(0.995) 双重约束下，
> 深层 max 均值 **13.6**、总敌对 max 均值 **15.8**。「结下死仇」仍可能（个别局到 43.7），
> 但不再是「一条边永久锁死 100」的吸收态。

> ⚠️ **过程中修掉一个自引入的 bug**：衰减写成 `deep + (H − deep) × decay_h` 时，
> 若 `H` 曾被和解类事件降到低于 `deep`，`(H − deep)` 为负、会把总数**继续往下带**，
> 结果出现「深层 17.5 而总数只有 9.0」的自相矛盾。已夹住 `surf = max(0, H − deep)`。

## 9.5 从众 → 敌对（散落的敌意 → 集体围攻）

> ✅ **已实现**（2026-10-05）。阈值：`conformity_see` / `conformity_min`（`behavior_thresholds.csv`）；
> 事件：`conformity_hostility`（`w_events.csv`，normal，base 3）。

### 9.5.1 机制

复用早已实现、但此前**只用于「加入闲聊意愿」**的 `conformity(i)`（§8.19）：

```python
if len(邻居中恨 j 的人) >= conformity_min(2):
    apply_event(i, j, "conformity_hostility", scale=从众度 × 人数)
```

**从众度由性格给出，不需要特例**：高 F 者随大流；高 J / 高 N 者有自己判断、不被裹挟 ——
所以「敢替被孤立的人说话」这种人**天然存在**，不必专门写一个"正义者"角色。

### 9.5.2 ⚠️ 信息来源：只看「公开可见的敌对行为」（P0 修正）

**原实现读的是真值敌对**（`self.H[k][j] >= see`）—— 这是**信息层穿透**：

> 低透明度的人把恨藏起来，却仍会在这里**扩散给从众者**，
> 直接破坏 §5.4「**藏得住的人真的藏得住**」。

**已改为「i 亲眼见过的公开敌对行为」**：复用 `hurt_day[k][j]`
（最近一次 k 对 j 做**重大**敌对行为的日 —— 而 `major` 档的当众羞辱 / 举报 / 排挤**本就都是公开事件**）：

```python
haters = [k for k in 邻居 if 0 <= day - hurt_day[k][j] <= see_window]   # 看得见的
```

**做过公开行为的人才被看见，藏着的人不会被跟风。**
参数语义随之改变：`conformity_see`（旧，读真值的敌对值门槛，**已废弃**）
→ `conformity_see_window`（新，公开行为的**可见窗口天数**，默认 14）。

### 9.5.3 实测：已实现，但**未触发**（前提不存在）

30 天：**调用 60 次、从众度分布正常（0.00–0.90）、满足条件次数 0**。

原因在 `H ≥ 25` 的边只有 5 条，而且是这个形状：

```
(0→2, 100)  (0→3, 57)  (0→11, 33)  (0→14, 43.7)  (2→0, 33)
```

读出来是：**节点 0 被 2、3、11、14 四个人都羞辱过，而只有 0 单向记恨他们。**
—— 这已经是**完整的欺凌结构（4 人欺负 1 人）**，但**没有任何目标被 2 人以上「恨」**，
所以从众等不到它的前提。

### 9.5.3 ⚠️ 由此发现的真问题：**排挤的判据方向反了**

排挤的门槛是「**≥3 人同时对同一目标敌对 ≥40**」。但这个判据假设了「多人恨同一人」——
而**欺凌的真实结构是「多对一」**：

| | 施害方 | 受害方 |
| --- | --- | --- |
| 人数 | **多人** | **一个人** |
| 关系方向 | 对受害者**做损害行为** | **单向**记恨（只有他受损） |

∴ **受害者只有一个人，只能单向记恨，永远凑不出「3 人恨他」** —— 从众再强也没用。
**正确的判据应该看「有多少人对他做过敌对行为」，而不是「有多少人恨他」。**

> 例：0 被 2、3、11、14 四个人欺负 —— 「有 4 个人在损害 0」才是可观测的集体行为；
> 而「有 3 个人恨 0」在这个结构里不可能成立，因为施害者不恨受害者。

> ✅ **2026-10-05 已修**（见 §6.4 修订与 §9.6）。

### 9.5.4 第二处方向问题（效果侧）

修好判据后实测排挤正常触发（4 次/30 天），但发现**排挤的效果方向也不完整**：
`do_exclude` 目前只做「**被排挤者 → 参与者**好感下降」（`exclude_affinity`，符合 §6.4 原文），也就是「**他恨上了那些排斥他的人**」。

但「被孤立」的核心表现是**大家不跟他玩了** —— 即「**参与者 → 被排挤者**」的好感下降。

> ✅ **2026-10-05 已补齐**：`do_exclude` 现在做**双向**好感下降。
> 实测（30 天）：被孤立者出现明显的**单向落差** —— 
> 节点 0「**他人 → 他 15.1**」而「**他 → 他人 61.4**」（落差 **+46.3**），
> 即「**全班都不喜欢他，而他还喜欢大家**」—— 「想融入但没人要他」，孤立成为**可观测的状态**。

## 9.6 排挤判据修订（视角从受害者移到施害者）

> ✅ **已实现**（2026-10-05）。阈值：`exclude_window` / `exclude_count` / `exclude_cooldown`（`behavior_thresholds.csv`）。

### 9.6.1 原判据的问题

原判据是「**≥3 人同时对同一目标敌对 ≥40**」。它假设「多人恨同一人」——
但**欺凌的真实结构是「多对一」**：

| | 施害方 | 受害方 |
| --- | --- | --- |
| 人数 | **多人** | **一个人** |
| 关系方向 | 对他**做损害行为** | **单向**记恨 |

**受害者只有一个人、只能单向记恨，永远凑不出「3 人恨他」。**
实测证实：`H ≥ 25` 的边是 `(0→2,100) (0→3,57) (0→11,33) (0→14,43.7) (2→0,33)`，
即**节点 0 被 2、3、11、14 四个人都羞辱过** —— 完整的欺凌结构，
但**没有任何目标被 2 人以上「恨」**，所以原判据永不成立。

### 9.6.2 修订后的判据

```
旧：有多少人【恨】他 ≥40        ← 受害者视角，凑不齐
新：有多少人【近期对他做过重大敌对行为】  ← 施害者视角，可观测
```

新增一张 N×N 表 `hurt_day[i][j]`（最近一次 i 对 j 做**重大**敌对行为的日），
由**调用点**用 `mark_hurt(施害者, 受害者)` 显式维护：

```python
def mark_hurt(self, perpetrator, victim):
    self.hurt_day[perpetrator][victim] = self.day
```

> ⚠️ **2026-10-07 修正：不能放在 `apply_event` 里按 `(i, j)` 自动维护。**
> `apply_event(i, j, …)` 的 `(i, j)` 是「**被作用方 → 作用方**」（如 `apply_event(被羞辱者, 施害者, "humiliate_hostility")`），
> 而本表与读者（§9.6 排挤、§9.5 从众）要的是「**施害者 → 受害者**」——两者在一次调用里**恰好相反**。
> 后果实测：受害者被同时记成施害者，排挤/从众判据因此被虚增（`hurt_day[受害者][施害者]` 也被写上）。
> 现在方向只由 `mark_hurt(施害者, 受害者)` 一处决定；调用点仅限 `tier = major` 的事件
> （`do_tease` 的当众羞辱、`do_report` 的举报），见 `tools/core_sim.py`。

排挤判据改为：`近期(≤ exclude_window) 对 j 做过重大敌对行为的人 ≥ exclude_count`。

### 9.6.3 两个必须处理的副作用（都是实测发现的）

**① 「损害」必须只算重大档。** 最初记录的是「任何 `delta > 0` 的 hostility」，
结果 `noise_hostility` 每天让**几乎所有人互相「损害」**，「被 3 人损害」成了常态 →
**排挤 268 次/30 天**（每天 9 次），语义完全失效。改为**只记 `tier = major`** 后仍偏高。

**② 排挤必须有冷却。** 真正的元凶是 `exclude_p` 是**每 tick** 掷的 ——
一旦有人满足条件，**同一个人一天会被排挤 9 次**。
而现实中「**孤立某人是一个状态，不是反复的动作**」。加入 `exclude_cooldown`（7 天）后：

| `exclude_window` | `exclude_count` | `exclude_cooldown` | 排挤次数/30天 | 四项指标 |
| --- | --- | --- | --- | --- |
| 14 | 3 | **7** | **4** ✓ | b=23 / mean 62.1 / SD 20.5 ✓ |
| 14 | 2 | 7 | 11 | ✓ |
| 30 | 2 | 7 | 17 | ✓ |

**采用 `14 / 3 / 7`** —— 一学期 4 次「有人被全班孤立」，量级合理。

> ✅ **2026-10-06 重标定（当前取值 `30 / 2 / 7`）**：其后又做了两处修正——① 补记施害者视角的
> `hurt_day[i][j]`（§9.6 方向修正，排挤判据才凑得齐「多少人欺负过 j」）；② `exclude_p` 0.04 → **0.06**。
> 配合这两处，`exclude_window` 放宽到 **30**、`exclude_count` 降到 **2**（与 `data/rules/behavior_thresholds.csv` 一致），
> 排挤上场率 **60% → 90%**（第五道门目标 ≥ 70%）、20 局共 210 次。
> 上文 `14 / 3 / 7` 是**当时的决策记录**，保留作对照；**当前口径一律以 `behavior_thresholds.csv` 为准**。

### 9.6.4 仍未完成的部分

排挤的**效果**目前只有单向：`exclude_affinity` 做的是「**被排挤者 → 参与者**好感下降」
（符合 §6.4 原文），即「**他恨上了排斥他的人**」。

## 9.7 孤立：从「单向记恨」到「双向疏远」

> ✅ **已实现**（2026-10-05）。事件：`exclude_affinity`（`w_events.csv`，`major`，base −4）。

### 9.7.1 问题

`do_exclude` 原本只做「**被排挤者 → 参与者**」好感下降（`exclude_affinity`，符合 §6.4 原文）——
即「**他恨上了排斥他的人**」。

但这样「被孤立」只表现为**受害者单向记恨**，**观察不到全班对他的疏远**。
孤立因此不是一个可观测的**状态**，只是当事人自己的情绪。

### 9.7.2 补齐

`do_exclude` 现在做**双向**好感下降（复用同一事件，不改公式）：

```python
apply_event(j, i, "exclude_affinity")   # 他恨上了排斥他的人（原有）
apply_event(i, j, "exclude_affinity")   # 大家不跟他玩了（补齐）
```

### 9.7.3 实测：单向落差 = 孤立的指纹

30 天（seed=12345）：

| 节点 | 他人 → 他 | 他 → 他人 | 落差 | 压力 |
| --- | --- | --- | --- | --- |
| **0** | **15.1** | **61.4** | **+46.3** | 59.9 |
| 10 | 33.2 | 59.4 | +26.1 | 33.1 |
| 3 | 43.3 | 59.8 | +16.5 | 53.5 |

全班「被好感」均值 62.8 / SD 18.3；排挤 4 次；四项达标 b=26 / sat 0.0% / mean 62.8 / SD 20.9。

> **「他人 → 他」远低于「他 → 他人」** 就是被孤立的特征签名：
> **全班都不喜欢他，而他还喜欢大家** —— 「想融入但没人要他」。
> 这也给了簇标签器的「孤立」标签一个**可计算的判据**（§8 观察层）：
> `被好感显著低于班级均值` 且 `给好感接近正常`。

## 9.8 深层敌对的软上限

> ✅ **已实现**（2026-10-05）。参数：`environment.csv` 的 `deep_cap`（默认 70）。

### 9.8.1 为什么需要上限

`H_deep` 只增不减、又不参与 `room_for` —— 这保证了「忘不掉」，但也意味着**单调累积**：
当众羞辱约 1.3 次/天，一学期（30 天）即可让少数边累加到百米量级。
若不设限，**那条边的举报门槛（`H ≥ 60`）会永久满足**，最终退化成「死仇复读机」——
关系不再变化，只剩一个永远触发的事件。

### 9.8.2 做法：软上限而非衰减

```python
cap = self.env.get("deep_cap", 70.0)
self.H_deep[i][j] = min(cap, self.H_deep[i][j] + abs(delta))
```

| 方案 | 语义 | 取舍 |
| --- | --- | --- |
| **软上限（采用）** | 「**恨到顶了**」，到了就不再加深 | 忘不掉依然成立；**总 `H` 仍可更高**（深层 + 表层），死仇强度不被压平 |
| 极慢衰减 ×0.995 | 百天尺度缓慢收敛 | 会削弱「不可消减」，与用户直觉不符 |

**实测**：`deep_max` 由 100 → **≤70**（各局 ［23.4, 70.0］），一致性（总 ≥ 深层）保持 ✓。

### 9.8.3 待观察

上限值 70 有效（实测深层 max 均值 20.2，未出现锁死；爆发指标已达标，见 §2.4.1 六）。
建议后续加入观测指标「**举报对子重复率**」（同一对子被举报 ≥2 次的比例），
用它来判断上限是否需要下调。

## 9.9 环境层 → 压力：基础项与减压侧

> ✅ **已实现**（2026-10-05）。参数：`noise_base_fear` / `stress_k`（`environment.csv`）、`sleep_relief`。

### 9.9.1 一个隐蔽的失效方式：信号只发给了小部分人

`noise_pressure` 原本的压力系数是：

```
fear = f_j·(P−50)/50 + f_e·(50−E)/50      ← 越内向、越专注越怕吵
```

即**只有「怕吵的人」会被嘈杂环境影响**。后果是：把 `stress_k` **放大 12 倍**，
爆发均值也只从 7.5 到 9.4 —— 因为**压力只落在少数人身上**，全班压力水平几乎不动。

**修正**：加入**基础项** —— 嘈杂环境对**所有人**都有压力：

```
fear = noise_base_fear + (原怕吵项)
```

起效立竿见影：爆发均值 **11.6 → 15.9**，进入目标区间。

> **教训**：调一个系数十倍无效时，先怀疑「这个信号是不是只发给了小部分人」，
> 而不是继续加大系数。

### 9.9.2 减压侧：先查哪里漏

压力上不去也可能不是「进得少」，而是**漏得快**。实测 `sleep_relief`：

| `sleep_relief` | 8 | **3** | 1 | 0 |
| --- | --- | --- | --- | --- |
| 爆发均值 | 8.8 | **11.6** | 12.2 | **9.0（反降）** |

**`0` 反而更差** —— 说明「睡觉」作为**主动减压出口**本身有价值（§8.8），全禁适得其反。
∴ 采用用户指定的 **3**：削弱它的强度、但保留这条出口。

## 9.10 深层的极慢衰减（防吸收态）

> ✅ **已实现**（2026-10-05）。参数：`decay.csv` 的 `deep_decay`（默认 0.995/天）。

### 9.10.1 「永不衰减」是一个吸收态

§9.3 把深层定义为**永不衰减**，§9.8 又加了软上限 —— 但两者合起来仍是一个**吸收态**：
到了上限就不动，**锁死在那里**。核验证据非常干净：

```
20 局实测：deep_max 均值 50.2，其中 6 局顶到上限 70
而这 6 局【全部】是「举报 > 0」的局 —— 举报>0 ⟺ deep=70，6/6 完全吻合
```

即：**只要那条边没锁死，举报就不会发生。**

吸收态的危害不止于平衡，而是**反涌现**：时间足够长，**所有局会掉进同一个终态**
（几条边锁死、举报门槛永久满足、格局冻结），局与局的差异被时间**单调抹掉**。
这正是「不同结果可以存在」的反面。

### 9.10.2 做法：极慢衰减

```python
self.H_deep[i][j] *= d["deep_decay"]      # 0.995/天
```

| 时间尺度 | 效果 |
| --- | --- |
| **30 天（一学期）** | `0.995^30 ≈ 0.86` → **几乎不衰减**，「忘不了」依然成立 |
| 百年尺度 | 会缓慢收敛 → **死仇也有戏剧性解冻的可能** |

这与 `deep_cap`（软上限）**并存**：上限管「涨到哪里」，极慢衰减管「能不能解冻」。
「不可消减」的**直觉被保留**（一学期内看不出衰减），而**结局空间的开放性被保住**。

### 9.10.3 实测

| 指标 | 加衰减前 | 加衰减后 |
| --- | --- | --- |
| **深层锁死率** | 6/20（30%） | **0/20（0%）** ✓ |
| `deep_max` 跨局 | ［19.0, 70.0］ | **［28.3, 69.7］** |
| 第四道门（分布判据） | 全绿 | **全绿**（爆发 15.5 / 均值 58.9 / SD 22.6 / 饱和 0%） |
| 跨局指纹相关度 | 0.129 | 0.146（多样性未受影响） |
