## 19.1 P2-1 周考与奖励（裁决 §17.6 开放问题④）

### 19.1.1 定位裁定：学制节点，不是事件

- 周考是**固定学制节点**（世界结构，与课程表、学期长度同级），不落 §11.2「触发不看日期」禁项——该禁项约束的是**社会事件触发器**；周考写进 `data/rules/exam.csv`，不进 `social_event_triggers.csv`，静态扫描范围不变（同 §17.1.3 期末考口径）。
- 结算挂 `day_settle` 相位（`phases.csv` 既有 settle 段，settle_at_end=1），**不新增相位、不改 tick 账目**；考试日白天流程照常，跨天结算时插入考试步骤。

### 19.1.2 考试结算模型

```text
考试日（exam_days 中的日次，或期末考 day = term_days）的 day_settle 追加：
1. exam_score[i] = clamp(
       grade[i] + round(exam_noise_sigma × N(0,1) − stress_exam_penalty × stress[i]/100),
       0, grade_max)
   N(0,1)：考试独立种子流（base_seed ⊕ 考试序号，base_seed 应 ≥ 256 以避免低序号 XOR 碰撞），按节点索引升序抽取——同种子逐位可复现
2. 全员按 exam_score 降序排名 → exam_rank[i]（同分按节点索引升序破平）
3. last_exam_score[i] ← exam_score[i]
4. 发奖（§19.1.3 / §19.1.4）→ 结果行写当日《每日简报》（§12）
```

**决策记录（2026-10-09）**：考试**不回写 grade**——考试是测量不是突变；`grade`、`study_acc` 与分段档不受考试扰动，对拍面最小。进步奖以 `last_exam_score` 差值衡量；首次周考的 `last_exam_score` 取开局初始成绩。
**决策记录（2026-10-09）**：考试结果本期**不回馈 A/H/T**（同 §17.0「成绩回馈 A/H/T」的 P0 裁决顺延，防标定扰动翻倍）；挂接为 §19.7 开放问题①。

### 19.1.3 进步奖

- 判据：`exam_score − last_exam_score ≥ progress_prize_delta`（**50**，用户定案保持）。
- 奖励：**取回全部被没收课外书**（依赖 P3 物品系统）；P3 未就绪时按计划文档定案**降级为纯荣誉简报行**（「本次周考获得进步奖」），不发替代品。

**可达性算术（标定用）**——假设玩家每天 120 学习 tick（课间 300 tick × 约四成在学，§17.1.2 同口径，且未遭非自愿打断清空 `study_acc`）：

| 周考 | 期初 grade | 自然进步（分段表推算） | 是否达 50 |
|---|---|---|---|
| W1（D7） | 250 | ≈ +76 | ✓ |
| W2（D14） | ≈ 326 | ≈ +57 | ✓ |
| W3（D21） | ≈ 383 | ≈ +47 | ✗ 差 3 分 |
| W4（D28） | ≈ 430 | ≈ +41 | ✗ |

结论：**第三周起纯涓流自然进步跌破 50**——设计意图即「进步奖奖励主动学习」：叠加提问/讲题（`ask_question_bonus_ticks` / `teach_lesson_bonus_ticks`，§18.2.4）与快速学习（`fast_study_speed=2.0`，§18.1）后 W3–W4 重新可达（快速学习占学习时长一半时 W3 ≈ +70）。若标定后仍过难/过易，调 `progress_prize_delta` 或分段表整列（§17.4），不改代码。

### 19.1.4 特等奖与免罚卷

- 判据：`exam_rank ≤ top_prize_rank`（**3**，计划文档定案「班级前 N」）。
- 奖励：**免罚卷 ×`top_prize_tokens`（1）**——per-actor 豁免计数器 `exemption_tokens[i]`，**进存档**；消费点在 P3「没收 / 巡查处罚」落地时接通（每次处罚自动消耗 1 张抵免），**本期无消费点、纯持有**（计划文档已接受该降级）。
- 期末考（D30）沿用同一结算函数；**不发进步奖**（距上次周考仅 2 天，判据失真），特等奖照发。
- 期末考**同样更新** `last_exam_score[i] ← exam_score[i]`——供存档「上局回顾」（§19.3.4）使用，学期结束后不再参与发奖判定。

### 19.1.5 UI 触点

- 考试日当天 HUD 横幅「今日周考」（时间 HUD 扩一行；期末倒计时已由 §17.1.3 覆盖）。
- 考试结果进当日《每日简报》：班级前 3 名单 + 玩家名次 / 分数 / 进步量 + 得奖行。
- 玩家看不到 NPC 具体分数（同 §17.1.3 口径）——简报只出名次与奖项。

### 19.1.6 参数落点与校验

- 新表 `data/rules/exam.csv`：`exam_days="7,14,21,28"` / `exam_noise_sigma=12` / `stress_exam_penalty=15` / `progress_prize_delta=50` / `top_prize_rank=3` / `top_prize_tokens=1`。
- 期末考日**不重复建键**，读 `time_runtime.csv` 既有 `term_days`（§17.1.3）。
- `check_config.py` 扩展：exam_days 全部落在 (0, term_days) 且递增无重复（term_days 本身属期末考，不进周考表）；sigma / penalty ≥ 0；`top_prize_rank ≥ 1`；`progress_prize_delta > 0`。
- 内核新增运行态：`exemption_tokens` / `last_exam_score` / `exam_rank`（豁免计数器进存档为计划定案）。

### 19.1.7 对拍与测试

- Python `core_sim.py` 镜像考试结算（公式 + 独立种子流 + 破平规则）；对拍扩展：同种子逐位比对 `exam_score` / `exam_rank` / `exemption_tokens` 序列。

## 19.2 P2-2 事件触发状态前置

### 19.2.1 范围裁定

- **明确否决「事件机制全部推翻重做」**（计划文档 §2.2 定案）：五天窗口 + 六道门全链重标定不可承受；「事件随行为受限」的意图用**门控条件列**达成。
- 门控加两处可选列 `require_state`：
  1. `social_event_triggers.csv`（**触发规则级**：与同 trigger_rule 的 OR 链取 AND）；
  2. `social_events.csv`（**事件级**：对该事件全部触发规则生效）；两级同时存在时取 AND。
- `w_events.csv`（UIF 的 E 项权重表，非事件触发器）**现有标定行一行不动**（空 = 无门控 = 现行为零变化）；新增内容的 E 项行如需门控，沿用同一列格式（向后兼容）。

### 19.2.2 语法与语义

```text
require_state = "metric op value;metric op value"    ; 分号 = AND
op ∈ {<, >, >=, <=, ==, !=}
空 / 缺列 = 无条件放行（所有既有行缺省即放行，行为零变化）
判值时机：社会事件触发检查点（既有 trigger 评估处）
门控不过 → 本次不触发，且不消耗 cooldown_days
```

## 19.6 实现顺序与验收

**实现顺序**：P2-2 门控层（独立，先行——为 P2-1/P2-3 的统计指标提供注册表）→ P2-1 周考结算与发奖 → P2-3 统计埋点与结局判定 →（可选）§19.4 → 标定复跑。

**验收清单**：
