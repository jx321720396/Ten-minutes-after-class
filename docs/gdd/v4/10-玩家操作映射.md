# 第十章 玩家操作映射

## 10.1 总原则（玩家不是特权者）

玩家与 NPC **共用同一套行为与同一套判定**：玩家能做的，NPC 都能做；NPC 的判定流程（门槛 → 意向 → 采样 → 效果）对玩家同样生效。差异只有两处：

| | NPC | 玩家 |
|---|---|---|
| 决策来源 | 决策算法（见 [`../design/NPC行为决策.md`](../design/NPC行为决策.md)） | 人的主动选择 |
| 独有能力 | 无 | 仅 3 项（见 §10.3） |

> **玩家的优势**：玩家发起行为时**跳过决策侧**（§4.4）——NPC 要先过"想不想"的概率判定，玩家只要想就能发起；但玩家仍要过"能不能"的判定侧概率（§4.4 / §8.22）。

## 10.2 玩家可用行为（与 NPC 完全相同）

**状态层（不占"行为"名分，只改位置/占用）**：走动 / 换座位（§8.4）、睡觉（§8.8）、学习（默认，§8.15）。

> **本节的分类面向玩家**，是 **UI 行动菜单的分组依据**——按「玩家在做什么」分三组。
> 同一批动作的**实现分类**（A–E 五类，按读哪条轴分）见 §8.16；**两者是同一批动作的两种切法，不要混进同一张表**。

### 10.2.1 开口说话（走过去，对某个人说）

“加入”是针对已有活动的通用参与操作，不另列“搭话”行为。空闲对象显示「闲聊」，已有闲聊中的成员显示「加入」，说明为「加入闲聊」；同一目标只提供一个对应当前状态的聊天操作。

| 菜单项（标识符） | 玩家视角 | 触发条件 | 依据 |
|---|---|---|---|
| 闲聊 `chat`（发起／加入） | 找人随便聊两句，或加入现有聊天 | 双方离得近；加入还需原会话有效并通过接受判定 | §8.5、§8.7、§8.21 |
| 求助 `ask_help` | 开口求人帮个忙 | 对目标好感 ≥30 | §8.10 |
| 安慰 `comfort` | 看谁难受了，去说句好话 | 目标压力 ≥70 且好感达门槛 | §8.13 |
| 当众调侃 `tease` | 当着大家的面开他玩笑 | 周围 ≥3 人围观 | §8.12 |
| 道歉 / 和解 `apologize` | 跟闹翻的人把话说开 | 双方敌对 ≥30 | §8.11 |
| 打听 `ask_about` | 向某人打听另一个人的事 | 任何时候（**玩家独有**） | §10.3 |

### 10.2.2 动手做事（不说，直接做）

| 菜单项（标识符） | 玩家视角 | 触发条件 | 依据 |
|---|---|---|---|
| 递纸条 `pass_note` | 把话写下来传过去，别人听不到 | 闲聊时改用纸条；私密传递不可加入 | §8.6 |
| 传流言 `rumor` | 把听到的闲话散出去 | 手里有流言 | §8.1 |
| 告密 `inform` | 单独把料告诉当事人 | 手里有关于他的流言 | §8.3 |
| 举报 `report` | 跑去老师那儿告状 | 见过他把柄、且足够敌对 | §8.2 |
| 秘密交换 `share_secret` | 说个秘密给他，换他守口如瓶 | 双方信任 ≥60 | §8.14 |
| 追逐打闹 `roughhouse` | 一群人疯玩一场 | 参与者在场 | §8.17.1 |
| 排挤 `exclude` | 带着一群人孤立某个人 | 目标已被群体敌对（≥3 人敌对 ≥40） | §9.6 |

> **追逐打闹 / 排挤是 2026-10-07 补入玩家菜单的**：此前 §10.2 漏列（却仍挂着已关闭的窃听），而两者早已在 `data/rules/behaviors.csv` 与第八章中定义。玩家**主动发起**它们时同样**跳过决策侧**（§10.1），只受时间预算约束；上表的「触发条件」即菜单项的可选门槛。

### 10.2.3 不接触（看 / 换位置 / 什么都不做）

| 菜单项（标识符） | 玩家视角 | 依据 |
|---|---|---|
| 走动 `move` | 换个位置站 / 坐 | §8.4 |
| 睡觉 `sleep` | 趴一整节课，谁都不理你 | §8.8 |
| 学习 `study` | 默认状态：没在忙别的就是在学习 | §8.15 |
| 情报日志 `intel_log` | 上课时翻已经发生的事（**界面**，不占时间） | §10.3 |
| 推理板 `clue_board` | 记下判断，自动标出对不上的地方（**界面**，不占时间） | §10.3 |

> **本作不设「什么都不做」这个选项**——不选，就是学习，压力会涨。

**时间成本**：每个行为都消耗 tick（一个课间段共 100 tick）。走动要花时间、互动要花时间——**课间只有 10 分钟，做不了太多事**。这就是玩家侧天然的操作预算，不需要额外的「每段最多 N 次」限制。

具体耗时见 **`data/rules/behaviors.csv`**（行为主表），核心法则：**收益越大，耗时越长**。

| 行为 | 耗时(tick) | 收益档 | 说明 |
| --- | --- | --- | --- |
| 学习 | 0 | 1 | 兜底状态：占满所有不忙的时间（见下方语义说明） |
| 流言 / 加入闲聊尝试（旧 join_chat） / 递纸条 | 10 | 2 | 一句话的量；加入后的持续聊天按 chat 耗时 |
| 走动 | 按距离 | 1 | `ceil(路径长度 / meters_per_tick)`；速度见 `data/rules/movement.csv`，不再固定 15 tick |
| 求助 / 告密 / **打听** | 20 | 3 | 「一次动作」档 |
| **闲聊 / 当众调侃** | **30** | 3 | 主行为，要聊一会儿 |
| 举报 | 40 | 5 | 重大事件，得跑一趟 |
| 排挤 | 40 | −4 | 群体驱逐 |
| 安慰 / 道歉和解 | 50 | 3–4 | 深度沟通 |
| 追逐打闹 | 50 | −3 | 群体活动：参与者相互好感↑、旁观者敌对↑ |
| **秘密交换** | **60** | 5 | 收益最大，耗时最长 |
| 睡觉 | 100 | 4 | 占用整个课间段 |

> **`duration` 的语义 = 占用「时间槽」的 tick 数**（期间不能再发起新行为）。`duration = 0` **不是「时间停止」**，而是「不占用时间槽」，其中有两种情形：
> - **兜底状态**（学习）：它**占满所有不忙的时间**，只是不作为动作登记——「没在忙」≡「在学习」。代价体现在压力涓流（每天 2 次、+1）。**本作不设「什么都不做」这个选项**。
> - **并行行为**（窃听）：搭便车，不做主行为时顺便生效（正在专注做事的人听不到）。**⛔ 该行为已关闭、不在任何版本排期内（§14.9），此条仅存语义定义——`duration = 0` 目前实际只有「兜底状态」一种情形。**

> 按此表，一个课间大致只够做 **2–4 件事**——「做不了太多事」是**算出来的**（时间预算），不是外加的限制。
> 实现：行为开始时双方进入**忙碌期** `busy_until = tick + duration`，期间不能发起新行为（替代早期的「一律 20 tick 冷却」）。

## 10.3 玩家独有能力（仅 3 项）

| 能力 | 说明 |
|---|---|
| **打听** | 消耗一次课间动作，向某人打听另一人的事；透露度 = 他对你的信任（§7.3） |
| **推理板** | 记录与标注、查看矛盾高亮（§7.5）——玩家独有的「显式信念」工作台 |
| **情报日志** | 上课段查看已获得的观测与事件（只读） |

## 10.4 玩家不能做的事

- 直接读写任何数值（好感 / 敌对 / 信任 / 透明度 / 压力）；
- 看到未经 §7 两层过滤（透明度 + 信任）的原始数据；
- 在非课间段操作（上课段只能查看情报日志与推理板）。

## 10.5 一切由数值驱动

玩家的每次操作只是在关系矩阵中拨动一个数值；**其后的一切（谁来找你、谁翻脸、谁抱团、谁崩溃）都由数值条件自动触发**，不存在为玩家预设的剧情分支。
