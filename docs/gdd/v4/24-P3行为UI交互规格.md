### 24.2.1 课外书经济完整版

| 环节 | 界面条目 |
|---|---|
| 受赠 | 弹层 / 结果页：`XX 塞给你一本课外书：「看这个，别老闷着。」` + 持有区书本数 +1；**首次获得时**给风险提示 `被老师看到正在看书，书会被收走。`（与P0–P2 UI 未完成清单 同一句） |
| 看书 | 门控解除，按钮变为可用（P0–P2 UI 未完成清单 的进行中 / 结算文案不变） |
| 被没收 | 短句 `老师把书收走了。` + 持有区书本数 −1；归零后「看课外书」按钮立刻变灰（原因 `你还没有课外书。`） |
| 取回 | 周考进步奖时：`老师把上次收走的课外书还给你了。`；**若被没收的书与进步奖取回范围不一致，必须明确写出**（避免玩家以为漏发） |

#### 24.2.1.1 好感赠书实现口径（2026-10-11）

用户裁定：只在闲聊时进行赠书判定。实现以与玩家同场闲聊自然完成为唯一判定点；拒绝、未接受邀请、主动离场和铃声中断均不判定。群聊按真实会话成员升序检查，每名符合条件的持书 NPC 每场最多掷骰一次，每课间最多成功一次。赠书从 NPC 持有量减一本、玩家加一本，每名 NPC 每局最多赠一次；不会凭空生成书，也不增加额外 A/T 收益。

参数均在 data/rules/leisure.csv，以下初值仍需标定验证：

| 参数 | 初值 | 含义 |
|---|---|---|
| book_gift_affinity_threshold | 60 | 赠书者对玩家的真实好感下限 |
| book_gift_trust_threshold | 40 | 赠书者对玩家的真实信任下限 |
| book_gift_probability | 0.1 | 符合条件的闲聊自然完成时赠书概率 |
| book_gift_max_per_break | 1 | 每课间成功赠书上限 |

受赠弹层只显示人物和赠书结果，不透露门槛。库存同步刷新，看书的持书门控解除（忙碌、上课等其他门控仍适用）。首次提示使用「被老师看到正在看书，书会被收走。」。老师巡查没收已接入；周考取回和完整存档未实现。按用户要求未运行测试，不代表数值或运行验收通过。Python 参考模型补记已成立的闲聊成员和结束点，群聊对拍尚未验收。

#### 24.2.1.2 巡查没收实现口径（2026-10-11）

- 老师在课间第 25/65 tick 分别以 25% 概率巡查，本段至多到场一次，停留 30 tick。上课默认在教室，不触发巡查处罚。
- 到场压力走 UIF；出门、睡觉、学习豁免。老师在场时调侃、打闹、排挤触发概率乘 0.3，音量目标乘 0.5。所有参数在 teacher.csv 和 w_events.csv。
- 到场发现读书，或在老师面前开始读书，收走正在读的一本，持有库存减一、没收账本加一；立即解除阅读占用，不发自然完成减压，不追加铃声中断压力。自然完成结算优先于巡查，因此恰好读完不会被没收。
- 玩家与 NPC 使用同一规则；仅持有而未阅读不会被收书。剩余书仍可读，再次在老师面前读书仍会没收一本。归零时按钮灰置。
- 有免罚卷时自动消耗一张，使该次巡查期间免收书，继续阅读；不抵免老师到场压力，不重复消费。当前发券来源未接通，默认零张。
- UI 提示老师到场/离场、没收或抵免结果，显示剩余书与老师保管数（**不再显示老师位置文字**，2026-10-12 裁定）。音乐/零食只显示被看到提示。
- 本轮不实现取回、考试发券、老师模型或跨会话存档。Python/GDScript 逻辑同步修改，按用户要求未运行测试、Godot 或对拍，尚未验收。

## 24.3 本批特有新组件：棋盘弹层

```text
┌──────────────────────────────┐
│ 和林小雨下一局                │
│      ● ○ ○ ● ○ ○            │
│    ○ ● ● ○ ○ ● ○            │  ← 15×15 或按 4×4 座位号的简化盘面
│  ...                         │
│ 该你了 · 课间还剩 42 秒        │  ← 剩余时间提示（未下完会被铃声中断）
└──────────────────────────────┘
```

| 项 | 规定 |
|---|---|
| 盘面 | 标准五子棋盘（尺寸由实现定），落子点热区不小于 44×44 px |
| 落子 | 点 / 触即落子；不做落子动画 |
| 时钟 | 面板**不暂停**课间计时（与选座面板不同，见 Q2 的裁决结论）：课间结束即中断，这是设计意图 |
| 围观 | 面板外的人照常活动，可见活动圈扩大 |
| 降级 | 文字对局（§24.2.2） |

## 24.5 验收

1. 受赠 / 被没收 / 取回三个环节，持有区数字与按钮可用性同步变化，无「数字变了按钮没变」的情况。
2. 被没收归零后按钮立刻灰置并给出原因。
3. 五子棋未下完时给中断短句，不产生「卡在面板里」的状态。
4. 围观者只通过活动圈体现，不新增独立 UI 元素。
5. 猜拳连胜记录不带来任何数值收益（对拍可验证：连胜与收益无关）。
6. 全批界面不出现任何 NPC 数值。
