# 第十四章 工程实现规范

> 本章是**程序实现的唯一依据**，汇总自 `docs/design/` 各篇。策划只需读 §1–§13；程序从本章入手。
> 对应的分篇文档仍保留（含更细的推导、手算例与待确认项），但**本章内容自包含**——两处冲突时以本章为准。

> **引擎定稿（2026-10-06）**：Godot 4.7.2（GDScript）。本章以 Godot / GDScript 约定为准；`docs/design/` 各篇中的 GDScript 代码块即实际实现语言。

## 14.1 架构总览

本作是**数据驱动模拟**：内核每 tick 计算完成后再通知表现层，**表现层不参与数值计算**。

**行为执行组件（2026-10-07）**：`scripts/systems/behaviors/` 中的十种 `RefCounted` 组件承载现有行为执行体，由 `BehaviorRegistry` 分发、`BehaviorContext` 提供共享结算服务；`SimCore` 保留时间、状态、公式、决策和完成机制，原 `_do_*` 签名保留为转发入口。此拆分不改变玩法、数值、随机数或通知顺序，组件不依赖场景树/UI。详见 [`../superpowers/specs/2026-10-07-behavior-components-design.md`](../superpowers/specs/2026-10-07-behavior-components-design.md)。

```
       ┌────────────── SimulationCore（无 UI 依赖，可无头运行）──────────────┐
       │  TimeSystem ──tick──► RuleScheduler ──► Behaviors(§8) ──► A/H/T / Stress │
       │        ▲                   │                                    │        │
       │        │                   └──► 涓流结算（传导 / 共同学习 / 独处，每天 2 次）│
       │   TermState（天 / 段 / 相位）              │                              │
       │                                          └──► ObserverLayer（簇标签 / 孤立，只读）│
       └──────────────────────────────────────────┼───────────────────────────────┘
                                                  ▼
              EventBus（信号）──► Presentation（场景、可视化、推理板、简报、存档）
```

**硬性边界**：`scripts/core/`、`scripts/systems/`、`scripts/npc/` 不得 `preload` 任何 `scenes/`；**模拟内核必须能在无渲染环境下跑完一局**（批量标定与单测依赖这一点）。

| 层 | 目录 | 职责 | 禁止 |
|---|---|---|---|
| 模拟内核 | `scripts/core/` | 时间推进、矩阵与压力状态、结算 | 依赖节点树 / UI |
| 规则层 | `scripts/systems/` | 行为触发与效果、影响力传导（§8） | 角色名 / ID 判断 |
| 观察层 | `scripts/systems/observer/` | 簇标签、孤立标签 | 回写任何数值 |
| 决策层 | `scripts/npc/` | NPC 的**规则选择**（用哪条、选谁） | 绕过规则直接改数值 |
| 表现层 | `scenes/`、`scripts/ui/`、`scripts/game/` | 渲染、输入、动画、推理板、简报 | 直接改矩阵（只能走内核 API） |
| 全局单例 | `autoload/` | 状态持有、事件总线、存档、配置读取 | 承载玩法规则 |

**目录约定**：`scenes/` 与 `scripts/` 同构（`ui/` `game/` `core/` `npc/` `systems/`）；全局单例在 `autoload/` 并注册 `project.godot`；配置与数值表在 `data/`（代码只读）；离线脚本在 `tools/`。

## 14.2 数据模型

**运行时状态**（一局的全部可变数据，索引 `0 … N-2` 为 NPC，`N-1` 固定为玩家）：

```gdscript
class Relations:                      # 关系矩阵：N×N 有向，0–100
    var affinity: PackedFloat32Array   # A[i][j] = i 对 j 的好感
    var hostility: PackedFloat32Array  # H[i][j] = i 对 j 的敌对（与 A 独立，不是负数）
    var trust: PackedFloat32Array      # T[i][j] = i 对 j 的信任

class ActorState:                     # 个体属性（长度 N）
    var opacity: PackedFloat32Array    # O[i] 透明度
    var stress: PackedFloat32Array     # S[i] 压力（唯一累积情绪变量）
    var mbti: PackedFloat32Array       # 4×N：E/N/F/P 各维度 0–100 连续值

class Belief:                         # 信念矩阵：三份 N×N（§14.5）
    var b_affinity: PackedFloat32Array # B_A[j] = i 猜测「j 对 i 的好感」
    var b_hostility: PackedFloat32Array
    var b_trust: PackedFloat32Array
```

- **有向存储**：`A[i][j] ≠ A[j][i]`，读写一律用"谁对谁"的语义；**建议提供 `a(i, j)` 访问器而非裸下标**，避免矩阵转置错误。
- **钳制统一在写入点**处理（§4.1 的 `clamp`）。
- N 由难度决定：简单抽 8（N=9）、标准抽 16（N=17）、困难全池 24（N=25）；**同种子同阵容**，绑定组（小情侣等）整组同抽。

**存档模型**：
- 粒度：**单日 = 一个自然存档单元**，存档点位于每天"放学结算"完成后（§2.5）。
- 内容（**全部可变运行时状态**，缺一不可——否则次日读档或回放对拍会漂移）：
  1. 关系矩阵：`A / H / T / H_deep`（N×N 平铺值，含表层与深层敌对）；
  2. 关系侧辅助状态：`hurt_day`（施害者证据，§9.6）、`witness_day`（举报把柄，§8.2）、`exclude_last_day`（排挤冷却）、`day_events`（当日事件计数，用于去重与"有互动"判定）；
  3. 个体属性：`O / Stress / MBTI`；
  4. 信念矩阵：`B_A / B_H / B_T`（§14.5）；
  5. 时间槽与行为状态：`current_act / busy_until / busy_phase / sleeping / in_conversation`；
  6. 环境层：`volume`（及任何班级级标量，§8.18）；
  7. 空间状态：`seat_of`（角色→座位映射，§9.1）与 `position`（课间临时位置，§8.4）；
  8. 状态标签运行时实例：`knot_days`（心结）等 `status_tags.csv` 状态；
  9. 事件日志引用：当天与学期的 `log_event` 索引（简报 / 回放的唯一数据源）；
  10. 玩家推理板状态（§7.5）；
  11. **本局抽取结果**：难度档、抽中的 NPC 索引映射、绑定组、座位分配；
  12. **随机数种子与 RNG 状态**：种子化 RNG 的完整状态（或等价的可重放计数）。
- 格式：`user://savegame.dat` + 版本号字段，便于迁移；版本升级需写迁移函数。
- 回放（§12.3）依赖事件日志可重放 → **随机数必须来自可复现的种子化 RNG**，且上述 1–12 任一缺失都会让"同种子重放"对不上。

## 14.3 规则引擎

**主循环**：

```
一局 = 30 天 × 每天 480 tick（课间 3×100 + 上课 2×90）
for day in 1..30:
    for phase in [上午课间, 上午上课, 中午午休, 下午上课, 下午课间]:
        for t in 1..phase.tick_count:
            run_rules(phase.active_rule_set)      # §2.3：上课只跑规则子集
            if global_tick % settle_interval == 0:  # 涓流：传导 / 共同学习 / 独处，一天 2 次
                apply_transmission(); apply_study_together(); apply_stress_drip()
            observer.update()                        # 簇标签器，只读
            emit(log_event)                          # 简报与推理解释的唯一数据源
    settle_day()                                     # §2.5 跨天结算 + 生成《每日简报》
```

**相位与规则启用**（§2.3）：

| 相位 | 启用规则 |
|---|---|
| 课间段 | 全部人物行为 + 玩家操作（§8） |
| 上课段 | 共同学习（相邻且双方都在学习）、流言传播（低频）、压力涓流；**闲聊发起／加入禁用** |
| 放学结算 | 不跑规则，执行跨天衰减与简报生成 |

> ⚠️ 涓流类（传导 / 共同学习 / 独处恢复）**不是每 tick 结算**，而是**每天 2 次**（`settle_interval` = 240 tick，上午 / 下午各一次）——结算判据必须基于**全程 tick 计数**，而不是相位内计数，否则会退化成"每相位一次"。

**规则实现约定**——每条规则实现为独立类，统一接口：

```gdscript
class Rule:
    func gather(ctx: SimContext) -> Array[CandidateAction]   # 谁能对谁发起
    func resolve(ctx: SimContext, action: CandidateAction) -> Array[Effect]  # 结果
    func apply_effects(ctx: SimContext, effects: Array[Effect]) -> void
```

- **决策与效果分离**：`gather` 处理触发条件（读 A/H/T/S/O/MBTI 与信念），`resolve` 处理结果判定（含概率），`apply_effects` 统一走 §4.1 增量公式并钳制。
- **行为选择（谁做什么）不在规则层定义** —— 它属于决策层（§14.6）。规则层只定义"行为发生后效果怎么算"。
- **数值外置**：所有增量、阈值、概率系数从 `data/rules/` 与 `data/balance/` 读取，脚本中不得出现魔法数字。

**同 tick 冲突消解**（拟定，M1 用批量局验证后固定）：

1. 优先级：危机类（举报、安慰）> 主动类（加入闲聊、调侃、道歉、秘密交换）> 被动类（回应、话题共鸣）> 环境类（共同学习 / 相邻概率修正）；
2. 同级按角色索引升序，保证可复现；
3. 已被占用（处于对话中）的角色本 tick 不再接受新交互。

**传导实现要点**：阈值 + 竞争归一化照旧（§5.2），饱和用统一软饱和 `sat_X(u) = u / (1 + |u|/U_X)`；**传导计算必须基于本结算点开始时的矩阵快照**，否则同点内写入互相污染、结果不可复现。性能：N³ 三重循环（最大 25³）在 14,400 tick 下的开销需实测，必要时改为稀疏更新（仅处理 `A'|H' > 0` 的对子）。

## 14.4 统一影响公式（要点）

完整定义见 §4（公式）与 §5（传导），推导与手算例见 `docs/design/统一影响公式.md`。核心链条：

```
P = E + C                # 事件推动 + 传导推动
E = base × M_personality × M(i,s)     # 性格倍率 × 关系调制
Δ = round( sat_X(P), 0.1 )            # 软饱和后四舍五入到 0.1
X ← clamp(X + Δ, 0, 100)              # 统一写入点
```

- `sat_X(u) = u / (1 + |u|/U_X)`：小量近似直通，大量收敛于 `U_X`。
- `M_personality = clamp(1 + Σ w_t·d_t, 0.1, 1.2)`（`d_t = (维度−50)/50`）：**性格只能温和放大或削弱，不能翻倍**。
- `M(i,s) = clamp((A[i][s] − H[i][s]) / 50, −1, +1)`：按**净态度**调制；态度不明显时只削弱，**敌对压过好感时反转**（这就是"敌对反应"的来源，不是靠额外的惩罚规则）。
- **三类结算方式**：事件类（即时，每次交互最多一次）、涓流类（传导 / 共同学习 / 独处，每天 2 次）、状态类（压力与跨天衰减，按 §2.5）。
- **数值铁律**：常规事件 `base ∈ [1,3]`、重大事件 `base ∈ [4,5]`（判据 = 前置条件苛刻）；涓流类单次 1–5；**单次结算幅度 ≥ 0.1，小于 0.1 的增量在 `round` 后会被舍去**（这也是不引入小数堆叠的原因）。
- **事件去重**：同一对子、同一规则、**同一课间段内只结算一次**。

## 14.5 信念矩阵（要点）

完整定义见 `docs/design/信念矩阵.md`。核心：**决策读信念，判定读真值**（与设计讨论中的「触发判定 / 决策判定」同义——触发判定 = 决策侧、决策判定 = 判定侧；本文统一沿用「决策 / 判定」命名，见 §4.4）。

- **三份矩阵** `B_A / B_H / B_T`，`B[i][j]` 的语义是"i 猜测 **j 对 i** 的态度"（与真值矩阵下标方向一致）。
- **观测三源**：直接互动、旁观他人互动、二手转述（流言）；玩家额外有"打听"（`ask_about`）。
- **更新规则**：`B ← B + η·(obs − B)`，其中
  - 学习率 `η = η0 · (0.3 + 0.7·T[i][j]/100)` —— **越信任对方，越相信自己的判断**；
  - 观测值 `obs = 真值 + 噪声`，噪声上限 `σ_max·(1 − O[j]/100)` —— **对方越透明，看得越准**；
  - `lambda_b` 每日把信念向先验缓慢回归（遗忘）。
- **初始值（开局先验）**：**由双方性格共同决定** —— `bias_A(i,j) = perceived(j) × (1 + bias_observer_k · observer(i))`，其中 `perceived(j)` 是**对方**「看起来」多友善（外向/共情型显得友善），`observer(i)` 是**我自己**多倾向于把人往好处想。
  **不是 `null`**（它是「不知道」，见 §9），**也不是复制真值矩阵**（那是开天眼）。
  · **乘法而非加法**：对方友善 + 我乐观 → 强烈高估；对方友善 + 我多疑 → 只略高估；对方冷淡 + 我乐观 → 仍略低估。
  · **天然不对称**：`bias(i,j) ≠ bias(j,i)`——同一个「话痨」，乐观者与多疑者判断不同（实测 92% 对子有双向差异）。
  · `bias_H = −bias_A`；`bias_T` **只受观察者影响**（对方「看起来」是否可信没意义，但「我是否容易先信任别人」有意义）。
  **偏差是性格的函数、不是随机数** → 「话痨型总被高估亲近、冰山型总被低估好感」成为**可预测的系统性错觉**。
- **读取规则**（最容易写错的地方）：**我自己的立场**（要不要做）读真值 `A[i][*]`、`T[i][*]`；**对方的反应预期**（他会不会接纳我）**必须读信念** `B_A[i][*]`、`B_T[i][*]` —— 读真值就等于开天眼。
- 误判是**特性而非缺陷**：它让"我以为他喜欢我"变成戏剧的来源（§7.4）。

## 14.6 NPC 行为决策（要点）

完整定义见 `docs/design/NPC行为决策.md`。**三段式**：门槛 → 意向评分 → softmax 采样。
> 三段式即 §4.4 统一判定公式中**决策侧（意向类）**的实现；判定侧（成不成）的 `score → p → 掷骰` 公式同见 §4.4。

**三类触发方式**：

| 类型 | 判据 | 行为 | 设计意图 |
|---|---|---|---|
| 环境类 | 固定基础概率 × 修正系数 | 闲聊、流言、窃听 | 不需要"想"——有条件就按概率发生 |
| 阈值类 | `p = σ((x − θ)/scale)`（越过阈值只是概率升高，不保证发生） | 举报、压力爆发 | 保留"积累到临界点"的相变手感，但不再 0/1 |
| 意向类 | 门槛 → 意向评分 → softmax | 闲聊的加入意向、当众调侃、安慰、求助、道歉、秘密交换 | 需要"选择"，因此受性格与信念影响 |

> **意向类还要按「判定来源」归类**（见 §8.16）：纯增益型 / 纯损害型 / **信念驱动型**（闲聊的加入分支读 `B_A`）/ **信任·透明度驱动型**（秘密交换读 `T`、告密读 `O`）/ **混合判定型**（当众调侃读 `A`+`H` 并用绝对阈值分档）。**方向用阈值、强度用 `|M|`** —— 不可用 `M` 的符号判方向（反例与实测见 §8.16）。
> **玩家路径**：玩家不跑 NPC 的决策侧（跳过"想不想"的采样），由人直接选择行为并进入判定侧（§10.1）。

**意向类完整算法**：

```
① 门槛（硬条件，取自主文档 §8 的"触发条件"）
   闲聊（加入）：自己空闲、目标已有有效且可加入的闲聊会话、满足范围（§8.5、§8.7）；接受概率见 §8.22
   调侃：周围 ≥3 人 且（A[i][j] ≥ 40 或（H[i][j] ≥ 25 或 A[i][j] < 25））  ← 好意 / 挑衅双轨，见 §8.12
   安慰：stress_j ≥ 70 且 A[i][j] ≥ 50
   求助：A[i][j] ≥ 30（内向型 ≥50）    道歉：H[i][j] ≥ 30（双向）    秘密交换：T[i][j] ≥ 60
   → 不通过的组合不进入候选集（概率恒为 0，不允许"小概率硬做"）

② 意向评分
   U_b(i) = Σ_X α_X(i) · Δ_X^pred(i, b)
   我自己的立场 → 真值；对方的反应预期 → 信念（§14.5）

③ 性格权重 α（Σα = 1；系数以 `data/balance/npc_weights.csv` 为准）
   α_A      ∝ 0.5 + 0.5·F/100 + 0.3·E/100          情感型 / 外向型更在意好感
   α_T      ∝ 0.5 + 0.30·J/100                      判断型更在意信任（**跟 J 正向**，选项 C）
   α_H      ∝ 0.5 + 0.5·(1−F/100) + 0.30·J/100     思考型 + 判断型更在意敌对（**跟 J 正向**，选项 C）
   α_stress ∝ 0.5 + 0.5·(1−E/100)                   内向型更在意压力消解
   系数落在 data/balance/npc_weights.csv

   ⚠️ **选项 C 语义**：α_T 与 α_H **都跟 J 正向**——J 型"爱恨分明"（谁值得信、谁是敌人，先判断再下结论）。
   此前文档写 α_H ∝ 1−J（随性型更在意敌对）与实现相反，已废弃。
   ⚠️ **连带**：§11 社会事件投票 `U_vote = α_A·A + α_T·T + α_I·influence` 引用的 α_T 语义已变，
   将来标定 `α_I` 时必须按新的 α 口径重定，不要沿用旧值。

④ 温度与采样
   p(b) ∝ exp( U_b / τ_i )
   τ_i = τ0 · (1 + 0.3·(1 − J_i/100)) · stress_modifier
   τ0 = 1.0 ｜ stress_modifier = 1.0（<70）/ 1.5（≥70，冲动）
```

τ 的物理含义：**τ → 0 退化成 argmax（刻板），τ → ∞ 退化成纯随机（噪声）**；1.0 附近是"有偏好但不死板"。

> **性能与可复现**：候选集上限 `top_n`（默认 5）；同一 tick 内的决策顺序必须确定性（按索引升序或固定种子洗牌），否则同种子不可复现。

## 14.7 工程不变式汇总（违反即为缺陷）

1. **禁止角色名 / ID 判断**：行为逻辑必须只依赖 `f(性格四维, 透明度, 状态)` 与信念；角色差异只能来自 `data/characters/` 的开局种子。
2. **观察层只读**：簇标签器与孤立标签**绝不回写**任何矩阵。
3. **决策读信念，判定读真值**：决策路径中不得出现 `A[j][i]`、`H[j][i]`、`T[j][i]`（"别人对我的态度"）。
4. **不引入脚本化剧情**：不得出现"第 N 天 / 第 N 段必然发生 X"。
5. **数值集中**：增量、阈值、系数一律来自 `data/`，脚本中不得出现魔法数字。
6. **可无头运行 + 可复现**：内核能在 `--headless` 下跑完整局；随机数一律来自种子化 RNG，同种子同结果。
7. **写入点唯一**：所有轴值变化都经 §4.1 的公式与 `clamp`，不得绕过。
8. **全部轴值域 0–100**；`null ≠ 0`（"不知道"不等于"中立"）。
