# 第二十六章 完整存档机制

> 策划规格 ｜ 记录日期：2026-10-11 ｜ 完整机制尚未实现。现有代码仅有通用 JSON 读写、部分时间字段恢复；主菜单继续游戏尚未接通。
> 依据：第十四章数据模型、第二章时间系统、第七章推理板、第十二章简报与报告。本章取代“只能在日末存档”的限制；日末仍是重要的自动保存点。

## 26.1 目标与范围

支持任意时刻请求保存、原位置续玩、多槽位、自动保存、备份和版本迁移。读取后恢复完整会话；不得推进时间、重新抽角色、重抽既有判定、重复发放线索或重复结算。

首版完整范围包含本地存档与学期归档；云同步、跨设备导入导出与回放播放器不在本章交付范围。完整快照负责续玩；历史事件日志本身不等同于可以驱动全局重放的指令记录。

| 功能 | 玩家获得的结果 |
|---|---|
| 继续游戏 | 读取最近一次成功保存且可恢复的进度；不同本局间按保存时间比较 |
| 手动保存／读取 | 暂停菜单选择槽位，新建或确认覆盖；读取当前局以外的存档需确认放弃未保存进度 |
| 快速保存／读取 | 独立快速槽；快速读取也须保护当前未保存进度 |
| 自动保存 | 新局初始化、阶段切换、日末结算完成及周期性保存 |
| 保存并退出 | 保存成功后退出或返回主菜单；失败时留在游戏中 |
| 学期归档 | 保留结束状态、最终报告、日志及最终推理板，允许再次查看 |

每局提供 3 个手动槽、1 个快速槽、3 份轮换自动档。周期性自动保存默认累计 60 秒有效游玩时间；暂停、加载、简报与结束界面不累计。槽数与间隔集中放入拟新增的 `data/rules/save_policy.csv`，不得散落在脚本中；本次只记录规格，不创建配置表。

新游戏创建独立 `run_id`，旧局存档保留；自动保存只轮换本局自动槽，不覆盖手动档、快速档或其他局。跨局自动清理与删除整局必须由玩家明确操作，不随新游戏自动发生。

存档卡显示本局名称、游戏日期／阶段、保存时间、槽位类型及结束状态（2026-10-12 起不再有难度档）。截图为可选表现，不得决定存档成败。损坏或不兼容的文件仍可显示原因，不能只按文件存在性启用继续。设置独立保存，重开或读档不重置音量等偏好。

## 26.2 快照安全点与请求协调

任意时刻接受请求，在当前 tick、玩家原子提交或整次阶段边界处理完成后取快照。不得为了保存推进额外 tick，也不得截取结算执行到一半的状态。

1. 接收请求，记录保存类型与目标槽。
2. 等本次原子操作完成，暂时冻结时钟、移动、交互输入与状态写入。
3. 内核和场景导出同一时刻的数据深拷贝，验证相互关联。
4. 恢复保存前的冻结状态；普通保存可继续游玩，再写入不可变快照。保存并退出保持暂停至结果明确。
5. 文件落盘校验成功后更新列表并提示成功；失败不得宣称已保存。

同一槽位串行写入，不允许重入覆盖。重复自动请求可合并；手动请求保留目标与明确回执。暂停期间不补跑时间，保存过程中产生的写盘等待不计入模拟。

| 正在进行的操作 | 保存与恢复规则 |
|---|---|
| 行走 | 保存位置、朝向、移动方式、目标、剩余路径与进度；恢复后继续同一移动 |
| 聊天、学习、睡眠 | 保存活动成员、占用、完成 tick 和请求状态，不能重新开始或提前完成 |
| 转笔判定与揭晓 | 保存请求、是否已判定、已生成结果与剩余展示时间；未判定的请求按原流程只判一次，已判定结果不得重抽 |
| 邀请或纸条等待选择 | 保存内容、编号、有效期、冷却、已读状态与当前选择步骤 |
| 阶段／跨天结算 | 整次边界完成后保存，包含幂等标记；不单独在内核结算事件回调中抓取快照 |
| 绘画与头像拖拽 | 当前已画部分收束为笔迹；头像拖拽取消并回到最近已提交位置，瞬态光标与拖拽影子不保存 |
| 简报与结束报告 | 保存对应报告与冻结模式，读取后仍停在该界面 |

阶段切换与日末自动保存必须在日志、报告归档及场景边界处理完毕后统一发起。首日自动保存也要等人物、几何与控制器装配完成。

## 26.3 全量状态清单

凡影响后续模拟、玩家已知信息或玩家创作的可变数据都必须保存。实现时逐字段登记为“持久化／确定性重建／可舍弃表现”，新增组件同步维护清单。

| 分组 | 必须包含 |
|---|---|
| 本局身份 | 本局编号、名称、种子、人数（16）、实际角色索引顺序、绑定组与角色标签 |
| 关系与信念 | `A / H / T / H_deep / B_A / B_H / B_T`，保持方向和精度 |
| 个体 | 性格四维、透明度、压力、成绩、学习累计、心结及其他状态实例 |
| 时间与结算 | 天数、相位索引、相位内及全局 tick、段首是否执行、边界幂等键、结算去重记录 |
| 行为与证据 | 当前／后续行为、占用、完成状态、睡眠、施害证据、目击记录、排挤冷却、事件计数 |
| 会话与交互 | 活动会话、成员归属、下一编号、玩家请求及响应、邀请结果／冷却、待处理交互流程 |
| 纸条及社会过程 | 活跃纸条、持有者、读写／转交状态、下一编号；已实现社会事件的阶段与运行时实例 |
| 空间与环境 | 座位映射、人物位置、移动状态、音量与其他班级级标量 |
| 漫游与控制器 | 独立 RNG、站立点占用、决策计时、剩余额度、挂起相位、归位标记、玩家／NPC 路径进度 |
| 玩家记录 | 情报历史、线索编号、事件与学期日志、日报、最终报告、推理板笔迹／颜色／头像标识与位置 |
| 随机流 | 内核、情报、漫游及其他影响结果的独立随机状态；种子和算法标识同时保存 |
| 时钟与展示流程 | `running / report / finished`、计时累计、`ended_day`、尚未结束且承载玩法结果的展示步骤 |

内核现用 `MtRandom`：保存完整状态数组与游标。情报、漫游现用独立 `RandomNumberGenerator`：分别保存 seed 与 state。仅存种子或按抽取次数猜测恢复不合格。

派生标签、感知与圈形按原规则重建，不回写矩阵；若观察器含影响显示连续性的稳定性滤波记忆，则保存其历史计数，不能以“标签可重算”为由抹掉历史。资源、信号、弱引用、节点引用、悬停、普通提示动画与声音播放游标不保存。暂停／转场拥有者由组件重建，不能恢复已不存在节点的锁。

日志直接随快照保存，首版不依赖外部日志文件。推理板使用数据模型持有，场景销毁不等于记录销毁；最终板面必须在任何清板操作前归档。存档内的真实矩阵不能通过 UI 泄露给玩家。

## 26.4 模块职责与装配

| 模块 | 职责 |
|---|---|
| `SimCore` 与子组件 | 导出、校验与恢复纯状态；持有矩阵的模块保持唯一所有权 |
| `MtRandom`、情报组件 | 导出与恢复各自随机流 |
| `SimulationClock` | 时钟累计、模式、日报日期恢复；核对内核时间，不独立改日历 |
| `ClassroomRoam`、Walker、玩家与交互控制器 | 恢复空间、移动、交互和展示流程 |
| 日志／报告／推理板模型 | 保存玩家记录，与渲染节点分离 |
| `GameState` | 本局身份与完整会话装配、统一快照协调 |
| `Save` | 槽位列表、文件封装、校验、备份、迁移和错误返回，不承担玩法规则 |

拟新增纯数据导出／恢复接口；恢复函数返回结构化成功或错误结果，不仅打印日志。内核不得依赖场景或 Save 单例，不序列化整个场景树。组件引用与事件出口在状态恢复后重新绑定，历史事件不再广播为新事件。

## 26.5 文件与编码

```text
user://saves/<run_id>/
  manual_01.dat … manual_03.dat
  quick.dat
  auto_01.dat … auto_03.dat
  archive.dat
  <槽位文件>.bak
user://settings.dat
```

每份文件自包含，不依赖其他存档。路径由内部槽位标识生成，本局显示名称不作为路径。旧 `user://savegame.dat` 仅为原型输入，不作为新机制唯一槽位。

封装字段：格式版本、游戏版本、规则兼容版本、空间版本、玩法配置指纹、保存时间、类型、本局元数据、完整状态与校验值。完整状态分为 `core / clock / scene / journal / board`；元数据来自同一快照，不能另外推算进度。

首版使用 JSON：64 位 seed/state 用十进制字符串；矩阵恢复为现有 Float64 精度，禁止显示级取整；整数键、向量、颜色与 PackedArray 显式编码和还原。校验值针对约定的实际状态字节计算，避免解析后键顺序或数值格式变化造成误判。限制文件大小与集合长度，校验必需字段、有限数值、矩阵尺寸、编号关联及索引范围，拒绝不完整状态，不静默补默认值。

完整性校验用于发现损坏，不承诺防篡改。存档列表可缓存，但以有效文件为准，缓存丢失可重新扫描。

## 26.6 读取与切换流程

1. 读取文件，验证封装与完整性；需要时尝试同槽备份。
2. 在内存中迁移并校验版本、规则、配置及空间兼容性。
3. 创建候选内核，导入全部状态并重建子组件引用，不推进 tick 或发布历史事件。
4. 创建暂停的候选教室，注入几何与座位，恢复人物、漫游、路径和控制器；装配期间不消耗玩法随机数，不让新局初始化覆盖已恢复状态。
5. 恢复时钟、日志、板面及待处理交互界面，检查活动／请求／人物对应关系。
6. 候选会话完整就绪后替换当前会话；失败回到原会话或菜单，保留原文件。
7. 读取后先暂停，由玩家点击继续；简报／结束模式保持冻结，无离线推进。

正常初始化所需的随机操作不得改变最终恢复状态；禁止恢复后补跑段首、重新发奖励或清空未完成活动。若目标移动路径不合法，按明确的空间迁移处理，不能无声瞬移到座位。

日末可能同时存在 `ended_day` 为上一天而 `core.day` 已为次日的状态，这是合法边界；显示简报日期，点击继续后进入内核指定日期，不再做一次跨天衰减。学期末同理，禁止启动额外一天。

## 26.7 可靠写入与失败处理

写同目录临时文件 → 关闭并回读完整校验 → 保留上一份有效文件为备份 → 替换正式文件 → 检查结果 → 更新列表。失败保留最后有效档，不先删除唯一有效副本。不得把这一流程宣传为对任意系统断电均绝对原子；恢复逻辑必须识别主档／备份／遗留临时文件，并只接受完整校验通过的候选。

主档坏而备份有效时，提示恢复的实际保存时间。遗留临时文件只有完整校验通过且身份／版本匹配时才可作为恢复候选，不能仅凭时间较新覆盖主档。自动轮换以成功写入为准，失败不丢掉上一轮可恢复文件。

保存失败显示原因与重试入口；保存并退出失败保持游戏暂停，允许重试或由玩家明确选择不保存退出。覆盖槽位、删除档案及删除整局均须确认；删除主档时一并处理该槽备份，不能随后自动把删除的档案恢复出来。

## 26.8 兼容与迁移

| 变化 | 处理 |
|---|---|
| 字段结构 | 按版本逐步迁移，保留原文件；迁移失败不覆盖 |
| 玩法代码或数值规则 | 依据规则兼容版本与配置指纹判断，只有明确声明兼容或有迁移时继续 |
| 字体、图标等表现资源 | 不影响玩法状态时允许加载，丢失可选截图不拒绝存档 |
| 座位、交互几何、导航布局 | 空间版本校验；明确迁移或拒绝恢复，禁止静默改变互动机会 |
| 未知未来版本 | 明确拒绝，不降版本读取 |
| 旧原型档缺完整内核／随机状态 | 无法补造历史进度，提示不支持完整续玩并保留文件 |

“文件存在”“文件有效”“可以在当前版本恢复”分别判断。未提供规则兼容声明时保守拒绝不同规则档；不能靠存档格式号相同就放行。

## 26.9 实施与验收

实施顺序：状态清单与编码契约 → 内核／随机流往返 → 场景移动与交互恢复 → 可靠写入及槽位 → 菜单／自动保存 → 报告归档与迁移。完整交付必须全部覆盖，不能把日末可恢复当作任意时刻恢复已完成。

核心验收：同一局在同一时刻分为直接续玩与保存后销毁重建两条路径，在相同规则、输入、步长与空间条件下，后续矩阵、事件、线索及随机状态一致。内核确定性往返须精确；真实场景验证路径、位置与交互结果，平台几何数值容差单独声明，不能用容差掩盖规则事件分叉。

- 单一人数（16 名 NPC + 玩家 = 17 节点；2026-10-12 起不再有难度档），覆盖行走、聊天、学习、睡眠、邀请、纸条、转笔待判定／揭晓。
- 保存和重复读档不重抽结果、不重复线索／奖励、不重复相位／日末结算。
- 核对计时累计、独立 RNG、编号、冷却、推理板、日志与报告完整往返。
- 阶段中、边界后、简报、第 30 天结束均能恢复，最终板面归档后可查看。
- 损坏、截断、未知版本、磁盘写入失败、替换中断、备份／临时文件恢复。
- 多局多槽不误覆盖，覆盖／删除确认，保存并退出失败不离开原局。
- 新旧格式迁移与空间不兼容均有明确行为，恢复失败原会话仍可用。

检验一：存档只保留原有规则运行出的状态，不预设派系、事件或结局；读档后由同一套底层规则继续演化。
