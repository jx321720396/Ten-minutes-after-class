## 0. 三条阅读前提

1. **可视化只呈现，不参与计算**（主文档 §4、§15）—— 界面上的任何元素都不得自己算数值。
2. **玩家看不到原始数值**：好感 / 敌对 / 信任 / 透明度 / 压力一律以"可见度"形态出现，呈现规则受 §9 约束（§12.4 明令）。
3. **本作最重要的那张图是"课间主视图"**：策划案的卖点是"不开面板就能看出班级格局"（§15.1）——如果只来得及画 3 张，就画它 + 行动面板 + 每日简报。

## 4. 绑定呈现规则（不得自由发挥）

### 4.1 技术规格（[`视觉风格指南.md`](视觉风格指南.md) §1）

1920×1080 横屏 · Mobile 渲染器 · 默认贴图过滤 Nearest · 正文 ≥ 28 px · 安全区上下各 5% / 左右各 3%。

### 4.2 透明度决定态度线形态（§9.2，硬性）

| 透明度 | 玩家看到的 |
|---|---|
| 高（80+） | 实线，颜色清晰，粗细准确反映强度 |
| 中（40–80） | 半透明虚线，颜色偏淡：方向可辨、强度不确定 |
| 低（20–40） | 时隐时现，旁边带问号，只能猜站哪边 |
| 极低（<20） | 完全不显示（"这个人是个谜"） |

**暖色 = 好感、冷色 = 敌对，颜色语义整局一致**。

### 4.3 其他硬约束

1. **情绪图标是唯一直接暴露情绪的窗口**，且只有 6 种、不暴露数值（§15.1）。
2. **活动圈是秒级（此刻谁和谁在一起）、簇是天级（谁和谁长期要好）** —— 两套尺度并存，视觉上必须能区分，不能互相替代（§15.1、§10.31.4）。
3. **掷骰的成功率从信念算**，界面不揭晓对方真实态度；概率是渐变的，**永远不出现 0% / 100%** 的硬闸门（§10.32.3、§10.32.4）。
4. **标签默认不可见**，只能通过观察（透明度）/ 被告知（信任 + 好感）/ 推断（行为痕迹）三条路径解锁 —— 界面上不得提供"直接看到标签"的入口（§9.6）。
5. **假信息必须留下可验证破绽**：情报 / 传话类 UI 不允许做成无差别噪声（§9.5）。
6. **矛盾高亮（M2）需要独立且醒目的视觉语言**，且不与状态色、情绪色冲突（视觉指南 §4）。
7. **UI 不呈现任何原始数值**：玩家不能读写好感 / 敌对 / 信任 / 透明度 / 压力（§12.4）。

## 6. 交付与验收

- **切图清单**：每张界面交付时附"节点 → 切图"对照，C 可直接接线（D 任务：D11–D12）。
- **自适应**：1920×1080 与更窄的横屏（如 1280×720）两种缩放下不裁切、不重叠；触屏命中区不小于 44 px。
- **素材入库**：单张贴图 ≤ 1 MB、九宫格优先、`.import` 随图提交、第三方素材先登记 `assets/CREDITS.md`（未登记禁止合入）。
- **验收口径**（A 判定）：课间主视图必须做到"**不用文字解释就能看出谁抱团、谁被孤立**"（§15.1、冲刺计划 D11–D12 验收）。
- **截图包**：5–8 张（主菜单 / 课间操作 / 聚散可视化 / 简报 / 结局），交 E 用于游戏页与开发者日志（比赛提交清单 §4）。
