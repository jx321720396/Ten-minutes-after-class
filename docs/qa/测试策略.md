# 测试策略

> 状态：草案 ｜ 维护者：程序 / 测试 ｜ 最后更新：2026-10-04
> 规格依据：`../gdd/core-gameplay-v3.0.md` §3.4（标定目标）、§11（铁律）、§15（涌现对照表）

## 1. 测试分层

| 层级 | 手段 | 覆盖对象 | 何时跑 |
|---|---|---|---|
| 静态 | CI：`gdformat --check`、`gdlint` | 风格、明显缺陷 | 每次 push / PR |
| 单元测试 | GUT 或 gdUnit4（`tests/unit/`） | 每条规则的分支、公式、钳制 | 每次 PR |
| 铁律测试 | 专用断言（`tests/invariants/`） | 四层分离与观察层只读 | 每次 PR |
| 无头集成 | `godot --headless` 跑整局（`tests/integration/`） | 时间系统、结算、存档 | 每次 PR（短局）/ 每日（满 30 天） |
| 批量标定 | `tools/` 跑 ≥100 局统计（`tests/balance/`） | 数值收敛与格局弧线 | 版本节点 |
| 涌现验收 | 人工对照 §15 清单（`tests/emergence/`） | 13 条现象的机制验证 | 里程碑验收 |

## 2. 铁律测试（本项目的特色要求）

这三条是设计红线，必须有自动化断言，避免被后续改动悄悄破坏：

1. **无角色 ID 判断**：静态扫描 `scripts/systems/`、`scripts/npc/`，禁止出现种子表中的 `alias` 字符串或硬编码角色索引常量（白名单：`data/` 加载代码）。
2. **观察层只读**：给 `Relations`/`Stress` 接口加写计数；断言 `ObserverLayer.update()` 调用期间写计数为 0。
3. **数值不落在脚本里**：扫描违规的浮点/整型字面量（白名单：`0`、`1`、`-1`、`100`、`0.5` 等结构常量，清单在测试内维护）。

## 3. 无头集成测试

内核必须能脱离渲染运行（见 `../design/架构总览.md` 边界约束），因此：

```
godot --headless --path . --script tests/integration/run_term.gd -- --days=30 --seed=12345
```

- **确定性**：同一 `seed` 必须产出完全相同的日志；这是回放（v3.0 §14.3）与标定的前提。
- **快照**：固定种子跑完整局后输出关系矩阵摘要（哈希）作为回归基线；数值改动导致变化时需人工确认。
- **存档往返**：每日存档 → 读档 → 继续推进，结果与不读档一致。

## 4. 标定验证（对应 v3.0 §3.4）

批量局统计脚本输出以下指标，作为 M1 的验收数据：

| 指标 | 目标 | 判定 |
|---|---|---|
| 好感增长曲线 | 陌生(20) → 朋友(60) 用 2–3 天 | 中位数落入区间 |
| 压力爆发频率 | 每 1–2 天一次，集中第 2、3 段课间 | 均值与分布同时满足 |
| 派系/格局弧线 | 第 1 周成阵营 → 第 2–3 周博弈 → 第 4 周稳定或大事件 | 人工抽检 + 簇数量时间序列 |
| 数值饱和 | 30 天后不应出现大面积 100 | 好感矩阵接近上限的比例 < 阈值（待定） |

## 5. 涌现验收（v3.0 §15）

§15 的 13 条现象逐条写成可复现用例（固定种子 + 操作序列 → 期望现象），作为里程碑回归清单。示例：

| 现象 | 验证方式 |
|---|---|
| 开朗学生被反复调侃后变成小透明 | 对同一目标连续 R10 若干次，观察好感/压力/透明度走向与 R2 敷衍率上升 |
| 墙头草在两个阵营间反复横跳 | 构造两个敌对立强连接集合，观察中间节点的 Δ 符号翻转次数 |
| 连佳豪都不理的人被全班孤立 | 观察"初始对全班好感 50"节点的好感衰减是否最终低于阈值 |

## 6. 手动测试重点

- 触屏与键鼠双端操作（移动、选话题、拖拽推理板标记）。
- 30 天连续游玩的内存与存档稳定性。
- 上课段快进时切到推理板/日志的交互不中断模拟。
- 无障碍：文字可读性、关键事件的视觉替代。
