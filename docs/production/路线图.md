# 路线图

> 状态：老师版迁移规划｜最后更新：2026-10-14｜依据：[主策划案](../gdd/core-gameplay-v3.1.md)第十四、十五章。

当前目标是制作移动端，开发与验收在 `main-mobile`；通用代码、数据、文档先在 `main` 落定，再按 `main → main-mobile` 同步，保留移动端已有实现。

本轮已修订策划，尚未实施老师版。教室、人物、时间、活动会话和日志为复用候选，不能把学生版 M1 与旧标定视为新玩法完成。

## M1-A：学习管理闭环

- [ ] 明确初始值、活动时段、老师耗时、跨天保留与首次考核目标。
- [ ] 16 名学生与老师独立实体，压力、动力、学业收益分别存储和展示。
- [ ] 动力 >50 学习、<50 娱乐、=50 保持；固定决策点，崩溃独立中断。
- [ ] 学习／娱乐累计净收益，跨天一次计入成绩，切换和读档不重复结算。
- [ ] 训斥、安抚有时间成本，处理一人时其余学生继续行动。

退出标准：可解释地完成每日学习／娱乐、干预与成绩变化；不能用反复瞬时操作无限补动力。

## M1-B：关系闭环

- [ ] 每课间一次：正交好感 +1、对角不加、圈外 −1、学习者对娱乐邻居敌对 +5，方向明确且独立叠加。
- [ ] 被动固定单位结算，配置驱动、全程可见，完成预览和去重。
- [ ] 学生根据好感与敌对自主选择接触；真实交流回写关系。
- [ ] 友善交流、停止打扰、老师调解能够减少敌对。
- [ ] 鼓励自主／指定聊天形成一次目标，等待、拒绝和到期可解释。

退出标准：同一开局不同管理策略形成不同关系结构与管理难题；只比较平均分不能作为涌现验收。

## M1-C：七天考核闭环

- [ ] 孤立、霸凌、退学、严重伤害判据及预警窗口配置化。
- [ ] 短暂独处、一次拒绝和一般争吵不直接触发失败。
- [ ] 老师介入能停止伤害、降低风险；关系不会被直接重置。
- [ ] 第七天平均成绩考核与辞退原因明确；日末简报有收益和干预明细。
- [ ] 多种子检查加压、减压、学业收益、敌对修复和角落座位偏差。

退出标准：首次周考及关系危机可连续运行、可预警、可解释；新实现完成相应配置校验与 Python／GDScript 对拍。

## 后续范围与排期

标准学期仍为 30 天。后续考核、成功结局、上课权限、完整搜包／没收与物品恢复需在参数和闭环验证后安排。

赛事目标日仍按 [原冲刺计划](聚光灯21天冲刺计划.md)跟踪为 10/18。本轮没有重新承诺老师版的完成日期；原倒排日历中的学生玩法、旧冻结范围和 Windows 优先止损规则不得直接替代当前移动端方向。

完整验收清单见 [里程碑](里程碑.md)，工程边界见 [架构总览](../design/架构总览.md)。
