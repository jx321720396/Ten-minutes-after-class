# 人物底部圈与活动融合圈计划案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本文件为设计与实施计划，本次不实现代码、不派发代理。

**Goal:** 在当前 3D 教室的所有纸片人物脚下显示统一颜色的个人圈；两人交互成功并共同活动时融合为不同颜色的连续活动圈，帮助玩家看清谁正在一起活动。

**Architecture:** 内核提供已成立交互的活动会话快照；表现层读取会话和人物地面位置，画独立圈或同组融合区域。脚下圈不参与行为判定、不写关系矩阵、不把观察层簇标签当作活动组。

**Tech Stack:** 项目既定 Godot 4.7.2、GDScript、3D MeshInstance3D、简单空间 Shader、GUT；兼容当前 Mobile 渲染路径，不引入插件、外部绘图素材或物理模拟。

**Spec:** 用户本聊天的脚下圈需求；玩法主文档 §10.31（活动加入）、§10.30（只读观察层）、§15（可视化）。本文进一步设计的配色、会话接口与尺寸属于实施建议，实施前按同一份设计收口。

## 1. 当前代码与交付范围

当前 `scripts/game/classroom_actors.gd` 有玩家与缺图人物的 Marker，但它是抬高的占位球体，不是脚下活动圈。不能直接把它改色当作此功能完成。

`scripts/core/sim_core.gd:get_activity_circles()` 仅按 `_current_act` 的行为名称汇总，不区分两处同类活动；聊天还使用 quiet 标记让一方 current_act 为空。这一接口不能作为新圈的成员事实源。

本计划覆盖玩家与全部 NPC。独自行动的人都有个人圈；任何实际可见的成功共同活动都有融合圈。观察层的朋友簇、阵营、孤立标签与本功能无关。

首版支持正式接通且有成功/活动生命周期的闲聊（发起／加入）、求助、安慰、共同打闹。闲聊与原“搭话”已合并，加入成功扩展原 chat 会话，不建立另一种搭话活动圈；完整接线见 [统一闲聊计划](2026-10-07-chat-playable-loop.md)。道歉只有双方接受并进入共同交互时才显示；失败、举报、排挤、流言的传播对象、仅旁观者不自动入组。共同学习要由正式共同学习会话提供成员，不能把所有学习者连成一组。秘密等未实现行为不为画圈新增玩法。

## 2. 用户可见规则

| 场景 | 显示 |
|---|---|
| 一个人独处、留座或行走 | 脚下一个浅灰蓝个人圈，所有角色颜色相同 |
| 两人等待判定或正在接近 | 保持两个个人圈，不预告结果 |
| 判定成功，双方近距离进入共同活动 | 两个圈同步变为活动颜色，中间连成连续区域 |
| 判定拒绝 | 不融合，个人圈保持基础色；拒绝通过转笔结果/短气泡显示 |
| 第三人加入成功 | 扩展当前活动圈，原组颜色保持不变 |
| 同一地点旁观但没加入 | 保留个人圈，不因靠近自动归组 |
| 某成员离开或共同活动结束 | 解除该成员的融合，恢复个人圈；剩余至少两人继续融合 |
| 只剩一人 | 融合组消失，最后一人恢复基础圈 |
| 不同活动恰好靠近 | 保持不同会话及边界，不因为颜色相同或位置接近合组 |
| 上课、日末、学期结束 | 结束不再有效的课间组；上课只保留规则允许的共同学习组 |

圈显示的是“正在共同活动”，不是喜欢、信任、成功率或永久归属。成功只提供成立条件，不让圈永久保留。

**生命周期边界：** 交互成功且共同活动开始时融合，活动结束/离开时拆分。如果当前行为实现仅在耗时结束后才揭晓成功，则必须明确该时点之后是否还有共同活动；没有持续活动就只播放一次短融合反馈然后拆分，不能用圈伪造持续活动。实施要按行为真实阶段分别接线，不能用一条历史成功事件一直挂圈。

## 3. 视觉方案与默认参数建议

采用贴地的低透明度色块＋细轮廓。个人是圆形，在透视镜头中自然呈椭圆；融合后是两个圆由圆角连接段形成的花生形/胶囊形，避免画成一条细线。

两人融合示意：`○  ○ → ●━━●`。实际是柔和连续区域，不保留两个互相叠加的圈的内部边框。

新增 `data/rules/activity_ring_style.csv`，字段 `key,value,note`，建议初值：

| key | 建议值 | 含义 |
|---|---:|---|
| personal_radius_m | 0.38 | 个人圈半径，按桌椅间距目视调整 |
| connector_radius_m | 0.24 | 连接段半宽 |
| ground_offset_m | 0.015 | 距真实地面高度，避免闪烁 |
| outline_width_m | 0.025 | 连续区域的外轮廓厚度 |
| fill_alpha | 0.16 | 底色透明度 |
| outline_alpha | 0.65 | 轮廓透明度 |
| blend_seconds | 0.22 | 融合和拆分的表现时长 |
| personal_color | #9AAEB8 | 所有人统一的灰蓝色 |

新增 `data/rules/activity_ring_palette.csv`：`slot,color`，建议活动颜色为青绿 #4DAA93、暖橙 #D6A05C、柔紫 #A18BC6、蓝 #719CCB、珊瑚 #CF8181。这些是 UI 配色，不表示行为善恶；任何活动色都应明显区别个人色。

首版所有融合组共用青绿即可满足用户核心要求；完整计划采用小调色板提高相邻组辨识度。颜色尽量分配空闲槽，组存续期间不换色；超过槽数允许重复，由独立边界和空间位置区分，不引入高复杂度配色算法。颜色分配不消费玩法 RNG，也不基于角色名/身份/关系值。

玩家圈与 NPC 个人圈同色。玩家身份用姓名“我”或已有选择标记表达；被选中对象可以有额外细白边，不能改变活动圈归属。关闭可视化设置只影响表现。

地面色块不是光源，不投射大阴影、不做强光晕。保留深度测试，桌椅可以遮住圈；不采用透墙显示。脚下阴影和活动圈是两件事，圈不代替角色接触阴影。

## 4. 真实活动组与只读接口

新增 `scripts/core/activity_sessions.gd`，继承 RefCounted，记录当前共同活动会话，不计算 A/H/T 或产生新的概率。SimCore 在行为成立/加入/结束的既有位置调用它。

最小内部接口：

- `start(kind: String, members: Array[int], links: Array[Vector2i], end_tick: int) -> int`：返回递增会话编号，不用 RNG。只有成立的共同活动调用。
- `join(session_id: int, member: int, linked_member: int) -> bool`：加入原活动组，保留编号；不得同时加入两个互斥活动。
- `leave(member: int) -> void`：移除成员及关联边；不足两人清除；若剩余图断开，拆成真实子组，主组保留旧编号，其他子组新编号。
- `end(session_id: int) -> void`：重复结束无副作用。
- `expire(global_tick: int) -> void`：结束已到期会话，不执行关系结算。
- `snapshot() -> Array[Dictionary]`：深拷贝只读输出。

每条快照字段：`session_id:int, kind:String, members:Array[int], links:Array[Vector2i], end_tick:int`。links 是实际共同活动联系，不能把同类行为的任意两人连边。end_tick 是内核活动生命周期结束时点；行为需要提前结束时显式 end/leave。

SimCore 新增 `get_active_sessions() -> Array[Dictionary]`，读取上述快照。现有 get_activity_circles 保留作行为类型统计，注释明确不能用来画真实共同活动圈。

现有兼容实现可能同时发出 chat、join_chat 两条通知，注册会话应在实际成立的统一执行点做一次；不能由 UI 订阅两条事件各创建一个圈。新交互通知统一为 chat，另带 start/join 参与方式，不能把 join_chat 当作第二种产品行为。失败不会创建会话；若结果仍未确定，也不创建。

当前独占交互机制若尚不支持真实三人群聊，此任务仅交付双人融合；join 接口为后续真实加入提供连接，不能为了演示扩圈允许忙碌者参与第二个独立交互。群聊共享一份会话属于独立行为任务。

## 5. 3D 融合区域的程序画法

新增 `scripts/game/activity_ring_presenter.gd`、`scenes/game/activity_ring_presenter.tscn`、`assets/shaders/activity_ring.gdshader`，脚本与场景目录同构。教室下实例化一个 Presenter，不给每个人挂独立输入脚本。

个人圈复用材质与简单水平平面。活动组每组一个水平矩形平面，覆盖所有成员的地面位置包围盒＋圈半径；shader 在平面 XZ 坐标计算圆形与连接段的并集，再统一绘制填充和外轮廓。

并集距离函数：圆 `length(p-center)-radius`；连接段为两点间的胶囊距离；取所有距离的最小值。这样重叠部分只着色一次，没有内部双轮廓或更深的叠加色。普通 min 即可形成连续形状，首版不做复杂液体模拟。

二维描边、透明度和颜色由同一个 shader 处理。不使用全屏特效、SubViewport 渲染、实时网格布尔运算或 CSG。

Shader 最多接收 25 个中心、24 个连接段（来自现有最大节点数，实施读取配置并校验容量）。多成员 links 有环时，表现层取一棵稳定生成树减少重复连线，只影响画法，不修改会话。首版 17 人最多 8 个双人融合组，其余个人，性能规模很小。

每帧读取人物**去除步态起伏后的地面位置**；不能将 ActorWalker 的 bob 高度加到圈上。当前教室地面平坦，固定到地面平面；未来多层地面才引入地面探测。

只有空间已支持近距离共同活动才绘制连续连接：沿用正式交互范围检查；远距离或跨家具的关系不得画长桥穿过教室。若内核仍能远程交互，报告空间接入缺陷，保持个人圈，不靠视觉遮掩成“已经走到一起”。首次实现必须用真实接近用例验收。

个人属于有效融合组时隐藏其基础圈，由融合材质负责成员底色。不同组靠近仍由不同材质实例分别显示，不进行跨组几何合并。

融合动画只对呈现过渡：基础色过渡到组色，连接段从细到正常宽度；拆分反向过渡。真值成员变化立即更新，不因动画把已离开的人继续算在活动中。暂停时停止跟随世界运动；转笔自己的演出可继续，融合必须等结果揭晓后显示，避免提前泄露锁定结果。

## Global Constraints

- 仅当前真实共同活动决定融合，距离、同类行为和高好感不能自动成立组。
- 不修改矩阵、标签、行为概率、耗时、目标选择或 RNG 序列；活动会话追踪也是只读玩法效果的记录。
- 公开活动可见不代表内心可见；底部圈不展示 A/H/T、隐藏成功率或永久朋友簇。
- 参数集中在 data，UI shader 只用传入参数；算法结构常量需说明。
- 不改 resources/*.tres、.godot；不安装插件。
- 当前并行改动只作接线参考，不覆盖其他人的行为完成/移动代码。

## Review Focus

1. 两处都在聊天但实际互不参与，不能融合成全班聊天圈（任务 1、2）。
2. 成功、失败和取消必须有明确生命周期；历史成功不永久留圈（任务 1）。
3. 人物起伏或上课归位不能带着圈漂浮或残留（任务 3）。
4. 组内叠加不变深、桌椅正确遮挡；当前 Mobile 渲染下可见（任务 2、3）。
5. 开关圈前后同种子关系/RNG 保持一致，转笔结果不提前泄露（任务 3）。

## 7. 最终验收

- [ ] 所有人独立圈同色；玩家无需特殊底色也能靠名字/选择标记找到。
- [ ] 两人交互成功后的有效共同活动拥有一个连续融合区域，颜色区别个人圈。
- [ ] 失败、未判定、仅靠近、旁观不会融合；转笔没有提前透露结果。
- [ ] 两处同类活动不会连成一组；第三人真实加入后扩展原圈。
- [ ] 离开、结束、取消、归位后准确拆分，不用历史关系保留圈。
- [ ] 深度、脚底高度、透明度与当前 3D 教室一致，无遮挡 UI 和穿透显示。
- [ ] 所有视觉参数可配置；无需新的人物/圈图片素材。
- [ ] 模拟与 RNG 不因圈改变；若空间/群聊依赖缺失，交付说明明确标注。

实施顺序：先确定真实会话和生命周期，再画圈，再接教室。不得先用 get_activity_circles 按行为名字融合全班，之后再补正确分组。
