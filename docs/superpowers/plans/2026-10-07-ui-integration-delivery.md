# 剩余 UI 落地与联调计划书

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在已有聊天、情绪气泡、人物圈基础上，补齐操作反馈、情报留存与每日结算，完成可玩的 UI 闭环。

**Architecture:** 复用当前 3D 教室、时间 HUD、移动控制、菜单及用户确认已有的情绪气泡与人物圈。新增组件只读取可展示数据、提交操作请求，不参与行为效果或随机判定。

**Tech Stack:** Godot 4.7.2、GDScript、Control / CanvasLayer，现有 3D 人物表现组件。

**Spec:** [主文档](../../gdd/core-gameplay-v3.1.md) §9、§12、§14；[架构总览](../../design/架构总览.md)。本计划收敛并替代[上一份 UI 总计划](2026-10-07-other-ui-rollout.md)的任务排期；专项组件设计仍保留作参考。

## 1. 本轮范围

按用户确认，**情绪气泡、人物圈已有，不再开发第二套**。聊天流程正在单独落地，本计划不重做目标选择、聊天判定、情报生成。

当前工作区可确认已有 `time_hud.gd`、`player_controller.gd`、`simulation_clock.gd` 及主菜单、暂停、设置。未找到可明确对应已完成人物圈与四情绪气泡的独立文件；执行者应从实际交付场景确认路径，再写入接线记录。这个登记包含在任务 1，不影响其余 UI 设计。

| 处理方式 | 内容 |
|---|---|
| 保留复用 | 时间 HUD、菜单、移动控制、聊天组件、情绪气泡、人物圈 |
| 新增或补齐 | 输入协调、点击终点、行为状态、情报日志、每日简报、期末出口 |
| 只联调 | 气泡触发、圈融合与解除、聊天结果与 UI 的时序 |
| 暂不扩展 | 自由连线推理板、关系全景图、回放、复杂存档槽位、24 NPC 档 |

## 2. 全局约束

- 本局按 16 NPC + 玩家；核心不引用 UI 节点，不因打开面板改变随机数调用或矩阵。
- 聊天模块决定信息内容与数量。情报 UI 保存交付时的快照，绝不能打开日志时读取当前真实矩阵更新它。
- 上课允许查已有情报，禁止发起课间操作；查看日志不占行为 tick，也不自动暂停时间。
- 判定动画只展示已经锁定的结果。显示的是信念估计概率，不给 UI 提供真实成功概率。
- 情绪气泡沿用放松、生气、哭泣、开心与男女素材；个人圈同色，共同活动成功后融合为另一颜色。
- 可调时长、偏移、样式参数集中到配置，复用已有键；不更改行为耗时、阈值或平衡数值。
- 每日简报按 §14 使用结算信息，和实时情报日志分开；没有日志依据不能编写原因或因果链。

## 3. 页面与操作

| 区域 | UI | 展示规则 |
|---|---|---|
| 左上 | 现有时间 HUD | 保留日期、阶段、倒计时 |
| 右上 | 情报按钮 | 新线索增加未读标记 |
| 右侧 | 情报抽屉 | 列表与详情，可滚动 |
| 底部中央 | 现有聊天面板 / 判定卡 / 新状态条 | 同一区域互斥，判定卡优先 |
| 场景内 | 已有情绪气泡、人物圈、目的地标记 | 保持人物锚点与实际活动状态 |
| 中央 | 每日简报、期末页、暂停 | 阻断世界输入 |

UI 点击必须消费事件，不能同时设置移动目的地。鼠标在情报抽屉外仍可操作世界；键盘焦点被 UI 占用时屏蔽 WASD。关闭最上层可关闭面板优先于打开暂停菜单。简报只能通过明确的继续按钮进入下一天。

转笔如采用全班暂停，沿用 `SimulationClock.hold(&"judgement")` / `release(&"judgement")`。普通状态条、气泡、线索提示不能自行暂停。打开暂停菜单后，转笔结束不能替菜单释放暂停。

## 4. 接口交付约定

以下是新 UI 的建议输入结构，不宣称当前代码已有同名信号。保留聊天与已有组件的原接口，在表现层做一次转换即可。

| 输入 | 必需内容 | 用途 |
|---|---|---|
| 行为状态 | action_id、behavior_id、target_id、stage、start_tick、end_tick | 接近、执行、完成、中断 |
| 已交付线索 | clue_id、source_id、subject_id、object_id、axis、display_text、day、phase_id、tick | 情报入库与展示 |
| 判定结果 | action_id、estimated_probability、accepted、feedback_key | 接现有判定和情绪反馈 |
| 实际活动 | session_id、member_ids、active | 接已有融合圈 |

关系方向始终是 subject → object；source 是信息来源，不能混为关系主体。若玩法允许显示数值，可额外传 `value`；UI 不能自设阈值把数值转换为“喜欢 / 讨厌”。

开始、完成、中断必须以行为模块的权威状态为准。多次刷新同一个 action 或 clue 不重复发提示；同一行为的结果只触发一次已有气泡，不能由新状态条再触发一遍。

## 11. 排期与验收顺序

| 批次 | 工作 | 前置 |
|---|---|---|
| A | 输入协调、点击终点、状态提示 | 现有移动与时钟 |
| B | 情报日志 | 可先用测试快照做页面，正式接聊天交付 |
| C | 简报与期末页 | 当天日志、标签与时钟边界 |
| D | 现有气泡和圈联调、视觉整理 | A—C 与聊天流程接线完成 |

优先做 **A → B**，让正在实施的聊天马上有可读、可留存的产出，再补 C、D。每批可以独立验收，不需要等待所有行为实装。

最终现场验收：点击地面 → 移动 → 发起聊天 → 显示执行状态 → 展示结果与已有情绪 → 接受后已有圈融合 → 完成后线索进入日志 → 上课能查历史 → 放学有简报 → 下一天正常继续 → 最后一天结束。

运行新增 GUT 用例及受影响的既有测试。纯 UI 接线不调整 Python；如果为了提供接口修改内核规则或状态推进，需要另外运行既有内核测试与跨语言验证。现存标定失败如实记录，不能顺手改数值来让 UI 任务通过。

## Review Focus

1. 面板点击穿透与 WASD 焦点：任务一。
2. 同一结果被多个组件重复消费：任务三、六。
