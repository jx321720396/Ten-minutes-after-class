# 聊天以外的 UI 落地计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 3D 教室中补齐移动、状态、情报与结算反馈，让玩家知道自己正在做什么、知道了什么以及一天发生了什么。

**Architecture:** 保留已有 TimeHUD、SimulationClock、PlayerController 和菜单。新增 UI 通过表现层适配器读取已允许展示的数据，操作请求仍交给内核；聊天的流程、判定、信息生成由正在开发的聊天模块负责。

**Tech Stack:** Godot 4.7.2、GDScript、Control / CanvasLayer、Sprite3D、地面 Shader。

**Spec:** [主文档](../../gdd/core-gameplay-v3.1.md) §9、§12、§14、§15；[架构总览](../../design/架构总览.md)；本轮用户确认的四种情绪及融合活动圈要求。

## 一、范围与当前基础

本计划是接入顺序与接口总表。移动标记、情绪、活动圈已有专项计划，执行时直接使用它们，不再重复设计：

- [点击位置与情绪反馈](2026-10-07-player-click-emotion-feedback.md)
- [人物底部活动圈](2026-10-07-activity-foot-rings.md)
- [时间组件](2026-10-07-time-component.md)

| 项目 | 检查到的状态 | 本轮处理 |
|---|---|---|
| 时间 HUD | 已显示日期、阶段、倒计时、进度与阶段提示 | 保留，补结算接线 |
| 移动控制 | 已有点击寻路及 WASD | 补终点标记与输入隔离 |
| 主菜单、暂停、设置 | 已有场景与脚本 | 复用，只处理整合缺口 |
| 情绪气泡 | 现有 speech_bubble 是通用气泡，不是八张情绪素材组件 | 接入四情绪男女两套 |
| 人物底圈 | 玩家仍有占位标记，真实融合活动圈尚需接入 | 按实际活动会话显示 |
| 情报日志、每日简报 | 尚无对应完整 UI 接线 | 新增最小可用版本 |
| 聊天流程 | 用户正在实施 | 不在这里重写 |

第一批采用 16 NPC + 玩家。困难档、多语言、复杂关系图、自由连线推理板、回放、完整存档槽位不加入本计划。

## 二、全局约束

- `scripts/core/` 不引用 UI、摄像机或场景节点；界面不改矩阵、不补抽随机数。
- 阈值、演出时间、偏移、半径与配色等可调参数集中配置，优先复用专项计划中的配置表，不创建重复键。
- 聊天情报是有时间戳的历史快照。界面不能在打开时换成当前真实矩阵，也不能自己决定透露哪条轴、几条信息。
- 情绪仅放松、生气、哭泣、开心；男女是素材变体。先完成玩家反馈，NPC 情绪展示另按可见性规则接入。
- 个人圈同色；成功建立共同活动后形成另一种颜色的融合区域。活动圈表示正在一起做事，不表示长期阵营。
- 不切换判定专用场景。转笔是屏幕 UI 演出，结果由行为模块提供并在开始时锁定。
- 上课允许查看既得情报，禁止借 UI 发起课间操作；查看情报不占行为 tick，也不自动暂停模拟。
- §14 的报告允许使用后台结算信息，不能简单套用情报日志的可见性过滤。实时情报与结算揭示必须使用不同入口。

## 三、画面布局与输入规则

| 区域 | 内容 | 规则 |
|---|---|---|
| 左上 | 现有时间卡 | 沿用，不再放第二套倒计时 |
| 右上 | “情报”按钮、未读标记 | 无新情报时安静，不持续闪烁 |
| 右侧抽屉 | 情报列表、线索详情 | 打开后仍可看见教室 |
| 底部中央 | 行为状态条 / 聊天面板 / 转笔卡 | 共享区域；转笔优先，避免三者叠放 |
| 人物脚下、头上 | 目标标记、活动圈、情绪 | 保留位置关系，避免大字号标签占满教室 |
| 屏幕中央 | 每日简报、学期结束、暂停菜单 | 阻断世界点击 |

普通聊天、查看情报时的时间规则遵循各自规格，不因面板出现就统一暂停。转笔若采用全班暂停，使用现有 `SimulationClock.hold(&"judgement")` / `release(&"judgement")`；暂停菜单继续沿用现有机制。释放一个拥有者不得释放其他拥有者的暂停。

UI 内鼠标事件先消费，避免点击按钮同时给玩家设置目的地。键盘焦点进入 UI 或出现阻断式面板时，停止世界 WASD 输入。Esc 顺序：关闭最上层可关闭面板 → 再打开暂停菜单；结算面板不能用 Esc 偷渡进入下一天。

先验收 1920×1080 与 1280×720。采用锚点和容器布局，不写死屏幕坐标；右侧抽屉与底部卡不能遮住必要的操作按钮。边框、背景和文字优先程序绘制，已有素材只用于笔、目的地与表情。

## 四、聊天模块只需要交付什么

以下是**建议的表现层接口**，不是已存在的内核 API。聊天开发者可以保留自己的命名，由适配器转换；不要求为了 UI 再重构内核。

| 输入 | 必须具备的字段 | UI 用途 |
|---|---|---|
| 行为展示状态 | `action_id, behavior_id, stage, target_id, start_tick, end_tick` | 接近、执行、完成、中断的状态条；空闲时隐藏 |
| 判定展示 | `action_id, estimated_probability, accepted, feedback_key` | 转笔演出；只展示估计概率，不接收真实概率 |
| 已交付情报 | `clue_id, source_id, subject_id, object_id, axis, value/display_text, day, phase_id, tick` | 入日志；关系方向是 subject → object，不能误写成 source → subject |
| 活动会话 | `session_id, member_ids, active, behavior_id` | 驱动融合圈；无真实会话时不按行为名称凑组 |

情报中的 value 只在聊天规则允许展示数值时使用；否则必须提供由信息层生成的 `display_text`，UI 不私设定性阈值。男女素材来源于外观配置，不能拿角色名判断。所有记录用稳定 ID 去重，不能在刷新、关窗再开时再次发放。

**文件：**新增 `scenes/ui/intel_log.tscn`、`scripts/ui/intel_log.gd`、`scripts/game/player_intel_store.gd`；修改协调器；新增 `tests/unit/test_player_intel_store.gd`。

**接口：**`PlayerIntelStore.add_clue(clue: Dictionary) -> bool`（新增返回 true，重复返回 false）；`get_clues() -> Array[Dictionary]`（返回副本）；`IntelLog.bind_store(store: PlayerIntelStore) -> void`。

- [ ] 写测试：同 clue_id 只保存一次；源数据随后改变不改变历史记录；A→B 与 B→A 保持分开；没有观测时显示空状态。
- [ ] 新情报出现一条提示：“获得一条线索”，详细内容进入抽屉。最近记录在前，点击查看来源、关系方向、轴以及取得时间。

## 十三、执行顺序和验收

建议开发顺序：**公共接线 → 点击标记 → 状态条 → 情报日志 → 情绪 → 融合圈 → 简报与结束 → 视觉整理**。其中情报日志可先用固定测试记录做 UI，正式数据只从聊天模块交付；融合圈先做个人圈，真实会话准备好再接融合。

最小完成标准是一条闭环：点击可达地点 → 玩家移动 → 发起已实现的行为 → 看到状态与判定反馈 → 已获得的线索进入日志 → 上课仍可查历史 → 放学有简报 → 第 30 天能结束并返回菜单。

实现时每个任务运行对应 GUT 用例；展示逻辑不得改变同种子内核结果。若新增行为会话或结算接口涉及内核，额外运行既有内核测试与对拍，和 UI 样式提交分开。项目现存标定失败必须如实记录，不以调数值掩盖 UI 接线问题。

## Review Focus

1. 点击面板同时触发地面移动：任务 1 输入测试。
2. 旧情报被当前矩阵悄悄刷新：任务 4 历史快照测试。
3. 相位结束把中断显示为成功：任务 3 状态测试。
4. 不相关的两组聊天被融合：任务 6 双会话验收。
5. 最后一天无有效结束出口、重复继续跨天：任务 7 流程测试。

## 十四、需要同步的旧文档口径

现有 UI 清单和主文档可视化章节仍有六种情绪、按活动类型多色圈等旧描述；本计划采用用户本轮明确的四种情绪、个人圈同色与成功会话融合。执行对应任务时同步修改主文档 §15 与 UI 清单，并在 CHANGELOG 记录；不要把旧清单的全部面板理解成本轮必须实现。

聊天透露数量、公式、行为门槛仍由聊天实施与主文档收口，本计划不裁决或改写。首批报告的降级项应标注为未完成，避免把 UI 有一个容器误记为完整玩法已实现。
