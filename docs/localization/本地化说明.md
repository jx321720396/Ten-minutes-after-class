# 本地化说明

> 状态：骨架 ｜ 维护者：文案 ｜ 最后更新：2026-10-19

## 1. 语言范围

| 语言 | 状态 | 备注 |
|---|---|---|
| 简体中文（`zh_CN`） | 基准语言 | 所有文案的源头 |
| 英文（`en`） | 待定 | 若参赛或发行需要再启动，需先确认平台要求 |

## 2. 工程流程（Godot）

1. 所有面向玩家的字符串使用 `tr()` 包裹，**禁止硬编码中文字面量到脚本与场景文本属性**。
2. 文案存放于 `data/localization/`（CSV，UTF-8）：首列为键 `key`，其后每语言一列。
   > 注：该目录将在需要时创建；当前阶段 UI 文案较少，允许暂缓。
3. 通过 Godot 的翻译导入生成 `.translation`，在项目设置中注册；`.translation` 属生成物，已在 `.gitignore` 中排除。
4. 键名规范：`模块.对象.用途`，例如 `ui.menu.new_game`、`report.daily.group_tag`、`rule.r10.failed`。

## 3. 文案规范

- **语气**：校园日常、克制、不煽情；简报与报告用陈述句陈述事实，避免替玩家下判断。
- **简报文案是数据驱动**：由日志片段拼接，禁止预制整句（主文档 §14），因此本地化必须按"片段 + 模板"组织，不能整段翻译。
- **术语一致**：与 [`../design/术语表.md`](../design/术语表.md) 对齐（如"好感/敌对/信任/透明度/压力/簇/孤立/推理板"）。
- **长度弹性**：UI 需预留 1.5 倍中文长度的空间（为未来英文翻译留余量），按钮文案尽量 ≤ 6 个汉字。
- **不暴露隐藏信息**：文案不得暗示玩家看不到的状态（与 主文档 §9 信息可见性规则一致）。

## 4. 百科词条的改稿流程

百科全书正文在 [`../../data/localization/encyclopedia.json`](../../data/localization/encyclopedia.json)（词条式，一条一个 `id`）。**直接手改 JSON 很容易碰坏转义与段落**，所以文案改动走「导出 → 逐词条改 → 回写」：

1. `python tools/export_encyclopedia.py` —— 生成 [`百科全书-词条编辑稿.md`](百科全书-词条编辑稿.md)：分类与词条各占一块，正文放在代码块里，段落之间空一行即分段。
2. 在编辑稿里改中文。`####` 那行是词条名，`- 别名 / - 一句话 / - 正文` 是内容，`id: … | category: … | implemented: …` 那一行是程序引用键（别动；`implemented` 改 `false` 即下线该条）。
3. `python tools/import_encyclopedia.py --dry-run` 先看报告（分类与词条的新增、删除、改动、顺序变化、未上线清单），确认无误再去掉 `--dry-run` 写回。校验不过（id 重复、`category` 不在分类表、正文代码块没收尾、正文为空）**不写盘**。
4. 回写后跑 `python tools/subset_font.py`：新文案里的汉字必须覆盖在 UI 字体子集内，否则运行期显示方框。
5. 改词条名要留意正文里的 `[t]旧名[/t]` 跨引用 —— 回写会把失效引用列成提示；改完同步引用，或把旧名留在 `别名` 里。

编辑稿是给人改的**镜像**，唯一事实源仍是 JSON；两边不一致时 `python tools/export_encyclopedia.py --check` 会退出码 1 报红。
