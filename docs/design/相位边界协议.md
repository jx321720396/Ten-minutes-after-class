# 相位边界协议

> 状态：定稿 ｜ 维护者：程序 ｜ 最后更新：2026-10-09
> 规格依据：主文档 §3（时间）、§10（规则）；对拍唯一事实源 `tools/core_sim.py` ↔ `scripts/core/sim_core.gd`

## 1. 为什么有这份协议

Python 参考内核 `tools/core_sim.py` 与 GDScript 内核 `scripts/core/sim_core.gd` 必须**同种子逐位对拍**（`tests/integration/test_tick_parity.py`）。相位边界（每段课间/上课切换时的一次性结算）的**执行顺序**决定核心 RNG 流的消费顺序——`free_join` 靠 `busy_until > global_tick` 决定跳过哪些节点并消耗核心 RNG，边界顺序不同 → 喂进 RNG 循环的节点集合不同 → 从第一个边界（tick 101）起全量发散。

历史根因：`check_interrupt` 在 GDScript 里**最先**执行、在 Python 里**最后**执行；且 GDScript 的 `check_interrupt` 内部**多跑了一次 `settle_finished_actions`**。

**统一裁决**（用户）：两套内核执行**同一份边界顺序**，保留「**先结束旧行为、再决定新行为**」；不靠把 GDScript 调用移到末尾去追平旧 Python（那会让新段决策读到未清理的旧段占用）。协议统一会改变旧 Python 的模拟结果，需重新标定，属修正规则执行顺序，不靠调参数掩盖。

## 2. 统一顺序（两套内核同一契约）

每次相位过渡按序执行，**不推进任何 tick**：

```text
① settle_finished_actions()   已到期动作/会话结算（完成奖励与情报；幂等）
② settle_sleep()              旧段睡眠收尾（减压 + 醒来）
③ check_interrupt()           中断「尚未完成且不能跨段」的动作（施加打断代价；不再内含 settle）
④ cleanup_phase()             清理旧段占用/会话/移动锁（清被中断者 current_act/busy_act/in_conversation、结束残留会话）
⑤ 日末跨天时 settle_day()      try_burst 等跨天结算（仅当旧相位是当天最后一段）
⑥ switch_phase()              phase_index=(+1)%size、phase=、tick_in_phase=0
⑦ roll_sleep() → free_join() → [break: phone_exposure() → roll_reports()]
```

> `check_interrupt` 判据用「**仍在进行**」`busy_until > global_tick`（而非旧的「跨段」`busy_phase != phase_index`）。在边界处两者等价：① 已先把到期动作结算清掉，② 新段尚无动作。用「仍在进行」才能在 ③（切换之前）安全判定。

## 3. 三职责拆分

两套内核都落成这三个入口，核心 RNG 消费序逐位一致：

| 入口 | 职责 | 核心 RNG |
|---|---|---|
| `settle_finished_actions()` | ① 只结算已到期动作，效果与通知不重复 | 无（会话线索走独立 PlayerChatIntel RNG） |
| `end_phase()` | ②③④⑤ 旧段特殊状态 + 中断 + 清理 + 条件跨天 | 仅 `settle_day → try_burst` |
| `begin_phase()` | ⑥⑦ 只初始化新段并执行新段判定 | `roll_sleep / free_join / phone_exposure / roll_reports` |

核心 RNG 消费序（决定对拍）：`try_burst`（跨天）→ `roll_sleep` → `free_join` → `phone_exposure` → `roll_reports`。

- **Python** `run_day()` 的相位循环：`begin_phase()` 之前是 `end_phase()`，`end_phase` 内部在 `phase_index + 1 >= len(day_phases)` 时 `settle_day()`；相位索引自增放在循环末尾（`end_phase` 之后）。
- **GDScript** `_transition_if_needed()`：段耗尽 → `_end_phase()`（内部条件 `_settle_day()`）→ `_phase_index = (_phase_index + 1) % size` → `_phase_setup_done = false`；下一次 `advance_tick` 走 `_begin_phase()` 完成切换与新段判定。首次 `_begin_phase` 是 bootstrap（`_phase_index=0`、`_phase_setup_done=false`）。

## 4. 幂等

边界标识用「**天 + 旧相位**」`(day, old_phase_index)`，而非全局 tick：

- GDScript 成员 `_settled_boundary := Vector2i(-1, -1)`；`_end_phase()` 开头判重：`(_day, _phase_index) == _settled_boundary` 则直接返回，执行完置键；`_reset_runtime()` 复位 `(-1, -1)`。
- 实时路径（`advance_tick` + `finish_time_boundary`）与 headless 逐 tick 路径都不会重复结算同一天同一旧相位。
- 幂等键取「旧相位」而非「新相位」：`_end_phase` 只在**切换之前**被调用，切段后 `_phase_index` 已指向新段，下一次 `_end_phase` 自然按新边界结算。

## 5. 对拍与测试

- 对拍：`tests/integration/test_tick_parity.py`，`A_mean/H_mean/T_mean/O_mean/stress_mean/grade_mean` 在 1% 判据下 0 发散，`*_hash` 逐位一致。
- GUT：`tests/unit/test_phase_boundary_protocol.gd` 六条——① 到期恰在铃声 = 完成非中断；② 跨段晚一 tick = 中断非完成；③ cleanup 清 `current_act/busy_act/in_conversation`；④ 重复 `_end_phase` 幂等（`_settled_boundary`，`stats["interrupts"]` 不翻倍）；⑤ 睡眠跨段唤醒恰一次；⑥ 抽象内核 `is_moving` 恒 false（对拍前置）。
- 移动状态两面对拍（`is_moving` 两层面）为长期后置项，不在本协议范围。
