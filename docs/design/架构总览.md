# 架构总览

> 状态：草案 ｜ 维护者：程序 ｜ 最后更新：2026-10-04
> 规格依据：`../gdd/core-gameplay-v3.0.md` §3（时间）、§4（三层 + 观察层）、§6–§7（数值与传导）、§10（规则）

## 1. 模拟内核 ↔ 表现层

本作是**数据驱动模拟**：内核每 tick 计算完成后再通知表现层，表现层不参与数值计算。

```
       ┌──────────────────────── SimulationCore（无 UI 依赖，可无头运行）────────────────────────┐
       │  TimeSystem ──tick──► RuleScheduler ──► Rules(R1..R13) ──► Relations(A/H/T) / Stress     │
       │        ▲                    │                                   │                       │
       │        │                    └──► TransmissionResolver（每 tick 末，§7.2 非线性传导）      │
       │   TermState（天/段/相位）                   │                                           │
       │                                             └──► ObserverLayer（O1 簇 / 孤立，只读）     │
       └─────────────────────────────────────────────┼──────────────────────────────────────────┘
                                                     ▼
                     EventBus（信号）──► Presentation（场景、可视化、推理板、简报、存档）
```

**硬性边界**：`scripts/core/`、`scripts/systems/`、`scripts/npc/` 不得 `preload` 任何 `scenes/`；模拟内核必须能在无渲染环境下跑完一局（批量标定与单测依赖这一点）。

## 2. 分层职责

| 层 | 目录 | 职责 | 禁止 |
|---|---|---|---|
| 模拟内核 | `scripts/core/` | 时间推进、矩阵与压力状态、结算 | 依赖节点树/UI |
| 规则层 | `scripts/systems/` | R1–R13 的触发与效果、影响力传导 | 角色名/ID 判断 |
| 观察层 | `scripts/systems/observer/` | O1 簇标签、孤立标签 | 回写任何数值 |
| 决策层 | `scripts/npc/` | NPC 的**规则选择**（用哪条规则、选谁） | 绕过规则直接改数值 |
| 表现层 | `scenes/`、`scripts/ui/`、`scripts/game/` | 渲染、输入、动画、推理板、简报界面 | 直接改矩阵（只能通过内核 API） |
| 全局单例 | `autoload/` | 状态持有、事件总线、存档、配置读取 | 承载玩法规则 |

## 3. 目录约定

```
autoload/        全局单例（注册到 project.godot）
  ├─ game_state.gd        当前局状态与推进入口
  ├─ event_bus.gd         全局信号总线
  ├─ config_loader.gd     读取 data/ 配置表
  └─ save_manager.gd      存档（单日 = 一个存档单元）
data/            配置与数值（代码只读）
  ├─ characters/  角色种子表
  ├─ rules/       规则参数
  └─ balance/     W_event 与系数
scenes/
  ├─ ui/          菜单与界面（main_menu 等）
  ├─ game/        玩法场景（clue_board_1 线索板）
  └─ components/  可复用组件
scripts/         与 scenes/ 同构：ui/ game/ core/ npc/ systems/
resources/       .tres 资源（主题、样式盒）
tests/           GUT / gdUnit4
tools/           离线脚本（批量标定、数据校验）
```

## 4. 关键数据流

1. `TimeSystem` 推进 tick，按当前相位（课间 / 上课 / 放学结算）决定启用哪些规则（v3.0 §3.3）。
2. `RuleScheduler` 按规则优先级与触发条件收集本 tick 的候选交互。
3. 规则执行 → 通过 `Relations` 与 `Stress` 接口写入，统一走 v3.0 §6.1 增量公式（传导类除外）。
4. 每 tick 末：`TransmissionResolver` 按 v3.0 §7.2 计算传导；`ObserverLayer` 只读输出标签。
5. 事件经 `EventBus` 广播给表现层与日志；日志是简报（v3.0 §13）与推理板的唯一数据源。
6. 每日结束执行跨天结算（v3.0 §3.5）并生成《每日简报》。

## 5. 不可破坏的约束

- **禁止脚本化**：不得出现"第 N 天/第 N 段必然发生 X"的硬编码剧情。
- **禁止角色 ID 判断**：行为层只能是 `f(性格四维, 透明度, 状态)` 的纯函数（v3.0 §11.1）。
- **观察层只读**：O1 与孤立标签不回写矩阵。
- **数值集中**：增量、阈值、系数一律来自 `data/`，脚本中不得出现魔法数字。
- **可无头运行**：内核必须支持 `godot --headless` 跑完整局（标定与测试前提）。
