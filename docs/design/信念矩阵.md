# 信念矩阵（Belief Matrix）

> 状态：草案 ｜ 维护者：程序 ｜ 最后更新：2026-10-04
> 关联：[`统一影响公式.md`](统一影响公式.md)（效果怎么算）｜ [`数据模型.md`](数据模型.md)（状态结构）
> 一句话：**NPC 与玩家都只按"自己以为的"行动；真值只有模拟内核知道。**

---

## 1. 问题：真实层 vs 感知层

系统里有两个完全不同的问题，之前只解决了一个：

| 问题 | 需要的量 | 谁知道 |
|---|---|---|
| "我要不要跟 j 好" | `A[i][j]`（**i 自己的立场**） | i 当然知道自己的态度 → 无问题 |
| "j 会不会接纳我" | `A[j][i]`（**别人对我的态度**） | 内核知道；**i 不该知道**，除非 j 透明 |

若 NPC 直接读 `A[j][i]`，就是**全知作弊**：玩家被透明度挡住的信息，NPC 一清二楚 —— 信息博弈（玩法文档 §9）当场失效。

**解法**：引入第二层数据——**信念矩阵**。真实值由内核维护，信念由各自的观测累积：

```
真实层（内核独占）    A[i][j]  H[i][j]  T[i][j]  O[i]  Stress[i]
感知层（各节点私有）  B_A[i][j]  B_H[i][j]  B_T[i][j]      ← 本文件定义
```

**分工铁律**：

- **决策读信念**：NPC 与玩家按"我以为的"行动；
- **判定读真实**：内核按真值结算结果。

两层之差就是**误判**，而误判正是本作的戏剧性来源（也 explain 了推理板为什么必须存在）。

## 2. 三份信念矩阵

| 标识 | 含义 | 对应真值 | 先验初值 |
|---|---|---|---|
| `B_A[i][j]` | i 估计的「j 对 i 的**好感**」 | `A[j][i]` | 40 |
| `B_H[i][j]` | i 估计的「j 对 i 的**敌对**」 | `H[j][i]` | 20 |
| `B_T[i][j]` | i 估计的「j 对 i 的**信任**」 | `T[j][i]` | 40 |

- 索引语义固定为"**i 对关于 j 的判断**"，注意与真值矩阵**转置**（`B_A[i][j] ↔ A[j][i]`）——这是最容易写错的地方，实现时必须用访问器 `belief(i, j, axis)` 而非裸下标。
- 对角线 `B_X[i][i]` 未定义（不估计自己），实现中置 0 且永不读写。
- 内存：3 × N×N（N ≤ 25 → 1875 个 float），可忽略；**成本在更新频率，不在容量**（见 §5.4）。

## 3. 初始化（开局先验）

初始信念由**双方性格**共同决定 —— 既不只看对方（"他看起来友善"），也不只看自己（"我倾向于把人往好处想"）：

```
B_X[i][j] = prior_X + bias_X(i, j) × w_bias        （X ∈ {A, H, T}）

perceived(j) = (E_j − 50)/50 · 0.5 + (F_j − 50)/50 · 0.5     ← 对方「看起来」多友善（外向/共情型显得友善）
observer (i) = (F_i − 50)/50 · 0.5 + (E_i − 50)/50 · 0.5     ← 我自己多倾向于把人往好处想（共情/外向型更乐观）

bias_A(i, j) = + perceived(j) × (1 + bias_observer_k · observer(i))   ← 对方特质 × 我的乐观度
bias_H(i, j) = − bias_A(i, j)                                         ← 同一人显得友善 → 被低估敌对
bias_T(i, j) = + bias_trust_ratio · observer(i) × 0.1                  ← 信任只受**观察者**影响
```

**乘法而非加法**：`perceived(j) × (1 + k·observer(i))` —— 于是

| 组合 | 结果 |
| --- | --- |
| 对方友善 + 我乐观 | **强烈高估**好感（"他肯定喜欢我"） |
| 对方友善 + 我多疑 | 只略高估 |
| 对方冷淡 + 我乐观 | 仍略低估（乐观也救不回来） |

**天然不对称**：`bias(i, j) ≠ bias(j, i)` —— 同一个"话痨"，乐观者与多疑者对他的判断不同。
实测初始 `B_A` 的 **92%** 对子存在双向差异（250/272），取值域 28.0~48.9。

**信任只受观察者影响**（`bias_T` 不依赖 `j`）：对方"看起来"是否可信没有意义，但**我是否容易先信任别人**有意义。

- **偏差是性格的函数，不是随机数** —— 让"话痨型总被高估亲近""冰山型总被低估好感"成为**可预测的**系统性错觉。
- **不是 `null`，也不是复制真值矩阵**：初始值是一个**有依据的猜测**（先验 + 可见性格偏差），而不是「不知道」（`null ≠ 0` 见 §11）或「开天眼」（复制真值违反铁律）。
- 实现：`tools/core_sim.py` 的 `_init_belief_bias()`（⚠️ 早期实现只写了纯先验，漏了本偏差项 —— 后果是开局所有人对所有人的猜测完全相同，既失去系统性错觉，也让搭话判据在开局无分化）。
- 玩家与 NPC 用同一套初始化（玩家初始对全班也是中性的，靠后续互动修正）。

## 4. 观测渠道（三源）

信念只从**可观察事件**更新，不互动不更新（否则等于凭空获得信息）。

| 渠道 | 触发 | 观测内容 | 准确度 |
|---|---|---|---|
| **直接互动** | i 与 j 发生搭话 / 求助 / 递纸条 / 安慰 / 被调侃 | j 对 i 的三轴态度 | 最高（有直接反馈） |
| **旁观** | i 看到 j 对第三人 k 的行为 | j 的**表达倾向与可信度** | 中：`η_旁观 = 0.3 × η_直接`，且**只更新 `B_H` 与 `B_T`**；\"j 对我具体什么感觉\"（`B_A`）仍必须亲自接触（见 §12 决策 ①） |
| **二手情报** | i 从 s 处听到关于 j 的说法 | s 转述的 j 对 i 的态度 | 准确度 = `O[s]` × `T[i][s]`（越低越是"传歪的"） |
| **主动打听** | i 花一次课间动作向 s 打听 j | s 眼中的 j（含"j 怎么看 k"） | 透露度 = `T[s][i]`；二手准确度 = `O[s]` × `T[i][s]` |

> 二手情报正是玩法文档 §10「消息传歪」的数据通路；它的最终数值效果仍走统一影响公式的 `E` 项。

## 5. 更新规则

### 5.1 观测值

```
obs_X = 真值_X(j→i) + σ_X · z(i, j, day, X) + bias_X(j) · w_bias

  σ_X    = tier( O[j] ) 对应的 σ_max_X        ← 查 §11 档位表（通透 ±2 / 可见 ±8 / 模糊 ±20 / 封闭 ±25）
  z(...)  = 确定性伪随机，取值 [−1, +1]，由 hash(i, j, day, X) 生成（**不是真随机**）
  bias_X(j) 同 §3（表达风格造成的系统偏差）
  二手来源：内容再乘保真度 fidelity = 0.7^hops（hops = 转手次数）；失真本身由「流言倾向偏移」负责，不另建机制（见 §12 决策 ②）
```

### 5.2 更新（指数收敛 = 信念学习）

```
B_X[i][j] ← clamp( B_X[i][j] + η_X · (obs_X − B_X[i][j]) , 0, 100 )

  η_X = η0_X · ( 0.3 + 0.7 · T[i][j]/100 )   ← 你越信任对方（真值），越愿意采信新证据
```

- `T[i][j]` 是 **i 自己对 j 的信任**（自己的量，i 当然知道）→ 合法。
- 高透明度（`O[j]` 大）→ `σ` 小 → 观测准 → 几次互动即可看透；
- 低透明度 + 低信任 → `σ` 大、`η` 小 → 长期停留在错判上，形成"谜一样的人"。

### 5.3 遗忘与回归

```
每天结算： B_X[i][j] ← B_X[i][j] + λ_b · ( prior_X − B_X[i][j] )      λ_b = 0.02
```
长期不往来 → 缓慢回中性；防止"三周前的一次误会"永久支配判断。

### 5.4 更新时机与成本

- 只在**本 tick 产生可观察事件**的对子上更新（直接互动、旁观、二手各算一次）；
- 复杂度 `O(事件数)`，与 N 的关系仅为"稀疏索引"，**不做全矩阵扫描**；
- 每 tick 使用**本 tick 开始时的真值快照**（与统一影响公式一致），保证结果可复现。

## 6. 行为读取表（谁读信念、谁读真值）

| 行为 / 判断 | 发起者的输入 | 说明 |
|---|---|---|
| 搭话 / 求助 / 分享秘密（决定"要不要去"） | 自己的 `A[i][j]`、`T[i][j]`、压力 | 自己的立场自己知道 |
| **"对方会不会接纳我"** | **`B_A[i][j]`、`B_T[i][j]`** | 关键：用信念，不用真值 |
| 调侃"会不会过火" | `B_A[i][j]` 高 + `B_H[i][j]` 低 | 误判 → 玩笑崩 |
| 道歉"对方会不会接受" | `B_H[i][j]` 低 + `B_A[i][j]` 高 | |
| 举报"会不会被怀疑" | `B_T[i][j]` | |
| 安慰"该不该凑过去" | 对方的**情绪图标**（可直接观察）+ `B_A[i][j]` | 情绪图标是唯一直接暴露的情绪窗口 |
| 决定自己的立场 / 传谣染色 | `A[i][j]`、`H[i][j]` | 我的立场我清楚 |
| **判定结果**（接受 / 拒绝 / 敷衍 / 是否被帮） | **内核实值 `A[j][i]`、压力** | 只有内核知道真相 |

## 7. 误判如何变成戏剧（自洽性检查）

一条完整链，全部只用到各自"看得见"的数据：

```
i 高估 j 的善意（B_A[i][j] = 62，真实 A[j][i] = 35）
  → i 决定搭话（读自己的 A[i][j] 与 B_A[i][j]）
  → 内核按真值判定：对搭话者好感 35 < 阈值 40 → 敷衍
  → i 压力 +8、A[i][j] 下修（统一影响公式）
  → 本次互动成为新观测：obs ≈ 35 + 噪声 → B_A[i][j] 从 62 向 35 收敛
```

**没有一步要求 NPC 读到它看不到的东西** —— 所以既不会"运行出错"，又天然长出"人心隔肚皮"的叙事。

## 8. 与统一影响公式（UIF）的对接

- UIF 只负责**写入真实值**：`A` `H` `T` `O` `Stress`；
- 信念矩阵**只读不写**，由 `A/H/T/O` 派生（§5），因此 UIF 公式本体无需改动；
- **UIF §6 的 NPC 意向计算中，凡是牵涉"对方态度"的输入，一律取 `B`**；牵涉"我自己态度"的取真值：
- **传导也必须用感知值**：UIF §2.2 的 `σ_X[j→k]` 取的是"i **感知到**的 j 对 k 的态度"（即本文件的感知层），而非真值——这是"**低透明度的人，真实态度不扩散**"的机制保证。

```
意向 U_b = Σ_X α_X(i) · Δ_X^pred(i, b)
           Δ_X^pred 里：自己的立场 → A[i][*]；对方的反应预期 → B_X[i][*]
```

- **玩家侧同构**：玩家的推理板（玩法文档 §9.5）= 玩家自己的 `B` 的显式化。NPC 用的是隐式 `B`，玩家用的是显式 `B` —— 机制一致，公平。

## 9. 工程约束与不变式（这是"不出错"的正式答案）

| # | 约束 | 校验方式 |
|---|---|---|
| 1 | **读写路径分离**：`scripts/npc/`（决策）只允许读 `B`；`scripts/systems/`（判定）只允许读真值 | 静态扫描测试：决策层出现 `A[j][i]`/`H[j][i]`/`T[j][i]` 即失败 |
| 2 | **确定性**：噪声来自 `hash(i,j,day,axis)`，采样来自种子化 RNG | 同种子跑两遍，逐 tick 状态哈希一致 |
| 3 | **有界**：所有写入 `clamp(0, 100)`；对角线不参与 | 不变式测试 |
| 4 | **无观测不更新**：没有可观察事件时 `B` 不变（除 §5.3 遗忘） | 单测：空跑一天，`B` 仅按遗忘变化 |
| 5 | **收敛性**：对高透明度 `O[j] ≥ 80` 且高信任的对子，持续互动后应 `|B_X[i][j] − 真值| ≤ ε` | 集成测试 |
| 6 | **不参与判定**：`B` 绝不出现在结果判定分支里 | 与 #1 同一扫描 |

> 为什么这样就不会"因为看不见而崩"：**看不见只影响"决策依据"，不影响"结算规则"**。NPC 永远基于自己持有的信息做决定，内核永远按真值结算；两者通过"观测 → 更新"闭环耦合，而不是通过共享真相耦合。

## 11. 信息可见性档位（透明度决定"能看见什么"）

透明度不只是观测噪声的参数，它**直接决定观测者能看到什么**。四档与玩法文档 §9.2 一致：

| 档位 | 透明度 | 立场分类 `X[j][k]` | 本次变化 `Δ` | 精确数值 | 观测噪声 `σ_X` |
|---|---|---|---|---|---|
| **通透** | 80–100 | 绿（亲近）/ 红（敌对）/ 灰（中立），清晰 | 方向 + 粗档（小 <5 / 中 5–15 / 大 >15） | ✗ | ±2 |
| **可见** | 50–79 | 同上，颜色偏淡 | 仅方向（↑ / ↓ / —） | ✗ | ±8 |
| **模糊** | 20–49 | `null`（显示 "?"） | 仅"有变化"提示 | ✗ | ±20 |
| **封闭** | 0–19 | `null` | `null` | ✗ | ±25 |

### 11.1 分类阈值（复用系统已有阈值，不另定）

```
亲近（绿）  A[j][k] ≥ 60        ← 簇标签器的强连接阈值
敌对（红）  H[j][k] ≥ 40        ← 敌意传导阈值 θ_H
中立（灰）  其余
```

这样"推理板上的颜色"与"簇标签器圈出的成团"永远一致。

### 11.2 `null ≠ 0`（信息博弈的支点）

- `null`：你看不见 → **你不知道**
- `0` / `—`：你看见了且没有变化 → **你知道没变**

低透明度的人之所以难对付，正因你**分不清"他没变"和"我看不到"**。UI 必须分开呈现。

### 11.3 只读查询（不新增任何存储）

可见性是**读取层函数**，不引入新矩阵、不产生同步问题：

```gdscript
func observe(viewer: int, target: int, other: int, axis: int) -> Dictionary:
    var tier := VisibilityTier.of(opacity[target])      # 由"被观测者"决定
    match tier:
        VisibilityTier.SEALED:
            return {"cls": null, "delta": null, "tier": tier}
        VisibilityTier.BLURRY:
            return {"cls": null, "delta": has_change(target, other, axis), "tier": tier}
        _:
            return {
                "cls": classify(axis, target, other),
                "delta": delta_bucket(target, other, axis, current_break_phase()),
                "tier": tier,
            }
```

### 11.4 只有"有交互或旁观"的人才会记录

客观可见性由 `O[j]` 决定，但**是否写入自己的信念 `B`** 要有主观过滤：只有与 j 发生过互动、或本课间旁观过 j 的人，才把这次观测写进自己的 `B`。否则等于换一种方式让全班全知。

### 11.5 呈现粒度与模糊档冷却

- **增量按课间段聚合**：一个课间段 100 tick 可能发生几十次互动，逐 tick 提示会刷屏。每段结束汇总一次（"这个课间，他对你的好感上升（中）"）。
- **模糊档提示要冷却**：每课间段最多提示 1 次，且以概率 `p = 0.5` 出现，内容只有"有变化"、**不给方向**。否则玩家可用提示频率反推对方变化次数，等于变相透露（见 §12 决策 ⑤）。

### 11.6 主动获取：`打听` 行为

新增一个可消耗课间动作的行为：

```
打听(target)：
  消耗    本课间一次动作
  获得    一条关于 target 的观测（写入自己的 B）
  透露度按 T[target][i] 分三级：
      T < 40        → 敷衍，且**可能给假信息**（假信息必须留下可验证破绽，见玩法文档 §9.5）
      40 ≤ T < 70   → 说表面话（粗分类，可能不准）
      T ≥ 70        → 说真心话，准确度 = O[target] × T[target][i]
  若拿到二手情报（关于第三人 k）：
      准确度 = O[被问者] × T[i][被问者] × 0.7^hops
```

对应玩法文档 §9.3「信任解锁信息」：想知道一个人是什么样的人，需要**付出社交成本**。

### 11.8 标签的三条获取路径（工程实现）

标签（行为标签 / 关系类 / 秘密类）**默认对玩家不可见**，通过三条路径解锁：

| 路径 | 判定 | 写入方式 |
|---|---|---|
| **观察** | `tier(O[j])` 达档 | 直接进入玩家的可见集合 |
| **被告知** | `T[j][player] ≥ 70` **且** `A[j][player] ≥ 50` | 目标主动告知，作为一次"观测"写入玩家信念 |
| **推断** | 同一行为反复出现 ≥ N 次 | 在推理板生成候选标签 + 证据链 |

实现要点：

- 标签的「可见集合」是**玩家侧的派生数据**，绝不写回真实标签（标签层只读铁律）；
- 路径 ③ 需按**行为类型**累计证据（如"看到某人掏手机 ≥3 次"），计数阈值放 `data/rules/tag_visibility.csv`；
- 三类标签的观察难度不同（行为标签易、关系类中、秘密类难）→ 用不同的 `N` 与档位门槛区分。

### 11.9 不变式

| # | 约束 | 校验 |
|---|---|---|
| 1 | 同一档位下，UI 模糊度与 NPC 的 `σ_X` 必须一致（玩家与 NPC 信息量对等） | 参数一致性测试 |
| 2 | `null ≠ 0` 用例必须覆盖（看不见 vs 看见了没变） | 单测 |

## 不变式（可静态审查的禁项）

**任何信念 / 态度更新不得读真值矩阵。** 即：走「决策 → 影响」的路径时，
只能读 `B[axis][i][*]`（信念）与可观测信号，**不得直接读 `A` / `H` / `T` 的真值**。

> **为什么写成不变式**：本会话曾两次违反它 ——
> ① `pick_target` 读 `H[j][i]`（别人对我的态度），被 `test_core` 拦下；
> ② `conformity_hostility` 读 `H[k][j]`（邻居对目标的真值敌对）→ **信息层穿透**，
>    低透明度者藏着的恨照样扩散，破坏 §7.4「藏得住的人真的藏得住」。
>
> 第二次的教训是：这类穿透**不会报错**，只会让「藏得住」这条核心保证悄悄失效。
> ∴ 它必须是一条**可审查的禁项**，而不是靠自觉。

**判定真值** 只允许出现在**行为结算**侧（`apply_event` 写入、簇标签器只读输出），
不得回流到**决策**侧。
