# 社会事件（Social Events）

> 状态：草案 ｜ 维护者：程序 ｜ 最后更新：2026-10-05
> 玩法定义见主文档 §13「社会事件」；关联 [`统一影响公式.md`](统一影响公式.md)（效果怎么算）｜ [`NPC行为决策.md`](NPC行为决策.md)（个体决策）｜ [`信念矩阵.md`](信念矩阵.md)（谁看得见什么）
> 一句话：社会事件是**有阶段结构的班级级过程**，但每个阶段内部仍由既有机制驱动——**它不是剧本**。

---

## 1. 与「重大事件」的区别

| | 重大事件 | 社会事件 |
|---|---|---|
| 在哪定义 | 主文档 §6.3 事件权重表 | 主文档 §13 + 本文件 |
| 粒度 | 单个事件 | **多阶段过程** |
| 时长 | 瞬时 | 跨多个相位、可能跨天 |
| 参与者 | 少数人 | **全体** |
| 结果 | 数值变化 + 状态标签 | **结构变化**（身份 / 标签 / 关系重排） |

## 2. 状态机

```
IDLE ──触发条件满足──► RUNNING(stage = 1..N) ──最后阶段完成──► RESOLVED ──► IDLE
                                                              │
                                                              └─► 产出：结构变化 + 日志归档
```

- 全局**至多一个**社会事件处于 `RUNNING`（并发上限见配置表）；
- 阶段推进由**相位边界**驱动（如"下午课间结束 → 进入上课阶段"）；
- `RESOLVED` 时把结果写入日志（供《每日简报》引用，主文档 §14）。

## 3. 阶段钩子

```gdscript
class SocialEventStage:
    var phase: String          # break / class / settle
    var duration_ticks: int
    func enter(ctx) -> void    # 例：注入一条「改选」流言
    func tick(ctx) -> void     # 例：每 settle_interval 微调候选人影响力
    func exit(ctx) -> void     # 例：生成候选人名单
```

**关键约束**：`tick` 内部**只允许调用既有系统**（`Rules` / `Transmission` / `Belief`），不得直接写矩阵；所有数值影响走统一影响公式，并使用**重大档** `base ∈ [4,5]`（主文档 §6.3）。

## 4. 配置表 `data/rules/social_events.csv`

| 字段 | 含义 |
|---|---|
| `event_id` | 事件标识（如 `committee_election`） |
| `trigger_rule` | 触发条件标识（引用 `data/rules/social_event_triggers.csv`） |
| `stages` | 阶段列表，格式 `phase:duration` 用 `\|` 分隔（如 `break:300\|class:180\|settle:1`） |
| `concurrency` | 是否允许与其他社会事件并发（默认 0） |
| `base_tier` | 数值档位（`major` = 4–5） |
| `cooldown_days` | 冷却天数（防同一事件短期内反复触发） |

触发条件表 `social_event_triggers.csv` 的字段：`trigger_rule`、`metric`（如 `leader_influence`）、`op`（`<` / `>` / `>=`）、`value`、`note`。**禁止出现日期/天数类 metric**。

## 5. 与既有系统的接口

| 阶段（以班委选举为例） | 调用的系统 |
|---|---|
| ① 酝酿 | `Rumor`（流言注入与传播，主文档 §10.1） |
| ② 提名 | `Observer`（簇标签 → 各簇话事人）、`Relations`（`influence` 计算） |
| ③ 模拟投票 | `NPCBehavior`（意向评分）+ `BeliefMatrix`（探口风 → 更新 `B`） |
| ④ 实际投票 | `NPCBehavior`（投票倾向 softmax）+ `UnifiedFormula`（结果影响） |
| ⑤ 结果公布 | `Observer`（簇标签重算）+ `Report`（简报条目） |

## 6. 不变式

| # | 约束 | 校验 |
|---|---|---|
| 1 | 触发条件**不得包含日期 / 天数判据** | 静态扫描配置表 |
| 2 | 阶段 `tick` 不得直接写矩阵（只能经既有系统） | 写计数断言 |
| 3 | 至多一个社会事件并发（除非配置允许） | 运行时断言 |
| 4 | 玩家**不能直接操纵结果**，只能通过既有行为影响 | 代码审查（无专用接口） |
| 5 | 同种子同结果 | 同种子跑两遍比对事件日志 |
