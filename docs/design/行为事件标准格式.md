# 行为事件标准格式（重构草案）

日期：2026-10-09。用途：逐项整理现有行为，再作为重构输入。本文件提出字段和组织方式，不表示新玩法已经实现或批准。现行规则仍以 `docs/gdd/core-gameplay-v3.1.md` 为准；与现行规则不同的建议必须明确标记，落地时同步主文档与 CHANGELOG。

## 1. 先区分三种记录

- **行为定义**：闲聊、学习、睡觉各自的规则，设计时填写，运行时只读。
- **执行实例**：某次行为的参与者、当前阶段、起止 tick、判定结果和已结算效果。每次执行单独生成。
- **反馈通知**：界面、日志、动画收到的消息，来自执行实例；通知本身不能再次加点。

行为 ID、单次执行 ID、数值效果 ID 分开。例如 `chat` 是行为，某次两人聊天有独立执行 ID，`topic_affinity` 是该行为使用的数值效果。角色 ID 只用于定位参与者，不能用来决定角色专属规则。

## 2. 标准维度

| 维度 | 必须写清楚的内容 |
| --- | --- |
| 标识与事件名 | 稳定英文 ID、中文名称、定义版本、实现状态 |
| 类型与用途 | 主动行为、持续状态、默认状态或被动反应；玩家目的与 NPC 选择条件 |
| 发起方式 | 玩家点击、NPC 自主选择、被邀请、系统条件触发；允许的游戏阶段 |
| 参与者 | 发起者、目标、旁观者；最少/最多人数；能否加入、退出 |
| 前置条件 | 清醒、在场、未被其他行为占用、资源足够、剩余时间等硬条件 |
| 位置与姿态 | 所在区域、座位归属、坐/站/睡姿、距离、遮挡、允许的座位关系 |
| 判定 | 分别填写 NPC 发起判定、接受判定、结果判定；公式、读值来源、掷骰时机 |
| 玩家确认 | 是否需要玩家同意；邀请超时、拒绝后果；不能用随机骰代替玩家选择 |
| 时间成本 | 接近、准备、执行、拒绝成本；单位为世界 tick；固定时长或结束条件 |
| 时间倍率 | 走路保持正常速度；玩家占用型行为默认三倍；特殊事件正常速度覆盖 |
| 资源与使用限制 | 道具、次数、冷却、座位等共享资源；预扣、扣除和返还时机 |
| 移动与并发 | 参与者能否移动、能否执行其他行为、是否独占座位/目标/会话 |
| 加减点 | 每条效果的指标、对象、方向、公式/配置引用、条件、结算阶段与次数 |
| 信息反馈 | 获得什么线索、谁能知道、来源与可靠程度；提示、日志、动画各自内容 |
| 具体流程 | 每阶段进入条件、动作、退出条件、下一阶段及失败分支 |
| 取消与中断 | 玩家取消、目标离开、阶段结束、外部事件打断；成本、效果、信息如何处理 |
| 优先级与冲突 | 多个行为争用角色时谁能抢占；邀请、移动和既有会话如何协调 |
| 结束与清理 | 成功/拒绝/无效/取消/中断分别如何释放占用、资源和倍率覆盖 |
| 验收标准 | 玩家与 NPC 共用规则；边界场景；同种子可复现；重复通知不重复结算 |

资源、冷却等无需求的维度填写“无”，不要为了格式额外增加玩法限制。

## 4. 三个行为的填法

### 闲聊：示例按现行规则填写，补充重构要求

- **参与者**：发起者与目标；多人加入沿用同一会话，不另建一份重叠聊天。
- **前置与位置**：清醒、在场、可参与，满足闲聊空间检查。当前普通范围为 1.2 米，并检查桌面阻隔；双方处于各自座位锚点时，同列前后相邻座位允许 1.8 米的例外，锚点容差 0.1 米。数值引用现有配置，不能写死在行为脚本里。不是全班任意两个坐着的人都能交流。
- **姿态建议**：坐着或站着均可，但执行期间保持位置；学习和睡觉的坐姿条件不能直接套给聊天。
- **确认与判定**：NPC 邀请玩家，需要玩家确认，接受后不再掷玩家接受骰；玩家邀请 NPC，按现有接受规则判定；加入既有聊天另有加入接受规则。开始执行前重查位置与状态。
- **时间**：发起聊天当前为 30 tick；加入后的共同结束时间按会话延长规则计算，不把加入尝试的 10 tick 当作完整聊天。玩家正式进入占用后默认三倍，接近过程不触发加速。
- **移动**：接受并进入执行时取消已有行走目标、锁定参与者移动；结束或中断时释放。只忽略新移动输入不足以阻止旧路线继续运行。
- **加点**：引用 `w_events.csv` 中 `topic_affinity`、`topic_trust`、`topic_stress`，经过公共数值公式。当前双向好感、双向信任，压力效果只作用于发起者；不能用“双方都加点”省略方向。现行关系效果在开始时结算，重构如果移到完成时，属于玩法变更。
- **反馈**：玩家闲聊自然完成才交付情报；信息反馈与关系加点分别记录。被打断不能伪装成自然完成。
- **加入去重**：新成员与原成员形成的新关系分别结算；原有关系不重算，个人压力效果按规定次数结算，不按关系对数重复扣减。
- **中断**：记录原因；已在开始结算的效果不因中断再次结算。全体释放占用与移动锁，结束唯一会话。

### 学习：重点补充位置条件，区分默认状态与主动任务

- **当前事实**：主文档和配置把学习作为不占用时间槽的默认状态，`duration = 0`；不能因此理解为“零时间获得收益”。
- **本次建议**：进入学习必须在允许学习的座位/书桌交互点，已坐下、清醒、未移动且未参加其他活动；离开座位或开始走路后退出学习。不能仅以“没有 busy”为学习条件。
- **默认学习**：只在满足上述条件时累计有效学习时间。走回座位属于接近阶段，走路保持正常速度；准备坐下后才进入学习状态。
- **主动学习任务**：如果今后加入“学习一段时间”按钮，应另写明确时长、完成/中断结算和占用规则。是否由它触发三倍速要明确配置，不能让默认学习导致所有空闲时间永久三倍速。
- **加点**：现有压力规则与计划中的学业增长分别引用各自配置；未实现的学业系统不能在行为卡中标成已实现。
- **中断待定项**：学业累计余数是否保留，需在重构时单独确定；不要默认全部清零或全部返还。

### 睡觉：用结束条件表达“睡完整个课间”

- **当前事实**：行为表为 100 tick，主文档描述本次课间不参与交互、课间结束减压；玩家是否睡觉由玩家选择，NPC 可自主判定。
- **本次建议**：在自己的座位坐下并进入趴桌睡姿才能执行；从远处发起时先走到座位，接近阶段保持正常速度。
- **时间需对齐**：如果允许课间中途开始，“固定 100 tick”和“本课间结束即完成”不是同一规则。建议在行为定义中使用“本课间剩余时间”，但这是待确定的重构规则，不能当作现有实现。
- **占用**：睡眠期间禁止移动和交互，也不能作为交互目标；表现层姿态不能代替内核睡眠状态。
- **加点**：按现行课间结束减压规则及配置填写。提前醒来是否获部分减压必须明确；草案不额外规定新的奖励。
- **倍率**：玩家正式进入睡眠占用后默认三倍，特殊事件正常速度覆盖优先；醒来或中断后清理占用。

## 5. 执行实例至少保存什么

```text
execution_id：本次执行的唯一标识
behavior_id / definition_version：使用哪份规则
actor / targets / participants：本次实际参与者
session_id：可选，关联多人持续会话
phase：请求 / 接近 / 准备 / 等待确认 / 执行 / 已结束
start_tick / expected_end_tick / actual_end_tick
decision_results：已经完成的确认与判定结果，避免重复掷骰
outcome / reason：完成 / 拒绝 / 无效 / 取消 / 中断，以及原因
settled_effects：已结算效果及对象方向，避免重复加点
delivered_feedback：已交付的信息，避免重复发放
owned_resources：持有的角色/座位占用与正常速度覆盖等
```

执行阶段、角色占用、会话和移动状态必须能互相校验。动作环、动画与提示读取这些状态，不另维护一份“看起来在聊天”的状态。

## 6. 重构组织建议

先用行为卡核对现有实现，再做公共执行流程。配置负责时长、阈值和数值引用；行为模块负责具体规则；统一执行器负责校验、占用、结算去重、中断与清理。无需先开发能解释任意流程的脚本语言。

场景座位锚点、姿态与移动由场景层提供事实；内核只接收位置、座位关系、姿态等纯数据，不直接依赖 Godot 表现节点。多人行为使用一个共享会话，避免双方各自计时、各自认为聊天结束。

重构先保留现行效果和判定口径；姿态条件、默认学习条件、睡眠中途开始等规则变化单独列出，落地时更新玩法主文档，避免结构重构顺便改变数值平衡。
