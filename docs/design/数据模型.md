初始值、跨天保留和周考达标线需另行配置；高考总分本次先按 750，压力／动力仍为 0–100；旧深层敌对、信念和传导不自动迁入。

## 深层敌对 `H_deep`（边矩阵）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `H_deep[i][j]` | `float[N][N]` | 记「i 对 j **忘不掉**的那部分敌对」；只增（软上限 `deep_cap`）、**永不衰减**、**不参与 `room_for`** |

**与 `H` 的关系**：`H` 仍是**总敌对**，`H_deep` 是其中不可衰减的部分。衰减按
`H = H_deep + (H − H_deep) × decay_h` 计算（深层原样保留）。

> **2026-10-17 老师版已删除**：`H_deep`（深层敌对）与 `decay_h` 都随运行时迁移移除，好感／敌对跨天原值保留
> （主文档 §4.3、§4.2），本节保留为学生版历史口径，不再作为实现依据。

**⚠️ 存档要求**：**存档/读档必须包含 `H_deep`**。它是关系状态的一部分 —— 若丢失，
「死仇」会被静默抹平，且**回放对拍会失败**（同一存档读回后走不出相同的结果）。

**同类伴生状态**：`hurt_day[i][j]`（最近一次 i 对 j 做**重大**敌对行为的日，用于排挤判据 §9.6）——
同样必须进存档，否则排挤行为在读档后会与存档前不一致。

**观察层标注（只读）**：「孤立」标签的判据是
`被好感显著低于班级均值 且 给好感接近正常`（§9.7.3）—— 属于观察层输出，**不得回写**。

## 1. 运行时状态（一局的全部可变数据）

```gdscript
# 关系矩阵：N×N 有向，0–100（N = 16 名 NPC + 1 玩家 = 17）
class Relations:
    var affinity: PackedFloat32Array   # A[i][j] = i 对 j 的好感
    var hostility: PackedFloat32Array  # H[i][j] = i 对 j 的敌对（与 A 独立，不是负数）
    var trust: PackedFloat32Array      # T[i][j] = i 对 j 的信任

# 个体属性（长度 N）
class ActorState:
    var opacity: PackedFloat32Array    # O[i] 透明度
    var stress: PackedFloat32Array     # S[i] 压力（唯一累积情绪变量）
    var mbti: PackedFloat32Array       # 4×N：E/N/F/P 各维度 0–100 连续值
```

- 索引 0–(N−2) 为 NPC，索引 N−1 固定为玩家（转学生），玩家与 NPC 共用同一套结构与规则。
- N = 17（16 名 NPC + 玩家）：一局全池入局（角色池 16 人，2026-10-12 起删除难度档），阵容由种子化洗牌决定顺序；**绑定组**（小情侣 01/02、佳豪对全班）按 `characters/bindings.csv` 覆盖初始关系。
- 有向存储：`A[i][j] ≠ A[j][i]`，读写一律用"谁对谁"的语义，避免矩阵转置错误（建议提供 `a(i, j)` 访问器而非裸下标）。
- 所有轴 `0–100`，钳制在写入点统一处理（主文档 §4.1 的 `clamp`）。

## 2. 静态配置（`data/`，只读）

### 2.1 角色种子表 `data/characters/seeds.csv`

对应 主文档 §11.4 的 16 角色种子表。**池 = 一局阵容（16 人全部入局）**，未入池的角色不存在；字段：

| 字段 | 说明 |
|---|---|
| `id` | 编号 01–24 |
| `alias` | 代称（仅显示用，**不得用于逻辑判断**） |
| `archetype` | 原型（用于抽取去重与初始关系规则） |
| `mbti` | 四字类型（展示用；数值以下面四列为准） |
| `e` `n` `f` `p` | 四维连续值 0–100 |
| `opacity_init` | 基础透明度（运行时 × 压力系数；MBTI 公式仅为新角色默认值生成器，不进运行时） |
| `identity_seed` | 身份层种子（如"班长""小情侣绑定 02"） |
| `tags_init` | 初始标签（如"玩手机"）— **环境事实**，需在文档中明示 |
| `initial_relations` | 特殊初始关系（如"对 01 好感 85/信任 80"） |

### 2.1b 外观呈现表 `data/characters/appearance.csv`

**表现层专用**：把内核给出的角色编号映射到一张立绘（依铁律 §11.1，本表**不参与任何行为判定**）。字段：

| 字段 | 说明 |
|---|---|
| `id` | 角色编号（对齐 `seeds.csv`） |
| `alias` | 代称（仅人工核对用） |
| `gender` | `male` / `female`（决定取男 / 女立绘） |
| `sprite` | 立绘名，对应 `scenes/characters/<sprite>.tscn`（贴图路径只在角色场景里写一次） |

课间空间（`scenes/game/classroom3D.tscn` 的 `Actors` 节点 / `scripts/game/classroom_actors.gd`）按内核只读访问器 `seat_of(i)` 把人物摆到 `Seats/<seat_id>` 上，座位表见 `rules/seats.csv`。

### 2.3 数值表 `data/balance/w_events.csv`

统一增量公式的 `W_event` 全表（主文档 §4.1）。字段：`event_id`、`axis`（affinity/hostility/trust/stress）、`base`、`w_e` `w_s` `w_f` `w_j`（性格敏感度）、`tier`（normal/major）、`note`。

**所有数值必须可追溯到 v3.0 的某条规则或标定目标（§2.4）**，不允许无出处的数字。

**全局铁律：常规 `delta ∈ [1,3]`、重大 `delta ∈ [4,5]`**（含正负号）——`config_loader` 启动时校验本表，越界直接报错；重大档仅限「前置条件苛刻」的事件，且优先用「多轴联动 + 状态标签 + 阈值相变」表达。见 [`统一影响公式.md`](统一影响公式.md) §2.5。

### 2.4 人数与难度档（2026-10-12 收敛）

- **一局固定 16 名 NPC**（+ 玩家 = 17 节点）：人数取 `rules/roster.csv` 的 `npc_count`，与 `characters/seeds.csv` 的角色池行数一致（`check_config.py` 校验两者相等）。
- **难度档概念已删除**：原 `easy / standard / hard`（8/16/24 NPC）三档与其覆盖机制（CSV 的 `difficulty` 列、`difficulty.csv` 的 `default` 列）一并作废；`SimCore.new(seed, npc_count)` 直接收人数，`GameState.start_game(seed, npc_count)` 与 `Config.default_npc_count()` 转调它。
- 若将来重新引入分档，须同时恢复「按难度覆盖参数」的装载约定并重跑标定 —— 现在所有规则表都是单一口径。

## 4. 存档模型

- 2026-10-11 完整规格见 [主文档第二十六章](../gdd/v4/26-完整存档机制.md)：任意时刻请求，在本次 tick／提交／边界完成后的安全点保存完整会话，日末仍自动保存；完整机制尚未实现。
- 内容覆盖全部可变内核状态、各独立 RNG、移动与交互流程、情报／日志／报告和推理板；保留成绩、深层敌对、证据、冷却、编号与幂等记录，不只保存种子。
- 拟采用 `user://saves/<run_id>/` 多槽位自包含文件及备份、版本迁移；现有原型 `user://savegame.dat` 不等于完整续玩。
- 单局回放（进阶，主文档 §14.3）依赖事件日志的完整记录：**日志必须可重放**，因此随机数必须来自可复现的种子化 RNG。

## 维度方向约定（钉死，禁止各调用点自行解释）

| 索引 | 维度 | 0 端 | 100 端 |
| --- | --- | --- | --- |
| `dims[0]` | 外向 E | 内向 | 外向 |
| `dims[1]` | 直觉 N | 实感 S | 直觉 N |
| `dims[2]` | 情感 F | 思考 T | 情感 F |
| **`dims[3]`** | **感知 P** | **判断 J** | **感知 P** |

> ⚠️ **本会话曾出现 6 处调用点各按不同语义使用 `dims[3]`**（有的当 J、有的当 P），
> 导致「J 越高越怕吵」这类注释与实现**方向相反**且长期未被发现。
> ∴ 现约定：**凡公式要表达「J」的，一律写成 `(50 − dims[3]) / 50`**，
> 并优先使用助手 `arg_j(i)` / `arg_i(i)`（见 `core_sim.py`），从根上消灭方向歧义。
