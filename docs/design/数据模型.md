# 数据模型

> 状态：草案 ｜ 维护者：程序 ｜ 最后更新：2026-10-04
> 规格依据：`../gdd/core-gameplay-v3.1.md` §5（态度轴）、§8（情绪）、§11（人物四层）、§3.5（跨天结算）

## 1. 运行时状态（一局的全部可变数据）

```gdscript
# 关系矩阵：N×N 有向，0–100（N = 难度抽取 NPC 数 8/16/24 + 1 玩家 = 9/17/25）
class Relations:
    var affinity: PackedFloat32Array   # A[i][j] = i 对 j 的好感
    var hostility: PackedFloat32Array  # H[i][j] = i 对 j 的敌对（与 A 独立，不是负数）
    var trust: PackedFloat32Array      # T[i][j] = i 对 j 的信任

# 个体属性（长度 N）
class ActorState:
    var opacity: PackedFloat32Array    # O[i] 透明度
    var stress: PackedFloat32Array     # S[i] 压力（唯一累积情绪变量）
    var mbti: PackedFloat32Array       # 4×N：E/N/F/P 各维度 0–100 连续值
```

- 索引 0–(N−2) 为 NPC，索引 N−1 固定为玩家（转学生），玩家与 NPC 共用同一套结构与规则。
- N 由难度决定：简单抽 8 个 NPC（N=9）、标准抽 16（N=17，等同 v3.0 原设计）、困难全池 24（N=25）；开局从 24 人池随机抽取，抽取使用种子化 RNG（见 §4），同种子同阵容。**绑定组同抽**：`identity_seed` 标注的绑定组（小情侣 01/02、班委团体）抽中组内任一角色则整组自动入局，按组内人数占用名额。
- 有向存储：`A[i][j] ≠ A[j][i]`，读写一律用"谁对谁"的语义，避免矩阵转置错误（建议提供 `a(i, j)` 访问器而非裸下标）。
- 所有轴 `0–100`，钳制在写入点统一处理（主文档 §6.1 的 `clamp`）。

## 2. 静态配置（`data/`，只读）

### 2.1 角色种子表 `data/characters/seeds.csv`

对应 主文档 §11.4 的 24 角色种子表。**24 人为全量池**，本局只用其中被抽中的子集（8/16/24，按难度），未抽中的角色不进矩阵、不占索引。字段：

| 字段 | 说明 |
|---|---|
| `id` | 编号 01–24 |
| `alias` | 代称（仅显示用，**不得用于逻辑判断**） |
| `archetype` | 原型（用于抽取去重与初始关系规则） |
| `mbti` | 四字类型（展示用；数值以下面四列为准） |
| `e` `n` `f` `p` | 四维连续值 0–100 |
| `opacity_init` | 基础透明度（运行时 × 压力系数；MBTI 公式仅为新角色默认值生成器，不进运行时） |
| `identity_seed` | 身份层种子（如"班长""小情侣绑定 02"） |
| `tags_init` | 初始标签（如"玩手机"）— **环境事实**，需在文档中明示 |
| `initial_relations` | 特殊初始关系（如"对 01 好感 85/信任 80"） |

### 2.2 规则参数 `data/rules/*.csv`

| 文件 | 内容 | 规格来源 |
|---|---|---|
| `transmission.csv` | `theta_a` `theta_h` `theta_t`（传导阈值）、`beta_a` `beta_h` `beta_t` `beta_o`（传导系数）、`u_a` `u_h` `u_t` `u_o` `u_s`（软饱和尺度）、`epsilon` | [`统一影响公式.md`](统一影响公式.md) §4 |
| `decay.csv` | 跨天衰减系数（好感/敌对/信任/压力） | 主文档 §3.5 |
| `phases.csv` | 各相位 tick 数与规则启用子集 | 主文档 §3.2、§3.3 |

### 2.3 数值表 `data/balance/w_events.csv`

统一增量公式的 `W_event` 全表（主文档 §6.1）。字段：`event_id`、`axis`（A/H/T/S）、`delta`、`delta_min`、`delta_max`、`note`。

**所有数值必须可追溯到 v3.0 的某条规则或标定目标（§3.4）**，不允许无出处的数字。

**全局铁律：`delta ∈ [1,5]`**（含正负号）——`config_loader` 启动时校验本表，越界直接报错；重大事件不得用大 `delta` 表达，改用「多轴联动 + 状态标签 + 阈值相变」。见 [`统一影响公式.md`](统一影响公式.md) §2.5。

### 2.4 难度分档（预留结构）

- 所有规则参数与数值表支持按难度覆盖：`easy / standard / hard`（对应抽取 8/16/24 个 NPC）。
- 初始实现三档共用同一份初始值；按 主文档 §3.4 标定目标跑批量局后，再对分档敏感参数（如相邻热络的涓流增量、`beta`、`theta`）逐档分化。
- 实现方式：CSV 加 `difficulty` 列（空 = 三档通用），装载时按当前难度优先取覆盖值、缺省回退通用值。

## 3. 派生数据（只读，不存储）

| 数据 | 派生方式 | 规格 |
|---|---|---|
| 情绪标签 | 压力区间 × 近期事件效价 × 性格底色 | 主文档 §8.3 |
| 簇标签 / 孤立标签 | 强连接图连通分量 + 稳定性滤波（≥5 tick / ≥10 tick） | 主文档 §10（观察层） |
| 感知态度 | 真实态度经透明度过滤 + 信任校准 | 主文档 §9.1、§7.4 |
| 力量指数（用于可视化） | 由 A/H/T 与压力组合，仅表现层使用 | 待定（见 `../art/视觉风格指南.md`） |

## 4. 存档模型

- 关卡粒度：**单日 = 一个自然存档单元**（主文档 §3.1）。存档点位于每天"放学结算"完成后。
- 存档内容：关系矩阵 + 个体属性 + 当日事件日志引用 + 玩家推理板状态 + 随机数种子。
- 格式：`user://savegame.dat`（现有原型路径）+ 版本号字段，便于后续迁移。
- 单局回放（进阶，主文档 §14.3）依赖事件日志的完整记录：**日志必须可重放**，因此随机数必须来自可复现的种子化 RNG。
